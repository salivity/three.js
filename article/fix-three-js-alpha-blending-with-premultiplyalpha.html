Fix Three.js Alpha Blending with PremultiplyAlpha

Transparent textures in Three.js often produce visible visual defects such as dark halos, dirty fringes, or inaccurate blending around translucent edges. These artifacts occur because standard interpolation blends fully transparent background pixels—typically stored as transparent black—into adjacent edge colors. You can eliminate these dark borders and achieve clean transparency by enabling premultiplyAlpha on your texture and configuring your material to handle premultiplied values correctly.

Understanding the Dark Fringe Issue

Standard straight alpha textures store color (\(RGB\)) and opacity (\(A\)) independently. When the GPU performs bilinear filtering on a straight alpha texture, it interpolates the color values and alpha values separately. If a bright, fully opaque pixel sits next to a transparent pixel with an RGB value of \((0, 0, 0, 0)\), the interpolated intermediate pixels become darker because their color values are being averaged toward black.

When drawn to the screen using standard alpha blending equations, this causes a noticeable dark fringe around the silhouette of transparent objects.

Premultiplied alpha solves this by multiplying the RGB components by the alpha value before interpolation:

\[\text{RGB}_{\text{premultiplied}} = \text{RGB} \times \text{Alpha}\]

During composition, the graphics hardware uses an additive blend mode for the color channels while using the alpha value for background attenuation, preventing transparent pixels from pulling edge colors toward black.

Enabling premultiplyAlpha on a Three.js Texture

To fix transparency artifacts, configure the texture to decode with premultiplied alpha and set your material's blending mode accordingly.

1. Configure the Texture

Set the premultiplyAlpha property of the THREE.Texture instance to true. This instructs WebGL to use the UNPACK_PREMULTIPLY_ALPHA_WEBGL pixel store parameter when uploading the texture data to the GPU.

import * as THREE from 'three';

const textureLoader = new THREE.TextureLoader();

const texture = textureLoader.load('textures/particle.png', (loadedTexture) => {
  loadedTexture.premultiplyAlpha = true;
  loadedTexture.needsUpdate = true;
});

2. Configure the Material

Once the texture is uploaded as premultiplied, the material rendering that texture must be notified so Three.js can adjust the blend function. Set premultipliedAlpha: true on the material alongside transparent: true.

const material = new THREE.MeshStandardMaterial({
  map: texture,
  transparent: true,
  premultipliedAlpha: true,
  roughness: 0.5,
  metalness: 0.1
});

const mesh = new THREE.Mesh(new THREE.PlaneGeometry(5, 5), material);
scene.add(mesh);

When premultipliedAlpha is enabled on the material, Three.js adjusts the underlying WebGL blend factors:

  • Source Factor: gl.ONE (instead of gl.SRC_ALPHA)
  • Destination Factor: gl.ONE_MINUS_SRC_ALPHA

Handling WebGLRenderer Canvas Transparency

If you are rendering transparent Three.js scenes over an HTML background, the WebGL canvas itself must also handle alpha premultiplication correctly to prevent dark edges where 3D elements overlap HTML DOM elements.

Ensure the WebGLRenderer initializes with matching settings:

const renderer = new THREE.WebGLRenderer({
  alpha: true,
  premultipliedAlpha: true,
  antialias: true
});

When both the renderer and canvas context agree on premultiplication, the browser compositor properly blends the canvas layer with the surrounding web page elements without fringe artifacts.
