Custom WebGL Stencil Masks Alongside Three.js

This article explains how to implement a custom stencil mask by directly accessing the WebGL rendering context alongside a Three.js scene. While Three.js provides high-level stencil properties on materials, managing the stencil buffer via raw WebGL grants precise control over multi-pass rendering, non-standard depth/stencil operations, and portal-like masking effects. You will learn how to configure the WebGL renderer, manipulate the low-level stencil buffer, and prevent Three.js state caching conflicts during execution.

1. Enable the Stencil Buffer

To use the stencil buffer, you must explicitly enable it when instantiating the Three.js WebGLRenderer. By default, the stencil buffer is enabled in Three.js, but explicitly defining it ensures your graphics pipeline allocates the required 8-bit buffer:

const renderer = new THREE.WebGLRenderer({
  antialias: true,
  stencil: true
});
renderer.autoClear = false; // Disable auto-clearing to control passes manually

Setting renderer.autoClear = false is essential because manual stencil rendering requires multiple discrete passes: clearing, drawing the mask, and drawing the masked content.

2. Access the Raw WebGL Context

You can retrieve the underlying WebGL context using renderer.getContext(). Alongside this, access renderer.state to synchronize Three.js's internal state machine with your manual modifications:

const gl = renderer.getContext();

3. Configure the Masking Workflow

A custom stencil operation requires two separate scene graphs or render groups:

  1. Mask Object: The geometry that defines the shape of the mask. Its color and depth writing are typically disabled.
  2. Target Object: The geometry that should only appear inside (or outside) the masked region.

4. Implement the Custom Render Loop

To execute the masking pass directly via WebGL, set up the stencil operations within your request animation frame loop:

function render() {
  requestAnimationFrame(render);

  // 1. Clear color, depth, and stencil buffers
  renderer.clear(true, true, true);

  // 2. Enable stencil testing directly via WebGL
  gl.enable(gl.STENCIL_TEST);

  // --- PASS 1: Write to the Stencil Buffer ---
  // Configure WebGL to always pass the test and write '1' into the stencil buffer
  gl.stencilFunc(gl.ALWAYS, 1, 0xFF);
  gl.stencilOp(gl.KEEP, gl.KEEP, gl.REPLACE);
  gl.stencilMask(0xFF); // Enable writing to the stencil buffer

  // Disable color and depth writes so the mask itself is invisible
  gl.colorMask(false, false, false, false);
  gl.depthMask(false);

  // Render the mask object
  renderer.render(maskScene, camera);

  // --- PASS 2: Render Content Using the Mask ---
  // Re-enable color and depth writes
  gl.colorMask(true, true, true, true);
  gl.depthMask(true);

  // Configure stencil to only pass where the buffer equals '1'
  gl.stencilFunc(gl.EQUAL, 1, 0xFF);
  gl.stencilOp(gl.KEEP, gl.KEEP, gl.KEEP);
  gl.stencilMask(0x00); // Disable further writing to the stencil buffer

  // Render the actual visible objects that need to be clipped
  renderer.render(contentScene, camera);

  // --- CLEANUP ---
  // Disable stencil test and reset WebGL state for standard Three.js usage
  gl.disable(gl.STENCIL_TEST);
  renderer.resetState();
}

5. Managing Three.js Internal State

Three.js tracks its own WebGL state internally to avoid redundant GPU calls. Directly altering the context with methods like gl.enable() or gl.stencilFunc() can desynchronize Three.js's internal cache.

Calling renderer.resetState() at the end of your custom rendering steps forces Three.js to re-bind its shaders, depth states, and stencil flags on the next frame. This prevents visual artifacts, broken materials, or unexpected occlusion issues when mixing custom WebGL pipeline instructions with native Three.js components.
