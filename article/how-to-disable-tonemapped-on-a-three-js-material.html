How to Disable toneMapped on a Three.js Material

When applying global tone mapping and exposure adjustments in Three.js, every rendered surface is altered by default to fit the dynamic range of the display. However, specific objects—such as user interface overlays, background plates, or color-critical assets—often need to display their exact hex colors without being affected by scene lighting or exposure. This guide explains how to disable the toneMapped property on individual Three.js materials so they completely bypass global tone mapping pipelines.

Understanding the toneMapped Property

In Three.js, tone mapping is usually configured on the renderer via renderer.toneMapping and controlled globally using renderer.toneMappingExposure.

Every material that inherits from the base THREE.Material class includes a boolean property called toneMapped. By default, this property is set to true, meaning the final pixel color calculated for that material will pass through the renderer's tone mapping algorithm. Setting toneMapped to false instructs the shader to output the raw calculated color directly to the screen, ignoring both the selected tone mapping operator and the global exposure value.

How to Set toneMapped to False

You can disable tone mapping either when instantiating a new material or by mutating an existing material instance.

1. During Material Instantiation

Pass toneMapped: false inside the material parameter configuration object:

import * as THREE from 'three';

const unmappedMaterial = new THREE.MeshBasicMaterial({
  color: 0xff0000,
  toneMapped: false
});

const mesh = new THREE.Mesh(geometry, unmappedMaterial);
scene.add(mesh);

This works with any material type, including MeshStandardMaterial, MeshPhysicalMaterial, and ShaderMaterial.

2. On an Existing Material

If the material is already created or imported via a model loader (such as GLTFLoader), modify the property directly on the instance:

material.toneMapped = false;
material.needsUpdate = true;

Setting material.needsUpdate = true ensures the WebGL program recompiles to remove the tone mapping calculations from the fragment shader.

Traversing an Imported Model

When working with imported 3D models where certain parts must ignore exposure, traverse the object hierarchy to disable tone mapping across all child meshes:

gltfModel.traverse((child) => {
  if (child.isMesh && child.material) {
    // Handle multi-materials or single materials
    if (Array.isArray(child.material)) {
      child.material.forEach((mat) => {
        mat.toneMapped = false;
        mat.needsUpdate = true;
      });
    } else {
      child.material.toneMapped = false;
      child.material.needsUpdate = true;
    }
  }
});

Common Use Cases

  • HUD and UI Elements: Keeping 2D overlays, text labels, and health bars crisp and color-accurate regardless of dynamic scene exposure.
  • Emissive Highlights: Preventing bright, glowing surfaces from shifting hue or desaturating due to photographic tone mappers like ACESFilmicToneMapping.
  • Skyboxes and Backgrounds: Ensuring that environmental backdrops display true to their original source imagery.
