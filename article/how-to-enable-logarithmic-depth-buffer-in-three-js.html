How to Enable Logarithmic Depth Buffer in Three.js

Rendering massive planetary scales in Three.js often causes distant meshes to flicker and tear, an artifact known as z-fighting. This occurs because standard depth buffers allocate precision linearly, leaving minimal depth resolution for objects far from the camera. This guide explains how to resolve this issue by enabling the logarithmicDepthBuffer parameter directly on the WebGLRenderer, ensuring stable rendering across astronomical distances.

The Problem: Z-Fighting at Planetary Scales

In 3D graphics, the depth buffer (Z-buffer) keeps track of how close objects are to the camera. By default, WebGL uses a reciprocal depth distribution. When setting up a massive scene—such as a solar system with a camera near plane of 0.1 and a far plane of 10,000,000—the standard 24-bit depth buffer exhausts its precision rapidly as distance increases. Polygons positioned near each other fight for the same depth values, producing distracting visual flickering.

How to Enable logarithmicDepthBuffer

To eliminate this flickering, you must pass logarithmicDepthBuffer: true into the WebGLRenderer initialization options. This must be set during instantiation; it cannot be toggled dynamically later.

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer({
    antialias: true,
    logarithmicDepthBuffer: true
});

renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

Camera Configuration

While the logarithmic depth buffer significantly improves depth distribution across vast scales, camera clipping planes still require proper configuration. Do not set camera.near to 0, as logarithmic depth calculations require a positive non-zero value.

const fov = 60;
const aspect = window.innerWidth / window.innerHeight;
const near = 0.1;
const far = 1e27; // Supports extreme cosmic scales

const camera = new THREE.PerspectiveCamera(fov, aspect, near, far);

How It Works

A logarithmic depth buffer recalculates depth values per vertex or per fragment using a logarithmic scale rather than a standard projection matrix division. This spreads depth precision evenly across exponentially growing distances, ensuring that objects separated by small distances billions of units away maintain their spatial ordering without visual overlap.

Performance and Shader Considerations

  1. Hardware Overhead: Computing logarithms in the shader pipeline introduces a slight performance cost. While negligible on modern desktop GPUs, it may impact performance on low-end mobile devices.
  2. Built-in Materials: Three.js automatically injects the required logarithmic depth code into all standard built-in materials (MeshStandardMaterial, MeshBasicMaterial, etc.).
  3. Custom Shaders: If using ShaderMaterial, you must include the standard Three.js logarithmic depth shader chunks:
    • In the vertex shader: 
      #include <logdepthbuf_pars_vertex>
void main() {
    #include <begin_vertex>
    #include <project_vertex>
    #include <logdepthbuf_vertex>
}
    • In the fragment shader: 
      #include <logdepthbuf_pars_fragment>
void main() {
    #include <logdepthbuf_fragment>
    gl_FragColor = vec4(1.0, 0.0, 0.0, 1.0);
}
