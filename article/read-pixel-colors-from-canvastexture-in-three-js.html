Read Pixel Colors from CanvasTexture in Three.js

This article explains how to extract specific pixel color values from a Three.js CanvasTexture via the WebGL pipeline rather than accessing the underlying 2D canvas context directly. By rendering the texture onto an off-screen WebGLRenderTarget and sampling the GPU buffer using WebGLRenderer.readRenderTargetPixels, you can retrieve accurate RGBA values entirely within Three.js APIs.

The Render Target Approach

When you cannot or do not want to call getImageData() directly on the source HTML canvas element, you must query the texture data after it has been uploaded to the GPU. Three.js does not provide a direct method to read raw texture memory without a render pass. Instead, you render the CanvasTexture onto a WebGLRenderTarget and read back the target's pixel data.

1. Set Up the Off-Screen Scene and Render Target

To sample pixels, create a dedicated 1×1 WebGLRenderTarget (or one matching the texture size if reading multiple coordinates) alongside a minimal orthographic camera and a plane mesh carrying the texture.

import * as THREE from 'three';

// Assume 'renderer' and 'canvasTexture' are already initialized
const width = canvasTexture.image.width;
const height = canvasTexture.image.height;

// Create a 1x1 render target for single-pixel reading
const pixelRenderTarget = new THREE.WebGLRenderTarget(1, 1, {
  minFilter: THREE.NearestFilter,
  magFilter: THREE.NearestFilter,
  format: THREE.RGBAFormat,
  type: THREE.UnsignedByteType,
});

// Set up an isolated orthographic scene
const readScene = new THREE.Scene();
const readCamera = new THREE.OrthographicCamera(-0.5, 0.5, 0.5, -0.5, 0, 1);

const quadMaterial = new THREE.MeshBasicMaterial({
  map: canvasTexture,
  depthTest: false,
  depthWrite: false,
});

const quadGeometry = new THREE.PlaneGeometry(1, 1);
const quadMesh = new THREE.Mesh(quadGeometry, quadMaterial);
readScene.add(quadMesh);

2. Extract the Pixel Color

To read a specific (x, y) coordinate, configure the camera view bounds to target that specific pixel, render the scene to the render target, and read the pixel buffer.

Keep in mind that WebGL's coordinate system starts at the bottom-left corner, whereas HTML canvas coordinates originate from the top-left corner. You must invert the vertical coordinate accordingly.

function getPixelColor(renderer, x, y, textureWidth, textureHeight) {
  // Convert top-left (canvas) coordinates to bottom-left (WebGL) coordinates
  const glY = textureHeight - y - 1;

  // Set the camera viewport to focus on the exact 1x1 pixel region
  readCamera.setViewOffset(
    textureWidth,
    textureHeight,
    x,
    glY,
    1,
    1
  );

  // Preserve existing renderer state
  const currentRenderTarget = renderer.getRenderTarget();

  // Render the quad into the 1x1 render target
  renderer.setRenderTarget(pixelRenderTarget);
  renderer.render(readScene, readCamera);

  // Read the pixel data into a Uint8Array
  const pixelBuffer = new Uint8Array(4);
  renderer.readRenderTargetPixels(pixelRenderTarget, 0, 0, 1, 1, pixelBuffer);

  // Restore the previous render target
  renderer.setRenderTarget(currentRenderTarget);
  readCamera.clearViewOffset();

  return {
    r: pixelBuffer[0],
    g: pixelBuffer[1],
    b: pixelBuffer[2],
    a: pixelBuffer[3],
  };
}

Usage Example

Call the function by passing your renderer and desired pixel coordinates:

const color = getPixelColor(
  renderer,
  50, // X coordinate
  100, // Y coordinate
  canvasTexture.image.width,
  canvasTexture.image.height
);

console.log(`RGBA: (${color.r}, ${color.g}, ${color.b}, ${color.a})`);

Performance Considerations

Reading pixels from GPU memory to CPU memory with readRenderTargetPixels causes a pipeline stall because the CPU must wait for the GPU to finish rendering. For real-time applications requiring frequent reads across multiple frames, minimize the frequency of reads or bundle multiple pixel lookups into a single render pass to maintain high performance.
