Request WebXR optionalFeatures in Three.js

Enabling advanced XR capabilities in Three.js requires explicitly requesting features when a WebXR session initializes. This guide explains how to configure optionalFeatures—such as hand-tracking and local-floor—using Three.js helper buttons like VRButton or custom session initialization code, ensuring your application gains access to device hardware capabilities without failing on unsupported platforms.

Configuring Features via VRButton or ARButton

Three.js provides VRButton and ARButton utilities to simplify WebXR setup. Both helper classes accept an options object as a second parameter, allowing you to define a sessionInit object containing your desired optionalFeatures.

import * as THREE from 'three';
import { VRButton } from 'three/addons/webxr/VRButton.js';

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.xr.enabled = true;
document.body.appendChild(renderer.domElement);

// Configure sessionInit with optionalFeatures
const sessionInit = {
  optionalFeatures: ['local-floor', 'hand-tracking', 'bounded-floor', 'layers']
};

// Pass sessionInit to the button utility
document.body.appendChild(VRButton.createButton(renderer, sessionInit));

Why Use optionalFeatures Instead of requiredFeatures?

The WebXR Device API separates capabilities into requiredFeatures and optionalFeatures:

  • requiredFeatures: If the user's browser, platform, or headset does not support any feature listed here, session initialization rejects immediately and fails to launch.
  • optionalFeatures: The browser attempts to grant access to these features, but if the device does not support them, the session initializes normally without throwing an error.

Features like hand-tracking should almost always be requested as optionalFeatures so that users using standard 6DoF motion controllers can still run the experience.

Accessing Feature Data in the Render Loop

Once requested, verify and handle the features in your scene logic.

Local Floor Reference Space

When local-floor is granted, set the renderer's reference space type to use floor-level tracking:

renderer.xr.setReferenceSpaceType('local-floor');

Hand Tracking

To access hand data when hand-tracking is active, use the hand controllers provided by renderer.xr:

const hand1 = renderer.xr.getHand(0);
scene.add(hand1);

const hand2 = renderer.xr.getHand(1);
scene.add(hand2);

// Optionally attach joint models using XRHandModelFactory
import { XRHandModelFactory } from 'three/addons/webxr/XRHandModelFactory.js';

const handModelFactory = new XRHandModelFactory();
hand1.add(handModelFactory.createHandModel(hand1, 'mesh'));
hand2.add(handModelFactory.createHandModel(hand2, 'mesh'));

Custom Session Initialization Without Helper Buttons

If you create a custom UI to start the WebXR session instead of using VRButton, pass the optionalFeatures directly to the WebXR API through navigator.xr.requestSession:

async function startXRSession() {
  const session = await navigator.xr.requestSession('immersive-vr', {
    optionalFeatures: ['local-floor', 'hand-tracking']
  });

  await renderer.xr.setSession(session);
}

This ensures the WebGL context binds to the newly created session with all requested features enabled.
