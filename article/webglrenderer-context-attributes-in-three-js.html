WebGLRenderer Context Attributes in Three.js

Configuring WebGL context attributes in Three.js is achieved by passing a configuration object directly into the THREE.WebGLRenderer constructor during instantiation. Attributes such as stencil, alpha, and antialias request specific buffer capabilities directly from the browser's underlying WebGL context. Because the WebGL rendering context is initialized alongside the HTML <canvas> element and its attributes are immutable once created, these properties must be explicitly declared at initialization.

Initializing WebGLRenderer with Context Attributes

To define context attributes, pass a JavaScript object containing key-value pairs into the THREE.WebGLRenderer constructor. For example, to explicitly enable the stencil buffer, pass { stencil: true }:

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer({
  canvas: document.querySelector('#webgl-canvas'),
  stencil: true,
  antialias: true,
  alpha: false,
  depth: true,
  powerPreference: 'high-performance',
  preserveDrawingBuffer: false
});

renderer.setSize(window.innerWidth, window.innerHeight);
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

In Three.js, stencil defaults to true, but explicitly setting it ensures clarity and prevents buffer allocation issues when creating complex effects like masking, planar clipping, or constructive solid geometry (CSG). Conversely, passing stencil: false saves memory if stencil operations are not needed.

Key WebGL Context Attributes

The configuration object accepts several standard WebGL context attributes:

  • stencil (boolean): Allocates a stencil buffer (typically 8 bits per pixel) for masking and clipping operations.
  • depth (boolean): Allocates a depth buffer (typically at least 16 bits) for depth testing. Defaults to true.
  • alpha (boolean): Determines whether the canvas contains an alpha channel for page compositing. Defaults to false.
  • antialias (boolean): Requests standard Multi-Sample Anti-Aliasing (MSAA) from the hardware. Defaults to false.
  • preserveDrawingBuffer (boolean): Retains the render buffers after rendering. If false, the buffer is cleared automatically after presentation. Set to true if you need to capture screenshots using canvas.toDataURL(). Defaults to false.
  • powerPreference (string): Provides a hint to the user agent regarding GPU selection on dual-GPU devices ('default', 'high-performance', or 'low-power').

Using Stencil Operations with Materials

Once stencil: true is initialized on the renderer, you can manipulate the stencil buffer using material properties. Three.js exposes standard WebGL stencil functions directly through THREE.Material:

const material = new THREE.MeshBasicMaterial({ color: 0xff0000 });

material.stencilWrite = true;
material.stencilRef = 1;
material.stencilFunc = THREE.AlwaysStencilFunc;
material.stencilZPass = THREE.ReplaceStencilOp;

This configuration writes the reference value 1 into the stencil buffer wherever the mesh's fragments pass the depth test, allowing subsequent render calls to read from and filter against that stencil mask.

Providing an Existing WebGL Context

If you must manage the WebGLRenderingContext or WebGL2RenderingContext manually outside of Three.js, create the context via the native canvas API and pass it using the context attribute:

const canvas = document.createElement('canvas');
const gl = canvas.getContext('webgl2', {
  stencil: true,
  antialias: true
});

const renderer = new THREE.WebGLRenderer({
  canvas: canvas,
  context: gl
});

When passing an existing context, all context-related properties defined in the Three.js parameters object are ignored in favor of the parameters used during the native canvas.getContext() call.
