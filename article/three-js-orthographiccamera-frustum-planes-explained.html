Three.js OrthographicCamera Frustum Planes Explained

In Three.js, an OrthographicCamera renders a scene using parallel projection, meaning objects maintain their size regardless of their distance from the camera. This article explains the roles and differences between the camera's left, right, top, and bottom frustum planes. These four boundaries, along with the near and far planes, construct a rectangular bounding box that defines the visible area of your 3D world, dictates the camera's aspect ratio, and controls how spatial coordinates map to the screen.

The Orthographic Frustum

Unlike a PerspectiveCamera, which uses a pyramid-shaped viewing frustum that expands into the distance, an OrthographicCamera uses a rectangular cuboid. Any object or part of a geometry outside of this box is clipped and not rendered.

The left, right, top, and bottom parameters specify the positions of the vertical and horizontal boundaries in the camera's local coordinate space.

The Difference Between the Planes

The primary differences lie in the axes they constrain and the directional boundaries they enforce:

  • left (Horizontal Minimum): Defines the minimum X-axis boundary of the view volume. Any geometry located to the left of this plane (where local \(X < left\)) is clipped.
  • right (Horizontal Maximum): Defines the maximum X-axis boundary of the view volume. Any geometry located to the right of this plane (where local \(X > right\)) is clipped.
  • top (Vertical Maximum): Defines the maximum Y-axis boundary of the view volume. Any geometry positioned above this plane (where local \(Y > top\)) is clipped.
  • bottom (Vertical Minimum): Defines the minimum Y-axis boundary of the view volume. Any geometry positioned below this plane (where local \(Y < bottom\)) is clipped.

Together:

  • left and right determine the total visible width (\(Width = right - left\)).
  • top and bottom determine the total visible height (\(Height = top - bottom\)).

Coordinate Origin and Framing

How you set these planes establishes where the origin \((0, 0)\) appears on the screen:

  • Centered Origin (Standard 3D): Setting symmetric boundaries (e.g., left = -5, right = 5, top = 5, bottom = -5) places the origin \((0, 0)\) directly in the center of the viewport.
  • Top-Left Origin (2D / UI Layouts): Setting asymmetric boundaries such as left = 0, right = canvasWidth, top = 0, and bottom = canvasHeight aligns the camera with standard 2D screen coordinates, placing \((0, 0)\) at the top-left corner.

Managing Aspect Ratio and Distortion

The relationship between horizontal boundaries (right - left) and vertical boundaries (top - bottom) determines the frustum's aspect ratio:

\[\text{Frustum Aspect Ratio} = \frac{\text{right} - \text{left}}{\text{top} - \text{bottom}}\]

If this ratio does not match the aspect ratio of the rendering canvas (\(\text{Canvas Width} / \text{Canvas Height}\)), the rendered scene will distort, causing spheres to look like ovals and squares to appear as rectangles.

To maintain proper proportions during window resizing, adjust the horizontal planes relative to the canvas aspect ratio:

const aspect = window.innerWidth / window.innerHeight;
const frustumSize = 10;

camera.left = (-frustumSize * aspect) / 2;
camera.right = (frustumSize * aspect) / 2;
camera.top = frustumSize / 2;
camera.bottom = -frustumSize / 2;

camera.updateProjectionMatrix();

Whenever you modify any of these four plane values after the camera has been instantiated, you must call camera.updateProjectionMatrix() to apply the changes to the rendering pipeline.
