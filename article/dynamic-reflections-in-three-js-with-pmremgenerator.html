Dynamic Reflections in Three.js with PMREMGenerator

This article explains how to generate dynamic reflections in Three.js using the PMREMGenerator.fromScene method. You will learn how to initialize the pre-filtered radiance environment map (PMREM) generator, capture the surrounding 3D geometry as an environment map, apply the resulting texture to materials, and manage updates efficiently in the animation loop while avoiding common rendering artifacts like recursive self-reflection and memory leaks.

Initializing the PMREMGenerator

PMREMGenerator precomputes mipmapped specular environment maps from cube maps or scenes, which are required for physically based materials like MeshStandardMaterial and MeshPhysicalMaterial. To generate reflections from your actual scene geometry, instantiate the generator by passing your WebGLRenderer instance:

const pmremGenerator = new THREE.PMREMGenerator(renderer);
pmremGenerator.compileCubemapShader();

Compiling the shader ahead of time ensures that the first generation pass runs smoothly without introducing shader compilation stutter.

Capturing the Scene

The fromScene() method renders the scene from the center of a cube camera and filters it into an environment map:

const renderTarget = pmremGenerator.fromScene(scene, sigma, near, far);
  • scene: The Three.js scene containing the surrounding geometry you want to reflect.
  • sigma (optional): Blur radius applied to the PMREM (default is 0).
  • near (optional): Near clipping distance for the capture camera (default is 0.1).
  • far (optional): Far clipping distance for the capture camera (default is 100).

The output is a WebGLRenderTarget containing the filtered cubemap. You can assign its .texture directly to scene.environment for global scene lighting and reflections, or to an individual material's envMap property.

Implementing Dynamic Updates in the Render Loop

To reflect changing geometry or animated objects, you must regenerate the environment map continuously or on demand. When performing dynamic captures, follow these critical steps:

  1. Hide the reflective mesh: If the mesh receiving the reflection is visible during fromScene(), it may reflect itself or occlude other geometry incorrectly.
  2. Dispose of the previous render target: Every call to fromScene() creates a new WebGLRenderTarget. You must dispose of the previous target to avoid rapid memory leaks.
  3. Generate the new target: Capture the scene and assign the new texture.
  4. Restore mesh visibility: Make the reflective mesh visible again for the main render pass.

Here is an example implementation inside the render loop:

let dynamicEnvTarget = null;

function animate() {
  requestAnimationFrame(animate);

  // Animate surrounding objects
  movingMesh.rotation.y += 0.01;

  // 1. Hide the reflective object to prevent self-reflection
  reflectiveMesh.visible = false;

  // 2. Dispose of the previous target before generating a new one
  if (dynamicEnvTarget) {
    dynamicEnvTarget.dispose();
  }

  // 3. Generate the PMREM from the current scene
  dynamicEnvTarget = pmremGenerator.fromScene(scene);
  reflectiveMesh.material.envMap = dynamicEnvTarget.texture;
  reflectiveMesh.material.needsUpdate = true;

  // 4. Restore visibility for final rendering
  reflectiveMesh.visible = true;

  // Render the final frame to the screen
  renderer.render(scene, camera);
}

Performance Optimization

Rendering a full PMREM each frame requires rendering the scene six times (once per cubemap face) followed by multiple filtering passes. This is computationally expensive. To optimize performance:

  • Throttle updates: Only run fromScene() every few frames, or only when surrounding geometry actively moves.
  • Use scene layers: Assign low-detail versions of surrounding meshes to a specific Object3D.layers mask and configure the camera to only render lightweight geometry during the reflection capture.
  • Clean up properly: When tearing down the scene or no longer needing dynamic reflections, call dynamicEnvTarget.dispose() and pmremGenerator.dispose() to release GPU memory.
