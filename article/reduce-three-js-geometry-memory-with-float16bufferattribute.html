Reduce Three.js Geometry Memory with Float16BufferAttribute

In graphics-heavy Three.js applications, high-density meshes can quickly saturate GPU memory and degrade performance. By replacing standard 32-bit floating-point geometry attributes with THREE.Float16BufferAttribute, you can cut the buffer memory footprint of your vertex attributes directly in half. This optimization leverages half-precision floating-point numbers (16-bit) to retain visual fidelity across models while lowering memory bandwidth overhead and mobile crash rates.

Understanding 32-Bit vs. 16-Bit Floats

By default, Three.js uses THREE.Float32BufferAttribute for vertex data such as positions, normals, and texture coordinates (UVs). A 32-bit float requires 4 bytes per component, meaning a standard position vector \((x, y, z)\) consumes 12 bytes per vertex.

THREE.Float16BufferAttribute uses half-precision floats conforming to the IEEE 754 standard, requiring only 2 bytes per component. This instantly reduces the memory footprint of that attribute by 50% without altering the geometry's vertex count or topology.

When to Use Float16 Without Quality Loss

Half-precision provides 1 sign bit, 5 exponent bits, and 10 mantissa bits (roughly 3 to 4 decimal digits of precision). Because of this:

  • UV Coordinates: UVs generally range between 0.0 and 1.0. A 16-bit float offers more than enough precision to map textures seamlessly without visible mapping shifts or seams.
  • Vertex Normals: Normals are unit vectors with values strictly constrained between -1.0 and 1.0. Precision loss at this scale is negligible, meaning lighting and shading calculations remain virtually identical to 32-bit representations.
  • Vertex Colors: RGB/RGBA channels clamped between 0.0 and 1.0 will look identical when stored in half-precision.
  • Vertex Positions: Best suited for models normalized within local bounds (e.g., centered around origin and scaled moderately). If an object is extremely large or placed far from the origin in world coordinates, precision issues can cause visible mesh distortion or jitter.

Implementation

To use Float16BufferAttribute, populate it with a Uint16Array containing half-precision binary representations, or use the DataUtils.toHalfFloat helper provided by Three.js to convert standard JavaScript numbers.

import * as THREE from 'three';

// 1. Example: Creating a new Float16BufferAttribute manually
const uvValues = [0, 0, 1, 0, 1, 1, 0, 1];
const halfFloatArray = new Uint16Array(uvValues.length);

for (let i = 0; i < uvValues.length; i++) {
  halfFloatArray[i] = THREE.DataUtils.toHalfFloat(uvValues[i]);
}

const geometry = new THREE.BufferGeometry();
geometry.setAttribute('uv', new THREE.Float16BufferAttribute(halfFloatArray, 2));

Converting Existing Geometries

To optimize imported models (such as GLTF or OBJ models), you can iterate over the attributes of existing geometries and convert select attributes from 32-bit to 16-bit in place:

import * as THREE from 'three';

function optimizeGeometryAttributes(geometry) {
  const targetAttributes = ['uv', 'normal'];

  targetAttributes.forEach((attrName) => {
    const attr = geometry.getAttribute(attrName);
    
    // Only convert if it's currently a Float32BufferAttribute
    if (attr && attr instanceof THREE.Float32BufferAttribute) {
      const count = attr.count * attr.itemSize;
      const halfArray = new Uint16Array(count);

      for (let i = 0; i < count; i++) {
        halfArray[i] = THREE.DataUtils.toHalfFloat(attr.array[i]);
      }

      geometry.setAttribute(
        attrName,
        new THREE.Float16BufferAttribute(halfArray, attr.itemSize, attr.normalized)
      );
      
      // Dispose old attribute buffer to free GPU resources
      attr.needsUpdate = false;
    }
  });
}

Hardware Support and Considerations

WebGL 2.0 natively supports half-float vertex attributes, making this method universally supported on modern desktop and mobile browsers. When applied selectively to UVs, normals, and appropriately scaled position buffers, Float16BufferAttribute slashes buffer storage requirements across both CPU RAM and GPU VRAM with zero discernible difference in visual quality.
