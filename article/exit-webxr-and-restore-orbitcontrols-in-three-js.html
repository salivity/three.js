Exit WebXR and Restore OrbitControls in Three.js

Transitioning an interactive Three.js application from an immersive WebXR session back to standard desktop or mobile view requires cleanly terminating the session, restoring camera transforms, and re-enabling pointer-based interactions. This guide covers how to listen for session termination, reset the WebXR manager, and properly reinitialize OrbitControls to prevent frozen camera matrices or control conflicts.

The Challenge with WebXR and OrbitControls

When an immersive session begins, Three.js overrides the standard camera matrix with the tracking data provided by the XR device, and renderer.xr.enabled takes over the rendering pipeline. Simultaneously, standard input controllers like OrbitControls are either disabled or superseded by XR input sources. Exiting the session without resetting the camera matrices and updating the controls will leave the user with an unresponsive or incorrectly oriented viewport.

Step 1: Terminate the WebXR Session

To initiate the shutdown of an active XR session programmatically, retrieve the current session from the WebGLRenderer and invoke its end() method.

async function exitXRSession(renderer) {
    const session = renderer.xr.getSession();
    if (session) {
        await session.end();
    }
}

Step 2: Handle the sessionend Event

Rather than forcing immediate state updates, attach an event listener to the XR session's sessionend event. This guarantees the browser and hardware have fully finalized their shutdown procedures before you attempt to restore the standard scene setup.

function setupXR(renderer, camera, controls) {
    renderer.xr.addEventListener('sessionstart', () => {
        // Disable OrbitControls during immersive mode
        controls.enabled = false;
    });

    renderer.xr.addEventListener('sessionend', () => {
        cleanupXR(renderer, camera, controls);
    });
}

Step 3: Reset the Camera and Re-enable OrbitControls

Once sessionend fires, you must reset the camera's projection matrix and position back to an appropriate default or saved state, re-enable OrbitControls, and trigger an update.

function cleanupXR(renderer, camera, controls) {
    // 1. Reset camera transformation
    camera.position.set(0, 1.6, 3);
    camera.quaternion.identity();
    camera.updateProjectionMatrix();

    // 2. Re-enable OrbitControls
    controls.enabled = true;
    controls.target.set(0, 1, 0); // Re-target focal point
    controls.update();

    // 3. Reset standard animation loop if using custom loops
    renderer.setAnimationLoop(render);
}

function render() {
    controls.update();
    renderer.render(scene, camera);
}

Key Considerations

  • Save Pre-XR Transforms: If you want the camera to return to where the user was looking before entering XR, store camera.position and controls.target in variables during sessionstart and restore them in cleanupXR.
  • Renderer Loop Handling: If you modified renderer.setAnimationLoop to accommodate XR-specific frame callbacks, ensure it points back to your standard desktop render function inside the cleanup routine.
