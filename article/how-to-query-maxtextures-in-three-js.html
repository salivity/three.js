How to Query maxTextures in Three.js

Optimizing WebGL performance requires understanding client-side hardware limitations, particularly how many textures a GPU can process simultaneously within a single shader. In Three.js, these hardware constraints are abstracted and exposed through the WebGLCapabilities module. This guide demonstrates how to directly query the maxTextures property from a WebGLRenderer instance to inspect the user's texture unit limits and prevent runtime WebGL errors.

Accessing the WebGLCapabilities Object

To query hardware limits, you must first instantiate a THREE.WebGLRenderer. The renderer automatically initializes an instance of WebGLCapabilities, which queries the underlying WebGL context for device-specific parameters.

You can access these capabilities via the capabilities property on the renderer:

import * as THREE from 'three';

// Create the WebGLRenderer instance
const renderer = new THREE.WebGLRenderer();

// Access the maxTextures limit
const maxTextures = renderer.capabilities.maxTextures;

console.log(`Maximum fragment shader textures supported: ${maxTextures}`);

What maxTextures Represents

The renderer.capabilities.maxTextures property corresponds directly to the underlying WebGL constant gl.MAX_TEXTURE_IMAGE_UNITS.

  • It defines the maximum number of hardware texture units accessible by the fragment shader.
  • Typical modern desktop GPUs generally support 16 or 32 texture units, while lower-end mobile devices might support fewer (such as 8 or 16).
  • If a custom shader material or complex multi-texture Three.js material attempts to bind more textures than this limit allows, WebGL will generate an error, and the material may fail to render correctly.

Related Texture Limits in WebGLCapabilities

When handling advanced multi-texturing or vertex-displacement mapping, maxTextures is only one part of the texture budget. Three.js also provides complementary properties through WebGLCapabilities:

// Maximum textures accessible in the vertex shader (gl.MAX_VERTEX_TEXTURE_IMAGE_UNITS)
const maxVertexTextures = renderer.capabilities.maxVertexTextures;

// Total maximum textures accessible across all shader stages combined (gl.MAX_COMBINED_TEXTURE_IMAGE_UNITS)
const maxCombinedTextures = renderer.capabilities.maxCombinedTextures;

// Maximum dimensions (width/height) for any 2D texture (gl.MAX_TEXTURE_SIZE)
const maxTextureSize = renderer.capabilities.maxTextureSize;

Practical Application

Querying maxTextures is useful for implementing dynamic fallbacks for low-end devices. For example, if a scene includes materials with base color, roughness, metalness, normal, ambient occlusion, and light maps, you can adjust shader complexity at runtime:

function configureMaterial(renderer, advancedMaterial, simpleMaterial) {
    const availableUnits = renderer.capabilities.maxTextures;

    // Fall back to a simplified material if hardware limits are constrained
    if (availableUnits < 16) {
        return simpleMaterial;
    }
    
    return advancedMaterial;
}

By querying renderer.capabilities.maxTextures during application initialization, you can adapt material fidelity dynamically to guarantee cross-device compatibility.
