Fast Three.js Raycasting with three-mesh-bvh

This guide demonstrates how to dramatically speed up raycasting in Three.js when dealing with complex, high-polygon BufferGeometry by using the three-mesh-bvh library. By constructing a Bounding Volume Hierarchy (BVH) for your geometry, ray intersection checks bypass unnecessary triangle tests, reducing search time from linear complexity to logarithmic complexity.

Why Default Three.js Raycasting Struggles

By default, Three.js performs raycasting on a mesh by testing the ray against every single triangle in its BufferGeometry. On meshes with hundreds of thousands or millions of faces, this linear loop halts the main rendering thread, causing severe frame drops. The three-mesh-bvh library solves this by organizing triangles into a hierarchical tree of bounding boxes, allowing raycasters to quickly discard entire chunks of the mesh that do not intersect the ray.

1. Installation

Install the package via npm:

npm install three-mesh-bvh

2. Extending Three.js Prototypes

The easiest way to integrate three-mesh-bvh is to patch the Three.js BufferGeometry and Mesh prototypes. This enables the library to automatically intercept standard raycast calls.

import * as THREE from 'three';
import { 
    computeBoundsTree, 
    disposeBoundsTree, 
    acceleratedRaycast 
} from 'three-mesh-bvh';

// Extend BufferGeometry
THREE.BufferGeometry.prototype.computeBoundsTree = computeBoundsTree;
THREE.BufferGeometry.prototype.disposeBoundsTree = disposeBoundsTree;

// Extend Mesh raycasting
THREE.Mesh.prototype.raycast = acceleratedRaycast;

3. Generating the Bounds Tree

Once extended, you must generate the BVH on your specific geometry before running raycasts. Call computeBoundsTree() on the target BufferGeometry:

const geometry = new THREE.TorusKnotGeometry(10, 3, 400, 64); // Dense geometry
geometry.computeBoundsTree();

const material = new THREE.MeshStandardMaterial({ color: 0x00ff00 });
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

You can pass optional configuration settings to computeBoundsTree(), such as maxLeafTris (default: 10) or strategy (e.g., CENTER, AVERAGE, or SAH for Surface Area Heuristic), to optimize build time versus query performance.

4. Performing Accelerated Raycasting

With the bounds tree computed and the prototype patched, standard Three.js raycasting calls will now execute via the BVH:

const raycaster = new THREE.Raycaster();
raycaster.setFromCamera(mouseCoordinates, camera);

// Raycasting is now accelerated automatically
const intersects = raycaster.intersectObject(mesh);

if (intersects.length > 0) {
    console.log('Hit point:', intersects[0].point);
}

5. Optimizing with firstHitOnly

If you only need to know whether an intersection occurs (such as in line-of-sight checks or shadow tests) rather than gathering all intersections sorted by distance, set raycaster.firstHitOnly = true:

raycaster.firstHitOnly = true;
const hits = raycaster.intersectObject(mesh);

This flag terminates the BVH traversal as soon as a single valid intersection is discovered, saving additional computation cycles.

6. Memory Management and Updates

  • Disposal: If a mesh or its geometry is removed, release the BVH memory by calling geometry.disposeBoundsTree().
  • Deforming Geometries: If vertices move, the BVH becomes invalid. You must call geometry.computeBoundsTree() again, or use the library's refit() helper for skinned and morphing meshes where triangle topology does not change.
