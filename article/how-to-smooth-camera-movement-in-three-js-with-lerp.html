How to Smooth Camera Movement in Three.js with Lerp

This guide covers how to achieve smooth, cinematic camera transitions in a Three.js application using linear interpolation. By leveraging THREE.MathUtils.lerp, you can eliminate abrupt camera cuts and rigid tracking by gradually shifting coordinate values toward a target destination on each render frame. Below is a direct breakdown of how linear interpolation works in Three.js, how to implement it inside the animation loop, and how to make the transition framerate-independent.

Understanding the MathUtils.lerp Function

Linear interpolation calculates a value between two given points based on a fractional alpha weight. The method signature is:

THREE.MathUtils.lerp(start, end, alpha);
  • start: The current value (e.g., current camera X position).
  • end: The destination value (e.g., target camera X position).
  • alpha: The interpolation factor between 0 and 1. A lower value (such as 0.05) produces a heavier, slower smoothing effect, while a value closer to 1 results in instantaneous snapping.

Implementing Lerp in the Animation Loop

To create continuous smoothing, update the camera's coordinates toward your target coordinates on every tick of the render loop.

import * as THREE from 'three';

// 1. Define current and target vectors
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
camera.position.set(0, 5, 10);

const targetPosition = new THREE.Vector3(0, 5, 10);
const targetLookAt = new THREE.Vector3(0, 0, 0);
const currentLookAt = new THREE.Vector3(0, 0, 0);

// Example trigger: Change destination on user interaction
function moveCameraTo(x, y, z) {
  targetPosition.set(x, y, z);
}

// 2. Interpolate inside the render loop
const alpha = 0.05;

function animate() {
  requestAnimationFrame(animate);

  // Smooth position
  camera.position.x = THREE.MathUtils.lerp(camera.position.x, targetPosition.x, alpha);
  camera.position.y = THREE.MathUtils.lerp(camera.position.y, targetPosition.y, alpha);
  camera.position.z = THREE.MathUtils.lerp(camera.position.z, targetPosition.z, alpha);

  // Smooth look-at target to prevent jerky rotations
  currentLookAt.x = THREE.MathUtils.lerp(currentLookAt.x, targetLookAt.x, alpha);
  currentLookAt.y = THREE.MathUtils.lerp(currentLookAt.y, targetLookAt.y, alpha);
  currentLookAt.z = THREE.MathUtils.lerp(currentLookAt.z, targetLookAt.z, alpha);

  camera.lookAt(currentLookAt);

  renderer.render(scene, camera);
}

animate();

Note: While Vector3.lerp() can be applied to entire vectors at once, MathUtils.lerp allows granular control over single axes, field of view (camera.fov), or custom damping algorithms.

Making Camera Smoothing Framerate-Independent

Using a fixed alpha value like 0.05 causes the camera to move faster on 144Hz monitors than on 60Hz monitors. To normalize motion across different refresh rates, scale your alpha using the frame's delta time (clock.getDelta()):

const clock = new THREE.Clock();
const dampingFactor = 5; // Adjust to control speed

function animate() {
  requestAnimationFrame(animate);

  const delta = clock.getDelta();
  // Framerate-independent alpha formula
  const dynamicAlpha = 1 - Math.exp(-dampingFactor * delta);

  camera.position.x = THREE.MathUtils.lerp(camera.position.x, targetPosition.x, dynamicAlpha);
  camera.position.y = THREE.MathUtils.lerp(camera.position.y, targetPosition.y, dynamicAlpha);
  camera.position.z = THREE.MathUtils.lerp(camera.position.z, targetPosition.z, dynamicAlpha);

  camera.lookAt(targetLookAt);
  renderer.render(scene, camera);
}

By applying this decay calculation, the interpolation rate remains visually identical regardless of hardware performance or monitor refresh rate.
