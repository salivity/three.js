How to Pass a Struct Array to Three.js ShaderMaterial

Passing a custom struct array to a Three.js ShaderMaterial enables you to send structured, complex datasets—such as multiple light sources, particle properties, or bounding volumes—directly to WebGL shaders. To achieve this properly, you must define the struct within the GLSL shader code, initialize a matching array of JavaScript objects in your material uniforms, and map property types to compatible Three.js classes. This guide details the complete setup, from shader declaration to runtime updates.

1. Define the Struct in GLSL

Declare your custom struct and a fixed-size uniform array of that struct type inside your vertex or fragment shader. WebGL requires uniform array lengths to be static constants at compile time.

// Fragment Shader
struct LightSource {
    vec3 position;
    vec3 color;
    float intensity;
};

// Fixed-size array declaration
uniform LightSource uLights[2];

varying vec2 vUv;

void main() {
    vec3 finalColor = vec3(0.0);
    
    for (int i = 0; i < 2; i++) {
        float dist = distance(vUv, uLights[i].position.xy);
        finalColor += uLights[i].color * (uLights[i].intensity / (1.0 + dist));
    }
    
    gl_FragColor = vec4(finalColor, 1.0);
}

2. Format the Uniforms in JavaScript

In JavaScript, define the uniform using an object whose value property contains an array of plain JavaScript objects. Each object in the array must mirror the exact field names defined in your GLSL struct.

import * as THREE from 'three';

const lightData = [
    {
        position: new THREE.Vector3(0.2, 0.5, 0.0),
        color: new THREE.Color(1.0, 0.2, 0.2),
        intensity: 1.5
    },
    {
        position: new THREE.Vector3(0.8, 0.5, 0.0),
        color: new THREE.Color(0.2, 0.5, 1.0),
        intensity: 2.0
    }
];

const customUniforms = {
    uLights: {
        value: lightData
    }
};

3. Attach Uniforms to the ShaderMaterial

Assign the formatted uniforms object directly to your ShaderMaterial instance:

const material = new THREE.ShaderMaterial({
    vertexShader: vertexShaderSource,
    fragmentShader: fragmentShaderSource,
    uniforms: customUniforms
});

Three.js automatically detects the nested structure and uploads each element to the corresponding WebGL uniform location (such as uLights[0].position, uLights[0].color, and uLights[0].intensity).

4. Updating Uniforms Dynamically

To update values during the render loop, modify the nested properties on the existing objects directly:

function animate(time) {
    requestAnimationFrame(animate);

    // Update individual values inside the struct array
    material.uniforms.uLights.value[0].position.x = Math.sin(time * 0.002);
    material.uniforms.uLights.value[1].intensity = 1.0 + Math.cos(time * 0.003);

    renderer.render(scene, camera);
}

Key Considerations

  • Type Matching: Ensure Three.js types map precisely to the GLSL types (THREE.Vector2 for vec2, THREE.Vector3 or THREE.Color for vec3, THREE.Matrix4 for mat4, and native JavaScript numbers for float or int).
  • Static Array Sizing: GLSL arrays must have a predetermined length. If you need dynamic sizing, allocate an array to the maximum expected capacity in the shader and pass an additional uniform int uActiveCount to limit the loop iterations in GLSL.
  • Avoid Reassigning the Array: Mutate the properties of the existing objects in the array rather than assigning a new array reference on every frame to avoid unnecessary memory allocations and uniform re-linking.
