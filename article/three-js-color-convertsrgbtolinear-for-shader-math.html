Three.js Color.convertSRGBToLinear for Shader Math

When working with custom shaders in Three.js, using hex colors directly can lead to incorrect lighting, washed-out tones, or distorted blending. This article explains why color space conversion is necessary and demonstrates how to use the Color.convertSRGBToLinear() method to prepare hex colors for accurate shader mathematics.

Why Color Space Conversion Is Required

Hexadecimal color codes (such as #ff5500) are defined in the sRGB color space, which applies a non-linear gamma curve optimized for human vision on computer displays. Modern rendering engines, including Three.js, perform lighting calculations and mathematical operations in a linear color space.

If you pass an sRGB hex color directly into a custom GLSL shader as a uniform, the GPU processes non-linear values as if they were linear. This breaks physically based lighting calculations, resulting in colors that appear too bright or incorrectly saturated. Converting the color to linear space beforehand aligns your custom shader inputs with Three.js's internal rendering pipeline.

Converting Hex Colors with convertSRGBToLinear()

The THREE.Color class provides the convertSRGBToLinear() method, which mutates the color instance by converting its RGB values from sRGB gamma space to linear space.

Step-by-Step Implementation

  1. Instantiate the Color: Initialize a THREE.Color instance with your hex value or string.
  2. Convert the Color: Call convertSRGBToLinear() on the instance.
  3. Pass to the Shader: Assign the converted color to your material's uniform object.
import * as THREE from 'three';

// 1. Create a color from a hex value
const baseColor = new THREE.Color(0xff4500);

// 2. Convert from sRGB space to Linear space
baseColor.convertSRGBToLinear();

// 3. Define the custom shader material
const customMaterial = new THREE.ShaderMaterial({
  uniforms: {
    uColor: { value: baseColor }
  },
  vertexShader: `
    varying vec2 vUv;
    void main() {
      vUv = uv;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `,
  fragmentShader: `
    uniform vec3 uColor;
    varying vec2 vUv;

    void main() {
      // uColor is now in linear space, ready for accurate lighting/math
      vec3 finalColor = uColor * 0.5; // Example math operation
      gl_FragColor = vec4(finalColor, 1.0);
    }
  `
});

Handling Cloned Colors

Because convertSRGBToLinear() modifies the original THREE.Color instance in place, you should clone the color if the original sRGB values are still needed for UI elements, HTML styling, or other non-shader operations:

const originalHexColor = new THREE.Color('#3498db');

// Clone before converting to avoid mutating the original
const shaderColor = originalHexColor.clone().convertSRGBToLinear();

const uniforms = {
  uColor: { value: shaderColor }
};

Modern Three.js Color Management Considerations

In recent releases of Three.js (r152 and newer), THREE.ColorManagement.enabled is set to true by default. While standard built-in materials (such as MeshStandardMaterial) handle color space conversions automatically, custom ShaderMaterial and RawShaderMaterial instances bypass the automated uniform conversion. Manually applying Color.convertSRGBToLinear() ensures your custom shader uniforms match the color fidelity and behavior of the engine's built-in materials.
