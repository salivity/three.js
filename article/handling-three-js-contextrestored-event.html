Handling Three.js contextrestored Event

WebGL context loss occurs when the browser or operating system reclaims the GPU resources, causing all active WebGL states, buffers, and textures to be cleared. This article explains how to handle the webglcontextrestored event in Three.js, outlining the steps required to intercept context loss, re-upload textures and geometries to the GPU, recompile shaders, and safely resume your rendering loop.

1. Intercepting Context Loss

Before the browser can fire the webglcontextrestored event, you must prevent the default context-loss behavior in the webglcontextlost listener. If default behavior is not prevented, the WebGL context is permanently disabled for that canvas element.

const canvas = renderer.domElement;

canvas.addEventListener('webglcontextlost', (event) => {
    event.preventDefault();
    cancelAnimationFrame(animationFrameId); // Pause the render loop
    console.warn('WebGL context lost. Rendering paused.');
}, false);

2. Listening for webglcontextrestored

Once the operating system or browser frees up GPU memory, it restores the context and triggers webglcontextrestored. At this point, the underlying WebGL instance is fresh, meaning all GPU-side allocations—textures, buffers, and shader programs—must be re-established.

canvas.addEventListener('webglcontextrestored', () => {
    console.info('WebGL context restored. Rebuilding resources...');
    rebuildSceneResources(scene);
    animate(); // Resume the render loop
}, false);

3. Rebuilding Textures and Geometries

Three.js stores geometry attributes and loaded texture images in CPU memory unless you explicitly purge them. When the context is restored, you do not necessarily need to re-fetch assets over the network. Instead, you notify Three.js to rebind and re-upload the cached CPU data to the newly created WebGL context by setting the needsUpdate flag.

Traverse your scene graph to mark materials, textures, and geometry attributes:

function rebuildSceneResources(scene) {
    scene.traverse((object) => {
        if (!object.isMesh) return;

        // 1. Rebuild Geometries
        if (object.geometry) {
            const attributes = object.geometry.attributes;
            for (const key in attributes) {
                if (attributes[key]) {
                    attributes[key].needsUpdate = true;
                }
            }
            if (object.geometry.index) {
                object.geometry.index.needsUpdate = true;
            }
        }

        // 2. Rebuild Materials and Textures
        if (object.material) {
            const materials = Array.isArray(object.material) 
                ? object.material 
                : [object.material];

            materials.forEach((mat) => {
                // Trigger shader recompilation
                mat.needsUpdate = true;

                // Mark any assigned texture maps as needing GPU upload
                for (const prop in mat) {
                    if (mat[prop] && mat[prop].isTexture) {
                        mat[prop].needsUpdate = true;
                    }
                }
            });
        }
    });
}

4. Handling Render Targets and Shadows

If your application uses custom WebGLRenderTarget objects or shadow maps, these must be explicitly re-initialized:

  • Shadow Maps: Reset the shadow map internal targets via renderer.shadowMap.needsUpdate = true.
  • Render Targets: Call renderTarget.dispose() to clear old GPU references, then recreate the target with identical dimensions and options to generate a valid WebGL framebuffer on the new context.
  • Post-processing Passes: If using EffectComposer, invoke its resize or setup logic to rebuild internal framebuffers.

5. Simulating Context Loss for Testing

To test your restoration pipeline without waiting for actual driver crashes or memory pressure, simulate context events using the WEBGL_lose_context extension:

const ext = renderer.getContext().getExtension('WEBGL_lose_context');

// Simulate context loss
ext.loseContext();

// Simulate restoration after 2 seconds
setTimeout(() => {
    ext.restoreContext();
}, 2000);
