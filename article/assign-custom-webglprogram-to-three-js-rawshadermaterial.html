Assign Custom WebGLProgram to Three.js RawShaderMaterial

This article explains how to bypass Three.js's internal shader compilation pipeline to attach an externally compiled native WebGLProgram directly to a RawShaderMaterial. By accessing the underlying WebGL rendering context, leveraging renderer.properties, and utilizing Three.js lifecycle hooks, you can execute low-level custom shader programs while retaining the benefits of the Three.js scene graph and mesh management.

Understanding the Three.js Program Pipeline

By default, Three.js compiles shaders into an internal WebGLProgram wrapper through its WebGLPrograms manager when a material is first rendered. When working with custom WebGL pipelines—such as external WebAssembly modules, third-party rendering engines, or pre-cached binaries—you need to inject an existing WebGLProgram directly rather than letting Three.js generate one from strings.

Step 1: Compile the Native WebGLProgram

Retrieve the rendering context using renderer.getContext() and compile your custom vertex and fragment shaders using the native WebGL API.

const gl = renderer.getContext();

function createCustomProgram(gl, vsSource, fsSource) {
    const vs = gl.createShader(gl.VERTEX_SHADER);
    gl.shaderSource(vs, vsSource);
    gl.compileShader(vs);

    const fs = gl.createShader(gl.FRAGMENT_SHADER);
    gl.shaderSource(fs, fsSource);
    gl.compileShader(fs);

    const program = gl.createProgram();
    gl.attachShader(program, vs);
    gl.attachShader(program, fs);
    gl.linkProgram(program);

    return program;
}

const customGLProgram = createCustomProgram(gl, vertexShaderSource, fragmentShaderSource);

Step 2: Initialize the RawShaderMaterial

Create an empty RawShaderMaterial. Supplying dummy shader strings prevents Three.js from throwing validation errors before your custom program takes over.

const material = new THREE.RawShaderMaterial({
    vertexShader: 'void main() {}',
    fragmentShader: 'void main() {}'
});

const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

Step 3: Override the Internal Material Program

Three.js tracks internal WebGL compilation state inside renderer.properties. To assign your compiled program, inject it directly into the material's properties dictionary before rendering, or assign it dynamically using the onBeforeRender callback.

mesh.onBeforeRender = function(renderer, scene, camera, geometry, material, group) {
    const materialProperties = renderer.properties.get(material);

    // Check if the custom program is already attached
    if (!materialProperties.currentProgram || materialProperties.currentProgram.program !== customGLProgram) {
        // Construct a lightweight interface mimicking the internal WebGLProgram wrapper
        materialProperties.currentProgram = {
            program: customGLProgram,
            getUniforms: () => ({}),
            getAttributes: () => ({})
        };
        materialProperties.program = materialProperties.currentProgram;
    }

    // Inform Three.js's state manager to bind the custom WebGLProgram
    renderer.state.useProgram(customGLProgram);
};

Step 4: Attribute and Uniform Synchronization

When using an external program, Three.js will bind attributes based on their name in the BufferGeometry. Ensure your custom vertex shader attribute names match the Three.js attribute names:

  • position corresponds to geometry.attributes.position
  • normal corresponds to geometry.attributes.normal
  • uv corresponds to geometry.attributes.uv

For uniforms, upload values directly using standard WebGL calls within onBeforeRender:

mesh.onBeforeRender = function(renderer) {
    renderer.state.useProgram(customGLProgram);

    const timeLocation = gl.getUniformLocation(customGLProgram, 'uTime');
    if (timeLocation) {
        gl.uniform1f(timeLocation, performance.now() * 0.001);
    }
};

This pattern provides direct execution of pre-compiled WebGL code while maintaining compatibility with Three.js transformation matrices, geometry buffers, and scene hierarchy.
