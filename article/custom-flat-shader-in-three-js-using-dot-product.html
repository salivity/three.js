Custom Flat Shader in Three.js Using Dot Product

This article explains how to compute the dot product between a triangle's face normal and a light vector to create a custom flat shader in Three.js. You will learn how standard flat shading differs from smooth shading, how to derive a true triangle face normal dynamically in GLSL using screen-space derivatives, and how to use the dot product (Lambertian reflectance) inside a THREE.ShaderMaterial to shade each polygon uniformly.

Understanding Flat Shading and the Dot Product

In standard smooth shading, normals are defined per-vertex and linearly interpolated across the triangle's surface. Flat shading requires the entire surface of an individual triangle to reflect light uniformly based on a single perpendicular vector: the face normal.

Light intensity on a diffuse surface is determined by Lambert's Cosine Law. Mathematically, this is expressed as the dot product between the normalized face normal vector (\(\mathbf{N}\)) and the normalized direction vector to the light source (\(\mathbf{L}\)):

\[\text{Intensity} = \max(\mathbf{N} \cdot \mathbf{L}, 0.0)\]

When the face points directly toward the light, the dot product is 1.0 (maximum brightness). When the face is perpendicular or facing away, the dot product is 0.0 or less (clamped to zero to prevent negative illumination).

Calculating the Face Normal in GLSL

While you can generate flat normals on the CPU using geometry.toNonIndexed() and geometry.computeVertexNormals(), computing the face normal directly in the fragment shader using standard WebGL derivatives (dFdx and dFdy) is more flexible and works on any geometry without altering its vertex buffers.

By taking the partial derivatives of the surface position relative to screen coordinates, you obtain two tangent vectors along the triangle's surface. The cross product of these two vectors yields the exact geometric face normal.

Shader Implementation

Below is a complete implementation using THREE.ShaderMaterial. The vertex shader passes the view-space position to the fragment shader, where the face normal and the dot product are calculated.

import * as THREE from 'three';

const flatShaderMaterial = new THREE.ShaderMaterial({
  uniforms: {
    uLightDirection: { value: new THREE.Vector3(1.0, 1.0, 1.0).normalize() },
    uColor: { value: new THREE.Color(0x3498db) },
    uAmbient: { value: 0.15 }
  },
  vertexShader: `
    varying vec3 vViewPosition;

    void main() {
      // Transform position to view space
      vec4 mvPosition = modelViewMatrix * vec4(position, 1.0);
      vViewPosition = mvPosition.xyz;
      gl_Position = projectionMatrix * mvPosition;
    }
  `,
  fragmentShader: `
    uniform vec3 uLightDirection;
    uniform vec3 uColor;
    uniform float uAmbient;

    varying vec3 vViewPosition;

    void main() {
      // 1. Calculate face normal using screen-space derivatives
      vec3 fdx = dFdx(vViewPosition);
      vec3 fdy = dFdy(vViewPosition);
      vec3 faceNormal = normalize(cross(fdx, fdy));

      // 2. Transform directional light to view space for consistent lighting
      // Alternatively, pass light pre-transformed or compute everything in world space
      vec3 lightDir = normalize(uLightDirection);

      // 3. Compute the dot product between face normal and light direction
      float NdotL = max(dot(faceNormal, lightDir), 0.0);

      // 4. Combine diffuse lighting with ambient term
      vec3 finalColor = uColor * (NdotL + uAmbient);

      gl_FragColor = vec4(finalColor, 1.0);
    }
  `
});

Key Considerations

  1. Winding Order: The cross product cross(fdx, fdy) relies on the triangle's screen-space winding order. If your lighting appears inverted, swap the operands to cross(fdy, fdx).
  2. Coordinate Spaces: Ensure both the face normal and the light vector reside in the same coordinate space (e.g., view space or world space) before calculating the dot product. Mixing spaces will lead to erratic illumination as the camera moves.
  3. Clamping: Always wrap the dot() function with max(..., 0.0) to ensure faces angled away from the light source do not produce negative values, which can corrupt color blending and post-processing passes.
