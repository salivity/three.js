How to Use copyFramebufferToTexture in Three.js

Capturing the current render output directly on the GPU is essential for visual effects like motion blur, screen reflections, and feedback loops. This article explains how to use the WebGLRenderer.copyFramebufferToTexture method in Three.js to copy pixels from the active drawing buffer directly into a texture. You will learn how to initialize a suitable texture, execute the copy operation within the render loop, and avoid common performance bottlenecks associated with CPU pixel reading.

Understanding copyFramebufferToTexture

The renderer.copyFramebufferToTexture(position, texture, level) method copies pixels directly from the current WebGL framebuffer into an existing texture on the GPU. Unlike renderer.readRenderTargetPixels(), this operation does not transfer data to the CPU, making it significantly faster and ideal for real-time effects.

Step 1: Create a FramebufferTexture

To store the copied pixels, create an instance of THREE.FramebufferTexture. The dimensions should typically match the renderer's drawing buffer size.

const width = window.innerWidth;
const height = window.innerHeight;

// Create a FramebufferTexture with matching dimensions
const screenTexture = new THREE.FramebufferTexture(
  width,
  height,
  THREE.RGBAFormat
);
screenTexture.minFilter = THREE.NearestFilter;
screenTexture.magFilter = THREE.NearestFilter;

Step 2: Set the Copy Position

Define a THREE.Vector2 representing the bottom-left coordinate of the area you want to copy from the framebuffer. To capture the full canvas starting from the bottom-left corner, set this to (0, 0).

const copyPosition = new THREE.Vector2(0, 0);

Step 3: Capture the Frame in the Render Loop

Call copyFramebufferToTexture immediately after rendering the scene to the screen, but before clearing or presenting the next frame.

function animate() {
  requestAnimationFrame(animate);

  // 1. Render the main scene
  renderer.render(scene, camera);

  // 2. Copy the rendered output into the texture
  renderer.copyFramebufferToTexture(copyPosition, screenTexture);

  // 3. Optional: Use screenTexture in subsequent passes or materials
}

Step 4: Handle Window Resizing

If your renderer resizes, recreate or dispose of the old texture to ensure the texture dimensions match the updated viewport.

window.addEventListener('resize', () => {
  const newWidth = window.innerWidth;
  const newHeight = window.innerHeight;

  camera.aspect = newWidth / newHeight;
  camera.updateProjectionMatrix();

  renderer.setSize(newWidth, newHeight);

  // Dispose old texture and recreate with new dimensions
  screenTexture.dispose();
  screenTexture.image.width = newWidth;
  screenTexture.image.height = newHeight;
});

Key Considerations

  • Render Target Context: This method copies from the currently active framebuffer. If you are rendering to an offscreen WebGLRenderTarget, it copies from that target instead of the default screen buffer.
  • Format Matching: Ensure the texture format matches the framebuffer color format (typically THREE.RGBAFormat).
  • Bounds Constraints: The region defined by position plus the texture dimensions must not exceed the viewport dimensions of the renderer, or WebGL will throw an INVALID_VALUE error.
