How to Add Custom GLSL to Three.js ShaderChunk

This article explains how to write custom GLSL code and register it globally within the Three.js ShaderChunk dictionary. By extending THREE.ShaderChunk, you can modularize your shaders, eliminate duplicate code, and inject reusable functions or uniforms into both built-in materials and custom ShaderMaterial instances using standard #include directives.

What is THREE.ShaderChunk?

THREE.ShaderChunk is a global JavaScript object that stores reusable GLSL code snippets as key-value pairs, where the key is the chunk name and the value is a string of GLSL code. Three.js relies on this system internally to build materials like MeshStandardMaterial and MeshBasicMaterial. When you use the #include <chunk_name> syntax in your GLSL code, Three.js parses the shader string and substitutes the directive with the corresponding snippet from THREE.ShaderChunk.

Registering a Custom Shader Chunk

To create and append your own chunk, define your GLSL code as a JavaScript string and assign it to a unique key on the THREE.ShaderChunk object before the materials using it are compiled.

import * as THREE from 'three';

// 1. Define your custom GLSL code
const customNoiseGLSL = `
  float simpleNoise(vec2 uv) {
    return fract(sin(dot(uv.xy, vec2(12.9898, 78.233))) * 43758.5453123);
  }
`;

// 2. Append it to THREE.ShaderChunk
THREE.ShaderChunk['custom_noise'] = customNoiseGLSL;

Using Custom Chunks in ShaderMaterial

Once registered, you can reference your custom chunk inside any THREE.ShaderMaterial using #include <chunk_name>. The Three.js preprocessor will replace the line with your GLSL code.

const customMaterial = new THREE.ShaderMaterial({
  vertexShader: `
    varying vec2 vUv;
    void main() {
      vUv = uv;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `,
  fragmentShader: `
    varying vec2 vUv;

    // Include the custom chunk here
    #include <custom_noise>

    void main() {
      float noiseValue = simpleNoise(vUv);
      gl_FragColor = vec4(vec3(noiseValue), 1.0);
    }
  `
});

Injecting Custom Chunks into Built-in Materials

You can also use your custom chunk to modify standard Three.js materials via the onBeforeCompile callback. This approach lets you inject custom logic without rewriting the core lighting, shadowing, or PBR pipelines.

const standardMaterial = new THREE.MeshStandardMaterial({ color: 0xffffff });

standardMaterial.onBeforeCompile = (shader) => {
  // Inject the custom chunk definition at the top of the fragment shader
  shader.fragmentShader = `
    #include <custom_noise>
    ${shader.fragmentShader}
  `;

  // Hook into an existing standard chunk to apply the custom logic
  shader.fragmentShader = shader.fragmentShader.replace(
    '#include <dithering_fragment>',
    `
    #include <dithering_fragment>
    gl_FragColor.rgb *= simpleNoise(vUv * 10.0);
    `
  );
};

Best Practices

  • Unique Identifiers: Prefix your chunk keys (e.g., prefix_chunkName) to avoid overwriting existing Three.js core chunks.
  • Registration Timing: Assign chunks to THREE.ShaderChunk before instantiating materials or rendering scenes, ensuring the GLSL strings are accessible at compile time.
  • Variable Scope: Ensure any variables, uniforms, or varyings required by your chunk are declared either inside the chunk or within the shader where it is included.
