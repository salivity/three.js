Understanding BufferAttribute Normalized in Three.js

In Three.js, the BufferAttribute.normalized property determines how standard integer typed arrays are converted into floating-point numbers when uploaded to the GPU. By default, shader attributes expect floating-point values, and setting this property to true instructs WebGL to automatically map integer data ranges to normalized floating-point ranges ([0.0, 1.0] for unsigned types and [-1.0, 1.0] for signed types) rather than converting them directly into raw float equivalents.

The Default Behavior: Direct Casting (normalized = false)

When normalized is set to false (the default value), integer values stored in a typed array like Uint8Array or Int16Array are cast directly into floating-point numbers within the vertex shader.

For example, if you pass a Uint8Array containing the value 255, the GPU reads that value directly as 255.0. While this may be desirable for custom shader logic, integer vertex IDs, or bone indices, it is unsuitable for attributes like vertex colors or unit vectors that shaders typically expect in unit ranges.

The Normalized Behavior: Range Remapping (normalized = true)

When normalized is set to true, the underlying WebGL call (glVertexAttribPointer) maps the integer values linearly across a normalized floating-point interval:

  • Unsigned Integers (Uint8Array, Uint16Array, Uint32Array): Mapped to the range [0.0, 1.0]. For example, in an 8-bit unsigned array, 0 maps to 0.0, and 255 maps to 1.0.
  • Signed Integers (Int8Array, Int16Array, Int32Array): Mapped to the range [-1.0, 1.0]. For instance, in an 8-bit signed array, -128 maps to -1.0, and 127 maps to 1.0.

Practical Use Cases and Performance Benefits

The primary advantage of using normalized integer attributes is significant memory savings and reduced bandwidth consumption across the CPU-to-GPU bus:

  1. Vertex Colors: Standard RGB or RGBA vertex colors in Three.js are conventionally represented with a Float32Array containing values between 0.0 and 1.0, consuming 4 bytes per component. By using a Uint8Array with values ranging from 0 to 255 and setting normalized = true, the GPU receives the identical [0.0, 1.0] values in the shader while reducing color attribute memory consumption by 75%.
  2. Normals and Tangents: Surface normals represent directional unit vectors between -1.0 and 1.0. Storing these in an Int8Array or Int16Array with normalized = true drastically shrinks the geometry payload while maintaining sufficient precision for lighting calculations.
  3. Quantized Geometry: Positions and UV coordinates can be quantized into fixed-point 16-bit integers (Uint16Array), saving 50% buffer memory compared to 32-bit floats.
// Example: Creating normalized vertex colors with Uint8Array
const colors = new Uint8Array([
  255, 0, 0,    // Red -> becomes vec3(1.0, 0.0, 0.0) in the shader
  0, 255, 0,    // Green -> becomes vec3(0.0, 1.0, 0.0)
  0, 0, 255     // Blue -> becomes vec3(0.0, 0.0, 1.0)
]);

const colorAttribute = new THREE.BufferAttribute(colors, 3, true);
geometry.setAttribute('color', colorAttribute);

By leveraging BufferAttribute.normalized, Three.js allows developers to achieve compact geometry footprints, lower VRAM consumption, and improved rendering performance without altering existing shader logic.
