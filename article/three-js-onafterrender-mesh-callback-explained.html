Three.js onAfterRender Mesh Callback Explained

In Three.js, the onAfterRender callback provides developers with a direct hook into the rendering lifecycle immediately after a specific mesh is drawn to the screen. This article explains the purpose of the onAfterRender callback, the parameters it provides, common use cases such as state restoration and debugging, and how it differs from its counterpart, onBeforeRender.

What is onAfterRender?

The onAfterRender property is an optional callback function available on any Object3D instance, including a Mesh. When defined, the WebGLRenderer executes this function immediately after the WebGL draw call for that particular mesh has finished.

The function signature provides access to the active rendering context and the object’s specific assets:

mesh.onAfterRender = function (renderer, scene, camera, geometry, material, group) {
    // Custom post-render logic
};

Parameters Passed to the Callback

  • renderer: The instance of WebGLRenderer executing the draw call.
  • scene: The root Scene containing the mesh.
  • camera: The active Camera through which the scene is rendered.
  • geometry: The BufferGeometry attached to the mesh.
  • material: The Material currently being applied.
  • group: The active geometry group if the mesh uses multi-materials.

Primary Purposes and Use Cases

1. WebGL State Restoration

While onBeforeRender is frequently used to alter WebGL state—such as modifying depth tests, stencil buffers, or face culling—onAfterRender is designed to restore those states. Reverting modified WebGL states ensures that subsequent objects rendered in the same frame are not inadvertently corrupted by custom settings.

2. Post-Draw Cleanups and Resource Management

Certain dynamic rendering pipelines modify uniforms, textures, or buffers on the fly. You can use onAfterRender to unset texture bindings, free temporary buffers, or mark custom render targets as finished to prevent memory leaks or unwanted frame carryover.

3. State Tracking and Visibility Confirmation

Because onAfterRender only triggers if the mesh actually passes the camera's frustum culling check and gets submitted to the GPU, it serves as a reliable confirmation that the mesh was rendered. Developers use it to reset transient animation flags, update visibility metrics, or synchronize external state only when an object is demonstrably active on screen.

4. Custom Low-Level GL Operations

If you are mixing native WebGL calls directly into a Three.js scene, onAfterRender allows you to immediately bind additional framebuffers, blit pixels, or read back GPU data using renderer.getContext() right after the mesh coordinates are projected.

Difference Between onBeforeRender and onAfterRender

  • onBeforeRender runs prior to the draw call. Its primary purpose is preparing the render: updating uniforms, dynamically changing materials, or setting specialized hardware states.
  • onAfterRender runs following the draw call. Its primary purpose is cleanup, state restoration, and post-draw synchronization.
