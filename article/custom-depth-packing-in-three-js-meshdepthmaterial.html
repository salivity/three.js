Custom Depth Packing in Three.js MeshDepthMaterial

This article demonstrates how to implement a custom depth packing algorithm in Three.js by modifying the internal shaders of MeshDepthMaterial. While Three.js natively supports BasicDepthPacking and RGBADepthPacking, specialized rendering pipelines—such as custom shadow mapping, deferred shading, or optimized screen-space effects—often require bespoke bit-distribution or multi-channel encoding schemes. By hooking into the material's compilation step with onBeforeCompile, you can inject custom GLSL packing functions directly into the fragment shader.

Understanding Three.js Depth Materials

By default, THREE.MeshDepthMaterial encodes fragment depth either as a raw float (BasicDepthPacking) or across four 8-bit channels (RGBADepthPacking) using standard Three.js shader chunks found in packing.glsl.js.

To replace this packing algorithm without rewriting the entire vertex skinning, morphing, and clipping logic provided by MeshDepthMaterial, use the onBeforeCompile hook. This lifecycle method gives you direct access to the GLSL code right before it is passed to WebGL.

Modifying the Fragment Shader via onBeforeCompile

To implement a custom packing method, replace the default packing chunk in the fragment shader with your own GLSL encoding function.

Here is an implementation that overrides the standard packing algorithm with a custom 24-bit encoding algorithm stored across the RGB channels:

import * as THREE from 'three';

// 1. Instantiate the base MeshDepthMaterial
const customDepthMaterial = new THREE.MeshDepthMaterial({
    depthPacking: THREE.RGBADepthPacking
});

// 2. Define custom GLSL packing functions
const customPackingParsChunk = /* glsl */ `
#include <packing>

// Custom 24-bit packing function into vec3 (RGB)
vec3 packDepthToRGB(const in float depth) {
    const vec3 bitShift = vec3(1.0, 255.0, 65025.0);
    const vec3 bitMask = vec3(1.0 / 255.0, 1.0 / 255.0, 0.0);
    vec3 res = fract(depth * bitShift);
    res -= res.yzz * bitMask;
    return res;
}
`;

// 3. Hook into onBeforeCompile to inject the custom logic
customDepthMaterial.onBeforeCompile = (shader) => {
    // Replace packing header declarations with custom functions
    shader.fragmentShader = shader.fragmentShader.replace(
        '#include <packing>',
        customPackingParsChunk
    );

    // Replace default depth packing assignment
    shader.fragmentShader = shader.fragmentShader.replace(
        'gl_FragColor = packDepthToRGBA( gl_FragCoord.z );',
        /* glsl */ `
        #if DEPTH_PACKING == 3201
            // Use custom depth packing logic
            gl_FragColor = vec4(packDepthToRGB(gl_FragCoord.z), 1.0);
        #else
            gl_FragColor = vec4(vec3(gl_FragCoord.z), 1.0);
        #endif
        `
    );
};

Unpacking Custom Depth in Post-Processing

Once the custom depth buffer is rendered to a THREE.WebGLRenderTarget, you must implement the inverse unpack function in any material or post-processing pass reading from this texture.

For the 24-bit packing implementation defined above, unpack the values in your consumer shader with the following GLSL function:

float unpackRGBToDepth(const in vec3 color) {
    const vec3 bitShift = vec3(1.0, 1.0 / 255.0, 1.0 / 65025.0);
    return dot(color, bitShift);
}

void main() {
    vec4 depthTexel = texture2D(tDepth, vUv);
    float linearDepth = unpackRGBToDepth(depthTexel.rgb);
    gl_FragColor = vec4(vec3(linearDepth), 1.0);
}

Handling Linear vs. Non-Linear Depth

By default, gl_FragCoord.z contains non-linear screen-space depth values between 0.0 and 1.0. If your pipeline requires linear view-space depth, update the packing calculation within your injected chunk:

// Convert non-linear depth to linear view-space depth [0.0, 1.0]
float viewZ = perspectiveDepthToViewZ(gl_FragCoord.z, near, far);
float linearDepth = viewZToNormalizedLogDepth(viewZ, near, far);
gl_FragColor = vec4(packDepthToRGB(linearDepth), 1.0);

When passing uniform parameters like camera near and far planes, add them to shader.uniforms within onBeforeCompile and declare them inside the injected customPackingParsChunk.
