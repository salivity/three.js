Three.js Character Grounding Using Raycasting

Maintaining proper contact between a moving character and an uneven mesh in Three.js requires a continuous downward raycasting loop. By shooting a ray from the character’s current position toward the ground on every frame, you can detect the exact surface elevation beneath the character, calculate the required vertical offset, and dynamically adjust the character's Y-axis position to prevent clipping or floating.

1. Setting Up the Raycaster and Vectors

To prevent the ray origin from starting below the terrain when walking up steep hills, instantiate the ray origin slightly above the character's base. You also need a reusable downward direction vector to avoid garbage collection overhead in your animation loop.

import * as THREE from 'three';

const raycaster = new THREE.Raycaster();
const downVector = new THREE.Vector3(0, -1, 0);
const rayOrigin = new THREE.Vector3();

// Configuration constants
const RAY_ELEVATION_OFFSET = 1.5; // Start the ray above the character's feet
const CHARACTER_HEIGHT_OFFSET = 0.0; // Distance from model origin to feet
const MAX_FALL_DISTANCE = 10.0; // Limit raycast length for performance

2. Isolating the Ground Collider

Raycasting against the entire scene graph severely degrades frame rates. Isolate your terrain mesh into a dedicated variable or an array of ground colliders. Ensure the terrain geometry has computed bounding spheres and boxes for efficient intersection checks.

// Reference to your terrain mesh
const terrainMesh = scene.getObjectByName('Terrain');

// Configure raycaster limits
raycaster.far = MAX_FALL_DISTANCE;

3. Implementing the Per-Frame Ground Check

Within your main animation loop (or character controller update function), update the ray origin based on the character's X and Z coordinates, execute the intersection test, and align the character's vertical position.

function updateGrounding(character, terrain, delta) {
  // Update the ray origin to follow the character with vertical clearance
  rayOrigin.copy(character.position);
  rayOrigin.y += RAY_ELEVATION_OFFSET;

  // Orient the ray downwards
  raycaster.set(rayOrigin, downVector);

  // Cast only against the ground object
  const intersects = raycaster.intersectObject(terrain, false);

  if (intersects.length > 0) {
    const groundPoint = intersects[0].point;
    const targetY = groundPoint.y + CHARACTER_HEIGHT_OFFSET;

    // Direct snapping for rigid movement
    // character.position.y = targetY;

    // Or smooth vertical interpolation to handle abrupt polygon transitions
    const smoothingFactor = 15.0;
    character.position.y += (targetY - character.position.y) * Math.min(delta * smoothingFactor, 1.0);
  } else {
    // Handle airborne/falling state if no terrain is detected below
    character.position.y -= 9.8 * delta;
  }
}

4. Integration into the Animation Loop

Execute the grounding function directly after processing horizontal movement inputs to guarantee the character's visual position synchronizes with the terrain before rendering the frame.

const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);

  const delta = clock.getDelta();

  // 1. Process character forward/sideways translation
  handleCharacterMovement(delta);

  // 2. Adjust vertical position via raycast
  updateGrounding(characterMesh, terrainMesh, delta);

  // 3. Render the scene
  renderer.render(scene, camera);
}

animate();

Key Considerations for Stability

  • Ray Elevation: If the ray origin is placed at the character's exact pivot point (often the feet), moving onto an upward slope causes the ray to start underground, resulting in missed intersections. Always add an offset along the positive Y-axis.
  • Surface Normals: The first intersection object (intersects[0]) provides the surface normal via intersects[0].face.normal. You can inspect this normal vector to calculate the slope angle and restrict the character from traversing excessively steep terrain.
  • Complex Geometry: If your terrain is subdivided or segmented into multiple chunks, pass the array of chunks directly into raycaster.intersectObjects(terrainChunks, false) rather than traversing a parent Group.
