Configure LineMaterial Resolution in Three.js

In Three.js, rendering thick lines requires the fat lines module using LineMaterial and Line2 instead of standard LineBasicMaterial. For these lines to maintain their intended pixel width and avoid visual distortion, the resolution uniform of LineMaterial must be accurately set to match the canvas viewport dimensions. This guide explains how to properly initialize the resolution property, handle dynamic window resizing, and account for device pixel ratios.

Why LineMaterial Requires a Resolution Uniform

Standard WebGL implementations generally limit line width to 1 pixel due to hardware constraints. Three.js bypasses this via LineMaterial, which constructs lines out of screen-space triangulated quads inside the vertex shader. To calculate these vertex offsets in screen space, the shader needs the exact pixel dimensions of the rendering area. If the resolution uniform is missing or incorrect, lines will appear skewed, scaled disproportionately, or entirely invisible.

Initializing LineMaterial

When instantiating LineMaterial, define the resolution property as a THREE.Vector2 representing the width and height of the rendering viewport:

import * as THREE from 'three';
import { LineMaterial } from 'three/addons/lines/LineMaterial.js';
import { LineGeometry } from 'three/addons/lines/LineGeometry.js';
import { Line2 } from 'three/addons/lines/Line2.js';

// Setup dimensions
const width = window.innerWidth;
const height = window.innerHeight;

// Create material with initial resolution
const lineMaterial = new LineMaterial({
    color: 0xff0000,
    linewidth: 5, // Width in screen pixels
    resolution: new THREE.Vector2(width, height)
});

// Create geometry and mesh
const geometry = new LineGeometry();
geometry.setPositions([
    -50, 0, 0,
    50, 0, 0
]);

const line = new Line2(geometry, lineMaterial);
line.computeLineDistances();
scene.add(line);

Handling Window Resizing

Because the resolution uniform is static once set, changing the browser window size causes lines to scale incorrectly. You must update the uniform in your window resize event handler:

window.addEventListener('resize', onWindowResize);

function onWindowResize() {
    const width = window.innerWidth;
    const height = window.innerHeight;

    // Update camera and renderer
    camera.aspect = width / height;
    camera.updateProjectionMatrix();
    renderer.setSize(width, height);

    // Update the LineMaterial resolution
    lineMaterial.resolution.set(width, height);
}

Managing Resizing with Renderer Getters

If the Three.js canvas occupies a container instead of the full window, or if you want a cleaner implementation that pulls dimensions directly from the renderer, use renderer.getSize():

function onWindowResize() {
    renderer.setSize(container.clientWidth, container.clientHeight);
    camera.aspect = container.clientWidth / container.clientHeight;
    camera.updateProjectionMatrix();

    // Directly assign renderer size to the uniform
    renderer.getSize(lineMaterial.resolution);
}

Accounting for Device Pixel Ratio (DPR)

By default, LineMaterial calculates line thickness in logical CSS pixels when passed the CSS viewport dimensions (renderer.getSize). If your renderer uses renderer.setPixelRatio(window.devicePixelRatio) and you want the line thickness to scale against the actual physical pixel buffer rather than logical pixels, use renderer.getDrawingBufferSize():

renderer.getDrawingBufferSize(lineMaterial.resolution);

For most user interfaces and consistent cross-device sizing, using logical dimensions via renderer.getSize(lineMaterial.resolution) is recommended, as it keeps lines visually uniform regardless of screen density.
