Extract Three.js BufferGeometry Vertices for Ammo.js

This article explains how to extract raw vertex coordinates and face index data from a Three.js BufferGeometry to generate collision shapes in Ammo.js. Integrating custom or complex 3D models with physics engines requires reading underlying geometry attributes, accounting for world transformations, and feeding the resulting coordinate arrays into Ammo.js mesh structures like btTriangleMesh or btConvexHullShape.

Accessing the Geometry Attributes

In Three.js, geometry vertices are stored in a BufferAttribute named position within BufferGeometry.attributes. The raw coordinates exist as a flattened Float32Array containing sequential x, y, z values.

Depending on how the 3D model was exported, the geometry may be indexed or non-indexed:

  • Indexed Geometry: Uses geometry.index to define which vertices form triangles. Multiple triangles share vertex indices to conserve memory.
  • Non-Indexed Geometry: Vertices are defined sequentially, where every three consecutive vertices (nine array elements) represent a single triangle.

Applying World Transformations

Physics engines typically require geometry data either scaled to its proper dimensions in local space or fully transformed into world coordinates. If you extract vertices directly from BufferGeometry, they will only reflect the model's unscaled local coordinate space.

To bake the current scale and rotation into the extracted vertices, apply the mesh's world matrix to a cloned geometry before extraction:

const clonedGeometry = mesh.geometry.clone();
clonedGeometry.applyMatrix4(mesh.matrixWorld);

Feeding Data into Ammo.js (btTriangleMesh)

For static environment colliders (like concave terrain or architecture), Ammo.js uses btBvhTriangleMeshShape, which is constructed from a btTriangleMesh.

Here is the process to read the position buffer and build the mesh:

function createAmmoTriangleMesh(geometry) {
  const position = geometry.attributes.position.array;
  const index = geometry.index ? geometry.index.array : null;

  const triangleMesh = new Ammo.btTriangleMesh(true, true);

  const v0 = new Ammo.btVector3();
  const v1 = new Ammo.btVector3();
  const v2 = new Ammo.btVector3();

  if (index) {
    // Process indexed geometry
    for (let i = 0; i < index.length; i += 3) {
      const idx0 = index[i] * 3;
      const idx1 = index[i + 1] * 3;
      const idx2 = index[i + 2] * 3;

      v0.setValue(position[idx0], position[idx0 + 1], position[idx0 + 2]);
      v1.setValue(position[idx1], position[idx1 + 1], position[idx1 + 2]);
      v2.setValue(position[idx2], position[idx2 + 1], position[idx2 + 2]);

      triangleMesh.addTriangle(v0, v1, v2, false);
    }
  } else {
    // Process non-indexed geometry
    for (let i = 0; i < position.length; i += 9) {
      v0.setValue(position[i], position[i + 1], position[i + 2]);
      v1.setValue(position[i + 3], position[i + 4], position[i + 5]);
      v2.setValue(position[i + 6], position[i + 7], position[i + 8]);

      triangleMesh.addTriangle(v0, v1, v2, false);
    }
  }

  // Free temporary vectors from WebAssembly heap
  Ammo.destroy(v0);
  Ammo.destroy(v1);
  Ammo.destroy(v2);

  const shape = new Ammo.btBvhTriangleMeshShape(triangleMesh, true, true);
  return shape;
}

Feeding Data into Ammo.js (btConvexHullShape)

For moving, dynamic objects that are not simple primitives (spheres or boxes), Ammo.js requires a convex shape via btConvexHullShape. This shape does not require triangle indices, only the individual vertices:

function createAmmoConvexHull(geometry) {
  const position = geometry.attributes.position.array;
  const shape = new Ammo.btConvexHullShape();

  const tempVec = new Ammo.btVector3();

  for (let i = 0; i < position.length; i += 3) {
    tempVec.setValue(position[i], position[i + 1], position[i + 2]);
    const isLast = (i >= position.length - 3);
    shape.addPoint(tempVec, isLast);
  }

  Ammo.destroy(tempVec);
  return shape;
}

Memory Management Considerations

Ammo.js compiles from C++ via Emscripten and manages its own memory heap. Any object instantiated using the new Ammo.* syntax allocates memory that JavaScript's garbage collector cannot free. When updating or disposing of collision shapes, always call Ammo.destroy() on shapes, vector structures, and triangle meshes when they are no longer in use to prevent memory leaks.
