Three.js: Object3D.visible vs layers.disableAll

In Three.js, both setting Object3D.visible = false and calling Object3D.layers.disableAll() prevent an object from appearing in the final render, but they function at fundamentally different stages of the pipeline. Setting visible = false provides a hard, global cutoff that halts child traversal and raycasting completely, whereas using layers.disableAll() relies on bitmask filtering during camera passes without automatically suppressing the object's children or scene graph updates.

Hierarchical Traversal and Child Inheritance

The most significant rendering difference involves how child objects are handled:

  • Object3D.visible = false: Visibility is inherited down the scene graph. When the WebGL renderer traverses the scene to build the render list, encountering an object with visible = false causes it to immediately skip that object and its entire subtree. Any children parented to this object will not be rendered, regardless of their own visible settings.
  • layers.disableAll(): Layers do not cascade hierarchically. Disabling all layers on a parent object sets its layer mask to 0, meaning the parent itself will not match any camera's mask and will not render. However, the renderer continues to traverse the parent's children. If a child object has an active layer matching the rendering camera, that child will still be drawn.

Scene Graph Traversal and Matrix Updates

Before drawing, Three.js updates the world transformation matrices via updateMatrixWorld().

  • With visible = false, the object is still part of the scene graph, and its local and world matrices are typically calculated during standard matrix updates unless explicitly disabled. However, the WebGL renderer skips the object entirely when constructing render lists, saving draw call assembly overhead.
  • With layers.disableAll(), the object is still evaluated by the renderer during traversal. The renderer checks the object's layer mask against the current camera's layer mask (camera.layers.test(object.layers)). The evaluation fails, preventing the mesh from being pushed to the render list, but the traversal step itself is executed.

Multi-Camera and Selective Visibility

  • visible = false is absolute and global across all cameras. If an object is invisible, it cannot be displayed by any camera rendering the scene in that frame.
  • Layers are designed for selective rendering. While layers.disableAll() removes an object from all standard cameras, the layer system is fundamentally per-camera. If you instead disable specific layers, an object can be visible to Camera A (e.g., a main viewport) while hidden from Camera B (e.g., a minimap or shadow map). visible = false cannot achieve this per-camera granularity.

Raycasting Interactions

Visibility mechanisms also alter interaction pipelines:

  • Raycaster.intersectObject() explicitly checks the target's visible property. If visible is false, the raycaster ignores the object and bypasses its children (when recursive is true).
  • Raycaster has its own layers property. If an object has called layers.disableAll(), it will have a mask of 0. Because raycaster.layers.test(object.layers) evaluates to false, the raycaster ignores the object, but if recursive raycasting is enabled, it may still test any child objects that possess active layer masks.

Summary

Use Object3D.visible = false when an entire object branch should be turned off globally, bypassing rendering and interaction for the object and all its children. Use layers.disableAll() or specific layer masking when you need fine-grained, camera-specific visibility, or when you need a parent to be invisible while maintaining the visibility and independent rendering of its children.
