Three.js Float Depth Buffer in WebGLRenderTarget

This guide demonstrates how to configure a THREE.WebGLRenderTarget to utilize a 32-bit floating-point depth buffer in Three.js. Standard render targets default to 16-bit or 24-bit fixed-point depth buffers, which often cause precision artifacts and Z-fighting across massive view distances. By attaching an explicit THREE.DepthTexture configured with THREE.FloatType, you can ensure the underlying WebGL context allocates an IEEE 754 32-bit floating-point depth buffer (DEPTH_COMPONENT32F) for your custom render passes.

Step-by-Step Implementation

To force high-precision floating-point depth storage on a render target, instantiate a THREE.DepthTexture, assign its type to THREE.FloatType, and attach it to the WebGLRenderTarget.depthTexture property.

import * as THREE from 'three';

const width = window.innerWidth;
const height = window.innerHeight;

// 1. Create the Render Target
const renderTarget = new THREE.WebGLRenderTarget(width, height, {
  minFilter: THREE.NearestFilter,
  magFilter: THREE.NearestFilter,
  generateMipmaps: false,
  stencilBuffer: false,
  depthBuffer: true
});

// 2. Create and configure the Float DepthTexture
const depthTexture = new THREE.DepthTexture(width, height);
depthTexture.format = THREE.DepthFormat;
depthTexture.type = THREE.FloatType; // Forces 32-bit float depth (DEPTH_COMPONENT32F)

// 3. Attach the depth texture to the render target
renderTarget.depthTexture = depthTexture;

Key Configuration Settings

  • depthTexture.type = THREE.FloatType: This is the critical line. In WebGL 2 contexts, setting this property maps the depth attachment to the gl.DEPTH_COMPONENT32F internal format instead of the default gl.DEPTH_COMPONENT16 or gl.DEPTH_COMPONENT24.
  • depthTexture.format = THREE.DepthFormat: Ensures the texture strictly holds depth data. Do not use THREE.DepthStencilFormat unless you are actively using a stencil buffer, in which case you must use THREE.FloatType alongside WebGL 2 support for DEPTH32F_STENCIL8.
  • Filter Modes: It is recommended to use THREE.NearestFilter for both minFilter and magFilter on floating-point depth textures, as linear filtering on float depth attachments is not universally supported across all GPUs without specific extensions.

Handling Resizing

When resizing the application, you must update both the render target and the depth texture dimensions to maintain proper pixel-to-texel mapping:

function onWindowResize() {
  const newWidth = window.innerWidth;
  const newHeight = window.innerHeight;

  renderTarget.setSize(newWidth, newHeight);
  renderTarget.depthTexture.image.width = newWidth;
  renderTarget.depthTexture.image.height = newHeight;
  renderTarget.depthTexture.needsUpdate = true;
}

Shader Reading Considerations

When sampling this texture inside a custom shader pass via a sampler2D uniform, read the red channel (texture2D(tDepth, vUv).r). The sampled value will contain non-linear, high-precision window depth normalized to the range [0.0, 1.0], which can be converted back to view-space linear distance without the severe banding typical of lower bit-depth buffers.
