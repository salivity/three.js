How to Get WebGL Shader Program Info in Three.js

This guide explains how to access, inspect, and extract active shader program information using Three.js's underlying WebGLPrograms manager. By accessing the compiled WebGLProgram instances tracked by the renderer, developers can retrieve GLSL source code, active uniforms, vertex attributes, and compilation diagnostics for debugging rendering pipelines and optimizing GPU performance.

Ensure Shaders Are Compiled

Three.js compiles shader programs lazily on demand. Before program data can be extracted, the renderer must compile the shaders by either executing a render call or manually precompiling the scene.

// Force compilation without rendering a full frame
renderer.compile(scene, camera);

// Or run a standard render loop iteration
renderer.render(scene, camera);

Accessing Cached Programs via renderer.info.programs

The WebGLPrograms class maintains an internal cache of all active shader configurations. Three.js exposes this cache directly through the renderer.info.programs array. Each entry in this array is an instance of WebGLProgram created by the WebGLPrograms factory.

const activePrograms = renderer.info.programs;

activePrograms.forEach((program) => {
    console.log(`Program ID: ${program.id}`);
    console.log(`Program Name/Type: ${program.name}`);
    console.log(`Cache Key: ${program.cacheKey}`);
    console.log(`Used count: ${program.usedTimes}`);
});

Extracting Uniforms, Attributes, and GLSL Source

Each WebGLProgram wrapper object provides methods and properties to query the compiled state, uniforms, attributes, and raw shader source:

activePrograms.forEach((program) => {
    // Retrieve GLSL source strings
    const vertexShaderSource = program.vertexShader.content;
    const fragmentShaderSource = program.fragmentShader.content;

    // Retrieve uniform definitions and active locations
    const uniforms = program.getUniforms();
    console.log('Uniforms:', uniforms);

    // Retrieve attribute locations
    const attributes = program.getAttributes();
    console.log('Attributes:', attributes);

    // Get the underlying native WebGLProgram object
    const glProgram = program.program;
});

Querying the WebGL Context Directly

If low-level hardware diagnostics are required, query the native WebGLRenderingContext using the program.program reference exposed by WebGLProgram:

const gl = renderer.getContext();

activePrograms.forEach((program) => {
    const glProgram = program.program;

    // Read total number of active uniforms
    const activeUniformsCount = gl.getProgramParameter(glProgram, gl.ACTIVE_UNIFORMS);

    for (let i = 0; i < activeUniformsCount; i++) {
        const uniformInfo = gl.getActiveUniform(glProgram, i);
        const location = gl.getUniformLocation(glProgram, uniformInfo.name);
        console.log(`Uniform #${i}: ${uniformInfo.name} | Type: ${uniformInfo.type} | Size: ${uniformInfo.size}`);
    }

    // Read total number of active attributes
    const activeAttribsCount = gl.getProgramParameter(glProgram, gl.ACTIVE_ATTRIBUTES);

    for (let i = 0; i < activeAttribsCount; i++) {
        const attribInfo = gl.getActiveAttrib(glProgram, i);
        const location = gl.getAttribLocation(glProgram, attribInfo.name);
        console.log(`Attribute #${i}: ${attribInfo.name} | Location: ${location}`);
    }
});

Accessing Material-Specific Programs

To inspect the program of a specific mesh or material rather than iterating through the entire cache, use the renderer.properties API to retrieve the associated program:

const materialProperties = renderer.properties.get(mesh.material);
const materialProgram = materialProperties.currentProgram;

if (materialProgram) {
    console.log('Material Program ID:', materialProgram.id);
    console.log('Material Uniforms:', materialProgram.getUniforms());
}
