Multiple Render Targets in Three.js WebGLRenderTarget

Multiple Render Targets (MRT) allow a fragment shader to write to several textures simultaneously in a single draw pass, dramatically improving performance for deferred rendering, G-buffer creation, and complex post-processing pipelines. In modern versions of Three.js (r150+), MRT is implemented directly through WebGLRenderTarget by setting the count property in its options, paired with a custom ShaderMaterial configured to use GLSL 3.0 output locations.

1. Instantiate WebGLRenderTarget with Multiple Attachments

To allocate multiple color attachments, pass the count parameter in the options object when instantiating THREE.WebGLRenderTarget. The count specifies how many color textures the target will maintain.

import * as THREE from 'three';

const width = window.innerWidth;
const height = window.innerHeight;

// Allocate a render target with 3 color attachments
const renderTarget = new THREE.WebGLRenderTarget(width, height, {
  count: 3,
  minFilter: THREE.NearestFilter,
  magFilter: THREE.NearestFilter,
  type: THREE.HalfFloatType // Optional: useful for HDR or high-precision data like normals
});

When count is greater than 1, Three.js exposes an array of textures via renderTarget.textures, where index 0 corresponds to the first attachment, index 1 to the second, and so on.

2. Configure a GLSL 3.0 Shader

Writing to multiple buffers requires WebGL 2 with GLSL 3.0 syntax. When creating the material, set glslVersion: THREE.GLSL3 on your ShaderMaterial and declare output variables with specific layout(location = ...) bindings that map to your target buffers.

const mrtMaterial = new THREE.ShaderMaterial({
  glslVersion: THREE.GLSL3,
  vertexShader: `
    out vec3 vNormal;
    out vec2 vUv;

    void main() {
      vNormal = normalize(normalMatrix * normal);
      vUv = uv;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `,
  fragmentShader: `
    precision highp float;

    in vec3 vNormal;
    in vec2 vUv;

    // Direct mapping to renderTarget.textures[0], [1], and [2]
    layout(location = 0) out vec4 gColor;
    layout(location = 1) out vec4 gNormal;
    layout(location = 2) out vec4 gDepth;

    void main() {
      // Target 0: Base Color
      gColor = vec4(1.0, 0.5, 0.2, 1.0);

      // Target 1: View-space Normals encoded to [0, 1]
      gNormal = vec4(vNormal * 0.5 + 0.5, 1.0);

      // Target 2: Depth visualization
      gDepth = vec4(vec3(gl_FragCoord.z), 1.0);
    }
  `
});

3. Render and Access the Textures

Render the scene into the configured render target as you normally would. Once the draw call completes, each attachment contains its respective output data.

// Render the scene to the multi-target buffer
renderer.setRenderTarget(renderTarget);
renderer.render(scene, camera);
renderer.setRenderTarget(null);

// Access individual output textures
const diffuseTexture = renderTarget.textures[0];
const normalTexture = renderTarget.textures[1];
const depthTexture = renderTarget.textures[2];

These textures can now be bound to uniforms in subsequent materials or post-processing passes (such as screen-space ambient occlusion, deferred lighting, or depth-of-field).

4. Handling Resizing and Cleanup

When resizing the viewport, call setSize on the render target to resize all internal texture attachments simultaneously:

function onWindowResize() {
  const newWidth = window.innerWidth;
  const newHeight = window.innerHeight;
  
  renderTarget.setSize(newWidth, newHeight);
}

To prevent GPU memory leaks, invoke dispose() when the render target is no longer needed:

renderTarget.dispose();
