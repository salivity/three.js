How to Use Three.js InstancedMesh setMatrixAt

Rendering massive numbers of distinct objects such as an asteroid belt can severely degrade performance if created with individual mesh instances. Three.js solves this bottleneck using THREE.InstancedMesh, which allows you to render thousands of objects sharing the same geometry and material using a single WebGL draw call. This guide demonstrates how to configure and use the InstancedMesh.setMatrixAt method to initialize the positions, rotations, and scales of 1,000 asteroids efficiently.

Understanding InstancedMesh.setMatrixAt

The InstancedMesh.setMatrixAt(index, matrix) method assigns a local transformation matrix (THREE.Matrix4) to a specific instance defined by its index. A 4x4 matrix contains the combined translation (position), rotation, and scale data for that instance.

To avoid allocating a new THREE.Matrix4 in every iteration of a loop, the best practice is to reuse a single dummy THREE.Object3D or THREE.Matrix4 helper to compute each transform.

Step-by-Step Implementation

  1. Define Geometry and Material: Create a base geometry (such as an irregular polyhedron) and a material that all instances will share.
  2. Instantiate the InstancedMesh: Provide the geometry, material, and total instance count (1000).
  3. Loop and Apply Matrices: Use a helper Object3D to calculate the position, rotation, and scale for each instance, then transfer its matrix via setMatrixAt.
  4. Flag the Buffer for Upload: Mark instanceMatrix.needsUpdate = true to inform the GPU that the matrix data is ready to be rendered.

Code Example

import * as THREE from 'three';

// 1. Setup base geometry and material for the asteroids
const asteroidGeometry = new THREE.DodecahedronGeometry(1, 1);
const asteroidMaterial = new THREE.MeshStandardMaterial({ 
    color: 0x888888, 
    roughness: 0.8 
});

// 2. Create the InstancedMesh with 1,000 instances
const count = 1000;
const asteroidField = new THREE.InstancedMesh(asteroidGeometry, asteroidMaterial, count);

// 3. Create a dummy Object3D to compute matrices efficiently
const dummy = new THREE.Object3D();
const radius = 50;

for (let i = 0; i < count; i++) {
    // Generate random spherical coordinates or ring coordinates
    const angle = Math.random() * Math.PI * 2;
    const distance = radius + (Math.random() - 0.5) * 15;
    
    // Position
    dummy.position.set(
        Math.cos(angle) * distance,
        (Math.random() - 0.5) * 10,
        Math.sin(angle) * distance
    );

    // Rotation
    dummy.rotation.set(
        Math.random() * Math.PI,
        Math.random() * Math.PI,
        Math.random() * Math.PI
    );

    // Scale variation
    const scale = 0.5 + Math.random() * 1.5;
    dummy.scale.set(scale, scale, scale);

    // Update the local matrix of the dummy object
    dummy.updateMatrix();

    // Set the calculated matrix at the specific instance index
    asteroidField.setMatrixAt(i, dummy.matrix);
}

// 4. Notify Three.js that the instance matrix array needs to be sent to the GPU
asteroidField.instanceMatrix.needsUpdate = true;

// Add to the scene
scene.add(asteroidField);

Key Considerations

  • Memory Allocation: Reusing a single dummy object prevents garbage collection spikes when initializing thousands of elements.
  • The needsUpdate Flag: Three.js stores all transformation matrices in an internal Float32Array attribute buffer. Without setting asteroidField.instanceMatrix.needsUpdate = true, the GPU will not receive the matrix changes.
  • Frustum Culling: Three.js uses the bounding volume of the original base geometry by default. If your asteroids span a large volume, call asteroidField.computeBoundingSphere() after populating the matrices so instances outside the initial origin point are not inadvertently culled.
