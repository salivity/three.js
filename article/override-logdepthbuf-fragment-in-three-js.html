Override logdepthbuf_fragment in Three.js

This guide explains how to intercept and override the logdepthbuf_fragment shader chunk in Three.js to implement custom depth writing behavior. Three.js uses logarithmic depth buffers to reduce z-fighting across scenes with massive scale differences. By modifying this chunk via material compilation hooks or global shader overrides, you can adjust depth bias, clamp values, or implement entirely bespoke fragment depth logic while still leveraging built-in materials.

Understanding logdepthbuf_fragment

By default, when logarithmicDepthBuffer: true is enabled on the WebGLRenderer, Three.js includes the logdepthbuf_vertex and logdepthbuf_fragment chunks into standard shaders. The fragment chunk calculates the final fragment depth written to gl_FragDepth:

#if defined( USE_LOGDEPTHBUF )
    gl_FragDepth = isPerspectiveMatrix( projectionMatrix ) ? log2( vFragDepth ) * logDepthBufFC * 0.5 : gl_FragCoord.z;
#endif

The variable vFragDepth is computed in the vertex stage (equal to 1.0 + gl_Position.w), and logDepthBufFC is a uniform equal to 2.0 / (log(far + 1.0) / log(2.0)). Overriding this fragment chunk allows you to modify the final depth value assigned to gl_FragDepth.

Method 1: Using onBeforeCompile (Per-Material Override)

The recommended approach to alter standard materials (such as MeshStandardMaterial or MeshBasicMaterial) without altering the global engine state is using the onBeforeCompile callback.

const material = new THREE.MeshStandardMaterial({
    color: 0x00ff00
});

material.onBeforeCompile = (shader) => {
    // Optional: Add custom uniforms if your custom depth logic requires them
    shader.uniforms.uDepthBias = { value: 0.001 };

    // Replace the standard logarithmic depth write with custom logic
    shader.fragmentShader = shader.fragmentShader.replace(
        '#include <logdepthbuf_fragment>',
        `
        #if defined( USE_LOGDEPTHBUF )
            // Compute base logarithmic depth
            float customLogDepth = isPerspectiveMatrix( projectionMatrix ) ? log2( vFragDepth ) * logDepthBufFC * 0.5 : gl_FragCoord.z;

            // Apply custom depth modifications (e.g., manual bias, clamping, or custom curves)
            customLogDepth += uDepthBias;

            // Write final depth
            gl_FragDepth = clamp(customLogDepth, 0.0, 1.0);
        #endif
        `
    );
};

If you modify uniforms or properties dynamically on a material customized via onBeforeCompile, ensure you define the uniforms in an accessible scope or attach references directly to material.userData.

Method 2: Overriding THREE.ShaderChunk (Global Override)

If you need the customized depth logic to apply universally across all built-in materials that utilize logarithmic depth, override THREE.ShaderChunk.logdepthbuf_fragment before initializing any materials:

import * as THREE from 'three';

THREE.ShaderChunk.logdepthbuf_fragment = `
#if defined( USE_LOGDEPTHBUF )
    // Custom global depth logic
    float depthVal = isPerspectiveMatrix( projectionMatrix ) ? log2( vFragDepth ) * logDepthBufFC * 0.5 : gl_FragCoord.z;
    
    // Custom manipulation: e.g., invert or offset
    gl_FragDepth = depthVal;
#endif
`;

This ensures that any material compiled after this assignment includes your modified logic wherever #include <logdepthbuf_fragment> is called.

Essential Considerations

  1. Renderer Settings: The chunk's contents are wrapped in #if defined( USE_LOGDEPTHBUF ). This definition is only added if renderer.logarithmicDepthBuffer is set to true or if you manually add #define USE_LOGDEPTHBUF to your material's defines.
  2. Vertex Dependency: The fragment logic depends directly on vFragDepth, which is set in logdepthbuf_vertex. If your custom depth calculation requires non-linear camera distances or alternative coordinates, you may need to override logdepthbuf_vertex alongside the fragment chunk to pass custom varying values.
  3. Performance and Extensions: Writing explicitly to gl_FragDepth disables early depth testing (Early-Z) on the GPU, which can reduce rendering performance on fill-rate-bound scenes. In WebGL 1 environments, writing to depth requires the EXT_frag_depth extension, which Three.js handles automatically when logarithmic depth is enabled.
