Three.js powerPreference High Performance Explained

Setting powerPreference: "high-performance" in Three.js instructs the browser and operating system to prioritize rendering throughput and graphical capability over battery conservation. This configuration option is passed directly to the underlying HTML5 WebGL context creation call, acting as a direct request for the host device to utilize its most capable graphics processing unit (GPU).

How It Works Under the Hood

When initializing a renderer in Three.js, you pass a configuration object to THREE.WebGLRenderer:

const renderer = new THREE.WebGLRenderer({
  powerPreference: "high-performance"
});

Three.js passes this setting directly to the HTML canvas element via canvas.getContext('webgl2', { powerPreference: 'high-performance' }) (or webgl).

The WebGL specification defines three valid values for powerPreference:

  • default: Allows the browser and operating system to decide the appropriate GPU configuration.
  • low-power: Favors battery conservation by requesting an energy-efficient GPU.
  • high-performance: Favors execution speed and visual fidelity by requesting a more powerful GPU.

Multi-GPU System Switching

The primary function of powerPreference: "high-performance" is resolving hardware selection on dual-GPU hardware. Common examples include laptops equipped with both an integrated GPU (such as Intel Iris or AMD Radeon Graphics built into the CPU) and a discrete GPU (such as an NVIDIA GeForce or AMD Radeon card).

When set to high-performance:

  1. Discrete GPU Allocation: The browser requests that the operating system activate and assign the discrete graphics card to handle the canvas context.
  2. VRAM and Bandwidth Allocation: The application gains access to dedicated video memory (VRAM) and higher memory bandwidth rather than sharing unified system RAM.
  3. Complex Shader Execution: Fragment and vertex shaders benefit from higher core counts and faster clock speeds.

It Is a Hint, Not a Guarantee

The powerPreference attribute is specified as a hint to the user agent (the browser). The browser and the host operating system retain ultimate authority over hardware allocation. The request may be ignored or overridden in the following scenarios:

  • Single-GPU Devices: On devices with only one GPU (such as many budget laptops, smartphones, or desktop systems without integrated graphics), this setting has no hardware-switching effect.
  • Operating System Policies: If an operating system is operating in a strict "Battery Saver" mode, it may force the browser to stay on the integrated GPU regardless of the WebGL request.
  • Browser Implementation: Certain browsers on specific platforms may not implement discrete GPU switching via the WebGL API due to driver stability concerns or sandbox restrictions.

When to Use High Performance

  • High-Poly Scenes: Scenes with large polygon counts, dense geometries, or detailed shadow maps.
  • Post-Processing Pipelines: Applications using complex multi-pass post-processing chains (e.g., depth of field, bloom, screen-space ambient occlusion).
  • WebGL Games: Fast-paced browser games requiring stable 60 or 120 FPS frame rates.

For lightweight 3D banners, simple user interface components, or applications targeting mobile web environments, omit this setting or specify low-power to prevent excessive thermal throttling and battery drain.
