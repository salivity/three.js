Clone SkinnedMesh with SkeletonUtils in Three.js

Duplicating animated 3D characters in Three.js often results in broken meshes and corrupted animations if handled with standard cloning methods. This article explains why the native Object3D.clone() fails on a SkinnedMesh and demonstrates how to properly use SkeletonUtils.clone to generate fully independent duplicates with preserved bone hierarchies and working animation playback.

The Problem with Native Object3D.clone()

When using mesh.clone() or scene.clone() on an object containing a SkinnedMesh, Three.js creates a shallow copy of the skeleton references. While the geometry and bone objects are duplicated, the skeleton.bones array on the duplicated SkinnedMesh continues to reference the bones of the original model, or the internal bone matrices desynchronize. Manipulating or animating the duplicated skeleton consequently transforms the original mesh or causes the duplicated mesh to distort incorrectly.

Using SkeletonUtils.clone

The SkeletonUtils module solves this issue by traversing the target hierarchy, cloning all bones and meshes, and then systematically re-binding the cloned SkinnedMesh instances to their corresponding cloned bones and skeletons.

1. Import SkeletonUtils

Import SkeletonUtils from the Three.js addons directory:

import * as THREE from 'three';
import * as SkeletonUtils from 'three/addons/utils/SkeletonUtils.js';

2. Duplicate the Entire Model Root

Always pass the highest common parent of both the SkinnedMesh and its bone hierarchy (typically the root gltf.scene) to SkeletonUtils.clone. Passing only the SkinnedMesh will omit the detached root bones from the duplication process.

// Assume 'gltf' is loaded via GLTFLoader
const originalModel = gltf.scene;

// Create a deep, skeleton-safe clone
const clonedModel = SkeletonUtils.clone(originalModel);

// Add the clone to your scene
scene.add(clonedModel);

3. Rebind AnimationMixer to the Clone

Because animations target specific bone names and object paths, you must instantiate a new THREE.AnimationMixer targeting the cloned root object:

// Set up an animation mixer specifically for the cloned instance
const clonedMixer = new THREE.AnimationMixer(clonedModel);

// Play an animation clip from the original GLTF data on the cloned mixer
const clip = gltf.animations[0];
const action = clonedMixer.clipAction(clip);
action.play();

Remember to update the new mixer in your render loop:

const clock = new THREE.Clock();

function animate() {
    requestAnimationFrame(animate);
    
    const delta = clock.getDelta();
    if (clonedMixer) clonedMixer.update(delta);

    renderer.render(scene, camera);
}

Material and Texture Management

SkeletonUtils.clone duplicates the skeleton hierarchy, but it retains shared references to materials and textures by default to preserve GPU memory.

If your duplicate requires unique visual properties (such as distinct color variations), traverse the cloned model and explicitly clone the material:

clonedModel.traverse((child) => {
    if (child.isMesh && child.material) {
        child.material = child.material.clone();
        child.material.color.setHex(0xff0000); // Unique color for this clone
    }
});
