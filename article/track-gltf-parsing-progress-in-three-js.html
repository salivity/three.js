Track GLTF Parsing Progress in Three.js

When loading massive 3D assets in Three.js, the standard progress callback only monitors file downloading, leaving users staring at a frozen interface while the browser parses complex geometry and textures. This article explains how to separate the download stage from the parsing stage, intercept internal GLTFParser tasks, and build an accurate progress indicator specifically for the CPU-intensive parsing and decoding phase.

The Problem With Standard GLTF Progress

In Three.js, GLTFLoader.load() accepts an onProgress callback that listens to standard browser ProgressEvent instances. This event reflects only network transfer metrics. Once 100% of the bytes arrive, GLTFLoader transitions to parsing JSON data, decoding Draco or Meshopt compressed buffers, and creating Three.js geometries and materials. For multi-gigabyte models, this post-download processing can take tens of seconds with zero native progress feedback.

Step 1: Separate Network Download From Parsing

To monitor parsing in isolation, retrieve the file via fetch first, convert it into an ArrayBuffer, and feed it to GLTFLoader.parseAsync().

async function loadAndParseGLTF(url, onParseProgress) {
  // 1. Download phase
  const response = await fetch(url);
  const buffer = await response.arrayBuffer();

  // 2. Parsing phase begins
  return await parseGLTFWithProgress(buffer, '', onParseProgress);
}

Step 2: Intercept the GLTFParser Dependencies

When GLTFLoader.parse() executes, it instantiates an internal GLTFParser. The parser processes independent sections of the GLTF file—such as meshes, materials, and textures—as individual asynchronous tasks (Promises).

By reading the raw JSON structure embedded inside the GLTF or GLB container, you can count the total elements to be processed, monkey-patch the parser's dependency resolution methods, and increment a counter as each asset resolves.

import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';

function parseGLTFWithProgress(buffer, path, onProgress) {
  return new Promise((resolve, reject) => {
    const loader = new GLTFLoader();

    // Intercept parser construction through a custom extension
    loader.register((parser) => {
      const json = parser.json;

      // Calculate total parse items: meshes and textures represent the bulk of CPU work
      const totalMeshes = json.meshes ? json.meshes.length : 0;
      const totalTextures = json.textures ? json.textures.length : 0;
      const totalItems = totalMeshes + totalTextures;

      if (totalItems === 0) {
        onProgress(1.0);
        return {};
      }

      let completedItems = 0;

      function itemLoaded() {
        completedItems++;
        const progress = completedItems / totalItems;
        onProgress(Math.min(progress, 1.0));
      }

      // Hook into mesh loading
      const originalLoadMesh = parser.loadMesh.bind(parser);
      parser.loadMesh = function (meshIndex) {
        return originalLoadMesh(meshIndex).then((result) => {
          itemLoaded();
          return result;
        });
      };

      // Hook into texture loading
      const originalLoadTexture = parser.loadTexture.bind(parser);
      parser.loadTexture = function (textureIndex) {
        return originalLoadTexture(textureIndex).then((result) => {
          itemLoaded();
          return result;
        });
      };

      return {};
    });

    loader.parse(buffer, path, resolve, reject);
  });
}

Step 3: Prevent UI Freezing During Parsing

Heavy parsing tasks can block the browser's main thread, preventing the DOM from redrawing your progress bar. To ensure the progress UI renders smoothly:

  1. Yield to the Main Thread: Introduce micro-delays if you use custom loop-based decoders, or rely on web-worker-based decoders like KTX2 and Draco.
  2. Batch Progress Updates: Throttle progress updates to requestAnimationFrame to ensure the browser has time to paint DOM changes between heavy memory allocations.
let currentProgress = 0;

function handleProgress(ratio) {
  currentProgress = Math.round(ratio * 100);
  requestAnimationFrame(() => {
    const progressBar = document.getElementById('parse-progress-bar');
    const label = document.getElementById('parse-label');
    if (progressBar && label) {
      progressBar.style.width = `${currentProgress}%`;
      label.textContent = `Parsing model: ${currentProgress}%`;
    }
  });
}

// Execution
loadAndParseGLTF('models/massive-asset.glb', handleProgress)
  .then((gltf) => {
    scene.add(gltf.scene);
  })
  .catch((error) => {
    console.error('Error parsing GLTF:', error);
  });

Using this approach decouples network transport from the actual geometry and material compilation, providing a fully transparent loading sequence for massive Three.js scenes.
