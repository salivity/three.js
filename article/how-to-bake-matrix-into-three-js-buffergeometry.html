How to Bake Matrix into Three.js BufferGeometry

In Three.js, transforming a 3D object typically occurs at the Object3D or Mesh level during the render loop, leaving the underlying vertex data unchanged. However, you can permanently "bake" transformations—such as translations, rotations, and scales—directly into a BufferGeometry's vertex attributes using the applyMatrix4 method. This article explains how to construct a transformation matrix, apply it permanently to the geometry coordinates, and update relevant attributes like normals and bounding volumes to ensure correct rendering.

Why Bake Transformations?

Baking transforms permanently modifies the vertex positions stored in GPU buffers. This is particularly useful when:

  • Merging multiple geometries into a single mesh to reduce draw calls.
  • Repositioning or adjusting the pivot point of a geometry without creating complex parent-child scene hierarchies.
  • Freezing imported model offsets so the parent mesh's position, rotation, and scale can remain at their identity defaults ((0, 0, 0) position/rotation and (1, 1, 1) scale).

Constructing and Applying the Matrix

The applyMatrix4 method on BufferGeometry takes a single THREE.Matrix4 instance and applies it to every vertex in the position attribute. If normal vectors exist, it also transforms them using the correct normal matrix logic.

Here is how to compose a matrix and bake it into the geometry:

import * as THREE from 'three';

// 1. Create your geometry
const geometry = new THREE.BoxGeometry(1, 1, 1);

// 2. Define the desired transformation components
const position = new THREE.Vector3(10, 0, 0);
const rotation = new THREE.Euler(0, Math.PI / 4, 0);
const quaternion = new THREE.Quaternion().setFromEuler(rotation);
const scale = new THREE.Vector3(2, 2, 2);

// 3. Compose the components into a Matrix4
const matrix = new THREE.Matrix4();
matrix.compose(position, quaternion, scale);

// 4. Permanently bake the matrix into the geometry
geometry.applyMatrix4(matrix);

Once executed, every vertex in geometry.attributes.position is multiplied by the matrix. The original vertex positions are permanently overwritten.

Recomputing Normals and Bounding Volumes

Altering vertex positions invalidates the geometry's existing spatial boundaries and can distort pre-computed lighting data. After calling applyMatrix4, always recalculate the vertex normals and bounding volumes:

// Recompute surface normals for correct lighting calculations
geometry.computeVertexNormals();

// Update bounding box and sphere for proper frustum culling and raycasting
geometry.computeBoundingBox();
geometry.computeBoundingSphere();

Alternative Convenience Methods

If you only need a simple, single-axis transformation rather than a full 4x4 matrix, Three.js provides built-in wrapper methods on BufferGeometry that invoke applyMatrix4 internally:

  • geometry.translate(x, y, z)
  • geometry.scale(x, y, z)
  • geometry.rotateX(radians)
  • geometry.rotateY(radians)
  • geometry.rotateZ(radians)

These helpers achieve the same outcome as constructing a THREE.Matrix4 manually, modifying the underlying vertex attributes directly and permanently.
