Query Max Varying Vectors in Three.js

When writing custom shaders in Three.js, you may need to know the hardware limits of the client's GPU to avoid shader compilation errors caused by passing too much interpolated data between stages. This article explains how to directly query the maximum number of varying vectors supported by a user's GPU using the Three.js WebGLRenderer and the underlying WebGL context.

Accessing the WebGL Context

Varying variables (or simply "varyings") transfer data from the vertex shader to the fragment shader. While Three.js abstracts most low-level WebGL commands, it provides direct access to the rendering context via renderer.getContext(). To find the limit for varying vectors, query this context using the standard WebGL parameter constant gl.MAX_VARYING_VECTORS.

Implementation

Ensure that your WebGLRenderer instance is already initialized before executing the query:

import * as THREE from 'three';

// 1. Initialize the renderer
const renderer = new THREE.WebGLRenderer();

// 2. Retrieve the underlying WebGLRenderingContext
const gl = renderer.getContext();

// 3. Query the maximum number of varying vectors
const maxVaryingVectors = gl.getParameter(gl.MAX_VARYING_VECTORS);

console.log(`Maximum Varying Vectors: ${maxVaryingVectors}`);

Understanding the Results

  • Minimum Specifications: The WebGL 1.0 specification guarantees a minimum of 8 varying vectors (each vector consists of 4 floating-point components, matching a vec4). WebGL 2.0 raises the minimum guarantee to 15 varying vectors.
  • Component Packing: When building custom GLSL shaders, smaller data types such as float or vec2 can be packed together into single varying vectors by the driver, but relying strictly on vector count limits ensures cross-device compatibility.
  • Context Availability: Always ensure the renderer has not lost its WebGL context before running this query, as calling getParameter on a lost context returns null.
