Asynchronously Load WebXR Controllers in Three.js

This article explains how to detect connected WebXR hardware, match the appropriate controller profile, and asynchronously load interactive 3D controller models inside a Three.js scene. By leveraging the WebXR Device API's profiles array alongside the official XRControllerModelFactory, developers can ensure that users see an accurate, hardware-matched 3D representation of their physical VR or AR controllers complete with working button and joystick animations.

The WebXR Controller Profile Pipeline

WebXR does not provide controller 3D meshes natively. Instead, when a controller connects, the browser populates an XRInputSource object containing an ordered array of strings called profiles. These strings describe the device hierarchy, starting from the most specific hardware identifier (e.g., oculus-touch-v3, valve-index) down to generic fallbacks (e.g., generic-trigger-squeeze-thumbstick).

The official WebXR Input Profiles project maintains 3D GLTF models and mapping definitions for these profiles. In Three.js, the XRControllerModelFactory automates the process: it queries the profiles array, downloads the matching GLTF asset and layout JSON from a CDN or local directory, and binds the model’s moving parts to the controller's gamepad axes and buttons.

Step-by-Step Implementation

1. Import Required Modules

To load hardware-matched models, import the base Three.js library and the XRControllerModelFactory add-on:

import * as THREE from 'three';
import { XRControllerModelFactory } from 'three/addons/webxr/XRControllerModelFactory.js';

2. Enable WebXR on the Renderer

Ensure the WebXR manager is active on your WebGLRenderer:

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);
renderer.xr.enabled = true;
document.body.appendChild(renderer.domElement);

3. Initialize Controller Grips and the Factory

Three.js separates controller ray pointers (targets) from the physical hand models (grips). Hardware controller models should be attached to the controller grip spaces:

const controllerModelFactory = new XRControllerModelFactory();

// Controller Grip 0 (e.g., Left or Right Hand)
const controllerGrip0 = renderer.xr.getControllerGrip(0);
const model0 = controllerModelFactory.createControllerModel(controllerGrip0);
controllerGrip0.add(model0);
scene.add(controllerGrip0);

// Controller Grip 1 (Opposite Hand)
const controllerGrip1 = renderer.xr.getControllerGrip(1);
const model1 = controllerModelFactory.createControllerModel(controllerGrip1);
controllerGrip1.add(model1);
scene.add(controllerGrip1);

How Asynchronous Matching and Loading Works

When a WebXR session starts and input devices are identified:

  1. connected Event Fired: The controllerGrip listens for the connected event emitted by the WebXR manager.
  2. Profile Negotiation: The event supplies the XRInputSource. The factory parses inputSource.profiles to find the highest-priority profile available in the motion-controller repository.
  3. Asset Fetching: The factory asynchronously downloads the matching .gltf or .glb mesh and its corresponding layout schema.
  4. Node Hierarchy Mapping: Once fetched, the mesh is instantiated as a child of the controllerGrip. The factory maps named bones and meshes (such as triggers, thumbsticks, and face buttons) to the indices of inputSource.gamepad.buttons and inputSource.gamepad.axes.
  5. Dynamic Updates: During each frame render, the internal model updates button depressions and stick angles according to user input.

Handling Disconnections and Fallbacks

Hardware disconnections should be handled cleanly to avoid rendering ghost controllers. When a device disconnects, Three.js fires the disconnected event:

controllerGrip0.addEventListener('disconnected', () => {
    // Optional: Add custom logic such as pausing the experience or hiding UI
});

If a user connects an uncatalogued or custom controller, the WebXR Input Profiles library traverses down the profiles array to a generic profile (such as generic-button). The factory will load a standard fallback model rather than failing completely.

Using Local Assets for Offline Support

By default, XRControllerModelFactory loads assets from the jsDelivr CDN hosting the @webxr-input-profiles/assets package. For offline environments or private networks, configure a local path:

const controllerModelFactory = new XRControllerModelFactory();
controllerModelFactory.setPath('./path-to-local-models/webxr-input-profiles/');

Ensure the local folder structure mirrors the organization of the official WebXR Input Profiles repository (containing profile vendor folders with corresponding .json and .glb assets).
