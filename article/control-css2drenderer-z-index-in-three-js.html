Control CSS2DRenderer z-index in Three.js

Controlling the stacking order (z-index) of HTML elements managed by the Three.js CSS2DRenderer can be challenging because the renderer dynamically modifies DOM hierarchy and styles based on 3D coordinates and camera distance. By default, CSS2DRenderer depth-sorts objects relative to the projection plane and re-appends DOM nodes to simulate visual depth. To strictly enforce a custom z-index on these elements, you must override this automatic behavior by manipulating the element’s CSS stacking context, enforcing properties during the render loop, or using separated rendering layers.

Understanding the Default Behavior

In Three.js, CSS2DRenderer maintains an internal renderList. In each render cycle, it computes the distanceToProjectionPlane for each CSS2DObject and sorts the list from furthest to nearest. It then appends each object’s DOM element sequentially to the renderer's wrapper container.

Because elements are absolutely positioned siblings within the same parent <div>, their visual stacking order is dictated by two factors:

  1. Their order in the DOM tree (furthest elements are appended first, nearest are appended last).
  2. Any explicit z-index applied to the elements.

When multiple elements overlap at similar depths, or when you want a background element to visually appear in front regardless of 3D distance, relying on DOM reordering fails.

Method 1: Assigning Explicit z-index with CSS

Because CSS2DObject creates an element with position: absolute;, assigning an explicit integer z-index overrides the natural DOM order (document order only determines stacking when elements share the same z-index).

Apply the z-index directly to the CSS2DObject's root element:

const labelDiv = document.createElement('div');
labelDiv.className = 'custom-label';
labelDiv.textContent = 'High Priority Element';

// Force an explicit z-index on the root element
labelDiv.style.zIndex = '1000';

const labelObject = new CSS2DObject(labelDiv);
scene.add(labelObject);

To prevent other CSS classes or updates from clearing it, you can declare it in your stylesheet using !important:

.custom-label {
    position: absolute; /* Ensures CSS positioning rules apply */
    z-index: 1000 !important;
}

.background-label {
    position: absolute;
    z-index: 1 !important;
}

Elements with z-index: 1000 will always render above elements with lower values, regardless of camera distance or DOM insertion order.

Method 2: Dynamic Enforcement in the Render Loop

If elements require dynamic stacking (for example, distance-based rendering with custom priority tiers), update the z-index inside the requestAnimationFrame loop prior to calling css2DRenderer.render().

function animate() {
    requestAnimationFrame(animate);

    // Calculate priority or evaluate condition
    if (shouldStayOnTop(customObject)) {
        customObject.element.style.zIndex = '9999';
    } else {
        // Base z-index on distance to prevent default DOM collisions
        const distance = camera.position.distanceTo(customObject.position);
        customObject.element.style.zIndex = `${Math.floor(10000 - distance)}`;
    }

    renderer.render(scene, camera);
    css2DRenderer.render(scene, camera);
}

Mapping the camera distance to an integer z-index maintains fine-grained depth order without letting DOM append-order inconsistencies disrupt element visibility.

Method 3: Multiple CSS2DRenderer Instances for Strict Layering

When managing distinct categories of labels (such as interactive UI overlays that must strictly sit above general world-space annotations), overriding z-index per element can lead to style maintenance issues. A clean architectural approach is using multiple CSS2DRenderer instances.

  1. Create two renderer containers and give the overlay container a higher z-index:
// Base 2D Renderer for world labels
const worldRenderer = new CSS2DRenderer();
worldRenderer.setSize(window.innerWidth, window.innerHeight);
worldRenderer.domElement.style.position = 'absolute';
worldRenderer.domElement.style.top = '0px';
worldRenderer.domElement.style.zIndex = '1';
document.body.appendChild(worldRenderer.domElement);

// Overlay 2D Renderer for UI markers
const overlayRenderer = new CSS2DRenderer();
overlayRenderer.setSize(window.innerWidth, window.innerHeight);
overlayRenderer.domElement.style.position = 'absolute';
overlayRenderer.domElement.style.top = '0px';
overlayRenderer.domElement.style.zIndex = '2';
overlayRenderer.domElement.style.pointerEvents = 'none'; // Allow events to pass through if needed
document.body.appendChild(overlayRenderer.domElement);
  1. Separate elements by scene or visibility layers, then render both in your animation loop:
function animate() {
    requestAnimationFrame(animate);

    webGLRenderer.render(scene, camera);
    worldRenderer.render(worldScene, camera);
    overlayRenderer.render(overlayScene, camera);
}

This isolates the stacking contexts completely, guaranteeing that everything rendered by the overlayRenderer appears above elements handled by the worldRenderer.
