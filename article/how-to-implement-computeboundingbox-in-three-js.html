How to Implement computeBoundingBox in Three.js

This guide explains how to manually define and override the computeBoundingBox method on a Three.js BufferGeometry. By overriding the default bounding box computation, you can assign custom collision and culling boundaries analytically for procedural meshes, avoiding the performance penalty of parsing large vertex buffers during real-time updates.

Understanding Bounding Boxes in Three.js

By default, calling geometry.computeBoundingBox() iterates over every coordinate in the geometry's position attribute to find the minimum and maximum coordinates. For procedural geometries with thousands of vertices, or shapes whose mathematical boundaries are already known (such as parametric surfaces, procedural terrain, or dynamic ribbons), iterating through vertex buffers is unnecessarily slow.

Three.js stores the axis-aligned bounding box (AABB) in the geometry.boundingBox property as a THREE.Box3. Raycasting, frustum culling, and collision detection systems query this bounding box directly.

Overriding computeBoundingBox

To define collision boundaries manually, attach a custom function directly to your BufferGeometry instance that updates the boundingBox property using predefined coordinates instead of vertex traversal.

import * as THREE from 'three';

// Create procedural geometry
const geometry = new THREE.BufferGeometry();

// Define known procedural limits
const dimensions = {
  minX: -50,
  minY: 0,
  minZ: -50,
  maxX: 50,
  maxY: 20,
  maxZ: 50
};

// Override the default computeBoundingBox method
geometry.computeBoundingBox = function () {
  if (!this.boundingBox) {
    this.boundingBox = new THREE.Box3();
  }

  // Set the analytical min and max coordinates
  this.boundingBox.min.set(dimensions.minX, dimensions.minY, dimensions.minZ);
  this.boundingBox.max.set(dimensions.maxX, dimensions.maxY, dimensions.maxZ);
};

// Invoke the method to initialize the bounding box
geometry.computeBoundingBox();

Assigning the Bounding Box Directly

If your procedural geometry has fixed boundaries and never recalculates its limits dynamically, you can assign the THREE.Box3 instance directly without overriding the method:

geometry.boundingBox = new THREE.Box3(
  new THREE.Vector3(-50, 0, -50),
  new THREE.Vector3(50, 20, 50)
);

While direct assignment works for static meshes, overriding computeBoundingBox ensures that internal Three.js functions or third-party physics and collision libraries that invoke geometry.computeBoundingBox() do not overwrite your manual coordinates with automated buffer calculations.

Handling Frustum Culling and Bounding Spheres

Three.js uses geometry.boundingSphere for camera frustum culling before checking the bounding box. If your manual bounding box does not align with the bounding sphere, objects may unexpectedly disappear from view.

You should calculate the bounding sphere from your manual bounding box or override computeBoundingSphere simultaneously:

geometry.computeBoundingSphere = function () {
  if (!this.boundingSphere) {
    this.boundingSphere = new THREE.Sphere();
  }

  if (!this.boundingBox) {
    this.computeBoundingBox();
  }

  // Derive bounding sphere directly from the manual bounding box
  this.boundingBox.getBoundingSphere(this.boundingSphere);
};

// Initialize both bounds
geometry.computeBoundingBox();
geometry.computeBoundingSphere();

Dynamic Procedural Updates

When procedural parameters change (such as terrain height scales or procedural wave amplitudes), update the dimension variables and trigger computeBoundingBox():

function updateProceduralDimensions(newHeight) {
  dimensions.maxY = newHeight;
  
  // Re-run the custom compute logic
  geometry.computeBoundingBox();
  geometry.computeBoundingSphere();
}

This ensures collision systems, spatial partitioners, and raycasters immediately receive updated bounds with zero vertex-loop overhead.
