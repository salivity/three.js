Use cameraPosition in Three.js ShaderMaterial

This article explains how to access the camera's world position within a custom Three.js ShaderMaterial without declaring or manually updating uniform values on every frame. By leveraging Three.js's built-in shader pipeline, the renderer automatically binds and updates the camera's position for you, keeping your render loop clean and performant.

Automatic Uniform Injection in ShaderMaterial

When using THREE.ShaderMaterial, Three.js automatically provides several built-in uniforms to both the vertex and fragment shaders. One of these built-in uniforms is cameraPosition, a vec3 representing the camera's position in world space.

Because Three.js injects this variable behind the scenes, you do not need to:

  1. Declare cameraPosition in your JavaScript uniforms dictionary.
  2. Update the uniform manually inside requestAnimationFrame().
  3. Declare uniform vec3 cameraPosition; manually inside your GLSL code.

Implementation Example

To use cameraPosition, reference the variable directly in your GLSL code.

JavaScript Setup

import * as THREE from 'three';

const material = new THREE.ShaderMaterial({
  uniforms: {
    // Add custom uniforms here, but omit cameraPosition
    uColor: { value: new THREE.Color(0xff0000) }
  },
  vertexShader: `
    varying vec3 vWorldPosition;

    void main() {
      // Pass the world position to the fragment shader
      vec4 worldPosition = modelMatrix * vec4(position, 1.0);
      vWorldPosition = worldPosition.xyz;

      gl_Position = projectionMatrix * viewMatrix * worldPosition;
    }
  `,
  fragmentShader: `
    uniform vec3 uColor;
    varying vec3 vWorldPosition;

    void main() {
      // cameraPosition is automatically available here as a vec3
      float distanceToCamera = distance(cameraPosition, vWorldPosition);

      // Simple depth-based visual output
      float intensity = 1.0 - clamp(distanceToCamera / 50.0, 0.0, 1.0);
      gl_FragColor = vec4(uColor * intensity, 1.0);
    }
  `
});

How It Works Behind the Scenes

During the render cycle, the WebGLRenderer evaluates the active camera and binds its world-space translation coordinates to an internal uniform assigned to the WebGL program.

Three.js automatically prepends internal shader chunks to your custom GLSL when compiling a ShaderMaterial. These prepended definitions declare variables like cameraPosition, viewMatrix, modelMatrix, and normalMatrix.

Important Distinction: RawShaderMaterial

This implicit behavior applies only to THREE.ShaderMaterial. If you use THREE.RawShaderMaterial, Three.js disables all automatic uniform declarations and chunk injections. In a RawShaderMaterial, you must explicitly declare uniform vec3 cameraPosition; in your GLSL and manually pass and synchronize the camera's position through the material's JavaScript uniform object.
