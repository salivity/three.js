Detect Float Texture Support in Three.js

This guide explains how to determine whether a user's GPU supports floating-point textures using the extensions object in Three.js. Floating-point textures are essential for high-precision rendering pipelines, such as High Dynamic Range (HDR) rendering, physics simulations via GPGPU, and high-accuracy depth buffers. By querying the WebGLRenderer.extensions manager, you can verify hardware compatibility at runtime and provide fallbacks for unsupported devices.

Accessing the Three.js Extensions Object

Three.js abstracts low-level WebGL extension queries through the renderer.extensions property on an initialized THREE.WebGLRenderer instance.

The two primary methods available on this object are:

  • renderer.extensions.has(name): Returns a boolean indicating whether the specified extension is supported and enabled.
  • renderer.extensions.get(name): Retrieves the actual WebGL extension object, caching the result internally.

To check for capabilities, initialize your renderer and use extensions.has() with the relevant extension strings.

Key Floating-Point Texture Extensions

Depending on whether the client runs WebGL 1 or WebGL 2, and whether you require 32-bit (full float) or 16-bit (half float) precision, you must check for different extensions:

  1. 32-Bit Full Float Textures (FloatType):

    • WebGL 1: Requires 'OES_texture_float' to sample from float textures.
    • WebGL 2: Float texturing is part of the core specification. However, rendering into a floating-point framebuffer requires the 'EXT_color_buffer_float' extension.

  2. 16-Bit Half Float Textures (HalfFloatType):

    • WebGL 1: Requires 'OES_texture_half_float'.
    • WebGL 2: Core support for sampling. Rendering to half-float targets requires 'EXT_color_buffer_float'.

  3. Linear Filtering (LinearFilter):

    • GPUs do not automatically support bilinear filtering on floating-point textures. To sample these textures with THREE.LinearFilter rather than THREE.NearestFilter, check for:
      • 'OES_texture_float_linear' (for 32-bit float textures).
      • 'OES_texture_half_float_linear' (for 16-bit half-float textures).

Implementation Example

The following pattern demonstrates how to verify read, write, and filtering support across both WebGL 1 and WebGL 2 contexts:

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer({ antialias: true });
const isWebGL2 = renderer.capabilities.isWebGL2;

function checkFloatTextureSupport(renderer) {
  const extensions = renderer.extensions;

  // 1. Basic Float Texture Sampling Support
  const supportsFloatTextures = isWebGL2 
    ? true 
    : extensions.has('OES_texture_float');

  // 2. Half-Float Texture Sampling Support
  const supportsHalfFloatTextures = isWebGL2 
    ? true 
    : extensions.has('OES_texture_half_float');

  // 3. Render Target (Framebuffer) Support
  const canRenderToFloat = isWebGL2
    ? extensions.has('EXT_color_buffer_float')
    : extensions.has('WEBGL_color_buffer_float') || extensions.has('EXT_color_buffer_half_float');

  // 4. Linear Filtering Support
  const supportsFloatLinear = extensions.has('OES_texture_float_linear');
  const supportsHalfFloatLinear = extensions.has('OES_texture_half_float_linear');

  return {
    supportsFloatTextures,
    supportsHalfFloatTextures,
    canRenderToFloat,
    supportsFloatLinear,
    supportsHalfFloatLinear
  };
}

const floatCaps = checkFloatTextureSupport(renderer);

if (!floatCaps.supportsFloatTextures) {
  console.warn('Floating-point textures not supported. Falling back to UnsignedByteType.');
}

Applying the Check to Textures

When creating a THREE.DataTexture or a THREE.WebGLRenderTarget, use the check results to assign the appropriate texture types and filtering modes:

const textureType = floatCaps.supportsFloatTextures 
  ? THREE.FloatType 
  : THREE.UnsignedByteType;

const minFilter = floatCaps.supportsFloatLinear 
  ? THREE.LinearFilter 
  : THREE.NearestFilter;

const renderTarget = new THREE.WebGLRenderTarget(512, 512, {
  type: textureType,
  minFilter: minFilter,
  magFilter: minFilter
});

Querying renderer.extensions before creating high-precision resources prevents WebGL runtime warnings, shader compilation errors, and broken render outputs on devices with constrained GPUs.
