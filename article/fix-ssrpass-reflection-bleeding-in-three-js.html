Fix SSRPass Reflection Bleeding in Three.js

Screen-space reflection (SSR) bleeding in Three.js occurs when reflected rays incorrectly register hits on surfaces hidden behind foreground geometry. Because screen-space passes only have access to 2.5D depth buffer data representing the visible front faces of meshes, you must explicitly define how the shader calculates object depth. Tuning the thickness property and disabling infiniteThick on the SSRPass instance resolves this artifact by establishing strict front-to-back volumetric boundaries for ray intersections.

Key Parameters to Prevent SSR Bleeding

1. ssrPass.thickness

The thickness property defines the assumed depth (in world/view units) of geometry rendered in the depth buffer.

  • The Problem: By default, the shader cannot know how deep an object is. If thickness is set too high, a ray that travels behind a foreground mesh will be registered as an intersection within the object's body, creating distorted reflections of objects located behind the occluder. If it is set too low, rays will pass through edges without triggering valid hits.
  • The Fix: Tune ssrPass.thickness to closely match the typical dimensions of the thinnest occluding geometry in your scene. A common baseline starts around 0.018 to 0.1, but this must be scaled proportionally to your scene's coordinate system. For metric-scale scenes, values between 0.01 and 0.05 generally prevent background leakages while maintaining clean edge reflections.

2. ssrPass.infiniteThick

The infiniteThick boolean controls whether geometry is treated as having an infinite boundary behind its front-facing surface.

  • The Problem: When infiniteThick is set to true, any ray that steps deeper than the front depth value is evaluated as a collision. This virtually guarantees severe reflection bleeding through walls, pillars, and small props.
  • The Fix: Explicitly set ssrPass.infiniteThick = false;. This enforces the thickness threshold, forcing the ray-marching algorithm to continue through open space behind the defined thickness threshold rather than falsely colliding with the back of an occluder.

Secondary Parameters for Fine-Tuning

To eliminate residual edge artifacts and depth-test errors around object contours, adjust these supporting settings:

  • ssrPass.maxDistance: Limits the absolute travel distance of reflection rays. Lowering this value prevents distant background objects from bleeding into foreground floor reflections.
  • ssrPass.surfNormalBias: Offsets the ray origin along the surface normal. Setting this to a small non-zero value prevents self-intersection (surface acne) without projecting the ray far enough to bypass thin geometry.

Configuration Example

import { SSRPass } from 'three/addons/postprocessing/SSRPass.js';

const ssrPass = new SSRPass({
  renderer,
  scene,
  camera,
  width: window.innerWidth,
  height: window.innerHeight,
  groundReflector: null,
  selects: reflectiveObjects
});

// Enforce finite geometry bounds
ssrPass.infiniteThick = false;

// Calibrate depth hit-box to scene units (adjust to asset scale)
ssrPass.thickness = 0.025;

// Restrict ray length to suppress far-field bleeding
ssrPass.maxDistance = 5.0;

composer.addPass(ssrPass);
