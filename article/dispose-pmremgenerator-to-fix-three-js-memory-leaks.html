Dispose PMREMGenerator to Fix Three.js Memory Leaks

Managing WebGL memory is critical in Three.js applications, especially when working with high-dynamic-range (HDR) environment maps. The PMREMGenerator (Prefiltered Mipmapped Radiance Environment Map Generator) allocates internal framebuffers and textures to generate prefiltered environment maps. Failing to release these resources will result in persistent GPU memory leaks. This article outlines the exact process required to thoroughly dispose of a PMREMGenerator instance, its internal render targets, the source assets, and the resulting textures.

Why PMREMGenerator Causes Memory Leaks

When you instantiate a PMREMGenerator, it allocates internal WebGL render targets and compile-specific shaders to blur and process cubemaps across multiple mipmap levels. Additionally, methods like .fromEquirectangular() or .fromScene() produce a new WebGLRenderTarget. If you re-generate environment maps dynamically (e.g., during scene changes or time-of-day transitions) without clearing both the generator and the generated targets, the orphaned textures remain allocated in GPU memory.

Complete Disposal Steps

To completely clear all allocated memory associated with environment map prefiltering, you must handle three separate components: the generated render target, the PMREMGenerator instance itself, and the original source texture.

1. Dispose of the Output Render Target

The prefiltered texture is held within a WebGLRenderTarget. You must dispose of the render target when swapping or unloading the environment:

// If you stored the generated render target
if (envRenderTarget) {
    envRenderTarget.dispose();
}

If you assigned the texture directly to scene.environment or scene.background, dispose of the texture reference:

if (scene.environment) {
    scene.environment.dispose();
    scene.environment = null;
}

2. Dispose of the PMREMGenerator Instance

Calling .dispose() directly on the PMREMGenerator instance frees its internal ping-pong render targets and processing materials from the GPU:

pmremGenerator.dispose();

Note: If you only need to process an environment map once at startup, dispose of the generator immediately after generating your texture rather than keeping the instance in memory.

3. Dispose of the Source Texture

If the source HDR or equirectangular texture is no longer needed after the PMREM output is created, explicitly dispose of it:

hdrTexture.dispose();

Full Implementation Example

Below is a robust implementation demonstrating generation and complete cleanup:

import * as THREE from 'three';
import { RGBELoader } from 'three/examples/jsm/loaders/RGBELoader.js';

let pmremGenerator = new THREE.PMREMGenerator(renderer);
pmremGenerator.compileEquirectangularShader();

let envMapRenderTarget = null;

// Load and process the environment map
new RGBELoader().load('environment.hdr', (texture) => {
    // Generate the prefiltered render target
    envMapRenderTarget = pmremGenerator.fromEquirectangular(texture);
    
    // Assign to scene
    scene.environment = envMapRenderTarget.texture;
    
    // The source texture is no longer needed once processed
    texture.dispose();
    
    // If no more environment maps will be generated, dispose of the generator now
    pmremGenerator.dispose();
    pmremGenerator = null;
});

// Cleanup function to call when unloading the scene or changing environments
function cleanupEnvironment() {
    if (scene.environment) {
        scene.environment.dispose();
        scene.environment = null;
    }

    if (envMapRenderTarget) {
        envMapRenderTarget.dispose();
        envMapRenderTarget = null;
    }

    if (pmremGenerator) {
        pmremGenerator.dispose();
        pmremGenerator = null;
    }
}

By ensuring the generated output target, the source image, and the generator's internal buffers are all explicitly released via their respective .dispose() methods, your application avoids WebGL context bloat and eliminates environment-related memory leaks.
