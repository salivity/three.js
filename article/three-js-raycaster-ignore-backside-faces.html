Three.js Raycaster: Ignore Backside Faces

This article explains how to configure a Three.js Raycaster to ignore the back faces of double-sided geometries (THREE.DoubleSide) during intersection tests. By default, meshes rendered with double-sided materials report ray hits on both interior and exterior surfaces. You will learn how to strictly enforce front-facing-only raycast detection without breaking visual rendering, using either an internal raycast override or post-intersection normal evaluation.

Why Three.js Intersects Back Faces

When a mesh material has its side property set to THREE.DoubleSide, the internal Mesh.prototype.raycast method evaluates intersections against both winding orders of the geometry's triangular faces. This causes the raycaster to return hits when passing through back-facing surfaces (such as the interior walls of an object viewed from the inside or an exit point on an enclosed shape).

To restrict raycasting strictly to front-facing geometry, you must ensure the ray intersection logic only evaluates THREE.FrontSide.

Method 1: Overriding the Mesh raycast Method (Recommended)

The most direct and clean approach is to intercept the mesh's raycast method. Three.js checks material.side on the CPU inside JavaScript at the exact moment raycast() is called. Modifying this value momentarily does not trigger a WebGL shader recompilation or require material.needsUpdate = true.

You can override the raycast method on the target mesh instance:

import * as THREE from 'three';

const mesh = new THREE.Mesh(geometry, new THREE.MeshStandardMaterial({
  side: THREE.DoubleSide
}));

// Override raycast behavior for this specific mesh
mesh.raycast = function (raycaster, intersects) {
  const originalSide = this.material.side;

  // Temporarily force FrontSide detection during the raycast
  this.material.side = THREE.FrontSide;

  // Execute standard raycast logic
  THREE.Mesh.prototype.raycast.call(this, raycaster, intersects);

  // Restore the original material side for visual rendering
  this.material.side = originalSide;
};

If your mesh uses an array of materials (multi-material), loop through the array:

mesh.raycast = function (raycaster, intersects) {
  const isArray = Array.isArray(this.material);
  const materials = isArray ? this.material : [this.material];
  const originalSides = materials.map(m => m.side);

  materials.forEach(m => { m.side = THREE.FrontSide; });

  THREE.Mesh.prototype.raycast.call(this, raycaster, intersects);

  materials.forEach((m, index) => { m.side = originalSides[index]; });
};

Method 2: Filtering Intersections by Face Normal

If you prefer not to modify mesh methods, you can filter the returned intersection array using vector math. A ray only strikes a front face if the surface normal points in the opposite direction of the ray.

Compute the dot product between the surface world normal and the ray direction vector:

  • A negative dot product indicates the vectors point toward each other (Front face).
  • A positive dot product indicates the vectors point in the same direction (Back face).
const intersects = raycaster.intersectObjects(scene.children, true);

const frontSideIntersects = intersects.filter(hit => {
  // If the hit has a precomputed world normal (Three.js r125+)
  if (hit.normal) {
    return hit.normal.dot(raycaster.ray.direction) < 0;
  }

  // Fallback for older versions using hit.face.normal
  if (hit.face) {
    const worldNormal = hit.face.normal.clone().transformDirection(hit.object.matrixWorld);
    return worldNormal.dot(raycaster.ray.direction) < 0;
  }

  return true;
});

Which Approach to Choose

  • Use Method 1 (Raycast Override) when you want the raycaster to ignore back faces at execution time. This avoids calculating intersections that will immediately be thrown away and correctly respects properties like raycaster.firstHitOnly.
  • Use Method 2 (Normal Filtering) when working with external libraries, loaders, or dynamic scenes where patching the raycast method across individual meshes is inconvenient.
