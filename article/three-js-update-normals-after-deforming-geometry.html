Three.js: Update Normals After Deforming Geometry

When you modify the vertices of a BufferGeometry in Three.js, the surface normals do not update automatically, causing lighting calculations and shading to appear flat or broken. This article explains how to correctly deform geometry vertices, trigger computeVertexNormals() to recalculate light reflection vectors, and mark the appropriate buffer attributes for a GPU update.

The Deformation and Recalculation Process

Lighting in Three.js relies heavily on normal vectors pointing outward from each vertex. Modifying the position attribute of a geometry alters its shape, but leaves the original normals intact. To fix lighting artifacts after a deformation, you must recalculate the normals and flag the buffer for upload to the GPU.

1. Update the Positions

First, modify the vertex coordinates stored in the geometry's position attribute. Once the changes are made, set needsUpdate to true on the position attribute so WebGL transmits the new coordinates to the GPU.

const positionAttribute = geometry.attributes.position;

for (let i = 0; i < positionAttribute.count; i++) {
    // Example: Displace vertex along the Y axis
    let y = positionAttribute.getY(i);
    positionAttribute.setY(i, y + Math.sin(i) * 0.5);
}

positionAttribute.needsUpdate = true;

2. Trigger computeVertexNormals

Once the position data is updated, call the computeVertexNormals() method directly on the geometry instance. This method reads the current vertex coordinates, computes face normals, and averages them across adjacent faces to create smooth vertex normals.

geometry.computeVertexNormals();

3. Flag the Normal Attribute for GPU Upload

While computeVertexNormals() recalculates the vector values inside the JavaScript array, you must ensure the underlying WebGL buffer updates. If the geometry already possessed a normal attribute prior to recalculation, set the needsUpdate flag on the normal attribute:

if (geometry.attributes.normal) {
    geometry.attributes.normal.needsUpdate = true;
}

Complete Example

Here is the complete sequence encapsulated in a single reusable function:

function deformAndRecalculate(mesh) {
    const geometry = mesh.geometry;
    const position = geometry.attributes.position;

    // Apply vertex deformation
    for (let i = 0; i < position.count; i++) {
        const x = position.getX(i);
        const z = position.getZ(i);
        
        // Simple wave deformation
        position.setY(i, Math.sin(x * 2.0) * Math.cos(z * 2.0));
    }

    // Flag positions for GPU update
    position.needsUpdate = true;

    // Recalculate the normals based on new positions
    geometry.computeVertexNormals();

    // Ensure the normal attribute updates on the GPU
    geometry.attributes.normal.needsUpdate = true;
}

Important Considerations

  • Indexed vs. Non-Indexed Geometry: computeVertexNormals() behaves differently depending on whether your geometry uses an index buffer. Indexed geometries share vertices across faces, resulting in smooth lighting. Non-indexed geometries have duplicate vertices per face, resulting in faceted (flat) shading unless manually converted using toCreasedNormals() or indexed beforehand.
  • Performance: Recalculating vertex normals on the CPU using computeVertexNormals() involves iterating over every face in the mesh. For complex meshes or continuous per-frame animations, consider deforming vertices and calculating normals inside a custom vertex shader on the GPU instead.
