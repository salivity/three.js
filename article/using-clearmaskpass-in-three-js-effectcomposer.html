Using ClearMaskPass in Three.js EffectComposer

In Three.js post-processing, ClearMaskPass is an essential utility used to deactivate an active stencil mask previously engaged by a MaskPass. This guide provides a concise walkthrough of how masking works in EffectComposer, how to configure the stencil buffer, and how to place ClearMaskPass correctly within your post-processing pipeline to isolate visual effects to specific objects without affecting the rest of the scene.

How Masking Works in EffectComposer

When applying post-processing effects, you often want an effect (such as a bloom, glitch, or color tint) applied only to specific objects or areas. EffectComposer manages this using the WebGL stencil buffer via three components:

  1. MaskPass: Sets up the stencil buffer by rendering a specific mask scene. Any subsequent passes in the composer chain are restricted to the visible pixels of this mask.
  2. Post-Processing Passes: Any effects placed after the MaskPass will only render within the masked boundaries.
  3. ClearMaskPass: Disables the stencil test on the WebGL context, allowing subsequent passes to render to the entire screen again.

Prerequisites

To utilize stencil masking in Three.js, you must ensure the stencil buffer is enabled in both the WebGLRenderer and the EffectComposer render target.

import * as THREE from 'three';
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { MaskPass } from 'three/addons/postprocessing/MaskPass.js';
import { ClearMaskPass } from 'three/addons/postprocessing/ClearMaskPass.js';
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';
import { DotScreenShader } from 'three/addons/shaders/DotScreenShader.js';

// 1. Ensure renderer has stencil enabled (enabled by default, but good practice to verify)
const renderer = new THREE.WebGLRenderer({ stencil: true });
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// 2. Ensure composer render target has stencilBuffer set to true
const renderTarget = new THREE.WebGLRenderTarget(
    window.innerWidth, 
    window.innerHeight, 
    { stencilBuffer: true }
);

const composer = new EffectComposer(renderer, renderTarget);

Structuring the Pass Chain

To use ClearMaskPass, insert it immediately after the passes you wish to restrict.

// Base scene and mask scene definitions
const mainScene = new THREE.Scene();
const maskScene = new THREE.Scene(); // Contains geometry defining the mask region
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);

// Step 1: Render the base scene
const basePass = new RenderPass(mainScene, camera);
composer.addPass(basePass);

// Step 2: Activate the stencil mask
const maskPass = new MaskPass(maskScene, camera);
composer.addPass(maskPass);

// Step 3: Add the passes that should ONLY apply inside the mask
const effectPass = new ShaderPass(DotScreenShader);
composer.addPass(effectPass);

// Step 4: Disable the mask using ClearMaskPass
const clearMaskPass = new ClearMaskPass();
composer.addPass(clearMaskPass);

// Step 5: Add subsequent passes that should affect the entire canvas
// Any pass added here will render globally, unaffected by the mask

Key Technical Considerations

  • No Rendering Output: ClearMaskPass does not draw pixels or clear visual color; it strictly disables the hardware stencil test (gl.disable(gl.STENCIL_TEST) under the hood).
  • Inverse Masking: If you need to render effects outside of the mask geometry instead of inside, set maskPass.inverse = true; before adding it to the composer. The ClearMaskPass will still disable the mask in the exact same manner.
  • Paired Usage: Every MaskPass in an active pipeline should be paired with a corresponding ClearMaskPass further down the chain. Failing to include ClearMaskPass will cause all subsequent passes to remain restricted to the stencil shape.
