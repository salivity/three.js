Initialize MeshoptDecoder WASM in Three.js

When working with glTF models compressed via EXT_meshopt_compression, Three.js requires the MeshoptDecoder utility to decompress geometry on the fly. This article explains how to manually initialize the underlying WebAssembly (WASM) module for MeshoptDecoder, ensuring assets are properly compiled and ready before passing the decoder to GLTFLoader, which is particularly crucial in modern bundler environments like Vite or Webpack.

Why Manual Initialization Is Required

By default, WebAssembly binaries must be loaded and compiled asynchronously before their exported functions can be called. If a GLTFLoader attempts to parse a compressed .gltf or .glb file before the MeshoptDecoder has finished compiling its WASM payload, runtime execution will throw an error. Manually controlling the initialization ensures your application waits for the decoder to be fully active before processing any 3D models.

Standard Asynchronous Initialization

The official Three.js distribution of MeshoptDecoder exports an asynchronous promise named ready. Awaiting this promise ensures that the WebAssembly binary has been fetched, compiled, and instantiated.

import * as THREE from 'three';
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
import { MeshoptDecoder } from 'three/addons/libs/meshopt_decoder.module.js';

async function initScene() {
    // 1. Wait for the WebAssembly module to compile and initialize
    await MeshoptDecoder.ready;

    // 2. Instantiate and configure GLTFLoader
    const loader = new GLTFLoader();
    loader.setMeshoptDecoder(MeshoptDecoder);

    // 3. Load the compressed glTF asset safely
    loader.load('path/to/model.glb', (gltf) => {
        const model = gltf.scene;
        // Proceed with adding the model to your Three.js scene
    });
}

initScene();

Manual Initialization with Custom WASM Paths

In specific production environments, such as content delivery networks (CDNs) or bundlers that do not automatically resolve the internal WASM URL, you may need to fetch the .wasm file manually using the Fetch API and feed it to the decoder.

If you are using the standalone meshoptimizer npm package, you can supply your own compiled WebAssembly instance or initialize it using WebAssembly.compile:

import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
import { MeshoptDecoder } from 'meshoptimizer';

async function setupMeshoptDecoder() {
    // Fetch the external WASM file directly
    const response = await fetch('/path/to/meshopt_decoder.wasm');
    const wasmBinary = await response.arrayBuffer();

    // Compile and initialize the module manually
    await MeshoptDecoder.ready;
    
    // Some custom builds support explicitly passing the buffer:
    if (typeof MeshoptDecoder.use === 'function') {
        const module = await WebAssembly.compile(wasmBinary);
        MeshoptDecoder.use(module);
    }

    const loader = new GLTFLoader();
    loader.setMeshoptDecoder(MeshoptDecoder);

    return loader;
}

Best Practices

  • Initialize Once: Call and await MeshoptDecoder.ready at application startup. You do not need to reinitialize it for every model; a single global initialization suffices for the entire runtime.
  • Combine with DRACOLoader: If your application loads models with varying compression standards, initialize both MeshoptDecoder and DRACOLoader simultaneously before beginning file downloads to avoid pipeline bottlenecks.
