Manual Three.js VideoTexture Updates on Video Frames

This guide explains how to manually synchronize a Three.js VideoTexture with an HTML <video> element using frame-specific listeners. While Three.js typically updates video textures automatically on each render tick, synchronizing updates directly with the video source saves GPU cycles and ensures textures refresh precisely when new visual data is decoded.

1. The Listener Mechanism: requestVideoFrameCallback

The most performant and precise method to listen for new video frames is HTMLVideoElement.requestVideoFrameCallback(). Unlike the standard timeupdate event—which fires at a low and irregular frequency—requestVideoFrameCallback() executes a callback whenever a new video frame is decoded and submitted for composition.

For manual stepping or scrubbing without continuous playback, the native 'seeked' event listener can also be used.

2. Disabling Automatic Texture Updates

By default, Three.js flags a VideoTexture for an update whenever videoTexture.update() is called inside the render loop. If you want full manual control over when GPU uploads occur, you should use a base THREE.Texture with the video as the source, or manually control the update flag using a condition.

import * as THREE from 'three';

const video = document.getElementById('videoElement');

// Using a standard Texture prevents Three.js from setting needsUpdate automatically
const videoTexture = new THREE.Texture(video);
videoTexture.minFilter = THREE.LinearFilter;
videoTexture.magFilter = THREE.LinearFilter;
videoTexture.format = THREE.RGBAFormat;

3. Attaching the Callback for Continuous Frame Synchronization

Attach requestVideoFrameCallback to your video element. Inside the callback, mark videoTexture.needsUpdate = true and re-register the callback to listen for subsequent frames.

function setupFrameListener(video, texture) {
  const onFrameAvailable = (now, metadata) => {
    // metadata contains frame details (e.g., presentedFrames, mediaTime)
    // You can apply logic here to update only on specific frames:
    if (metadata.presentedFrames % 2 === 0) {
      texture.needsUpdate = true;
    }

    // Re-register the callback for the next video frame
    video.requestVideoFrameCallback(onFrameAvailable);
  };

  // Initial call to attach the listener
  if ('requestVideoFrameCallback' in video) {
    video.requestVideoFrameCallback(onFrameAvailable);
  } else {
    // Fallback for browsers lacking requestVideoFrameCallback support
    video.addEventListener('timeupdate', () => {
      texture.needsUpdate = true;
    });
  }
}

setupFrameListener(video, videoTexture);

4. Attaching Listeners for Specific Events (Scrubbing / Paused Playback)

When stepping through a video programmatically (for example, scrubbing through specific timestamps while the video is paused), use the 'seeked' event listener on the video element:

video.addEventListener('seeked', () => {
  // Manually flag the texture for an update once the seek operation completes
  videoTexture.needsUpdate = true;
});

// Programmatically step to a specific frame timestamp
function seekToFrame(timeInSeconds) {
  video.currentTime = timeInSeconds;
}

5. Managing the Render Loop

Because the texture's needsUpdate flag is set only when the listener triggers, your standard Three.js render loop does not need to manage video synchronization logic:

function animate() {
  requestAnimationFrame(animate);

  // The texture updates onto the GPU only when needsUpdate was set by the listener
  renderer.render(scene, camera);
}

animate();
