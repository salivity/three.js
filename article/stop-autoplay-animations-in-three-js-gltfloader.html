Stop Autoplay Animations in Three.js GLTFLoader

This guide explains how to prevent and safely disable the automatic playback of embedded animations when importing 3D models with Three.js GLTFLoader. By default, Three.js does not play animations without an AnimationMixer, but many viewer setups, boilerplates, and loaders automatically trigger playback within their loading callbacks. Below are the precise steps and code practices required to keep embedded glTF animations halted immediately upon loading until you explicitly trigger them.

Why GLTF Animations Autoplay

Three.js requires an AnimationMixer to advance animation clips. In glTF files, animations are stored inside the gltf.animations array. If an animation plays immediately upon loading, it is because your code (or a library wrapper) creates an AnimationMixer, retrieves an AnimationAction via mixer.clipAction(), and calls .play() within the GLTFLoader.load() success callback.

Preventing Playback at the Loader Level

The safest way to disable automatic playback is to instantiate the AnimationMixer without triggering .play() on any clip actions. Store references to the clips so they can be triggered later via user interaction or custom game logic.

import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';

const loader = new GLTFLoader();
let mixer = null;
const actions = {};

loader.load('model.glb', (gltf) => {
    const model = gltf.scene;
    scene.add(model);

    // 1. Initialize the mixer
    mixer = new THREE.AnimationMixer(model);

    // 2. Prepare animations without playing them
    gltf.animations.forEach((clip) => {
        const action = mixer.clipAction(clip);
        // Do NOT call action.play() here
        actions[clip.name] = action;
    });
});

Safely Halting Pre-Configured or Wrapper Autoplay

If you are using a setup where actions are already running, or if you use automated tools that launch animations automatically, call .stop() on all running actions immediately after initialization:

loader.load('model.glb', (gltf) => {
    const model = gltf.scene;
    scene.add(model);

    mixer = new THREE.AnimationMixer(model);

    gltf.animations.forEach((clip) => {
        const action = mixer.clipAction(clip);
        
        // Immediately halt and reset the action if previously played
        action.stop();
        action.reset();
        
        // Optional: Keep it on the first frame without running
        action.paused = true;
    });
});

Managing the Animation Loop Safely

Even if .play() is called, the animation will not visibly progress in the scene unless the mixer's time is updated. To safely ensure background processing does not silently advance hidden animations, guard the mixer.update() call inside your render loop:

const clock = new THREE.Clock();
let isAnimationEnabled = false;

function animate() {
    requestAnimationFrame(animate);

    const delta = clock.getDelta();

    // Only advance the mixer when you explicitly allow it
    if (mixer && isAnimationEnabled) {
        mixer.update(delta);
    }

    renderer.render(scene, camera);
}

animate();

By decoupling action creation from .play() and conditionally controlling the mixer.update(delta) call in the render loop, you ensure embedded glTF animations remain completely static upon loading.
