How to Share Image Data with Three.js Source

In Three.js, the Source class decouples raw image or pixel data from individual texture configurations, allowing developers to share one underlying graphical asset across multiple distinct textures. This guide covers how to instantiate and assign a THREE.Source instance to multiple Texture objects, configure unique sampling properties—such as wrapping, filtering, and UV offsets—for each texture independently, and optimize GPU memory by avoiding redundant texture uploads.

Understanding the Role of THREE.Source

Historically, THREE.Texture held both the visual data (an image, canvas, or video) and the rendering settings (wrapping, filtering, mipmapping, and transformation). Starting in Three.js r139, the visual data layer was separated into THREE.Source.

A Source holds the reference to the actual image element or typed array data, while the Texture handles the sampler state. When multiple Texture instances point to the same Source, WebGL creates only one GPU texture resource for the image data, while allowing your scene to use distinct sampling states for different materials.

Creating and Assigning a Shared Source

You can create a THREE.Source directly using an HTML image, video, or canvas element, or by extracting the .source property from a texture loaded via TextureLoader.

import * as THREE from 'three';

// Option A: Extract a Source from an existing loaded texture
const loader = new THREE.TextureLoader();
const baseTexture = loader.load('textures/pattern.png');
const sharedSource = baseTexture.source;

// Option B: Manually instantiate a Source using an HTML Image element
const image = new Image();
image.src = 'textures/pattern.png';
const manualSource = new THREE.Source(image);

Once you have a Source instance, assign it to the .source property of any new Texture instances:

// Texture 1: Standard mapping
const textureA = new THREE.Texture();
textureA.source = sharedSource;
textureA.needsUpdate = true;

// Texture 2: Repeating tiled pattern
const textureB = new THREE.Texture();
textureB.source = sharedSource;
textureB.wrapS = THREE.RepeatWrapping;
textureB.wrapT = THREE.RepeatWrapping;
textureB.repeat.set(4, 4);
textureB.needsUpdate = true;

Managing Independent Sampler States

Because Source only manages the pixel buffer, every texture referencing it retains full control over its individual rendering settings:

  • Wrapping: Assign THREE.RepeatWrapping, THREE.MirroredRepeatWrapping, or THREE.ClampToEdgeWrapping on individual textures.
  • Transformations: Modify .repeat, .offset, .center, and .rotation independently on each texture without affecting the others.
  • Filtering: Configure .minFilter and .magFilter per texture (for example, applying THREE.NearestFilter for a pixelated look on one object and THREE.LinearMipmapLinearFilter on another).

Updating Dynamic Data

When using dynamic sources like an HTMLCanvasElement or an HTMLVideoElement, updating the underlying data must be flagged directly on the Source object rather than the Texture:

// Trigger an update for all dependent textures when the canvas redraws
sharedSource.needsUpdate = true;

Setting needsUpdate = true on the Source notifies Three.js to re-upload the image data to the GPU. All linked Texture objects will reflect the update in the next render frame.
