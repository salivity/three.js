How to Set Precision in Three.js RawShaderMaterial

This article explains how to define precision qualifiers—highp, mediump, and lowp—when writing custom shaders with RawShaderMaterial in Three.js. Unlike standard ShaderMaterial, RawShaderMaterial does not automatically inject default WebGL precision declarations or uniforms into your shader source. You will learn how to declare global default precisions, how to specify precision on individual variables, and how to maintain cross-platform compatibility across desktop and mobile devices.

Why Precision Must Be Defined Manually

When using THREE.ShaderMaterial, Three.js automatically prepends precision definitions (such as precision highp float;) along with built-in attributes and uniforms to your GLSL strings.

THREE.RawShaderMaterial bypasses all preprocessing. The GLSL code you provide is passed directly to the WebGL compiler. While vertex shaders have a default precision of highp in most WebGL implementations, fragment shaders have no default float precision. If you omit the float precision declaration in a fragment shader, the shader will fail to compile.

Setting Global Precision Qualifiers

The standard method for defining precision in a RawShaderMaterial is declaring global precision directives at the very top of your vertex and fragment shader code strings.

Fragment Shader Example

In your fragment shader, declare the precision for floating-point and integer types at the beginning of the file:

precision highp float;
precision mediump int;

varying vec2 vUv;
uniform vec3 uColor;

void main() {
    gl_FragColor = vec4(uColor, 1.0);
}

Vertex Shader Example

Although vertex shaders default to highp on most hardware, explicitly declaring it ensures consistent behavior:

precision highp float;
precision highp int;

attribute vec3 position;
attribute vec2 uv;

uniform mat4 modelViewMatrix;
uniform mat4 projectionMatrix;

varying vec2 vUv;

void main() {
    vUv = uv;
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}

Setting Precision on Individual Variables

You can override the global precision for specific variables to optimize performance or memory usage. This is done by placing the precision qualifier directly before the type declaration.

precision highp float; // Default float precision

uniform lowp vec4 uBaseColor;       // 8-bit per channel color representation
uniform mediump sampler2D uTexture; // Texture coordinates or standard texture lookups
varying highp vec3 vWorldPosition;  // High precision required for accurate spatial math

Supported Precision Levels

  • highp: Highest precision (typically 32-bit floats). Required for position coordinates, world-space calculations, and depth values to avoid visual artifacts like vertex jitter or Z-fighting.
  • mediump: Intermediate precision (typically 16-bit floats with a range of -2^14 to 2^14). Ideal for texture coordinates, normals, and lighting vectors.
  • lowp: Lowest precision (typically 8-bit to 10-bit fixed point with a range of -2 to 2). Best suited for standard RGB colors and simple multipliers.

Handling Mobile Compatibility in WebGL 1

If your application targets WebGL 1, some mobile GPUs do not support highp precision in fragment shaders. You can conditionally fall back to mediump using GLSL preprocessor directives:

#ifdef GL_FRAGMENT_PRECISION_HIGH
    precision highp float;
#else
    precision mediump float;
#endif

In WebGL 2, highp support is mandatory in fragment shaders, making this conditional check unnecessary if you enforce a WebGL 2 rendering context in Three.js.
