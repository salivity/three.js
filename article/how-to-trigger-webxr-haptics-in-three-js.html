How to Trigger WebXR Haptics in Three.js

Haptic feedback significantly enhances immersion in virtual reality by providing tactile responses to user interactions, such as pressing buttons or colliding with objects. In Three.js, haptics are achieved by accessing the underlying XRInputSource from the WebXR Device API and triggering the controller's haptic actuators through the standard Gamepad API. This guide walks you through detecting supported controllers, accessing the haptic actuator, and executing vibration pulses directly within your Three.js application.

Accessing the WebXR Controller in Three.js

Three.js abstracts VR controllers via renderer.xr.getController(index) and renderer.xr.getControllerGrip(index). However, haptic pulses are dispatched directly on the native browser Gamepad object associated with the input source, rather than Three.js objects.

Listen for the connected event on the Three.js controller to get a reference to the native WebXR XRInputSource:

const controller = renderer.xr.getController(0);
scene.add(controller);

let controllerInputSource = null;

controller.addEventListener('connected', (event) => {
    // event.data is the XRInputSource
    controllerInputSource = event.data;
});

controller.addEventListener('disconnected', () => {
    controllerInputSource = null;
});

Triggering the Haptic Pulse

Once you have access to the XRInputSource, the vibration functionality is found on inputSource.gamepad.hapticActuators.

The primary method used to trigger vibration is pulse(value, duration):

  • value: A float between 0.0 (no vibration) and 1.0 (maximum intensity).
  • duration: The length of the vibration in milliseconds.

Reusable Haptic Function

Browsers may implement either the standard hapticActuators array or the newer vibrationActuator interface. Here is a safe, cross-browser helper function:

function triggerHaptic(inputSource, intensity = 0.5, duration = 100) {
    if (!inputSource || !inputSource.gamepad) return;

    const gamepad = inputSource.gamepad;

    // Standard WebXR Haptic Actuator
    if (gamepad.hapticActuators && gamepad.hapticActuators.length > 0) {
        const actuator = gamepad.hapticActuators[0];
        actuator.pulse(intensity, duration);
    } 
    // Fallback for modern standard vibrationActuator (dual-rumble)
    else if (gamepad.vibrationActuator && gamepad.vibrationActuator.playEffect) {
        gamepad.vibrationActuator.playEffect('dual-rumble', {
            startDelay: 0,
            duration: duration,
            weakMagnitude: intensity,
            strongMagnitude: intensity,
        });
    }
}

Complete Implementation Example

The following example triggers a brief vibration whenever the user pulls the controller trigger (selectstart event):

import * as THREE from 'three';
import { VRButton } from 'three/addons/webxr/VRButton.js';

// 1. Initialize Scene, Camera, and Renderer
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(70, window.innerWidth / window.innerHeight, 0.1, 100);

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);
renderer.xr.enabled = true;
document.body.appendChild(renderer.domElement);
document.body.appendChild(VRButton.createButton(renderer));

// 2. Setup Controller
const controller = renderer.xr.getController(0);
scene.add(controller);

let inputSource = null;

controller.addEventListener('connected', (event) => {
    inputSource = event.data;
});

controller.addEventListener('disconnected', () => {
    inputSource = null;
});

// 3. Trigger Haptics on User Action
controller.addEventListener('selectstart', () => {
    // Fire a 100ms vibration at 80% intensity
    triggerHaptic(inputSource, 0.8, 100);
});

// 4. Animation Loop
renderer.setAnimationLoop(() => {
    renderer.render(scene, camera);
});

Key Considerations

  • User Activation: WebXR requires an active XR session before hardware inputs and actuators become accessible. Haptics will not execute outside of immersive mode.
  • Hardware Limitations: Some VR hardware does not allow pulses shorter than a single internal frame cycle (typically 10–16ms). Setting a duration lower than hardware capabilities will usually default to a minimum recognizable click.
