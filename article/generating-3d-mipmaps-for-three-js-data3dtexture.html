Generating 3D Mipmaps for Three.js Data3DTexture

Generating custom 3D mipmaps for a Three.js Data3DTexture requires downsampling volumetric voxel data across three dimensions using an eight-point box filter, computing accurate intermediate levels down to a \(1 \times 1 \times 1\) voxel, and assigning these arrays directly to the texture's mipmaps property. This guide breaks down the mathematical formulation of 3D box filtering, non-power-of-two boundary handling, and the concrete implementation needed to pass precomputed mip levels into Three.js with the correct filter settings.

Mathematical Downsampling of 3D Volumes

In a standard 2D texture, each successive mipmap level reduces dimensions by half along two axes, averaging four texels into one. In a 3D volume, the reduction occurs across three axes (\(X, Y, Z\)). Every step downsamples a \(2 \times 2 \times 2\) block of voxels into a single voxel, meaning each downsampled value is the arithmetic mean of eight adjacent voxels from the previous level.

Given a mip level \(L\) with dimensions \(W_L \times H_L \times D_L\), the dimensions of the next level \(L+1\) are:

\[W_{L+1} = \max(1, \lfloor W_L / 2 \rfloor)\] \[H_{L+1} = \max(1, \lfloor H_L / 2 \rfloor)\] \[D_{L+1} = \max(1, \lfloor D_L / 2 \rfloor)\]

For a single-channel voxel at coordinate \((x, y, z)\) in level \(L+1\), the mathematical box filter is:

\[V_{L+1}(x, y, z) = \frac{1}{8} \sum_{dz=0}^{1} \sum_{dy=0}^{1} \sum_{dx=0}^{1} V_L(2x + dx, 2y + dy, 2z + dz)\]

When working with multi-channel data (such as RGBA), this averaging must be performed independently per component.

Handling Odd Dimensions and Boundaries

If any dimension of the parent level is odd, an exact \(2 \times 2 \times 2\) block cannot be formed at the edge. To avoid reading out-of-bounds values or biasing the result, clamp sample indices to the maximum index of the parent level (\(W_L - 1, H_L - 1, D_L - 1\)) and normalize the sum by the actual count of valid unique samples contributing to that voxel:

\[V_{L+1}(x, y, z) = \frac{1}{N} \sum_{dz=0}^{\min(1, D_L - 1 - 2z)} \sum_{dy=0}^{\min(1, H_L - 1 - 2y)} \sum_{dx=0}^{\min(1, W_L - 1 - 2x)} V_L(2x + dx, 2y + dy, 2z + dz)\]

where \(N\) is the total count of valid voxels summed in the footprint.

Indexing Volumetric Data in Memory

In Three.js, volumetric data is stored linearly in typed arrays (such as Uint8Array or Float32Array). For a volume with width \(W\), height \(H\), depth \(D\), and \(C\) channels per voxel, the 1D index for a coordinate \((x, y, z, c)\) is:

\[\text{Index}(x, y, z, c) = ((z \times H + y) \times W + x) \times C + c\]

Algorithmic Implementation

Below is the complete algorithmic function for generating all downsampled levels from a base 3D typed array and constructing the mipmap hierarchy:

function generate3DMipmaps(baseData, width, height, depth, channels) {
  const mipmaps = [];
  
  // Level 0 is the full-resolution source
  mipmaps.push({
    data: baseData,
    width: width,
    height: height,
    depth: depth
  });

  let currentData = baseData;
  let currW = width;
  let currH = height;
  let currD = depth;

  while (currW > 1 || currH > 1 || currD > 1) {
    const nextW = Math.max(1, Math.floor(currW / 2));
    const nextH = Math.max(1, Math.floor(currH / 2));
    const nextD = Math.max(1, Math.floor(currD / 2));

    const nextData = new baseData.constructor(nextW * nextH * nextD * channels);

    for (let z = 0; z < nextD; z++) {
      for (let y = 0; y < nextH; y++) {
        for (let x = 0; x < nextW; x++) {
          
          for (let c = 0; c < channels; c++) {
            let sum = 0;
            let count = 0;

            const srcX = x * 2;
            const srcY = y * 2;
            const srcZ = z * 2;

            for (let dz = 0; dz < 2; dz++) {
              const sampleZ = srcZ + dz;
              if (sampleZ >= currD) continue;

              for (let dy = 0; dy < 2; dy++) {
                const sampleY = srcY + dy;
                if (sampleY >= currH) continue;

                for (let dx = 0; dx < 2; dx++) {
                  const sampleX = srcX + dx;
                  if (sampleX >= currW) continue;

                  const srcIdx = ((sampleZ * currH + sampleY) * currW + sampleX) * channels + c;
                  sum += currentData[srcIdx];
                  count++;
                }
              }
            }

            const dstIdx = ((z * nextH + y) * nextW + x) * channels + c;
            nextData[dstIdx] = sum / count;
          }

        }
      }
    }

    mipmaps.push({
      data: nextData,
      width: nextW,
      height: nextH,
      depth: nextD
    });

    currW = nextW;
    currH = nextH;
    currD = nextD;
    currentData = nextData;
  }

  return mipmaps;
}

Integration with Three.js Data3DTexture

Three.js automatically attempts to call gl.generateMipmap(gl.TEXTURE_3D) if generateMipmaps is set to true. When supplying custom calculated mipmaps, WebGL automatic mipmap generation must be disabled so the precomputed pyramid is transmitted directly to the GPU:

import * as THREE from 'three';

const width = 64;
const height = 64;
const depth = 64;
const channels = 4; // RGBA

const baseData = new Uint8Array(width * height * depth * channels);
// Populate baseData with volumetric data...

const mipmaps = generate3DMipmaps(baseData, width, height, depth, channels);

const texture = new THREE.Data3DTexture(
  mipmaps[0].data,
  mipmaps[0].width,
  mipmaps[0].height,
  mipmaps[0].depth
);

texture.format = THREE.RGBAFormat;
texture.type = THREE.UnsignedByteType;
texture.mipmaps = mipmaps;

// Instruct Three.js to use the provided mipmap array
texture.generateMipmaps = false;
texture.minFilter = THREE.LinearMipmapLinearFilter;
texture.magFilter = THREE.LinearFilter;
texture.needsUpdate = true;

Disabling texture.generateMipmaps prevents the WebGL context from overwriting the CPU-generated levels, ensuring correct trilinear interpolation across all volumetric scale boundaries.
