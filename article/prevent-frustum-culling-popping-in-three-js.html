Prevent Frustum Culling Popping in Three.js

Object popping occurs in Three.js when an object suddenly vanishes or reappears at the viewport edges because the camera frustum fails to intersect the object's calculated bounding volume. This issue is especially common with vertex shader displacement, skinned meshes, and wide-angle cameras. This guide explains how to define a custom bounding sphere margin on your geometry to aggressively expand the culling threshold and eliminate visible popping.

Why Frustum Culling Causes Popping

By default, Three.js uses an object's geometry.boundingSphere to check if that object falls within the camera's view frustum. If the camera frustum does not intersect this sphere, the entire mesh is discarded from the render pass.

When vertices are moved dynamically via GPU shaders or skeletal animation, the CPU-side boundingSphere remains static to the original base geometry. Even without shaders, tight bounding spheres can cause an object's visual edge to clip out of view prematurely. Expanding the radius of the bounding sphere adds an invisible margin around the geometry, ensuring the renderer draws the mesh until it is comfortably outside the screen view.

Method 1: Expanding the Existing Bounding Sphere Radius

The simplest approach is to compute the default bounding sphere first, then directly inflate its radius.

// Ensure the initial sphere is calculated
mesh.geometry.computeBoundingSphere();

// Add a flat offset margin (e.g., 2 world units)
const padding = 2.0;
mesh.geometry.boundingSphere.radius += padding;

// Alternatively, scale the radius by a percentage factor
// mesh.geometry.boundingSphere.radius *= 1.5;

Adding a flat padding value is ideal for smaller objects, while scaling by a percentage works reliably across objects of varying dimensions.

Method 2: Defining a Custom Static Bounding Sphere

For complete control, you can define a custom THREE.Sphere from scratch with a specified center and oversized radius.

import * as THREE from 'three';

// Create a custom center and an aggressively enlarged radius
const customCenter = new THREE.Vector3(0, 0, 0);
const customRadius = 25.0; // Set larger than the actual mesh footprint

mesh.geometry.boundingSphere = new THREE.Sphere(customCenter, customRadius);

Assigning an explicit THREE.Sphere bypasses vertex iteration entirely and guarantees the margin you specify remains strictly enforced.

Method 3: Overriding computeBoundingSphere for Dynamic Geometries

If your pipeline periodically calls geometry.computeBoundingSphere()—such as when updating buffer attributes or loading new morph targets—your custom margin will be overwritten. To maintain the margin permanently, override the geometry's calculation method:

const marginFactor = 1.35; // 35% margin increase

mesh.geometry.computeBoundingSphere = function () {
  // Call the prototype method to calculate the baseline sphere
  THREE.BufferGeometry.prototype.computeBoundingSphere.call(this);

  // Apply the custom expansion margin
  if (this.boundingSphere) {
    this.boundingSphere.radius *= marginFactor;
  }
};

// Execute once to apply the custom logic
mesh.geometry.computeBoundingSphere();

Performance Consideration

While disabling frustum culling completely via mesh.frustumCulled = false eliminates popping, it forces the GPU to process vertices regardless of visibility. Using an inflated bounding sphere margin is the optimal middle ground: it eliminates clipping artifacts while preserving frustum culling benefits when objects are completely behind the camera.
