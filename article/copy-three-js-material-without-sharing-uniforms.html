Copy Three.js Material Without Sharing Uniforms

Duplicating materials in Three.js using the built-in copy method can inadvertently cause instances to share the same uniform references, resulting in unwanted global state changes across meshes. This guide explains how to properly use the .copy() method while completely decoupling uniform references using UniformsUtils.clone() so that each material instance maintains independent properties.

The Shallow Copy Problem

When you invoke targetMaterial.copy(sourceMaterial), Three.js copies top-level material properties. However, for materials with uniforms—such as ShaderMaterial or materials customized with onBeforeCompile—the underlying reference to complex objects (like Vector2, Vector3, Color, or nested uniform maps) can remain linked between the original and the duplicate. Modifying a uniform property on the duplicated material will directly alter the original.

Duplicating Material Properties with Independent Uniforms

To completely isolate the duplicate's uniforms from the original, you must use THREE.UniformsUtils.clone() alongside the .copy() method.

Here is the correct implementation:

import * as THREE from 'three';

// Assume sourceMaterial is an existing ShaderMaterial
const sourceMaterial = new THREE.ShaderMaterial({
    uniforms: {
        uTime: { value: 0.0 },
        uColor: { value: new THREE.Color(0xff0000) },
        uOffset: { value: new THREE.Vector2(1.0, 2.0) }
    },
    vertexShader: `...`,
    fragmentShader: `...`
});

// Step 1: Create a new material instance of the same type
const duplicateMaterial = new THREE.ShaderMaterial();

// Step 2: Copy base properties from source
duplicateMaterial.copy(sourceMaterial);

// Step 3: Deep clone uniforms to break reference sharing
duplicateMaterial.uniforms = THREE.UniformsUtils.clone(sourceMaterial.uniforms);

Handling Custom Uniforms on Built-in Materials

If you injected custom uniforms into built-in materials (like MeshStandardMaterial) via onBeforeCompile, .copy() does not automatically clone the custom uniform dictionary. You must duplicate the custom uniform reference manually:

// Clone and reassign custom uniforms
duplicateMaterial.userData.customUniforms = THREE.UniformsUtils.clone(
    sourceMaterial.userData.customUniforms
);

// Ensure the onBeforeCompile hook references the duplicate's uniforms
duplicateMaterial.onBeforeCompile = (shader) => {
    shader.uniforms.uCustomTime = duplicateMaterial.userData.customUniforms.uCustomTime;
};

// Notify Three.js to recompile the shader program for the duplicate
duplicateMaterial.needsUpdate = true;

Textures vs. Value Types

UniformsUtils.clone() performs a deep clone on objects such as THREE.Vector2, THREE.Vector3, THREE.Vector4, THREE.Matrix3, THREE.Matrix4, and THREE.Color.

Textures (THREE.Texture), however, are intentionally retained by reference to prevent duplicate GPU texture memory allocations. If you need fully independent textures (for example, to mutate canvas-based textures independently), you must explicitly clone the texture object:

duplicateMaterial.uniforms.uTexture.value = sourceMaterial.uniforms.uTexture.value.clone();
duplicateMaterial.uniforms.uTexture.value.needsUpdate = true;
