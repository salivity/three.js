Set unpackAlignment for Three.js DataTexture

This article explains how to correctly configure the unpackAlignment property when uploading raw byte arrays into a custom texture using Three.js. By understanding pixel storage modes in WebGL, you can eliminate texture skewing and memory misalignment errors that often occur when handling unaligned image formats like RGB or single-channel grayscale data.

Understanding Pixel Alignment

By default, WebGL aligns texture rows to 4-byte boundaries (gl.UNPACK_ALIGNMENT = 4). When your custom byte data—such as a Uint8Array—contains data rows whose byte lengths are not multiples of four, the WebGL runtime misinterprets where each new row begins. This misalignment results in skewed, sheared, or corrupted rendering.

Typical scenarios requiring custom alignment include:

  • Single-channel formats (THREE.RedFormat, THREE.LuminanceFormat) where the width is not a multiple of 4.
  • Three-channel formats (THREE.RGBFormat) where width * 3 is not a multiple of 4.

Defining unpackAlignment on a DataTexture

In Three.js, raw byte data is loaded into the GPU using THREE.DataTexture. You set the alignment by modifying the unpackAlignment property directly on the texture instance before rendering.

import * as THREE from 'three';

// 1. Define dimensions and create raw byte data (e.g., single-channel 8-bit data)
const width = 15; // Non-multiple of 4
const height = 15;
const size = width * height;
const data = new Uint8Array(size);

// Fill with sample data
for (let i = 0; i < size; i++) {
  data[i] = Math.floor(Math.random() * 256);
}

// 2. Create the DataTexture
const texture = new THREE.DataTexture(
  data,
  width,
  height,
  THREE.RedFormat,
  THREE.UnsignedByteType
);

// 3. Define the unpackAlignment property
// Setting this to 1 allows byte-by-byte reading without 4-byte padding
texture.unpackAlignment = 1;

// 4. Mark texture for GPU upload
texture.needsUpdate = true;

Valid Values for unpackAlignment

The unpackAlignment property accepts four valid integer values corresponding to the underlying WebGL implementation:

  • 1: Byte alignment. Individual rows are not padded. Use this for 1-byte per pixel formats or tightly packed 3-byte (RGB) data of arbitrary dimensions.
  • 2: Rows are aligned to even-numbered bytes.
  • 4: Word alignment (default). Each row begins on a 4-byte boundary. Standard for 4-channel RGBA data (Uint8Array with 4 bytes per pixel naturally aligns here regardless of width).
  • 8: Double-word alignment, used for specific high-precision multi-byte types.

Setting texture.unpackAlignment = 1; is the safest choice for custom byte textures whenever data width and channel counts do not naturally create row lengths divisible by 4.
