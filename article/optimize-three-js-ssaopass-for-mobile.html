Optimize Three.js SSAOPass for Mobile

Screen Space Ambient Occlusion (SSAO) significantly enhances 3D realism by simulating soft contact shadows where geometry meets, but it is notoriously GPU-intensive. On mobile devices, unoptimized post-processing easily causes thermal throttling and steep frame-rate drops. This guide outlines how to configure the SSAOPass in Three.js specifically for mobile hardware by fine-tuning the kernelRadius and sample count (kernelSize) alongside companion settings to achieve crisp contact shadows without sacrificing real-time performance.

Understanding Key SSAO Parameters

The SSAOPass in Three.js relies on two primary variables to balance visual fidelity against computational cost:

  • kernelSize (Sample Count): Dictates how many depth samples the shader takes per fragment to compute occlusion. The Three.js default is typically 32. Higher values result in smoother, more accurate shadows, but drastically increase texture lookups, which cripples mobile fill rates.
  • kernelRadius: Defines the maximum world-space distance from a surface within which neighboring geometry can cast an occlusion shadow. A larger radius samples a broader area, while a tighter radius concentrates the effect strictly around crevices and joints.

Tuning Settings for Mobile Devices

To maintain 60 frames per second on mobile GPUs, your goal is to minimize sample lookups while keeping the occlusion concentrated where it matters most—close contact points.

1. Reduce kernelSize

Lower the sample count to 8 or 16. A value of 8 provides the best balance of speed and effect for lower-end hardware, while 16 is ideal for mid-to-high-end smartphones. Avoid using 32 on mobile browsers.

2. Restrict kernelRadius

When working with a reduced sample count, a large kernelRadius causes visible banding, noise, and floating shadow artifacts. By reducing kernelRadius to a smaller value (typically between 2 and 8, depending on your scene's scale), samples stay dense and clustered, hiding the low sample count while accentuating tight contact shadows.

3. Enable Bilateral Blur

Because low sample counts introduce grain, always enable the built-in bilateral blur pass. The blur pass is significantly cheaper computationally than computing extra SSAO samples and effectively smooths out noise.

Implementation Example

Below is an optimized configuration setup for mobile:

import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { SSAOPass } from 'three/addons/postprocessing/SSAOPass.js';

const composer = new EffectComposer(renderer);
composer.addPass(new RenderPass(scene, camera));

const width = window.innerWidth;
const height = window.innerHeight;

// Initialize the pass
const ssaoPass = new SSAOPass(scene, camera, width, height);

// Mobile Optimization Settings
ssaoPass.kernelSize = 8;         // Drop from 32 to 8 or 16 samples
ssaoPass.kernelRadius = 4;       // Keep radius tight to prevent sample dispersion
ssaoPass.minDistance = 0.001;    // Ignore objects closer than this threshold
ssaoPass.maxDistance = 0.1;      // Cut off occlusion past this distance

// Enable blur to hide noise from the lower sample count
ssaoPass.blur = true;

composer.addPass(ssaoPass);

Additional Optimization: Half-Resolution Rendering

If dropping the kernelSize to 8 does not resolve performance bottlenecks on budget devices, downsample the SSAO buffer. You can pass half the viewport dimensions to ssaoPass.setSize(width / 2, height / 2). Rendering SSAO at half resolution cuts pixel-processing requirements by 75%, and the soft nature of ambient occlusion ensures that the reduction in resolution remains largely unnoticeable on high-DPI mobile screens.
