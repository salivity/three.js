Read WebXR Gamepad Thumbstick Axes in Three.js

Reading thumbstick and touchpad axes from a WebXR controller in Three.js requires querying the native Gamepad API embedded within the controller's underlying XRInputSource. This article explains how to capture the active WebXR input source using Three.js controller events, read normalized horizontal and vertical axis coordinates within the render loop, navigate standard axis index mappings, and apply deadzones for responsive user interaction.

Accessing the XRInputSource

Three.js abstracts VR controllers via renderer.xr.getController() and renderer.xr.getControllerGrip(). However, the visual controller object does not directly expose thumbstick axis values. Instead, you must capture the controller’s XRInputSource when the device connects.

Listen to the connected event on the controller object to store a reference to its input source:

const controller1 = renderer.xr.getController(0);
scene.add(controller1);

controller1.addEventListener('connected', (event) => {
  // Store the XRInputSource for access in the render loop
  controller1.userData.inputSource = event.data;
});

controller1.addEventListener('disconnected', () => {
  controller1.userData.inputSource = null;
});

The "xr-standard" Axis Mapping

When a WebXR session is active, compliant hardware reports an inputSource.gamepad conforming to the "xr-standard" mapping.

The gamepad.axes property is an array of floating-point values ranging from -1.0 to 1.0:

  • axes[0]: Primary touchpad horizontal axis (left: -1.0, right: 1.0)
  • axes[1]: Primary touchpad vertical axis (up/forward: -1.0, down/back: 1.0)
  • axes[2]: Primary thumbstick horizontal axis (left: -1.0, right: 1.0)
  • axes[3]: Primary thumbstick vertical axis (up/forward: -1.0, down/back: 1.0)

On modern VR controllers without a physical touchpad (such as Meta Quest Touch controllers), axes[0] and axes[1] are typically reserved or inactive, while the physical thumbstick inputs are assigned to axes[2] and axes[3].

Reading Axes in the Render Loop

Because gamepad values update continuously based on physical user input, you must poll the gamepad.axes array on each frame inside the animation loop.

function render() {
  handleControllerInput(controller1);
  renderer.render(scene, camera);
}
renderer.setAnimationLoop(render);

function handleControllerInput(controller) {
  const inputSource = controller.userData.inputSource;

  if (inputSource && inputSource.gamepad) {
    const axes = inputSource.gamepad.axes;

    // Check if thumbstick axes exist
    if (axes.length >= 4) {
      const thumbstickX = axes[2];
      const thumbstickY = axes[3];

      applyMovement(thumbstickX, thumbstickY);
    }
  }
}

Applying a Deadzone

Physical hardware components frequently suffer from minor sensor drift. To avoid unwanted character movement or camera rotation when the user is not touching the stick, filter the inputs using a deadzone threshold:

function applyMovement(x, y) {
  const deadzone = 0.15;

  const filteredX = Math.abs(x) > deadzone ? x : 0;
  const filteredY = Math.abs(y) > deadzone ? y : 0;

  if (filteredX !== 0 || filteredY !== 0) {
    // Translate or rotate relevant Three.js objects
    userGroup.position.x += filteredX * 0.05;
    userGroup.position.z += filteredY * 0.05;
  }
}

This direct polling pattern inside the Three.js render loop ensures low latency and accurate input synchronization with the virtual scene.
