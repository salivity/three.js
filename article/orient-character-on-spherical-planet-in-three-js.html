Orient Character on Spherical Planet in Three.js

When creating spherical planetary traversal in Three.js, a standard fixed world-up axis breaks standard character movement controls. To fix this, you must dynamically calculate the surface normal at the character's current position, assign that normal to the character's Object3D.up vector, and derive a proper rotation quaternion to keep the character perpendicular to the planet while preserving horizontal steering.

1. Calculate the Surface Normal

In a spherical coordinate system centered on a planet, the surface normal is simply the normalized vector pointing from the planet's center to the character's position.

const planetPosition = new THREE.Vector3(0, 0, 0); // Assuming planet center is at origin
const surfaceNormal = new THREE.Vector3();

surfaceNormal.copy(character.position).sub(planetPosition).normalize();

2. Update the Object3D.up Vector

By default, Three.js objects treat (0, 1, 0) as their upward reference vector. When moving across a sphere, this vector must continually match the current surface normal so methods like lookAt() calculate the correct orientation.

character.up.copy(surfaceNormal);

Simply setting character.up is not enough to automatically rotate the mesh; it only provides the reference frame for future orientation calculations.

3. Align the Character's Orientation

To orient the character both upright relative to the surface and forward relative to movement, you must project the movement direction onto the tangent plane of the sphere.

Step-by-Step Implementation in the Update Loop

function updateCharacterOrientation(character, planetPosition, moveDirection) {
    // 1. Calculate and assign the new Up vector
    const surfaceNormal = new THREE.Vector3();
    surfaceNormal.copy(character.position).sub(planetPosition).normalize();
    character.up.copy(surfaceNormal);

    // 2. Project the forward direction onto the tangent plane
    const forward = moveDirection.clone();
    forward.projectOnPlane(surfaceNormal).normalize();

    // 3. Compute target look-at point
    if (forward.lengthSq() > 0.001) {
        const targetPosition = character.position.clone().add(forward);
        character.lookAt(targetPosition);
    }
}

4. Direct Quaternion Alignment (Alternative Approach)

If you manage rotation directly using quaternions rather than Euler angles or lookAt(), you can rotate the character using Quaternion.setFromUnitVectors:

const currentUp = new THREE.Vector3(0, 1, 0); // Initial local up
const targetRotation = new THREE.Quaternion();

// Rotate from local up to the planet surface normal
targetRotation.setFromUnitVectors(currentUp, surfaceNormal);

// Apply rotation smoothly
character.quaternion.slerp(targetRotation, 0.1);

To include steering when using direct quaternion alignment, multiply the surface-alignment quaternion with an independent yaw quaternion around the local Y-axis:

const yawQuaternion = new THREE.Quaternion();
yawQuaternion.setFromAxisAngle(new THREE.Vector3(0, 1, 0), characterYawAngle);

character.quaternion.copy(targetRotation).multiply(yawQuaternion);

5. Keeping the Character Grounded

To prevent floating or clipping caused by numerical drift, project the character's position back to the exact radius of the planet after applying forward velocity:

const planetRadius = 50;
character.position.copy(surfaceNormal.multiplyScalar(planetRadius));

Updating the up vector, projecting forward movement along the tangent plane, and constraining position to the planet's radius inside your animation loop ensures stable orientation across all faces and poles of the sphere.
