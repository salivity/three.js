Map Materials to OBJ with MTLLoader in Three.js

This guide explains how to sequentially load and map specific material names to an .obj file using Three.js's MTLLoader and OBJLoader. When working with separate OBJ and MTL assets, material definitions must be parsed and registered with the OBJ loader before geometry generation, or manually mapped to the parsed meshes using their assigned material identifier names.

The Standard Sequential Loading Workflow

In Three.js, MTLLoader reads the material definition file (.mtl) and generates a MaterialCreator instance. To map these materials to the geometry automatically, pass the prepared MaterialCreator to OBJLoader.setMaterials() prior to calling OBJLoader.load().

import * as THREE from 'three';
import { OBJLoader } from 'three/addons/loaders/OBJLoader.js';
import { MTLLoader } from 'three/addons/loaders/MTLLoader.js';

const mtlLoader = new MTLLoader();
const objLoader = new OBJLoader();

mtlLoader.load('models/model.mtl', (materials) => {
    materials.preload();
    objLoader.setMaterials(materials);

    objLoader.load('models/model.obj', (object) => {
        scene.add(object);
    });
});

Modifying or Mapping Materials Before Parsing the OBJ

The MaterialCreator object stores parsed materials inside its internal materials dictionary. The keys of this dictionary match the newmtl definitions inside the .mtl file, which correspond directly to the usemtl statements inside the .obj file.

You can inspect, replace, or inject custom materials into this dictionary before passing it to OBJLoader:

mtlLoader.load('models/model.mtl', (materials) => {
    materials.preload();

    // Replace a specific material name with a custom Three.js material
    materials.materials['BaseMetal'] = new THREE.MeshStandardMaterial({
        color: 0x999999,
        metalness: 0.8,
        roughness: 0.2
    });

    // Add an alias or missing material name defined in the OBJ
    materials.materials['AlternatePaint'] = materials.materials['DefaultPaint'];

    objLoader.setMaterials(materials);
    objLoader.load('models/model.obj', (object) => {
        scene.add(object);
    });
});

Remapping Materials Post-Load via Mesh Traversal

If you need to assign materials dynamically after geometry creation, or if the .obj contains multiple mesh groups where specific material names need runtime changes, traverse the resulting THREE.Group.

Three.js assigns the matching material to the material property of each child THREE.Mesh. The original material name defined in the .mtl or .obj is preserved on the material's .name attribute.

const customMaterialMap = {
    'Glass': new THREE.MeshPhysicalMaterial({ transmission: 0.9, opacity: 1, transparent: true }),
    'Chrome': new THREE.MeshStandardMaterial({ metalness: 1.0, roughness: 0.0 })
};

objLoader.load('models/model.obj', (object) => {
    object.traverse((child) => {
        if (child.isMesh) {
            // Handle multi-material setups (arrays) or single materials
            if (Array.isArray(child.material)) {
                child.material = child.material.map((mat) => customMaterialMap[mat.name] || mat);
            } else if (customMaterialMap[child.material.name]) {
                child.material = customMaterialMap[child.material.name];
            }
        }
    });

    scene.add(object);
});

Key Considerations

  • materials.preload() is required: Always call preload() on the MTLLoader output before passing it to objLoader.setMaterials(). This builds the underlying THREE.Material instances.
  • Name matching: Ensure that the string keys match the case-sensitive usemtl identifiers found in the .obj file.
  • Asset paths: If the .mtl file references external texture maps, set mtlLoader.setPath('path/to/textures/') or mtlLoader.setResourcePath('path/to/textures/') so the loader resolves image paths accurately.
