Memory Difference: Three.js Shallow Copy vs Clone

Understanding the memory difference between a shallow copy and a recursive clone of an Object3D in Three.js comes down to how JavaScript handles object allocation across a scene graph hierarchy. While a shallow copy only duplicates the immediate properties and references of a single node in system RAM, a recursive clone traverses the entire descendant tree, instantiating new JavaScript objects, matrices, and arrays for every child. Crucially, neither method automatically duplicates heavy GPU resources like geometries or textures, meaning the memory impact is strictly isolated to the CPU heap.

CPU Memory (JavaScript Heap)

The primary difference in memory footprint occurs in standard system RAM (the JavaScript heap).

  • Shallow Copy: When performing a shallow copy (such as copying properties manually or invoking .copy(source, false)), Three.js only duplicates the top-level Object3D instance. This allocates memory for a single set of internal transformation matrices (matrix, matrixWorld), spatial vectors (position, rotation, scale), and core event listeners. It ignores all child nodes, keeping JavaScript heap allocation minimal (typically a few kilobytes).
  • Recursive Clone: Invoking .clone(true) (which is the default behavior in Three.js) recursively calls .clone() on every child, grandchild, and descendant in the children array. If an object hierarchy contains 500 sub-nodes, the recursive clone instantiates 500 new Object3D (or Mesh, Group, etc.) instances. Each instance allocates its own transformation matrices, bounding data, and cache objects. The memory overhead scales linearly, \(O(N)\), where \(N\) is the total number of descendants in the hierarchy.

GPU Memory (VRAM)

A common misconception is that cloning a Three.js mesh duplicates its geometry and textures in GPU memory.

  • Shared References: Both a shallow copy and a recursive clone share references to underlying BufferGeometry and Material instances.
  • VRAM Overhead: Because geometries (vertex buffers, normals, UVs) and material assets (textures, uniforms, shaders) reside in WebGL buffers on the GPU, neither cloning method increases VRAM consumption. The newly cloned meshes point to the exact same GPU buffers as the original.
  • Exceptions: If your application logic manually clones geometries (mesh.geometry = source.geometry.clone()) or materials alongside the recursive clone, VRAM usage will multiply proportionally to the size of the vertex buffers and texture maps.

Summary of Memory Trade-offs

Resource Type Shallow Copy Recursive Clone (recursive = true)
JS Heap (Node Instances) Allocates only 1 node Allocates \(N\) nodes (entire tree)
Matrix & Vector Allocations 1 set of transforms \(N\) sets of transforms
Child Array References Not duplicated (or references kept) Entire hierarchy recreated
GPU BufferGeometry (VRAM) Shared (0 extra VRAM) Shared (0 extra VRAM)
GPU Textures & Shaders (VRAM) Shared (0 extra VRAM) Shared (0 extra VRAM)

Use a shallow copy when you only need to mirror properties onto an existing node or duplicate a leaf object. Use a recursive clone when an independent hierarchical structure is required for independent transformations, being mindful of the CPU memory scaling if dealing with large, deeply nested scene graphs.
