How Object3D.up Works with lookAt in Three.js

In Three.js, the Object3D.up vector acts as a directional guide that defines the roll and vertical orientation of an object when calling the lookAt() method. While lookAt() points an object’s view axis directly at a target coordinate, the up vector determines which way the top of that object faces. Without it, an object pointing at a target would have an infinite number of valid rotational orientations along its viewing axis.

Basis Construction and Cross Products

When Object3D.lookAt(target) is invoked, Three.js constructs a rotation matrix using standard vector mathematics to orient the object's local coordinate system:

  1. Forward Vector: The engine computes the direction vector between the object’s current world position and the target position. For cameras, the negative Z-axis points toward the target; for standard 3D meshes, the positive Z-axis aligns with the target vector.
  2. Right Vector (Local X-axis): Three.js calculates the cross product of the normalized direction vector and the normalized Object3D.up vector. This generates a perpendicular vector representing the object's local X-axis (its "right" side).
  3. Corrected Up Vector (Local Y-axis): The engine then computes the cross product of the newly formed right vector and the direction vector. This produces a final, orthogonal local Y-axis aligned as closely as possible to Object3D.up.

Default Values and Execution Order

By default, every Object3D inherits an up vector of (0, 1, 0), representing the positive Y-axis in world space.

Because lookAt() reads the up vector at the moment of execution to calculate the orientation matrix, any changes to Object3D.up must be made before calling lookAt(). Updating object.up after calling lookAt() produces no visual change until lookAt() or another matrix recalculation is triggered again.

// Correct usage
camera.up.set(0, 0, 1); // Set Z as up
camera.lookAt(targetPosition);

The Collinear Singularity (Gimbal Lock)

A critical limitation occurs when the direction vector toward the target is parallel or anti-parallel (collinear) to the up vector. For instance, if an object has an up vector of (0, 1, 0) and attempts to look directly up at (0, 10, 0) or directly down at (0, -10, 0):

  • The cross product of two parallel vectors results in a zero vector (0, 0, 0).
  • Three.js cannot calculate a valid right vector or orthogonal basis.
  • This results in erratic rotation snapping, inverted rendering, or mathematical errors (NaN values in transformation matrices).

To resolve this issue, the up vector must be temporarily shifted to another axis (such as (0, 0, 1) or (0, 0, -1)) whenever the view vector aligns directly with the current up vector.
