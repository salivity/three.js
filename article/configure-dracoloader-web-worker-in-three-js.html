Configure DRACOLoader Web Worker in Three.js

Decoding Draco-compressed 3D models can be computationally expensive, often freezing the main browser thread and dropping frame rates during asset loading. This guide explains how to offload Draco decompression to background Web Workers using Three.js's DRACOLoader, ensuring smooth rendering and responsive user interactions while loading high-density 3D meshes.

1. Host the Draco Decoder Binaries

DRACOLoader relies on specialized WebAssembly (WASM) and JavaScript decoding libraries to run workers in the background. You must make these static files accessible from your public directory.

Copy the decoder files from your Three.js installation located at: node_modules/three/examples/jsm/libs/draco/

Place them into your project's public folder (for example, /public/draco/). The directory should contain:

  • draco_decoder.wasm
  • draco_wasm_wrapper.js
  • draco_decoder.js

2. Instantiate and Configure DRACOLoader

Three.js includes built-in Web Worker orchestration within DRACOLoader. Once provided with a valid path to the decoder binaries, the loader automatically spawns Web Workers to handle the decompression pipeline.

Use setDecoderPath to point to your hosted files, and optionally configure worker limits:

import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
import { DRACOLoader } from 'three/examples/jsm/loaders/DRACOLoader.js';

// 1. Initialize DRACOLoader
const dracoLoader = new DRACOLoader();

// 2. Set the path to the folder containing the decoder binaries
dracoLoader.setDecoderPath('/draco/');

// 3. Optional: Configure the maximum number of Web Workers (default is 4)
dracoLoader.setWorkerLimit(navigator.hardwareConcurrency || 4);

// 4. Optional: Force JavaScript decoder instead of WASM (not recommended)
// dracoLoader.setDecoderConfig({ type: 'js' });

3. Attach DRACOLoader to GLTFLoader

After configuring DRACOLoader, bind it to your GLTFLoader instance. When the GLTFLoader encounters a model utilizing the KHR_draco_mesh_compression extension, it delegates decompression tasks directly to the worker pool.

// Initialize GLTFLoader and assign the configured DRACOLoader
const gltfLoader = new GLTFLoader();
gltfLoader.setDRACOLoader(dracoLoader);

// Load the compressed model
gltfLoader.load(
  '/models/compressed_model.glb',
  (gltf) => {
    scene.add(gltf.scene);
  },
  (xhr) => {
    console.log(`${(xhr.loaded / xhr.total) * 100}% loaded`);
  },
  (error) => {
    console.error('An error occurred while loading the model:', error);
  }
);

4. Manage Worker Lifecycle and Cleanup

Web Workers consume system memory and persistent background resources. When decoding is complete or the scene is being unmounted, dispose of the worker pool to prevent memory leaks:

// Terminate active workers and release memory
dracoLoader.dispose();

Calling dispose() shuts down all instantiated worker threads managed by that specific DRACOLoader instance.
