Efficient Three.js lookAt Without Vector3 Allocation

Updating an object's orientation with lookAt inside a Three.js animation loop can degrade performance if vector instances are created continuously. Instantiating objects inside a 60 or 120 FPS render loop triggers frequent garbage collection cycles, causing noticeable frame drops and micro-stutter. This article demonstrates how to eliminate allocations by reusing a persistent Vector3 instance, mutating its coordinates directly, and extracting world positions correctly.

The GC Overhead Problem

A common anti-pattern in Three.js is passing a newly created vector to lookAt inside the render function:

function animate() {
    requestAnimationFrame(animate);
    // Anti-pattern: Allocates a new object every frame
    camera.lookAt(new THREE.Vector3(target.x, target.y, target.z));
    renderer.render(scene, camera);
}

Even though a Vector3 is lightweight, generating 60 to 120 objects per second forces the browser's JavaScript engine to run garbage collection sweeps, disrupting smooth rendering.

Solution: Reuse a Pre-allocated Vector3

To avoid allocations, declare a single Vector3 outside the render loop and update its values using .set() or .copy().

// Allocate once in the module or component scope
const targetPosition = new THREE.Vector3();

function animate() {
    requestAnimationFrame(animate);

    // Update the values of the existing vector in place
    targetPosition.set(targetX, targetY, targetZ);

    // Pass the pre-allocated vector
    camera.lookAt(targetPosition);

    renderer.render(scene, camera);
}

Using .set(x, y, z) overwrites the internal numerical values without creating a new heap allocation.

Targeting Moving Objects with getWorldPosition

When tracking another Object3D (such as a mesh) that is part of a hierarchy or moving dynamically, avoid querying .position directly if the target has transformed parent objects. Instead, use .getWorldPosition(), which accepts an existing target vector to populate:

const worldTarget = new THREE.Vector3();

function animate() {
    requestAnimationFrame(animate);

    // Writes the world coordinates directly into worldTarget without allocating
    targetMesh.getWorldPosition(worldTarget);

    camera.lookAt(worldTarget);

    renderer.render(scene, camera);
}

Class-Based or Component Encapsulation

If your application uses components or classes, store the vector as a private or member variable to prevent polluting global scope while ensuring it persists across frames:

class CameraRig {
    constructor(camera) {
        this.camera = camera;
        this.lookTarget = new THREE.Vector3();
    }

    update(targetX, targetY, targetZ) {
        this.lookTarget.set(targetX, targetY, targetZ);
        this.camera.lookAt(this.lookTarget);
    }
}

By keeping vectors static across frames and mutating them in place, lookAt executes without memory overhead, resulting in stable frame rates and zero garbage collection pressure.
