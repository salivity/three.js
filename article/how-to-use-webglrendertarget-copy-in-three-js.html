How to Use WebGLRenderTarget Copy in Three.js

Duplicating frame buffers in Three.js is a common requirement for post-processing effects, feedback loops, and state preservation. This article explains how to duplicate a frame buffer configuration using the WebGLRenderTarget.copy method, demonstrate its implementation, and clarify how to transfer both the target setup and its pixel contents efficiently.

Understanding WebGLRenderTarget.copy

The WebGLRenderTarget.copy() method creates a duplicate of an existing render target by copying its dimensions, depth, viewport, scissor settings, and texture configuration.

It is important to note that .copy() duplicates the structural and configuration parameters on the CPU side—including cloning the texture definition—rather than executing a GPU-level pixel memory copy. To duplicate the actual rendered pixel data across buffers, you combine .copy() with WebGLRenderer.copyTextureToTexture or a simple blit pass.

Step-by-Step Implementation

1. Create and Render to the Source Target

Initialize your primary WebGLRenderTarget and render your scene into it:

import * as THREE from 'three';

const width = window.innerWidth;
const height = window.innerHeight;

// Create the source render target
const renderTargetA = new THREE.WebGLRenderTarget(width, height, {
  minFilter: THREE.LinearFilter,
  magFilter: THREE.LinearFilter,
  format: THREE.RGBAFormat,
  type: THREE.HalfFloatType
});

// Render the scene into renderTargetA
renderer.setRenderTarget(renderTargetA);
renderer.render(scene, camera);
renderer.setRenderTarget(null);

2. Duplicate the Configuration with .copy()

Create an empty render target and duplicate the specifications from renderTargetA:

// Create an unconfigured target
const renderTargetB = new THREE.WebGLRenderTarget();

// Duplicate the configuration from renderTargetA
renderTargetB.copy(renderTargetA);

After calling renderTargetB.copy(renderTargetA), renderTargetB shares identical dimensions, internal texture parameters, filtering modes, and format options without manually redefining them.

3. Copying Pixel Data to the Duplicate

To copy the rendered frame buffer pixels from the source to the duplicate target without re-rendering the scene, use WebGLRenderer.copyTextureToTexture:

// Copy pixel data from renderTargetA's texture to renderTargetB's texture
renderer.copyTextureToTexture(
  renderTargetA.texture,
  renderTargetB.texture
);

When to Use This Approach

  • Ping-Pong Buffering: Alternating between two identically configured frame buffers for iterative shaders (e.g., blur passes, water simulations, or particle systems).
  • Snapshotting: Preserving a rendered frame as a background or texture asset while continuing to render new frames to the primary target.
  • Format Consistency: Ensuring a secondary buffer perfectly matches the precision and color depth of an existing render target dynamically.
