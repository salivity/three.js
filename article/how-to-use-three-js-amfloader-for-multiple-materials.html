How to Use Three.js AMFLoader for Multiple Materials

This article explains how to load Additive Manufacturing Format (AMF) files containing multiple distinct materials into a Three.js scene using the AMFLoader utility. You will learn how to import the loader, process the returned multi-mesh hierarchy, and assign or customize separate materials for each volume defined within the 3D model.

Importing and Setting Up AMFLoader

The AMFLoader is not included in the Three.js core package; it is an add-on located in the examples directory. You must also include the jszip library if your AMF files are compressed (.amf files are often zip-compressed XML).

import * as THREE from 'three';
import { AMFLoader } from 'three/addons/loaders/AMFLoader.js';

Loading the Multi-Material Model

AMF files structure complex assemblies by defining distinct <volume> tags inside an <object> tag, with each volume mapped to a specific material ID or embedded color. When AMFLoader parses an AMF file, it returns a THREE.Group where each distinct volume is converted into an individual THREE.Mesh.

Use the following pattern to load the file and add it to your scene:

const scene = new THREE.Scene();
const loader = new AMFLoader();

loader.load(
    'models/multi_material_part.amf',
    (group) => {
        // The loader returns a THREE.Group containing child meshes
        scene.add(group);
    },
    (xhr) => {
        console.log((xhr.loaded / xhr.total * 100) + '% loaded');
    },
    (error) => {
        console.error('An error occurred loading the AMF file:', error);
    }
);

Handling Native Materials and Colors

If your AMF file includes embedded RGBA color data in its <material> definitions, AMFLoader will automatically parse these values and instantiate a THREE.MeshPhongMaterial for each volume with the corresponding diffuse color and opacity. Ensure your scene has sufficient lighting (such as a THREE.DirectionalLight and THREE.AmbientLight) to render these materials properly.

Overriding and Customizing Distinct Materials

To apply custom materials—such as PBR shaders (MeshStandardMaterial), custom textures, or specific rendering properties—traverse the resulting THREE.Group in the loader's completion callback:

loader.load('models/multi_material_part.amf', (group) => {
    // Define an array or map of replacement materials
    const customMaterials = [
        new THREE.MeshStandardMaterial({ color: 0xff0000, roughness: 0.3, metalness: 0.1 }),
        new THREE.MeshStandardMaterial({ color: 0x0055ff, roughness: 0.7, metalness: 0.0 }),
        new THREE.MeshPhysicalMaterial({ color: 0xffffff, transmission: 0.9, opacity: 1, transparent: true })
    ];

    let materialIndex = 0;

    group.traverse((child) => {
        if (child.isMesh) {
            // Option A: Assign based on order of appearance
            if (customMaterials[materialIndex]) {
                child.material = customMaterials[materialIndex];
                materialIndex++;
            }

            // Option B: Inspect the mesh name or userData for AMF identifiers
            // AMFLoader assigns volume metadata to child.name when available
            if (child.name === 'SupportStructure') {
                child.material = new THREE.MeshBasicMaterial({ wireframe: true });
            }

            child.castShadow = true;
            child.receiveShadow = true;
        }
    });

    // Optional: AMF files typically use millimeters; rescale if necessary
    group.scale.set(0.001, 0.001, 0.001);

    scene.add(group);
});

Key Considerations

  1. Units and Scale: The AMF specification uses millimeters as the default measurement unit. Three.js scenes typically use arbitrary units often treated as meters. Adjust group.scale if your model renders too large.
  2. Transparency: If any sub-material utilizes alpha transparency defined in the AMF, ensure material.transparent = true is active on the corresponding mesh material to prevent rendering artifacts.
