CustomBlending Equations and Factors in Three.js

This article explains how to implement advanced blending behavior in Three.js using THREE.CustomBlending. By overriding the default blending modes, you can explicitly configure source and destination factors (blendSrc, blendDst) along with blending equations (blendEquation) for both color and alpha channels. Below, you will find the mathematical concepts behind WebGL blending, a breakdown of available factors, and a practical code example configuring a custom material.

Understanding WebGL Blending Mechanics

When a fragment is rendered, Three.js uses WebGL to combine the newly computed pixel color (the source, \(S\)) with the color already existing in the framebuffer (the destination, \(D\)). The final pixel color is calculated using the following general formula:

\[\text{Final Color} = (\text{Source} \times \text{blendSrc}) \ [\text{blendEquation}] \ (\text{Destination} \times \text{blendDst})\]

By default, Three.js presets like THREE.NormalBlending or THREE.AdditiveBlending configure these parameters automatically. To take direct control, you must set the material's blending property to THREE.CustomBlending.

Key Properties for CustomBlending

To configure custom blending, define the following properties on any Three.js material (such as MeshBasicMaterial, MeshStandardMaterial, or ShaderMaterial):

  • blending: Must be set to THREE.CustomBlending.
  • blendEquation: Determines how the factored source and destination colors are mathematically combined for RGB. Defaults to THREE.AddEquation. Alternatives include THREE.SubtractEquation, THREE.ReverseSubtractEquation, THREE.MinEquation, and THREE.MaxEquation.
  • blendSrc: Defines the multiplier applied to the incoming source color (RGB).
  • blendDst: Defines the multiplier applied to the existing destination color (RGB).
  • blendEquationAlpha: (Optional) Sets the blend equation specifically for the alpha channel. If omitted, it mirrors blendEquation.
  • blendSrcAlpha: (Optional) Sets the factor for the incoming source alpha.
  • blendDstAlpha: (Optional) Sets the factor for the existing destination alpha.

Common Blend Factors

Three.js provides various factor constants via the main namespace:

  • THREE.ZeroFactor: Multiplies the component by 0.
  • THREE.OneFactor: Multiplies the component by 1.
  • THREE.SrcColorFactor / THREE.OneMinusSrcColorFactor: Multiplies by the source color or \((1 - \text{source color})\).
  • THREE.SrcAlphaFactor / THREE.OneMinusSrcAlphaFactor: Multiplies by the source alpha or \((1 - \text{source alpha})\).
  • THREE.DstColorFactor / THREE.OneMinusDstColorFactor: Multiplies by the destination color or \((1 - \text{destination color})\).
  • THREE.DstAlphaFactor / THREE.OneMinusDstAlphaFactor: Multiplies by the destination alpha or \((1 - \text{destination alpha})\).

Implementation Example

The following example configures a material with a non-standard blend: a multiply-like effect that subtracts the source from the destination while handling the alpha channel independently.

import * as THREE from 'three';

// 1. Instantiate the material
const customMaterial = new THREE.MeshBasicMaterial({
  color: 0xff0055,
  transparent: true,
  opacity: 0.8
});

// 2. Enable CustomBlending
customMaterial.blending = THREE.CustomBlending;

// 3. Define the RGB Blend Equation and Factors
// Resulting RGB = (Destination * 1) - (Source * DestinationColor)
customMaterial.blendEquation = THREE.ReverseSubtractEquation;
customMaterial.blendSrc = THREE.DstColorFactor;
customMaterial.blendDst = THREE.OneFactor;

// 4. Define Separate Alpha Equation and Factors
// Resulting Alpha = (SourceAlpha * 1) + (DestinationAlpha * (1 - SourceAlpha))
customMaterial.blendEquationAlpha = THREE.AddEquation;
customMaterial.blendSrcAlpha = THREE.OneFactor;
customMaterial.blendDstAlpha = THREE.OneMinusSrcAlphaFactor;

// 5. Notify Three.js that the material needs an update if altered post-creation
customMaterial.needsUpdate = true;

// Create mesh and add to scene
const mesh = new THREE.Mesh(new THREE.PlaneGeometry(5, 5), customMaterial);
scene.add(mesh);

Important Considerations

  • Transparency: Always set transparent: true on the material. If transparency is disabled, Three.js may skip depth sorting and blend state management, rendering the blending settings ineffective.
  • Premultiplied Alpha: If your textures or render targets use premultiplied alpha, standard factors like THREE.SrcAlphaFactor can produce darker borders or incorrect color accumulation. Adjust your factors to THREE.OneFactor for the source if alpha has already been multiplied into the RGB channels.
  • Depth Testing & Writing: Complex blend modes often require turning off depthWrite (material.depthWrite = false) to prevent transparent surfaces from occluding objects rendered behind them.
