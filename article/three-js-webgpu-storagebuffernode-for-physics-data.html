Three.js WebGPU StorageBufferNode for Physics Data

Managing large-scale physics simulations in Three.js WebGPU requires offloading data storage and calculation directly to GPU compute pipelines. This article details how to define and use storage buffer nodes to store, read, and mutate massive arrays of physics data—such as particle positions, velocities, and masses—using the Three.js Node system and Three Shading Language (TSL).

1. Initialize the Typed Array and Buffer Attribute

GPU storage buffers require raw binary data. Start by creating a standard JavaScript typed array containing your physics parameters and wrap it inside a StorageBufferAttribute.

import * as THREE from 'three';
import { StorageBufferAttribute } from 'three/webgpu';

const particleCount = 100000;
// Storing vec4 data: x, y, z (position) and w (mass)
const particleData = new Float32Array(particleCount * 4);

for (let i = 0; i < particleCount; i++) {
  const stride = i * 4;
  particleData[stride] = (Math.random() - 0.5) * 100;     // Position X
  particleData[stride + 1] = (Math.random() - 0.5) * 100; // Position Y
  particleData[stride + 2] = (Math.random() - 0.5) * 100; // Position Z
  particleData[stride + 3] = Math.random() * 5.0 + 1.0;   // Mass
}

const storageAttribute = new StorageBufferAttribute(particleData, 4);

2. Define the Storage Buffer Node

Convert the attribute into a node using the storage factory function from the Node/TSL API. This creates an underlying StorageBufferNode capable of read and write operations inside WebGPU compute and render passes.

import { storage } from 'three/tsl';

// Define the storage node by specifying the attribute, element type, and item count
const positionStorageNode = storage(storageAttribute, 'vec4', particleCount);

// Velocity buffer created with the same structure
const velocityData = new Float32Array(particleCount * 4);
const velocityAttribute = new StorageBufferAttribute(velocityData, 4);
const velocityStorageNode = storage(velocityAttribute, 'vec4', particleCount);

3. Mutate Buffer Data in a Compute Node

To run physics computations on the GPU, reference the storage buffer node elements by their invocation index within a compute shader node.

import { Fn, instanceIndex, vec3, vec4, float } from 'three/tsl';

const computePhysics = Fn(() => {
  const index = instanceIndex;

  // Read current physics state
  const posMass = positionStorageNode.element(index);
  const vel = velocityStorageNode.element(index);

  const position = posMass.xyz;
  const mass = posMass.w;
  const velocity = vel.xyz;

  // Apply simple gravity
  const gravity = vec3(0.0, -9.81, 0.0);
  const delta = float(1.0 / 60.0);

  const newVelocity = velocity.add(gravity.mul(delta));
  const newPosition = position.add(newVelocity.mul(delta));

  // Write updated states back to the storage buffer nodes
  velocityStorageNode.element(index).assign(vec4(newVelocity, 0.0));
  positionStorageNode.element(index).assign(vec4(newPosition, mass));
})().compute(particleCount);

4. Bind to Render Pipeline and Dispatch

Storage buffer nodes can be directly bound to a mesh or particle material for rendering without copying data back to the CPU. During each frame, execute the compute pass before rendering.

import { SpriteNodeMaterial } from 'three/webgpu';

// Read positions directly in the vertex stage
const material = new SpriteNodeMaterial();
material.positionNode = positionStorageNode.element(instanceIndex).xyz;

// Simulation loop
function animate() {
  requestAnimationFrame(animate);

  // Execute compute pass on the GPU
  renderer.compute(computePhysics);

  // Render scene using updated buffer data
  renderer.render(scene, camera);
}

This workflow ensures physics computations and data storage remain exclusively in GPU memory, avoiding CPU-to-GPU bandwidth bottlenecks.
