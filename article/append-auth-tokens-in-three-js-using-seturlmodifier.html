Append Auth Tokens in Three.js Using setURLModifier

This article explains how to intercept and modify asset requests in Three.js by using the setURLModifier callback on a THREE.LoadingManager. You will learn how to append dynamic authentication tokens, such as JSON Web Tokens (JWT) or temporary access keys, to model, texture, and material URLs before they are fetched by the browser.

The Role of setURLModifier

When loading 3D assets such as glTF files, models often reference external textures, binaries, and dependencies. Standard HTTP headers cannot always be injected into child asset requests triggered internally by Three.js loaders.

The LoadingManager.setURLModifier() method solves this by acting as an interceptor. It accepts a callback function that receives the original URL of any requested resource, modifies it, and returns the updated string before the network request executes.

Basic Implementation

To append a dynamic token to your asset requests, instantiate a LoadingManager, configure the setURLModifier callback, and pass that manager to your desired loader (e.g., GLTFLoader, TextureLoader).

import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';

// Function to retrieve the latest authentication token
function getAuthToken() {
  return localStorage.getItem('authToken') || 'default-fallback-token';
}

// 1. Create the LoadingManager
const loadingManager = new THREE.LoadingManager();

// 2. Define the URL modifier callback
loadingManager.setURLModifier((url) => {
  // Ignore base64 data URIs and object blob URLs
  if (url.startsWith('data:') || url.startsWith('blob:')) {
    return url;
  }

  try {
    // Parse the incoming URL relative to the current window location
    const parsedUrl = new URL(url, window.location.href);

    // Append or update the dynamic token parameter
    parsedUrl.searchParams.set('token', getAuthToken());

    return parsedUrl.toString();
  } catch (error) {
    console.error('Failed to modify asset URL:', error);
    return url;
  }
});

// 3. Pass the manager to any Three.js loader
const gltfLoader = new GLTFLoader(loadingManager);

gltfLoader.load(
  'https://assets.example.com/models/character.gltf',
  (gltf) => {
    scene.add(gltf.scene);
  },
  undefined,
  (error) => {
    console.error('An error occurred during loading:', error);
  }
);

Handling Dynamic and Expiring Tokens

Because setURLModifier is invoked immediately before each individual asset request is dispatched, it handles dynamically changing tokens natively.

If your application uses short-lived tokens, ensure your token retrieval function returns the freshest value:

  • Synchronous Updates: If your application refreshes tokens in the background, reading directly from a global state variable or storage provider (like localStorage or sessionStorage) ensures subsequent asset fetches use the renewed token.
  • Child Asset Resolution: For nested dependencies (like .bin buffers or .png textures declared inside a .gltf), Three.js invokes setURLModifier separately for each asset, ensuring every dependency receives a valid token parameter.

Best Practices

  • Filter Local Schemes: Always check for data: and blob: schemes. Attempting to parse inline data URIs with new URL() can degrade performance or throw syntax errors.
  • Use the URL API: Avoid manual string concatenation like url + '?token=' + token. The native URL and URLSearchParams APIs properly handle existing query strings, encoded characters, and hash fragments.
  • CORS Settings: When query parameters are added, ensure your remote storage bucket (e.g., AWS S3, Google Cloud Storage) is configured to allow the incoming query parameter without triggering CORS preflight rejections.
