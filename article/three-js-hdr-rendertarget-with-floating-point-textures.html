Three.js HDR RenderTarget with Floating-Point Textures

This article provides a technical overview of creating and configuring a custom WebGLRenderTarget in Three.js to support floating-point textures for High Dynamic Range (HDR) post-processing. You will learn the correct parameters required for 16-bit and 32-bit floating-point precision, how to preserve color data beyond the standard 0.0–1.0 range, and how to structure a post-processing pass that correctly tone-maps the final output to the screen.

Configuring the WebGLRenderTarget

By default, a standard Three.js WebGLRenderTarget uses an 8-bit unsigned byte data type (THREE.UnsignedByteType), which clamps color values between 0.0 and 1.0. To support HDR values, you must set the render target's type property to a floating-point format.

In modern WebGL workflows, THREE.HalfFloatType (16-bit floating-point) is preferred over THREE.FloatType (32-bit floating-point). It offers sufficient dynamic range and precision for HDR rendering while using half the bandwidth and providing wider compatibility across mobile hardware.

import * as THREE from 'three';

const width = window.innerWidth;
const height = window.innerHeight;

const hdrRenderTarget = new THREE.WebGLRenderTarget(width, height, {
  minFilter: THREE.LinearFilter,
  magFilter: THREE.LinearFilter,
  format: THREE.RGBAFormat,
  type: THREE.HalfFloatType,
  stencilBuffer: false,
  depthBuffer: true,
  colorSpace: THREE.LinearSRGBColorSpace
});

Critical RenderTarget Options

  • type: THREE.HalfFloatType: Enables 16-bit floating-point storage per channel, allowing pixel values to exceed 1.0 without clipping highlights.
  • format: THREE.RGBAFormat: Standard four-channel storage ensuring alpha support for compositing.
  • colorSpace: THREE.LinearSRGBColorSpace: High-precision HDR computations must remain in linear color space. Color management in modern Three.js handles conversions automatically if configured linearly.
  • minFilter / magFilter: Set to THREE.LinearFilter. Most hardware supports bilinear filtering on half-float textures (via the OES_texture_half_float_linear WebGL extension, which Three.js checks internally).

Renderer Configuration

To prevent premature clipping during the initial render, the main renderer's tone mapping must not be applied directly when rendering into the HDR target. Tone mapping should only be evaluated on the final screen pass.

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(width, height);
renderer.outputColorSpace = THREE.SRGBColorSpace;

// Keep tone mapping disabled for off-screen passes
renderer.toneMapping = THREE.NoToneMapping;

Implementing the Post-Processing Pipeline

An HDR post-processing workflow renders the initial scene into the floating-point target, extracts the unbounded color information, performs effects such as bloom or depth of field, and finally resolves the image with tone mapping.

Step 1: Render Scene to Custom Target

renderer.setRenderTarget(hdrRenderTarget);
renderer.render(scene, camera);

Step 2: Tone-Map to Screen

Displaying the HDR texture directly on an SDR monitor requires compressing values back to a displayable range using a tone-mapping algorithm (such as ACES Filmic or Reinhard) in a full-screen shader pass.

const postMaterial = new THREE.ShaderMaterial({
  uniforms: {
    tDiffuse: { value: hdrRenderTarget.texture }
  },
  vertexShader: `
    varying vec2 vUv;
    void main() {
      vUv = uv;
      gl_Position = vec4(position, 1.0);
    }
  `,
  fragmentShader: `
    uniform sampler2D tDiffuse;
    varying vec2 vUv;

    // ACES Filmic Tone Mapping Curve
    vec3 ACESFilmicToneMapping(vec3 color) {
      float a = 2.51;
      float b = 0.03;
      float c = 2.43;
      float d = 0.59;
      float e = 0.14;
      return clamp((color * (a * color + b)) / (color * (c * color + d) + e), 0.0, 1.0);
    }

    void main() {
      vec4 texColor = texture2D(tDiffuse, vUv);
      vec3 mapped = ACESFilmicToneMapping(texColor.rgb);
      gl_FragColor = vec4(mapped, texColor.a);
    }
  `
});

const postScene = new THREE.Scene();
const postCamera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), postMaterial);
postScene.add(quad);

// Render to canvas
renderer.setRenderTarget(null);
renderer.render(postScene, postCamera);

Handling Window Resizing and Memory

When the browser window resizes, update the dimensions of the render target to match the canvas to prevent texture distortion and pixelation.

window.addEventListener('resize', () => {
  const newWidth = window.innerWidth;
  const newHeight = window.innerHeight;

  renderer.setSize(newWidth, newHeight);
  hdrRenderTarget.setSize(newWidth, newHeight);
});

When discarding the render target, call hdrRenderTarget.dispose() to free GPU VRAM immediately, as floating-point buffers consume more memory than standard 8-bit targets.
