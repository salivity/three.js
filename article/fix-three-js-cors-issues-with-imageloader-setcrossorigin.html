Fix Three.js CORS Issues With ImageLoader setCrossOrigin

When loading external textures or assets across origins in Three.js, web browsers enforce Cross-Origin Resource Sharing (CORS) policies that can block images or taint the WebGL canvas. This article explains how to use the setCrossOrigin property on Three.js's ImageLoader to explicitly set the cross-origin attribute on requested images, allowing you to bypass strict CORS limitations during development when assets are hosted on different ports or remote servers.

Understanding the Problem

Browsers prevent WebGL from rendering textures sourced from different origins (including different ports on localhost) unless the target server explicitly grants permission via HTTP headers, and the requesting client explicitly requests cross-origin access. Without configuring this request, the browser fails to load the image into the WebGL context, resulting in a security error such as:

SecurityError: The operation is insecure. or Access to image at '...' from origin '...' has been blocked by CORS policy.

Using setCrossOrigin on ImageLoader

The ImageLoader class in Three.js provides the .setCrossOrigin() method, which sets the crossOrigin attribute on the underlying HTML <img> element before the request is dispatched.

To request anonymous cross-origin access, pass the string 'anonymous' to setCrossOrigin():

import * as THREE from 'three';

// 1. Instantiate the ImageLoader
const imageLoader = new THREE.ImageLoader();

// 2. Configure cross-origin credentials
imageLoader.setCrossOrigin('anonymous');

// 3. Load the image asset
imageLoader.load(
    'http://localhost:8080/textures/my-texture.jpg',
    (image) => {
        // Create a texture from the loaded image
        const texture = new THREE.CanvasTexture(image);
        
        // Apply the texture to a material
        const material = new THREE.MeshBasicMaterial({ map: texture });
        const geometry = new THREE.BoxGeometry(1, 1, 1);
        const mesh = new THREE.Mesh(geometry, material);
        scene.add(mesh);
    },
    undefined,
    (error) => {
        console.error('An error occurred while loading the image.', error);
    }
);

Values for setCrossOrigin

  • 'anonymous': Requests cross-origin access without sending user credentials (such as HTTP cookies or HTTP authentication). This is the standard setting for public texture servers and local development servers.
  • 'use-credentials': Requests cross-origin access and includes credentials. Use this only if the serving origin requires authentication.

Applying setCrossOrigin to TextureLoader

In most Three.js workflows, textures are loaded using THREE.TextureLoader rather than directly using ImageLoader. TextureLoader wraps ImageLoader internally and inherits the same method:

const textureLoader = new THREE.TextureLoader();
textureLoader.setCrossOrigin('anonymous');

const texture = textureLoader.load('http://localhost:8080/textures/my-texture.jpg');
const material = new THREE.MeshBasicMaterial({ map: texture });

Essential Local Development Setup

Setting setCrossOrigin('anonymous') solves the client-side configuration, but it requires two additional conditions to function correctly:

  1. Do not use the file:// protocol: Browsers automatically block cross-origin requests made via file:///path/to/index.html. Always serve your project using a local development server such as Vite, npx serve, or Python's http.server.
  2. Enable server headers: The origin serving the image files must respond with the Access-Control-Allow-Origin header set to * or your specific local development domain (e.g., http://localhost:3000).
