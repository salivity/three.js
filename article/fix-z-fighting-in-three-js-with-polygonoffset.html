Fix Z-Fighting in Three.js with PolygonOffset

Z-fighting occurs in Three.js when two coplanar or nearly coplanar surfaces occupy the same depth space, causing visual flickering as the depth buffer struggles to determine which pixel is closer. This guide explains how to resolve z-fighting using Three.js materials by enabling polygonOffset and properly setting polygonOffsetFactor and polygonOffsetUnits to pull decals, outlines, or layered geometry cleanly in front of or behind base surfaces.

Understanding the Z-Fighting Problem

When two meshes share identical or extremely close world coordinates, rasterization floating-point rounding causes alternating pixels to win the depth test. Rather than physically translating the geometry in 3D space—which can break alignments or scale dependencies—WebGL provides an offset mechanism directly within the graphics pipeline to modify depth values before the depth test executes.

Enabling Polygon Offset in Three.js

Three.js exposes the WebGL polygon offset functionality on all instances derived from THREE.Material. To activate it, you must explicitly set polygonOffset to true and supply values for the two offset parameters.

const overlayMaterial = new THREE.MeshStandardMaterial({
  color: 0xff0000,
  polygonOffset: true,
  polygonOffsetFactor: -1,
  polygonOffsetUnits: -1
});

How polygonOffsetFactor and polygonOffsetUnits Work

The total depth offset applied to a polygon is calculated via the formula:

\[\text{Total Offset} = (m \times \text{factor}) + (r \times \text{units})\]

  • \(m\) (Maximum Depth Slope): The rate of depth change relative to screen coordinates. Polygons viewed at steep angles have a high slope.
  • \(r\) (Smallest Resolvable Value): A constant representing the smallest measurable difference in the depth buffer.

polygonOffsetFactor

This parameter scales the offset according to the slope of the polygon relative to the camera view. A higher slope requires a larger offset to avoid clipping. Setting this ensures that surfaces viewed at sharp angles do not start z-fighting.

polygonOffsetUnits

This parameter provides a constant minimum offset regardless of the surface angle. It moves the entire polygon by a fixed number of depth-buffer increments.

Recommended Value Configurations

Depth values range from 0.0 (near plane) to 1.0 (far plane). Therefore:

  • Negative values push fragments closer to the camera (ideal for decals, selection outlines, and overlays).
  • Positive values push fragments farther away from the camera (ideal for background panels or underlays).

1. Overlays and Decals (Bring Forward)

To render an overlay directly on top of a base mesh, apply negative values to the overlay material:

decalMaterial.polygonOffset = true;
decalMaterial.polygonOffsetFactor = -1;
decalMaterial.polygonOffsetUnits = -1;

If slight z-fighting persists on steep viewing angles, increase the factor:

decalMaterial.polygonOffsetFactor = -2;
decalMaterial.polygonOffsetUnits = -1;

2. Hidden Line / Silhouette Rendering (Push Backward)

When rendering solid geometry inside wireframes or edge geometry, push the solid surface back:

baseMaterial.polygonOffset = true;
baseMaterial.polygonOffsetFactor = 1;
baseMaterial.polygonOffsetUnits = 1;

Best Practices

  • Modify only one layer: Apply the offset to either the top layer or the bottom layer, not both, to keep depth relationships predictable.
  • Keep values small: Start with -1 for both properties. Using excessively large numbers (e.g., -100) can cause the polygon to clip through other nearby objects that are legitimately in front.
  • Camera precision: If large offsets fail to solve the issue, ensure your camera's near plane is not set too low (e.g., 0.0001), as an overly wide near-to-far ratio drastically reduces depth buffer precision across the entire scene.
