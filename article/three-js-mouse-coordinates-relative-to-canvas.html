Three.js Mouse Coordinates Relative to Canvas

This guide explains how to mathematically calculate the exact 2D screen-space coordinates of a mouse event relative to a specific Three.js <canvas> element. When working with interactive 3D scenes, DOM mouse events provide global viewport coordinates that do not inherently align with a canvas's local pixel dimensions or Three.js's Normalized Device Coordinate (NDC) system. Below are the direct formulas and code required to transform raw event data into accurate local pixel and NDC values.

Step 1: Account for the Canvas Position in the Viewport

Standard DOM pointer events (such as pointermove, mousemove, or click) provide properties like clientX and clientY, which represent the cursor's position relative to the browser viewport.

To make these coordinates relative to the canvas, measure the canvas's current position and dimensions in the viewport using getBoundingClientRect():

const rect = renderer.domElement.getBoundingClientRect();

The relative pixel coordinates \((x_{\text{pixel}}, y_{\text{pixel}})\) from the top-left corner of the canvas element are calculated as:

\[x_{\text{pixel}} = \text{event.clientX} - \text{rect.left}\] \[y_{\text{pixel}} = \text{event.clientY} - \text{rect.top}\]

Step 2: Handle Canvas Internal Resolution Scaling

If the CSS size of the canvas does not match its internal rendering buffer dimensions (canvas.width and canvas.height), scale the pixel coordinates by the ratio of internal pixels to displayed CSS pixels:

\[x_{\text{internal}} = (\text{event.clientX} - \text{rect.left}) \times \left(\frac{\text{canvas.width}}{\text{rect.width}}\right)\]

\[y_{\text{internal}} = (\text{event.clientY} - \text{rect.top}) \times \left(\frac{\text{canvas.height}}{\text{rect.height}}\right)\]

Step 3: Convert to Normalized Device Coordinates (NDC)

For raycasting and 3D object interaction, Three.js requires coordinates in Normalized Device Coordinates (NDC). In this system:

  • The center of the canvas is \((0, 0)\).
  • The X-axis ranges from \(-1\) (far left) to \(+1\) (far right).
  • The Y-axis ranges from \(-1\) (bottom) to \(+1\) (top).

Because DOM coordinate spaces have an inverted Y-axis (top is \(0\), moving downward increases \(Y\)), the Y-axis must be inverted during calculation.

The conversion formulas are:

\[x_{\text{ndc}} = \left( \frac{\text{event.clientX} - \text{rect.left}}{\text{rect.width}} \right) \times 2 - 1\]

\[y_{\text{ndc}} = -\left( \frac{\text{event.clientY} - \text{rect.top}}{\text{rect.height}} \right) \times 2 + 1\]

Implementation Example

Attach the event listener directly to the renderer's DOM element to avoid capturing extraneous events outside the canvas boundaries:

const mouse = new THREE.Vector2();

function onPointerMove(event) {
    const rect = renderer.domElement.getBoundingClientRect();

    // Normalized Device Coordinates (-1 to +1)
    mouse.x = ((event.clientX - rect.left) / rect.width) * 2 - 1;
    mouse.y = -((event.clientY - rect.top) / rect.height) * 2 + 1;

    // Optional: Local screen-space pixel coordinates (0 to rect.width/height)
    const pixelX = event.clientX - rect.left;
    const pixelY = event.clientY - rect.top;
}

renderer.domElement.addEventListener('pointermove', onPointerMove);

Using rect.left and rect.top dynamically accounts for scroll offsets, CSS transforms, padding, and responsive layout reflows without requiring hardcoded offset values.
