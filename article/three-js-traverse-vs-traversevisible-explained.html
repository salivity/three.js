Three.js traverse vs traverseVisible Explained

When building 3D applications with Three.js, developers frequently need to iterate through the scene graph to inspect, modify, or update objects. This article explains the fundamental differences between the traverse and traverseVisible methods in Three.js, detailing how each handles object visibility, how child inheritance impacts traversal, and when to use each method for optimal performance and functionality.

Understanding traverse

The Object3D.traverse() method recursively executes a specified callback function on the object calling it and on all of its descendants, regardless of their visibility state.

Even if an object or one of its parent containers has its visible property set to false, traverse will still process the object and continue walking down the entire hierarchy.

scene.traverse((child) => {
  if (child.isMesh) {
    // This runs for EVERY mesh in the scene,
    // including hidden meshes and meshes inside hidden groups.
    console.log(child.name);
  }
});

Common Use Cases for traverse

  • Resource Management: Disposing of geometries, materials, and textures across an entire imported model before removing it from memory.
  • Global Modifications: Updating shadow settings (castShadow, receiveShadow) or applying global custom shaders across the entire scene graph.
  • Finding Objects: Searching for a specific node by name or type when you cannot be certain if its parent elements are visible.

Understanding traverseVisible

The Object3D.traverseVisible() method also recursively visits the object and its descendants, but with one critical distinction: it only executes the callback on objects whose visible property evaluates to true.

More importantly, if an object has visible = false, traverseVisible stops recursing down that entire branch. Any children attached to that hidden object will be completely skipped, even if those individual child objects have visible = true set on themselves.

scene.traverseVisible((child) => {
  if (child.isMesh) {
    // This ONLY runs for meshes where the mesh AND
    // all of its ancestors have visible = true.
    console.log(child.name);
  }
});

Common Use Cases for traverseVisible

  • Raycasting and Interaction: Checking interactions only against elements that are currently rendered and visible to the user.
  • Animation Updates: Skipping calculations or skeletal bone updates for parts of a scene or character rigs that are toggled off.
  • Performance Optimization: Limiting expensive per-frame computations solely to active visual elements.

Key Differences Summary

Feature traverse traverseVisible
Visibility Check Ignores the visible property entirely. Requires visible === true.
Child Branch Skipping Never skips branches based on visibility. Skips the entire subtree if a parent is hidden.
Execution Count Always processes every descendant node. Only processes nodes in actively visible branches.
Best For Asset loading, batch setup, cleanup, disposal. Render loops, raycasting, interactions, visible updates.

Important Caveat: Inherited Visibility

Three.js does not calculate an inheritedVisible property automatically on objects. A child object inside a hidden group will still report child.visible === true if its individual flag was never changed to false.

Because traverseVisible cuts off evaluation at the hidden parent level, it correctly avoids processing children that are visually hidden by inheritance. Conversely, if you use standard traverse and simply check if (child.visible) inside the callback, you may get false positives because the check will not account for hidden parents higher up in the hierarchy.
