Using EventDispatcher.hasEventListener in Three.js

In Three.js, managing event subscriptions effectively is critical for maintaining performance and preventing unintended behavior in interactive scenes. This article demonstrates how to use the EventDispatcher.hasEventListener method to strictly check for existing callback registrations before attaching new ones, ensuring that duplicate callback bindings are eliminated across your application.

The Duplicate Listener Problem in Three.js

Three.js implements an internal event system via the EventDispatcher class, which components like OrbitControls, custom controllers, and loaders often utilize or extend. When you invoke addEventListener(type, listener), the dispatcher appends the listener to an internal array.

If this method is invoked multiple times with the same function—such as during re-renders, scene rebuilds, or dynamic component mounting—the function will execute repeatedly for a single triggered event. This can lead to memory leaks, redundant computations, and unexpected side effects in your rendering pipeline.

Using hasEventListener for Guarded Registration

The hasEventListener method accepts an event type (string) and the specific listener (function reference). It returns a boolean indicating whether the listener is already present in the target's listener array.

import * as THREE from 'three';

// Initialize a dispatcher or an object that extends EventDispatcher
const dispatcher = new THREE.EventDispatcher();

// Define a stable function reference
function onObjectSelected(event) {
    console.log('Object selected:', event.target);
}

// Check before binding
if (!dispatcher.hasEventListener('select', onObjectSelected)) {
    dispatcher.addEventListener('select', onObjectSelected);
}

By wrapping the registration in this conditional check, subsequent attempts to attach onObjectSelected to the 'select' event are safely ignored.

Abstracting a Safe Binding Utility

To enforce strict callback bindings across a project, you can encapsulate the pattern into a reusable utility function:

function addUniqueEventListener(target, type, listener) {
    if (!target || typeof target.addEventListener !== 'function') {
        throw new Error('Target must implement Three.js EventDispatcher.');
    }

    if (!target.hasEventListener(type, listener)) {
        target.addEventListener(type, listener);
        return true; // Successfully added
    }

    return false; // Skipped duplicate binding
}

You can use this utility whenever configuring scene interactions:

addUniqueEventListener(controls, 'change', renderScene);
addUniqueEventListener(controls, 'change', renderScene); // Ignored safely

Critical Requirement: Stable Function References

EventDispatcher.hasEventListener compares callbacks using strict equality (===). Consequently, inline anonymous functions and newly instantiated arrow functions will fail the duplicate check because each declaration creates a new reference in memory.

Incorrect (Anonymous Function):

// This check always returns false, resulting in duplicate registrations
dispatcher.addEventListener('change', () => updateScene());
if (!dispatcher.hasEventListener('change', () => updateScene())) {
    dispatcher.addEventListener('change', () => updateScene());
}

Correct (Named Function or Bound Reference):

// Store the instance method or bound reference
class SceneManager {
    constructor(controls) {
        this.controls = controls;
        this.handleUpdate = this.handleUpdate.bind(this);
    }

    init() {
        if (!this.controls.hasEventListener('change', this.handleUpdate)) {
            this.controls.addEventListener('change', this.handleUpdate);
        }
    }
}

By maintaining a dedicated reference to your callback, hasEventListener can accurately identify previously registered functions, providing a lightweight and robust safeguard against duplicate execution.
