Three.js 4K Texture Mipmap GPU Memory Overhead

Enabling Texture.generateMipmaps = true on a 4K texture in Three.js introduces an additional GPU memory (VRAM) overhead of approximately 33.33% (one-third) above the base image's memory footprint. For a standard uncompressed 8-bit RGBA 4096×4096 texture, the base allocation is 64 MB, and generating mipmaps incurs an additional ~21.33 MB of VRAM, bringing the total footprint to roughly 85.33 MB.

The Mathematical Overhead of Mipmapping

A mipmap chain is a sequence of progressively downscaled copies of the original image, where each successive level is halved along both the width and height dimensions.

Because each mip level has one-fourth the number of pixels of the preceding level, the additional memory consumption forms a geometric series:

\[\sum_{k=1}^{\infty} \left(\frac{1}{4}\right)^k = \frac{1}{4} + \frac{1}{16} + \frac{1}{64} + \dots = \frac{1}{3} \approx 33.33\%\]

Because the chain stops when reaching a \(1 \times 1\) pixel level, the real-world overhead caps strictly at approximately 33.333% of the base texture's size.

Memory Calculations for 4K Textures

GPU memory consumption depends directly on the pixel dimensions and the data format. Uncompressed textures in Three.js default to standard 8-bit channels (THREE.UnsignedByteType).

1. Standard 3D Power-of-Two 4K (4096 × 4096)

  • Total Pixels (Base Level): \(4096 \times 4096 = 16,777,216\) pixels
  • Base Memory (RGBA / 4 bytes per pixel): \(16,777,216 \times 4 \text{ bytes} = 67,108,864 \text{ bytes}\) (64 MB)
  • Mipmap Overhead (+33.33%): \(64 \text{ MB} \times \frac{1}{3} \approx\) 21.33 MB
  • Total GPU Memory Allocated: 85.33 MB

2. Ultra HD Standard (3840 × 2160)

  • Total Pixels (Base Level): \(3840 \times 2160 = 8,294,400\) pixels
  • Base Memory (RGBA / 4 bytes per pixel): \(8,294,400 \times 4 \text{ bytes} = 33,177,600 \text{ bytes}\) (31.64 MB)
  • Mipmap Overhead (+33.33%): \(31.64 \text{ MB} \times \frac{1}{3} \approx\) 10.55 MB
  • Total GPU Memory Allocated: 42.19 MB

Impact of Texture Format Variations

The 33.33% overhead rule applies consistently across other formats, but shifts the absolute memory consumption:

  • HDR / Half-Float Textures (THREE.HalfFloatType): Uses 8 bytes per pixel (16 bits per channel). A 4096×4096 RGBA HDR image requires 128 MB for the base layer, creating a 42.67 MB mipmap overhead (170.67 MB total).
  • Full-Float Textures (THREE.FloatType): Uses 16 bytes per pixel (32 bits per channel). A 4096×4096 RGBA Float image requires 256 MB for the base layer, generating an 85.33 MB mipmap overhead (341.33 MB total).
  • Compressed Textures (KTX2, Basis, BCn, ASTC): Compressed formats reduce both the base size and mipmap sizes by roughly 75% to 85%, but the mipmap overhead still constitutes ~33.33% of the compressed base size.

Performance Trade-Off

Although generateMipmaps = true costs an additional ~21.33 MB of VRAM per 4096×4096 RGBA texture, it significantly reduces texture aliasing (shimmering artifacts) when viewed at distances or steep angles. It also improves rendering performance and GPU cache efficiency by fetching smaller, pre-filtered texels that fit better within high-speed GPU cache lines.
