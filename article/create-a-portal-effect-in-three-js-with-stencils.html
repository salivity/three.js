Create a Portal Effect in Three.js with Stencils

Creating a portal effect in Three.js requires isolating what a viewer can see through a specific opening, achieved primarily through the GPU's stencil buffer. By utilizing material properties such as stencilWrite, stencilRef, and stencilFunc, you can mask the 3D scene so that certain geometry is only rendered within the pixel boundaries of a defined portal frame. This guide covers how to configure the renderer, write to the stencil buffer with a portal mask, and restrict the visibility of portal-exclusive objects to create a seamless visual illusion.

1. Enable the Stencil Buffer in WebGLRenderer

To use stencil testing, the WebGL context must be initialized with the stencil buffer active. In Three.js, this is enabled by default, but it is best practice to define it explicitly:

const renderer = new THREE.WebGLRenderer({ stencil: true });

2. Configure the Portal Mask Geometry

The portal mask acts as the "window" into the hidden view. This object writes an identifier value into the stencil buffer wherever its pixels are drawn, without necessarily rendering any colors to the screen.

Set up the portal mask material with the following stencil properties:

  • stencilWrite: true: Tells the renderer to execute stencil operations for this material.
  • stencilRef: 1: Specifies the reference value to write into the stencil buffer.
  • stencilFunc: THREE.AlwaysStencilFunc: Ensures the stencil test passes for all drawn fragments.
  • stencilZPass: THREE.ReplaceStencilOp: Replaces the current stencil buffer value with the stencilRef value (1) wherever the depth test passes.
  • colorWrite: false: Disables writing to the color buffer if you want an invisible boundary, or keep it true if your portal is a tinted glass or textured surface.
  • depthWrite: false: Prevents the portal plane from blocking depth testing for the geometry behind it.
const portalGeometry = new THREE.PlaneGeometry(3, 5);
const portalMaterial = new THREE.MeshBasicMaterial({
  colorWrite: false,
  depthWrite: false,
  stencilWrite: true,
  stencilRef: 1,
  stencilFunc: THREE.AlwaysStencilFunc,
  stencilZPass: THREE.ReplaceStencilOp,
});

const portalMesh = new THREE.Mesh(portalGeometry, portalMaterial);
portalMesh.renderOrder = 1;
scene.add(portalMesh);

3. Configure the Objects Inside the Portal

Any object that should only be visible when looking through the portal must read from the stencil buffer and only render when the buffer's value matches the portal's stencilRef.

Configure the hidden objects' material properties:

  • stencilWrite: true: Activates stencil testing for the object.
  • stencilRef: 1: Must match the reference value set by the portal mask.
  • stencilFunc: THREE.EqualStencilFunc: Causes the fragment to render only if the stencil buffer value at that screen pixel is equal to stencilRef.
const hiddenObjectGeometry = new THREE.TorusKnotGeometry(1, 0.3, 100, 16);
const hiddenObjectMaterial = new THREE.MeshStandardMaterial({
  color: 0x00ff88,
  stencilWrite: true,
  stencilRef: 1,
  stencilFunc: THREE.EqualStencilFunc,
});

const hiddenObject = new THREE.Mesh(hiddenObjectGeometry, hiddenObjectMaterial);
hiddenObject.position.set(0, 0, -2);
hiddenObject.renderOrder = 2;
scene.add(hiddenObject);

4. Manage Render Order

Correct execution order is essential. The portal mask must be rendered before the objects that depend on its stencil marks:

  1. Outer Scene (Normal Objects): renderOrder = 0 (default)
  2. Portal Mask Plane: renderOrder = 1 (writes 1 to the stencil buffer)
  3. Interior Objects: renderOrder = 2 (renders only where the stencil buffer equals 1)

By managing renderOrder and matching the stencil buffer states across materials, Three.js restricts the interior objects strictly to the silhouette of the portal plane.
