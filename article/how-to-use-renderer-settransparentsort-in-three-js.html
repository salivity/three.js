How to Use renderer.setTransparentSort in Three.js

In Three.js, rendering semi-transparent objects often leads to visual artifacts because transparent meshes must be drawn in a precise order, typically from back to front. While Three.js implements a default painter's algorithm based on distance to the camera, complex scenes or overlapping geometries often require manual intervention. This guide explains how to write and apply a custom sorting function using renderer.setTransparentSort to gain full control over the transparent render queue.

Why Override Transparent Sorting?

By default, the Three.js WebGLRenderer sorts transparent items based on their camera-space depth (z), alongside groupOrder and renderOrder. However, the default calculation uses the object's origin (pivot point) or bounding sphere center. If you have large intersecting planes, nested objects, or specific UI elements that must appear in a distinct sequence regardless of camera position, the default sort can fail. Overriding it allows you to inject custom logic, such as sorting by custom depth formulas, layer hierarchies, or custom material priorities.

The Structure of Render Items

When renderer.setTransparentSort() invokes your callback, it passes two render item objects (a and b). These objects contain internal metadata used by the Three.js render list:

  • a.object: The Object3D or Mesh instance.
  • a.geometry: The geometry of the object.
  • a.material: The active material.
  • a.z: The computed distance from the camera along the view vector.
  • a.renderOrder: The user-assigned renderOrder property.
  • a.groupOrder: The sorting order if objects belong to groups.
  • a.id: The internal unique ID.

Like standard JavaScript Array.prototype.sort(), your function should return:

  • A negative value if a should be rendered before b.
  • A positive value if b should be rendered before a.
  • Zero if the order remains unchanged.

Implementing a Custom Sort Function

To replace the sorting mechanism, define a comparator function and pass it to renderer.setTransparentSort.

Example: Strict Depth-Based Sorting with Custom Priority

The following implementation prioritizes a custom property defined on mesh.userData.priority, falling back to camera depth:

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer({ antialias: true });

// Define custom transparent sort
function customTransparentSort(a, b) {
  // Check for custom priority defined in userData
  const priorityA = a.object.userData.priority || 0;
  const priorityB = b.object.userData.priority || 0;

  if (priorityA !== priorityB) {
    return priorityA - priorityB;
  }

  // Preserve renderOrder if explicitly set
  if (a.renderOrder !== b.renderOrder) {
    return a.renderOrder - b.renderOrder;
  }

  // Default Three.js behavior: Back-to-front rendering (larger z drawn first)
  if (a.z !== b.z) {
    return b.z - a.z;
  }

  // Final fallback to unique object ID for a stable sort
  return a.id - b.id;
}

// Assign the function to the renderer
renderer.setTransparentSort(customTransparentSort);

Example: Front-to-Back Sorting

If you are using custom blending modes (such as additive blending) where drawing front-to-back minimizes overdraw or achieves specific optical effects, reverse the depth comparison:

renderer.setTransparentSort((a, b) => {
  if (a.renderOrder !== b.renderOrder) {
    return a.renderOrder - b.renderOrder;
  }
  // Front-to-back sorting
  return a.z - b.z;
});

Restoring Default Behavior

If you need to revert to the standard Three.js sorting routine at runtime, pass null to setTransparentSort:

renderer.setTransparentSort(null);

Passing null restores the internal reversePainterSortStable function used by default in Three.js.
