Layering a 3D UI in Three.js Using clearDepth

This article explains how to layer a secondary 3D user interface (UI) on top of a primary 3D game environment in Three.js using the renderer.clearDepth() method. By decoupling the depth buffer between rendering passes, you can display interactive 3D UI elements or HUDs directly over world geometry, completely preventing scene geometry from clipping through UI components regardless of their spatial coordinates.

The Problem with Single-Scene Rendering

In a standard Three.js setup, every mesh shares the same depth buffer (Z-buffer). If you attempt to place 3D elements—such as floating health bars, inventory screens, or interactive holographic menus—inside the main game scene, distant UI elements can be obstructed by closer world geometry. Moving UI meshes closer to the camera can cause field-of-view distortion and scale inconsistencies.

The Solution: Two Scenes and a Cleared Depth Buffer

The optimal approach separates your application into two independent scenes and cameras:

  1. World Scene & Camera: Handles the terrain, characters, and environment, typically via a PerspectiveCamera.
  2. UI Scene & Camera: Handles UI components, using either an OrthographicCamera for fixed 2D-like positioning or a separate PerspectiveCamera for 3D perspective-tilted panels.

By disabling the renderer's automatic clearing behavior, you can manually render the game world, wipe only the depth buffer, and then render the UI over the top. The color data remains intact, but the UI is drawn as if the depth buffer were completely empty.

Step-by-Step Implementation

1. Configure the WebGLRenderer

By default, WebGLRenderer clears the color, depth, and stencil buffers automatically before every call to renderer.render(). Disable this behavior to control the buffers manually:

renderer.autoClear = false;

2. Define Separate Scenes and Cameras

Create distinct scene and camera instances for your game environment and your interface:

// Main game world
const worldScene = new THREE.Scene();
const worldCamera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);

// UI overlay
const uiScene = new THREE.Scene();
const uiCamera = new THREE.OrthographicCamera(
    window.innerWidth / -2, 
    window.innerWidth / 2, 
    window.innerHeight / 2, 
    window.innerHeight / -2, 
    1, 
    1000
);
uiCamera.position.z = 10;

3. Structure the Render Loop

In your animation loop, perform the rendering passes in this exact order:

function animate() {
    requestAnimationFrame(animate);

    // 1. Manually clear all buffers (color, depth, stencil)
    renderer.clear();

    // 2. Render the background / game world
    renderer.render(worldScene, worldCamera);

    // 3. Clear only the depth buffer
    renderer.clearDepth();

    // 4. Render the UI scene on top
    renderer.render(uiScene, uiCamera);
}

animate();

Handling Pointer Events and Raycasting

When implementing mouse interactions (such as button clicks or dragging items), raycasting must check the UI scene first:

  1. Cast a ray into uiScene using the uiCamera.
  2. If an intersection occurs, trigger the UI event and halt execution.
  3. If no UI element is intersected, cast the ray into worldScene using worldCamera to handle in-game targeting or movement.

This approach guarantees an intuitive interface layer that prevents unwanted clicks on the world behind active UI elements.
