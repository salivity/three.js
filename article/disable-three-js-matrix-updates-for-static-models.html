Disable Three.js Matrix Updates for Static Models

Rendering a massive static city model in Three.js can severely bottleneck the CPU because the engine recalculates transformation matrices for every object on every frame by default. By explicitly disabling automatic matrix calculations across static objects and computing their matrices only once, you can eliminate unnecessary scene-graph traversals and drastically reduce per-frame CPU overhead.

The Problem with Default Matrix Calculations

In Three.js, every Object3D (including meshes, groups, and cameras) has its matrixAutoUpdate flag set to true by default. During the render loop, Three.js traverses the entire scene hierarchy and recalculates both local matrices (matrix) and world matrices (matrixWorld) for each node, accounting for potential changes in position, rotation, or scale.

When dealing with a complex city model comprising thousands of static buildings, street furniture, and infrastructure meshes, these redundant calculations consume vital CPU cycles that should be reserved for physics, animations, or draw-call dispatching.

Disabling Automatic Updates

To stop Three.js from recalculating transforms for static assets, set matrixAutoUpdate to false. Because the transforms will no longer compute automatically, you must manually trigger an initial calculation after positioning your objects so their final locations register properly.

Here is how to traverse a loaded city model, apply transformations, disable auto-updates, and freeze the matrices:

// Assume 'cityModel' is an Object3D or Group containing the static city
cityModel.traverse((child) => {
  if (child.isMesh) {
    // 1. Apply any required initial transformations
    // child.position.set(...);
    // child.rotation.set(...);

    // 2. Force an initial matrix calculation
    child.updateMatrix();

    // 3. Disable future per-frame matrix recalculations
    child.matrixAutoUpdate = false;
  }
});

// 4. Update the entire hierarchy's world matrices once
cityModel.updateMatrixWorld(true);

Freezing World Matrix Updates

In recent versions of Three.js, the scene renderer also supports matrixWorldAutoUpdate. While matrixAutoUpdate prevents the object's local matrix from recalculating, setting matrixWorldAutoUpdate = false on a static root node ensures that Three.js does not attempt to evaluate parent-child transform cascades for that subtree during the render phase:

cityModel.matrixWorldAutoUpdate = false;

If you set this property, ensure you call cityModel.updateMatrixWorld(true) immediately beforehand so the initial nested transformations are baked into the world space.

Updating Static Objects When Needed

Freezing matrices does not prevent you from ever moving objects again. If a building collapses, moves, or gets replaced dynamically at runtime, you can temporarily flag it for an update:

function moveStaticObject(mesh, newPosition) {
  mesh.position.copy(newPosition);
  
  // Recalculate local and world matrices explicitly
  mesh.updateMatrix();
  mesh.updateMatrixWorld(true);
}

By manually orchestrating matrix updates only when transformations actually take place, the CPU frame budget remains dedicated to dynamic scene elements rather than thousands of unchanging city meshes.
