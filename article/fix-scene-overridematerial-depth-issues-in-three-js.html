Fix Scene.overrideMaterial Depth Issues in Three.js

In Three.js, setting Scene.overrideMaterial globally forces every mesh in the scene hierarchy to render with a single designated material, bypassing individual material settings. While useful for creating masks or uniform passes, this behavior frequently breaks depth-based rendering—such as shadow maps, alpha testing, and occlusion culling—by stripping out geometry-specific pipeline configurations like skinning, displacement, and transparency cutouts. This article explains the underlying mechanism of why standard depth evaluation fails under Scene.overrideMaterial and provides actionable methods to circumvent these limitations.

Why Scene.overrideMaterial Breaks Depth Rendering

When you set scene.overrideMaterial, the Three.js WebGL renderer skips the material assigned to each individual Mesh and uses the override material's shader program and state configuration for the entire render pass. This causes three primary depth-related failures:

  1. Loss of Alpha Testing and Cutouts: Meshes using transparent textures with alphaTest (such as foliage or chain-link fences) rely on texture lookups in the fragment shader to discard fragments. An override material (like a basic MeshDepthMaterial) typically lacks these specific texture maps, causing the renderer to write the mesh's full, rectangular geometry to the depth buffer rather than its cut-out silhouette.
  2. Vertex Transformation Discrepancies: Skinned meshes (SkinnedMesh) and meshes with morph targets require specific vertex shader logic to calculate their current pose. If the overrideMaterial does not have skinning = true or morphTargets = true enabled, vertices are rendered in their bind poses, creating a mismatch between visual geometry and depth representations.
  3. Overwritten Depth States: Individual meshes often require distinct depth settings, such as depthWrite: false for additive particle systems or custom polygonOffset values to prevent Z-fighting. The override material enforces its own depthWrite, depthTest, and blending modes uniformly across every object.

Workarounds and Solutions

1. Manual Traversal and Conditional Material Swapping

Instead of applying a global override on the scene level, manually traverse the scene graph before rendering. This allows you to apply substitute materials while preserving object-specific attributes like texture maps and animation flags.

const depthMaterialCache = new Map();

function getDepthMaterial(mesh) {
  if (!depthMaterialCache.has(mesh)) {
    const depthMat = new THREE.MeshDepthMaterial({
      depthPacking: THREE.RGBADepthPacking,
      map: mesh.material.map || null,
      alphaTest: mesh.material.alphaTest || 0,
      skinning: mesh.isSkinnedMesh,
      morphTargets: mesh.geometry.morphAttributes.position !== undefined
    });
    depthMaterialCache.set(mesh, depthMat);
  }
  return depthMaterialCache.get(mesh);
}

// Render Pass
scene.traverse((child) => {
  if (child.isMesh) {
    child.userData.originalMaterial = child.material;
    child.material = getDepthMaterial(child);
  }
});

renderer.render(scene, camera);

// Restore
scene.traverse((child) => {
  if (child.isMesh && child.userData.originalMaterial) {
    child.material = child.userData.originalMaterial;
    delete child.userData.originalMaterial;
  }
});

2. Using mesh.customDepthMaterial

If the goal is to correct shadow mapping or specific depth pre-passes without interfering with the main beauty pass, assign materials to customDepthMaterial on the mesh itself instead of using scene.overrideMaterial.

mesh.customDepthMaterial = new THREE.MeshDepthMaterial({
  depthPacking: THREE.RGBADepthPacking,
  map: mesh.material.map,
  alphaTest: 0.5
});

Three.js automatically uses customDepthMaterial during the shadow map generation pass, leaving standard depth tests and scene rendering intact.

3. Layer-Based Multi-Pass Rendering

If specific objects must not participate in the override material pass (such as skyboxes, UI elements, or transparent overlays), organize objects using THREE.Layers.

Configure the camera to only view the layer intended for the depth-dependent pass:

// Setup layers
const DEFAULT_LAYER = 0;
const OVERRIDE_EXCLUDE_LAYER = 1;

transparentObject.layers.set(OVERRIDE_EXCLUDE_LAYER);

// Perform pass with override
scene.overrideMaterial = customOverrideMaterial;
camera.layers.disable(OVERRIDE_EXCLUDE_LAYER);
renderer.render(scene, camera);

// Reset for normal rendering
scene.overrideMaterial = null;
camera.layers.enable(OVERRIDE_EXCLUDE_LAYER);

4. Shader Modification with onBeforeCompile

If you need consistent lighting, depth, or post-processing hooks without swapping materials, inject custom GLSL logic into the existing materials via material.onBeforeCompile. This allows all individual material properties—such as displacement, clipping planes, skinning, and alpha discard—to evaluate correctly while altering the final output buffer as needed.
