Three.js Octree Collision Detection for Complex Terrain

Performing collision detection against complex, high-polygon terrains in Three.js can quickly degrade performance if done using standard brute-force raycasting. An Octree solves this problem by partitioning 3D space hierarchically into an eight-child tree structure, reducing collision query complexity from linear \(O(N)\) to logarithmic \(O(\log N)\). This guide explains the mechanics of an Octree, demonstrates how to construct and update one using Three.js utilities, and details how to execute fast collision queries against massive terrain geometries.

The Problem with Brute-Force Testing

Three.js includes a built-in Raycaster that can test intersections against meshes. However, when applied to a dense terrain geometry containing tens or hundreds of thousands of triangles, the raycaster must evaluate every individual triangle to test for an intersection. At 60 frames per second, running these checks for characters, projectiles, or camera clipping causes severe frame drops.

How an Octree Optimizes Queries

An Octree is a tree data structure where each internal node has exactly eight children, corresponding to the octants of a 3D bounding box (Axis-Aligned Bounding Box, or AABB).

  1. Root Creation: An initial bounding box envelops the entire terrain mesh.
  2. Subdivision: If a node contains more than a defined threshold of triangles (e.g., 16 to 32 triangles) and has not reached the maximum depth limit, it subdivides into eight equal sub-boxes.
  3. Distribution: Triangles from the parent are sorted into whichever child octants they intersect.
  4. Querying: When a ray, sphere, or player capsule is tested for collision, the algorithm traverses only the branches whose bounding boxes intersect the query volume, ignoring the vast majority of non-relevant triangles in the terrain.

Implementing an Octree with Three.js

Three.js provides an optimized Octree implementation within its add-ons library (three/addons/math/Octree.js), alongside a Capsule primitive (three/addons/math/Capsule.js) commonly used for player collision.

1. Import and Setup

Import the necessary modules alongside your core Three.js dependencies:

import * as THREE from 'three';
import { Octree } from 'three/addons/math/Octree.js';
import { Capsule } from 'three/addons/math/Capsule.js';

2. Build the Octree from Terrain Geometry

Once your terrain mesh is loaded or generated, construct the Octree by passing the mesh directly. Ensure the terrain's world matrix is fully updated before generation:

const worldOctree = new Octree();

// Assume terrainMesh is your loaded GLTF or generated PlaneGeometry
terrainMesh.updateMatrixWorld(true);

// Populate the octree with the terrain's geometry
worldOctree.fromGraphNode(terrainMesh);

The fromGraphNode method traverses the target object, extracts all triangle faces, and places them into the spatial tree.

3. Defining the Collider

For player movement on uneven terrain, a vertical capsule provides smooth traversal over steps and slopes:

const playerRadius = 0.5;
const playerHeight = 1.8;

const playerCollider = new Capsule(
    new THREE.Vector3(0, playerRadius, 0),
    new THREE.Vector3(0, playerHeight - playerRadius, 0),
    playerRadius
);

4. Executing the Collision Check

Inside your animation loop, check for collisions between the collider and the Octree. The capsuleIntersect method returns an object containing the penetration depth and normal if a collision occurs:

function playerCollisions() {
    const result = worldOctree.capsuleIntersect(playerCollider);

    if (result) {
        // Push the collider out of the geometry along the collision normal
        playerCollider.translate(result.normal.multiplyScalar(result.depth));

        // Optional: Check if the surface is walkable
        const isGrounded = result.normal.y > 0.5;

        return { collided: true, isGrounded };
    }

    return { collided: false, isGrounded: false };
}

5. Raycasting Against the Octree

If you need point-to-point line-of-sight checks or projectile impacts rather than volume collisions, query the Octree directly with a ray:

const ray = new THREE.Ray(originPoint, directionVector);
const hit = worldOctree.rayIntersect(ray);

if (hit) {
    console.log(`Collision at distance: ${hit.distance}`);
    console.log(`Hit point:`, hit.point);
}

Key Performance Best Practices

  • Separate Visuals from Collisions: Never build an Octree from high-resolution visual meshes that include micro-details like foliage or tiny rock ridges. Create a low-poly invisible collision proxy of the terrain, and generate the Octree strictly from that proxy.
  • Precompute Static Terrains: Building an Octree via fromGraphNode incurs a one-time CPU cost. For production environments, build the Octree once during initialization or offload the structure generation to a Web Worker so the main thread remains responsive.
  • Chunked Terrains: For open-world environments that stream terrain tiles, maintain an individual Octree for each terrain chunk. Load, query, and dispose of Octrees dynamically relative to the player's current coordinate zone to keep memory consumption low.
