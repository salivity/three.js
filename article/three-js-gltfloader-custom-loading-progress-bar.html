Three.js GLTFLoader: Custom Loading Progress Bar

Loading 3D assets in Three.js often requires substantial bandwidth, which can leave users staring at a blank screen if visual feedback is not provided. This guide demonstrates how to build a custom HTML/CSS progress bar driven by the onProgress callback of Three.js's GLTFLoader. You will learn how to extract transfer data from the loading event, calculate the completion percentage, update the DOM in real time, and cleanly dismiss the loading interface once the model is rendered.

1. Create the HTML and CSS Overlay

First, construct the markup and styles for the progress bar. Position it over the Three.js canvas using fixed positioning so it remains visible while the scene initializes.

<div id="loading-container">
  <div id="progress-bar"></div>
  <span id="progress-text">0%</span>
</div>

<style>
  #loading-container {
    position: fixed;
    top: 0;
    left: 0;
    width: 100%;
    height: 100%;
    background-color: #1a1a1a;
    display: flex;
    flex-direction: column;
    justify-content: center;
    align-items: center;
    z-index: 9999;
    transition: opacity 0.5s ease;
  }

  #progress-bar {
    width: 0%;
    height: 8px;
    background-color: #4caf50;
    border-radius: 4px;
    max-width: 300px;
    transition: width 0.1s ease;
  }

  #progress-text {
    color: #ffffff;
    margin-top: 10px;
    font-family: sans-serif;
    font-size: 14px;
  }
</style>

2. Understand the onProgress Callback

The GLTFLoader.load() method accepts four arguments:

  1. URL: Path to the 3D file (.gltf or .glb).
  2. onLoad: Invoked when loading is complete.
  3. onProgress: Invoked periodically during the download with a ProgressEvent (often referred to as xhr).
  4. onError: Invoked if an error occurs.

The onProgress callback receives an event containing:

  • xhr.loaded: The number of bytes transferred so far.
  • xhr.total: The total size of the file in bytes (derived from the server's Content-Length HTTP header).

The percentage loaded is computed as:

const percentComplete = (xhr.loaded / xhr.total) * 100;

3. Implement the Loader Script

Connect the DOM elements to the GLTFLoader instance.

import * as THREE from 'three';
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';

// Reference the UI elements
const loadingContainer = document.getElementById('loading-container');
const progressBar = document.getElementById('progress-bar');
const progressText = document.getElementById('progress-text');

// Initialize the loader
const loader = new GLTFLoader();

loader.load(
  'models/my-model.glb',

  // 1. onLoad Callback
  function (gltf) {
    scene.add(gltf.scene);

    // Hide and remove the loading screen
    loadingContainer.style.opacity = '0';
    setTimeout(() => {
      loadingContainer.style.display = 'none';
    }, 500);
  },

  // 2. onProgress Callback
  function (xhr) {
    if (xhr.lengthComputable) {
      const percentComplete = Math.round((xhr.loaded / xhr.total) * 100);
      progressBar.style.width = `${percentComplete}%`;
      progressText.textContent = `${percentComplete}%`;
    } else {
      // Fallback for servers that do not provide Content-Length
      const mbLoaded = (xhr.loaded / (1024 * 1024)).toFixed(2);
      progressText.textContent = `Loaded ${mbLoaded} MB`;
    }
  },

  // 3. onError Callback
  function (error) {
    console.error('An error occurred while loading the model:', error);
    progressText.textContent = 'Failed to load asset.';
    progressText.style.color = '#ff4d4d';
  }
);

4. Important Considerations

  • Content-Length Header: The calculation xhr.loaded / xhr.total requires the server to send an accurate Content-Length response header. If assets are served with Transfer-Encoding: chunked or without this header, xhr.total will be 0, and xhr.lengthComputable will evaluate to false. Always check xhr.lengthComputable to avoid Infinity% or NaN% displays.
  • Large Texture Parsing: onProgress measures network download time, not GPU upload or parsing time. Very complex GLTF files may pause for a brief moment at 100% while Three.js compiles shaders and uploads textures into GPU memory before the onLoad callback executes.
