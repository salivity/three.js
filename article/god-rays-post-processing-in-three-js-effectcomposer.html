God Rays Post-Processing in Three.js EffectComposer

God rays, or volumetric light scattering, add dramatic atmosphere and realism to 3D scenes by simulating light shafts breaking through occluding geometry. This article explains how to implement the God Rays post-processing effect in Three.js using an EffectComposer. You will learn how to configure the light source mesh, set up the necessary render passes, customize the effect parameters, and optimize the render loop for smooth performance.

Core Principles of God Rays

The God Rays effect is a screen-space shader effect. Instead of calculating true atmospheric photon scattering throughout 3D volume, it casts rays outward from the screen position of a designated light emitter mesh. Any objects positioned between the camera and this light source act as occluders, blocking the scattering effect and casting volumetric shadows toward the viewer.

Implementation with Three.js and postprocessing

While Three.js provides lower-level shader chunks in its addons, the modern standard for volumetric light scattering in Three.js is the postprocessing library (pmndrs/postprocessing), which provides a complete, hardware-accelerated GodRaysEffect built specifically for Three.js scenes.

1. Installation

Install the library into your project:

npm install three postprocessing

2. Setting Up the Scene and Light Emitter

Create your standard Three.js scene and add a dedicated mesh to serve as the light source. This mesh represents the origin of the rays (such as a sun or lamp).

import * as THREE from 'three';
import { EffectComposer, RenderPass, EffectPass, GodRaysEffect } from 'postprocessing';

// 1. Scene, Camera, and Renderer setup
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
camera.position.set(0, 0, 10);

const renderer = new THREE.WebGLRenderer({
  powerPreference: 'high-performance',
  antialias: false,
  stencil: false,
  depth: false
});
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// 2. Create the Light Emitter Mesh
const sunGeo = new THREE.SphereGeometry(1.5, 32, 32);
const sunMat = new THREE.MeshBasicMaterial({
  color: 0xffddaa,
  transparent: true
});
const sunMesh = new THREE.Mesh(sunGeo, sunMat);
sunMesh.position.set(0, 2, -15);
scene.add(sunMesh);

// 3. Create an Occluder (blocking geometry)
const obstacleGeo = new THREE.BoxGeometry(2, 5, 2);
const obstacleMat = new THREE.MeshStandardMaterial({ color: 0x333333 });
const obstacle = new THREE.Mesh(obstacleGeo, obstacleMat);
obstacle.position.set(0, 1, -5);
scene.add(obstacle);

// Add ambient light for the occluder
const ambientLight = new THREE.AmbientLight(0xffffff, 0.4);
scene.add(ambientLight);

Configuring the EffectComposer and Passes

The EffectComposer manages the rendering pipeline. To display god rays, you need two passes:

  1. RenderPass: Renders the standard scene.
  2. EffectPass: Applies the GodRaysEffect targeting the light emitter mesh.
// Initialize EffectComposer
const composer = new EffectComposer(renderer);

// Add standard render pass
const renderPass = new RenderPass(scene, camera);
composer.addPass(renderPass);

// Configure GodRaysEffect
const godRaysEffect = new GodRaysEffect(camera, sunMesh, {
  height: 480,
  kernelSize: 1,
  density: 0.96,
  decay: 0.93,
  weight: 0.4,
  exposure: 0.6,
  samples: 60,
  clampMax: 1.0
});

// Add EffectPass containing the GodRaysEffect
const effectPass = new EffectPass(camera, godRaysEffect);
composer.addPass(effectPass);

Effect Parameters Explained

  • density: Controls the spacing and spread between ray steps. Higher values pull the rays closer to the emitter.
  • decay: Controls how quickly the ray intensity dissipates as it travels away from the source. Values between 0.9 and 0.98 produce natural-looking falloff.
  • weight: The intensity added by each ray sample.
  • exposure: Overall brightness of the scattered light result.
  • samples: Number of texture lookups along the ray path. Higher numbers (e.g., 60 to 100) yield smoother rays without banding, but require more GPU performance.
  • clampMax: Caps the maximum brightness to prevent blown-out highlights.

The Render Loop and Resizing

Replace standard renderer.render(scene, camera) calls with composer.render() inside the requestAnimationFrame loop. Update the composer when the window resizes to preserve correct aspect ratio and buffer dimensions.

function animate() {
  requestAnimationFrame(animate);

  // Optional: rotate the occluder to see dynamic light shafts
  obstacle.rotation.y += 0.01;

  composer.render();
}

animate();

window.addEventListener('resize', () => {
  camera.aspect = window.innerWidth / window.innerHeight;
  camera.updateProjectionMatrix();

  renderer.setSize(window.innerWidth, window.innerHeight);
  composer.setSize(window.innerWidth, window.innerHeight);
});

Optimization Best Practices

  • Off-Screen Visibility: Screen-space god rays can cause visual artifacts when the light emitter moves outside the camera frustum. If the emitter goes off-screen, decrease godRaysEffect.intensity or blend it out to avoid hard clipping.
  • Resolution Scaling: Use the height parameter in the effect options (e.g., 480 or 720) to render the scattering pass at a lower resolution than native display size. Light rays naturally blur, so rendering them at reduced resolution saves significant GPU fill rate with minimal visual loss.
  • Sample Count: Keep samples within the 30–60 range on mobile or performance-constrained hardware to maintain 60 frames per second.
