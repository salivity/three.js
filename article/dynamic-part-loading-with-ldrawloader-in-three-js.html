Dynamic Part Loading with LDrawLoader in Three.js

This guide explains how to dynamically resolve and load individual building block part files using Three.js and the LDrawLoader add-on. Rendering modular construction components on demand requires configuring the loader's internal path-resolution logic, supplying the core color definitions, and dynamically instantiating specific .dat or .ldr geometry files. By decoupling individual parts from pre-assembled model files, applications can build custom assembly tools, catalog viewers, or interactive construction environments in WebGL.

Understanding LDraw File Organization

LDraw models rely on a library hierarchy of primitives, subparts, and standard parts:

  • Parts (/parts): Standard complete components (such as 3001.dat for a standard 2x4 brick).
  • Primitives (/p): Basic geometric primitives used to construct parts (e.g., cylinders, studs, boxes).
  • Colors (LDConfig.ldr): The master configuration file defining standard colors, material opacities, and surface finishes.

When loading an individual part dynamically, LDrawLoader must know where to find both the referenced part and all of its underlying subparts and primitives.

Step 1: Initialize the Loader and Material Definitions

Before loading specific geometries, load the color definitions so parts render with accurate materials. Instantiate the LDrawLoader and configure it to parse LDConfig.ldr:

import * as THREE from 'three';
import { LDrawLoader } from 'three/examples/jsm/loaders/LDrawLoader.js';

const scene = new THREE.Scene();
const loader = new LDrawLoader();

// Ensure smooth surface normals on curved brick surfaces
loader.smoothNormals = true;

// Preload color definitions
async function initLDrawMaterials(configPath) {
    const response = await fetch(configPath);
    const text = await response.text();
    loader.parse(text); // Pre-populates the internal color library
}

Step 2: Configure Dynamic Library Resolution

By default, LDrawLoader attempts to resolve referenced files relative to the model path. To fetch individual parts dynamically from a server or CDN, override the file location logic using setPartsLibraryPath:

// Point the loader to the root folder holding the 'parts/' and 'p/' directories
loader.setPartsLibraryPath('https://example.com/ldraw-library/');

When a part requests nested primitives (such as stud.dat), the loader automatically fetches them from https://example.com/ldraw-library/p/ or https://example.com/ldraw-library/parts/.

If your part files are stored with non-standard file naming or require authorization headers, you can pass a custom THREE.LoadingManager to the loader:

const manager = new THREE.LoadingManager();

// Intercept and map dynamic URLs
manager.setURLModifier((url) => {
    if (url.endsWith('.dat')) {
        // Dynamically reroute part requests if necessary
        return url.replace('/parts/', '/custom-parts-cache/');
    }
    return url;
});

const customLoader = new LDrawLoader(manager);
customLoader.setPartsLibraryPath('/ldraw-assets/');

Step 3: Load Individual Parts at Runtime

To load a specific component dynamically without assembling a full .ldr scene, point the loader directly to the target .dat file:

async function loadSinglePart(partId, colorCode = 4) {
    // Construct the direct path or rely on partsLibraryPath
    const partPath = `parts/${partId}.dat`;

    return new Promise((resolve, reject) => {
        loader.load(
            partPath,
            (group) => {
                // Apply a default color code if not hardcoded inside the file
                // (Code 4 corresponds to standard Red in LDraw)
                group.userData.partId = partId;
                
                // Invert coordinates: LDraw uses an inverted Y-axis relative to Three.js
                group.rotation.x = Math.PI;

                scene.add(group);
                resolve(group);
            },
            undefined,
            (error) => {
                console.error(`Failed to load part: ${partId}`, error);
                reject(error);
            }
        );
    });
}

// Example usage: Load a single 2x4 Brick (Part 3001)
loadSinglePart('3001', 4).then((meshGroup) => {
    meshGroup.position.set(0, 0, 0);
});

Step 4: Dynamically Altering Part Materials

LDraw components are returned as a THREE.Group containing sub-meshes with conditional line segments and surface geometries. To dynamically adjust the color of an instantiated part without reloading the geometry, traverse the group and update the material references:

function setPartColor(partGroup, colorHex) {
    partGroup.traverse((child) => {
        if (child.isMesh && child.material) {
            // Check if this geometry represents standard brick surfaces
            if (Array.isArray(child.material)) {
                child.material.forEach((mat) => mat.color.set(colorHex));
            } else {
                child.material.color.set(colorHex);
            }
        }
    });
}

This pattern allows the application to keep a single geometry template in memory while instantiating multiple building blocks with distinct positions, rotations, and surface colors dynamically.
