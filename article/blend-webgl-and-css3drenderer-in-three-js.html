Blend WebGL and CSS3DRenderer in Three.js

This article explains how to configure Three.js to seamlessly interleave standard WebGL objects and HTML-based CSS3D elements within the same 3D scene. By layering the CSS3DRenderer behind a transparent WebGLRenderer and utilizing invisible WebGL "occlusion meshes" that write exclusively to the depth buffer, you can achieve proper visual sorting where WebGL objects can move naturally both in front of and behind interactive HTML elements.

The Architecture: Layering and Depth Masking

Because the DOM and WebGL use entirely separate rendering pipelines, a standard CSS3DObject cannot write to the GPU's WebGL depth buffer. To create the illusion that HTML elements exist within the WebGL depth hierarchy, the DOM layers must be stacked precisely, and a synchronized depth-masking geometry must be injected into the WebGL scene.

  1. Stack the Renderers: The CSS3DRenderer DOM element sits at the bottom of the stack, and the WebGLRenderer DOM element is placed directly on top with a transparent background.
  2. Synchronize Cameras: Both renderers use the exact same PerspectiveCamera instance or identical camera transformations.
  3. Occlude with Invisible Meshes: For every CSS3DObject in the scene, a corresponding Mesh with identical dimensions and transforms is added to the WebGL scene. This mesh uses a material configured to write to the depth buffer while remaining completely invisible (colorWrite: false).

When a WebGL element is placed behind the HTML element, the invisible occlusion mesh writes depth data over that region. The WebGL element fails the depth test and is discarded, revealing the underlying CSS3D element. When a WebGL element moves in front, its depth value is closer to the camera than the occlusion mesh, allowing it to pass the depth test and render on top of the CSS3D element.

Step 1: Configure the Canvas and DOM Structure

Ensure the WebGLRenderer is initialized with transparency enabled so the CSS3DRenderer container remains visible beneath it.

import * as THREE from 'three';
import { CSS3DRenderer, CSS3DObject } from 'three/addons/renderers/CSS3DRenderer.js';

// 1. Setup CSS3DRenderer (Bottom Layer)
const cssRenderer = new CSS3DRenderer();
cssRenderer.setSize(window.innerWidth, window.innerHeight);
cssRenderer.domElement.style.position = 'absolute';
cssRenderer.domElement.style.top = '0';
cssRenderer.domElement.style.left = '0';
document.body.appendChild(cssRenderer.domElement);

// 2. Setup WebGLRenderer (Top Layer)
const webglRenderer = new THREE.WebGLRenderer({ alpha: true, antialias: true });
webglRenderer.setSize(window.innerWidth, window.innerHeight);
webglRenderer.setPixelRatio(window.devicePixelRatio);
webglRenderer.setClearColor(0x000000, 0); // Completely transparent
webglRenderer.domElement.style.position = 'absolute';
webglRenderer.domElement.style.top = '0';
webglRenderer.domElement.style.left = '0';
webglRenderer.domElement.style.pointerEvents = 'none'; // Allow DOM interaction beneath
document.body.appendChild(webglRenderer.domElement);

Step 2: Create the CSS3D Element and the Occlusion Mask

Create the HTML element and instantiate both the CSS3DObject and the matching WebGL occlusion mesh.

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);

const width = 300;
const height = 200;

// 1. Create the HTML Element
const element = document.createElement('div');
element.style.width = `${width}px`;
element.style.height = `${height}px`;
element.style.background = 'rgba(0, 127, 255, 0.8)';
element.innerHTML = '<h1>Interactive HTML</h1>';

// 2. Create the CSS3DObject
const cssObject = new CSS3DObject(element);
cssObject.position.set(0, 0, 0);
scene.add(cssObject);

// 3. Create the Occlusion Mesh
// Geometry must match the CSS element's dimensions in scene units
const planeGeometry = new THREE.PlaneGeometry(width, height);
const planeMaterial = new THREE.MeshBasicMaterial({
    colorWrite: false, // Prevents drawing color to the canvas
    depthWrite: true   // Writes coordinates to the depth buffer
});

const occlusionMesh = new THREE.Mesh(planeGeometry, planeMaterial);
occlusionMesh.position.copy(cssObject.position);
occlusionMesh.rotation.copy(cssObject.rotation);
scene.add(occlusionMesh);

Step 3: Handle Pointer Events

Because the WebGLRenderer is positioned above the CSS3DRenderer, setting pointer-events: none on the WebGL canvas enables normal mouse interactions (clicks, scrolling, inputs) with the underlying HTML elements.

If interactive WebGL elements also require raycasting, attach the raycasting event listeners to the window or to a shared parent wrapper rather than directly to the WebGL canvas.

Step 4: The Render Loop

Both renderers must be updated in sequence during the animation loop using the identical camera configuration:

function animate() {
    requestAnimationFrame(animate);

    // Any transformations applied to the CSS3D object must be mirrored on the occlusion mesh
    occlusionMesh.position.copy(cssObject.position);
    occlusionMesh.rotation.copy(cssObject.rotation);
    occlusionMesh.scale.copy(cssObject.scale);

    // Render CSS3D first, then WebGL on top
    cssRenderer.render(scene, camera);
    webglRenderer.render(scene, camera);
}

animate();

With this configuration, standard WebGL meshes positioned at a greater distance along the camera axis than the plane will be masked out by the occlusion plane's depth values, while meshes positioned closer to the camera will render normally across the top of the HTML element.
