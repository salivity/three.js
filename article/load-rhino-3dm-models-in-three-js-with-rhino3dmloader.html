Load Rhino 3DM Models in Three.js with Rhino3dmLoader

Loading and rendering native Rhinoceros 3D (.3dm) files in Three.js requires converting mathematical Non-Uniform Rational B-Splines (NURBS) surfaces into renderable triangle meshes directly within the browser. This guide details how to integrate the Rhino3dmLoader, configure the underlying WebAssembly runtime (rhino3dm.js), load .3dm assets asynchronously, and optimize complex NURBS models for smooth WebGL rendering.

How NURBS Processing Works in Three.js

Standard graphics pipelines cannot render mathematical NURBS surfaces natively; they require polygonal meshes consisting of vertices, edges, and faces. The Rhino3dmLoader bridges this gap by utilizing the official rhino3dm WebAssembly library (built from openNURBS). When a .3dm file is passed to the loader, the library parses geometry, extracts metadata (such as layers and materials), and tessellates NURBS surfaces into THREE.BufferGeometry instances on the client side if pre-calculated render meshes are not already embedded in the file.

Prerequisites and Asset Setup

To use Rhino3dmLoader, you need access to the loader module and the matching rhino3dm WASM dependencies:

  1. Import Rhino3dmLoader from three/addons/loaders/3DMLoader.js.
  2. Locate rhino3dm.js and rhino3dm.wasm inside the node_modules/rhino3dm/ directory.
  3. Host the rhino3dm.wasm and rhino3dm.js files statically on your web server so the client can fetch them during initialization.

Implementation Guide

1. Configure the Loader

Initialize the loader and point it to the directory hosting your WebAssembly binaries using the setLibraryPath method:

import * as THREE from 'three';
import { Rhino3dmLoader } from 'three/addons/loaders/3DMLoader.js';

const scene = new THREE.Scene();

// Initialize loader
const loader = new Rhino3dmLoader();

// Specify the path to the folder containing rhino3dm.js and rhino3dm.wasm
loader.setLibraryPath('/path/to/rhino3dm/');

2. Load and Traverse the Model

Invoke loader.load() to parse the .3dm file. The callback returns a THREE.Object3D group representing the Rhino hierarchy:

loader.load(
  'models/complex_nurbs_model.3dm',
  (object) => {
    // Traverse the loaded model hierarchy
    object.traverse((child) => {
      if (child.isMesh) {
        child.castShadow = true;
        child.receiveShadow = true;

        // Apply standard PBR materials if necessary
        if (!child.material || child.material.type === 'MeshBasicMaterial') {
          child.material = new THREE.MeshStandardMaterial({
            color: child.material.color || 0xcccccc,
            roughness: 0.4,
            metalness: 0.2
          });
        }
      }
    });

    scene.add(object);
  },
  (progress) => {
    const percent = (progress.loaded / progress.total) * 100;
    console.log(`Loading: ${Math.round(percent)}%`);
  },
  (error) => {
    console.error('An error occurred while loading the 3DM file:', error);
  }
);

Best Practices for Complex NURBS Models

Complex NURBS topologies can cause severe frame drops and long load times if not prepared properly. Implement the following optimizations:

  • Pre-generate Render Meshes in Rhino: Client-side tessellation of raw NURBS curves and surfaces via WebAssembly is computationally intensive. In Rhino, set the viewport to "Shaded" mode or run the ExtractRenderMesh command before saving. Saving the file with render meshes allows the loader to extract existing polygon data directly, bypassing heavy browser-side tessellation.
  • Tessellation Settings: If the model must rely on client-side meshing, configure tessellation options via loader.setMeshingParameters() to balance visual fidelity and polygon count.
  • Material Mapping: Rhino materials are automatically mapped to equivalent Three.js materials where possible. Ensure your scene includes an adequate light setup (such as THREE.AmbientLight and THREE.DirectionalLight or an environment map) to properly illuminate MeshStandardMaterial surfaces generated from the CAD data.
  • Worker Threads: Rhino3dmLoader handles parsing inside Web Workers when supported, preventing the primary UI thread from freezing during the decompression and processing of large model files.
