Handling Sharp Corner Miters in Three.js Fat Lines

Drawing thick lines with Three.js using the Line2, LineGeometry, and LineMaterial extensions often introduces undesirable spikes and visual artifacts at acute corners. Because Three.js fat lines generate screen-space quads inside vertex shaders, sharp turns force miter joins to project outward excessively. Resolving these sharp corner miter issues requires geometry preprocessing, joint supplementation, or adjusting the underlying shader calculations.

The Cause of Miter Spikes

Three.js fat lines are rendered as camera-facing instanced geometry. At each vertex where two segments meet, the vertex shader computes the intersection of the two offset segment edges (a miter joint). When the angle between two segments becomes very sharp, the intersection point moves exponentially farther away from the actual corner vertex. Without a hard clamp or bevel fallback, this produces long, needle-like spikes that cut across the scene.

Technique 1: Geometry-Level Corner Beveling

The most reliable way to avoid extreme miters without editing the core library is to preprocess the path points before passing them to LineGeometry.setPositions().

When iterating through path vertices, calculate the interior angle between incoming and outgoing direction vectors. If the angle drops below a threshold (for example, less than 45 to 60 degrees), replace the single sharp corner vertex with two offset vertices pulled slightly back along the adjacent segments. This artificially creates a bevel joint, preventing the vertex shader from encountering acute angles that cause severe expansion.

function bevelSharpAngles(points, minAngleDeg = 45, bevelDistance = 0.5) {
  const minAngleRad = (minAngleDeg * Math.PI) / 180;
  const result = [];

  for (let i = 0; i < points.length; i++) {
    const curr = points[i];
    const prev = points[i - 1];
    const next = points[i + 1];

    if (!prev || !next) {
      result.push(curr);
      continue;
    }

    const v1 = new THREE.Vector3().subVectors(prev, curr).normalize();
    const v2 = new THREE.Vector3().subVectors(next, curr).normalize();
    const angle = v1.angleTo(v2);

    if (angle < minAngleRad) {
      result.push(curr.clone().addScaledVector(v1, bevelDistance));
      result.push(curr.clone().addScaledVector(v2, bevelDistance));
    } else {
      result.push(curr);
    }
  }

  return result;
}

Technique 2: Adding Joint Caps Using Instanced Points

Another common approach to eliminate miter calculation issues is to turn off or ignore sharp join calculation and place overlapping screen-space round caps at each vertex.

You can overlay a THREE.Points object using the identical vertex coordinates as your Line2. By configuring a point cloud with a circular texture and setting sizeAttenuation: false with a size equivalent to your LineMaterial.linewidth, every vertex receives a round join that covers gaps or hides truncated corner geometry. Ensure depth test and render order settings are identical to prevent Z-fighting between the lines and the caps.

Technique 3: Modifying LineMaterial via onBeforeCompile

The standard LineMaterial computes join positions in line.vert.glsl. By injecting code via Material.onBeforeCompile, you can limit the maximum length of the miter vector.

lineMaterial.onBeforeCompile = (shader) => {
  shader.vertexShader = shader.vertexShader.replace(
    '// original miter calculation',
    `
    // Clamping the miter length to prevent extreme protrusion
    float miterLength = length(miter);
    float maxMiter = 2.0; // Set limit relative to line width
    if (miterLength > maxMiter) {
      miter = (miter / miterLength) * maxMiter;
    }
    `
  );
};

This ensures that even when paths double back on themselves at near-zero-degree angles, the expansion vector is clamped to a fixed factor of the line width, turning sharp spikes into controlled trapezoidal joins.

Choosing the Right Approach

  • Use geometry-level beveling if you need stable, uniform rendering across all platforms and standard materials without shader maintenance.
  • Use joint caps if you want rounded corners on flat, planar drawings without complicating the geometry path coordinates.
  • Use shader clamping if you have dynamic, constantly animating paths where modifying vertex buffers per frame would incur too much CPU overhead.
