Three.js DataUtils Float to Half-Float Conversion

In Three.js applications, rendering performance and memory efficiency often depend on how vertex data and textures are structured before reaching the GPU. The DataUtils module plays a critical role in memory optimization by providing direct utility functions—most notably DataUtils.toHalfFloat()—to convert standard 32-bit single-precision floats into 16-bit half-precision floating-point numbers. This article explains the technical role of DataUtils during this conversion, how it cuts memory consumption in half, and where this optimization is best applied in WebGL workflows.

The Function of DataUtils in Half-Float Conversion

Standard JavaScript numbers and WebGL buffer attributes generally default to 32-bit precision (Float32Array). While 32-bit floats provide high precision, they consume 4 bytes of memory per value. The DataUtils module provides mathematical conversion methods that translate these values into the IEEE 754 half-precision binary16 format:

  • DataUtils.toHalfFloat( val ): Takes a standard number (or single-precision float) and converts it to a 16-bit integer bit-pattern representing the half-float value.
  • DataUtils.fromHalfFloat( val ): Reverses the process, converting a 16-bit representation back to a standard floating-point number.

Because standard JavaScript lacks native 16-bit float primitives in typed arrays across all target environments, Three.js uses a Uint16Array to store the packed binary representations generated by DataUtils.toHalfFloat().

Performance and Memory Optimization Benefits

Converting attributes and texture data to half-floats yields several tangible optimizations in WebGL pipelines:

  1. Reduced Memory Bandwidth: Storing values as half-floats cuts memory usage by 50% compared to full 32-bit floats (2 bytes instead of 4 bytes per component). This significantly reduces the overhead of CPU-to-GPU data transfers.
  2. Improved GPU Cache Utilization: Smaller data sizes mean more vertex data and texels fit into the GPU's onboard cache simultaneously, decreasing texture fetch latency and memory stalls during shader execution.
  3. Optimized Texture Buffers: When generating dynamic textures, floating-point render targets, or HDR environment maps, using THREE.HalfFloatType with data processed through DataUtils preserves high dynamic range while consuming half the VRAM of standard float textures.

Practical Applications in Three.js

The conversion provided by DataUtils is primarily used in two areas:

  • Custom Buffer Attributes: Mesh data that does not require extreme numerical precision—such as UV coordinates, vertex colors, or localized normals—can be converted using DataUtils.toHalfFloat() and placed into a Uint16Array. When bound to geometry via THREE.Float16BufferAttribute, the WebGL implementation decodes these values directly into floating-point numbers in the vertex shader.
  • HDR Data Textures: High-dynamic-range pipelines often use half-float data to store luminance values beyond the standard [0.0, 1.0] range without incurring the full memory penalty of 32-bit floating-point textures.

Precision Considerations

While DataUtils enables significant optimization, half-floats feature a 5-bit exponent and a 10-bit mantissa (fraction), compared to the 8-bit exponent and 23-bit mantissa of 32-bit floats. Consequently, half-floats have a maximum value of 65,504 and lower precision. Developers should avoid half-float conversions for world-space positions in expansive scenes or coordinates requiring extreme precision, as doing so may cause visual artifacts such as spatial jitter or color banding.
