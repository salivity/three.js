Update SkinnedMesh Geometry Dynamically in Three.js

Updating the geometry of a SkinnedMesh dynamically in Three.js requires careful management of vertex attributes, bone matrices, and skinning data. This article explains how to modify geometry coordinates in-place without corrupting the skeletal bindings, how to handle structural topology changes that alter vertex counts, and how to properly recalculate normals and bounding volumes to ensure seamless skeletal animation.

Modifying Existing Vertices In-Place

If the vertex count and topology remain unchanged (such as sculpting, morphing, or applying displacement offsets), the connection between vertices, bones, and skin weights remains valid. You only need to update the position attribute buffer directly.

const positionAttribute = skinnedMesh.geometry.attributes.position;

for (let i = 0; i < positionAttribute.count; i++) {
    // Read original vertex position
    let x = positionAttribute.getX(i);
    let y = positionAttribute.getY(i);
    let z = positionAttribute.getZ(i);

    // Apply your dynamic modifications
    y += Math.sin(x) * 0.1;

    // Write back to buffer
    positionAttribute.setXYZ(i, x, y, z);
}

// Flag the buffer for a GPU upload
positionAttribute.needsUpdate = true;

// Recalculate normals and bounding volumes
skinnedMesh.geometry.computeVertexNormals();
skinnedMesh.geometry.computeBoundingBox();
skinnedMesh.geometry.computeBoundingSphere();

Because skinIndex and skinWeight buffer attributes map directly to vertex indices, preserving the index count prevents any skeletal desynchronization.

Changing Geometry Topology or Vertex Count

If your dynamic update adds, removes, or rebuilds vertices, the standard vertex-to-weight mapping is destroyed. In Three.js, every vertex requires four bone indices (skinIndex) and four bone weights (skinWeight).

When supplying a completely new BufferGeometry:

  1. Construct Matching Attribute Buffers: Ensure your new geometry has both skinIndex and skinWeight attributes initialized with four components per vertex.
  2. Transfer or Calculate Weights: For newly generated vertices, calculate weights by interpolating the weights of adjacent original vertices (e.g., using barycentric coordinates) or by finding the nearest neighbor on the original surface.
const vertexCount = newPositions.length / 3;

const skinIndices = new Uint16Array(vertexCount * 4);
const skinWeights = new Float32Array(vertexCount * 4);

// Populate skinIndices and skinWeights corresponding to each new vertex
populateSkinData(skinIndices, skinWeights);

newGeometry.setAttribute('position', new THREE.BufferAttribute(newPositions, 3));
newGeometry.setAttribute('skinIndex', new THREE.Uint16BufferAttribute(skinIndices, 4));
newGeometry.setAttribute('skinWeight', new THREE.Float32BufferAttribute(skinWeights, 4));

// Assign new geometry to the existing mesh
skinnedMesh.geometry.dispose();
skinnedMesh.geometry = newGeometry;

Weights for each vertex must sum to 1.0. Normalizing values avoids unnatural pinching or mesh tearing during bone movement.

Preserving the Bind Pose

A common issue when swapping or updating geometries on a SkinnedMesh is visual collapse caused by mismatched bind matrices. A SkinnedMesh uses bindMatrix and bindMatrixInverse to record the transformation of the mesh relative to its bones at the moment of binding.

If the base transformation of the new geometry differs from the original rest pose, you must re-bind the skeleton:

// Ensure skeleton inverses are up to date
skinnedMesh.skeleton.calculateInverses();

// Re-bind using the current skeleton and mesh world matrix
skinnedMesh.bind(skinnedMesh.skeleton, skinnedMesh.matrixWorld);

If the new geometry is generated directly in the mesh's local rest coordinate system, manual re-binding is unnecessary; retaining the original skeleton reference on the mesh is sufficient.

Recalculating Bounds for Frustum Culling

Three.js relies on the bounding sphere and bounding box for view frustum culling. Animated and dynamically modified geometries can easily step outside stale bounding volumes, causing the mesh to disappear unexpectedly.

After every geometry modification:

skinnedMesh.geometry.computeBoundingSphere();
skinnedMesh.geometry.computeBoundingBox();

If the mesh deforms heavily through bone animation after updating, expand the bounding sphere radius manually or set skinnedMesh.frustumCulled = false to prevent culling issues entirely.
