Setup Three.js WebXR local-floor for Seated VR

This article provides a direct guide on configuring the WebXRManager in Three.js to request a local-floor reference space, specifically tailored for seated virtual reality experiences. You will learn the necessary renderer configurations, how to set the reference space type, and how to properly adjust your scene's camera rig to align real-world seating with your virtual environment.

Enabling WebXR and Requesting local-floor

By default, Three.js attempts to negotiate a stable reference space when entering an immersive session. To explicitly require local-floor, configure the WebGLRenderer instance's xr property (WebXRManager) using setReferenceSpaceType.

import * as THREE from 'three';
import { VRButton } from 'three/addons/webxr/VRButton.js';

// 1. Initialize renderer
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// 2. Enable WebXR
renderer.xr.enabled = true;

// 3. Explicitly request local-floor
renderer.xr.setReferenceSpaceType('local-floor');

// 4. Attach the entry button
document.body.appendChild(VRButton.createButton(renderer));

Why Use local-floor for Seated Experiences?

A local reference space places the tracking origin at the headset's initial position upon session start, which can cause inconsistent eye-level heights if the user shifts or starts while slouching.

In contrast, local-floor establishes the tracking origin (\(Y = 0\)) at the physical floor directly below the user. This ensures:

  • The user's real-world seated height is respected naturally.
  • Virtual chairs, cockpits, or desks align correctly with the physical floor.
  • Head tracking accurately maps vertical posture changes.

Setting Up a Camera Rig for Seated Navigation

Because WebXRManager overrides the camera object's position directly using headset telemetry, you must place the camera inside an empty THREE.Group (often called a camera rig) to move or orient the user within the virtual world.

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);

// Create the rig
const userRig = new THREE.Group();
userRig.add(camera);
scene.add(userRig);

// Position the rig relative to your virtual scene (e.g., placing the user inside a vehicle)
userRig.position.set(0, 0, 0); 
userRig.rotation.y = 0;

With local-floor active, keep userRig.position.y at the virtual floor height (\(Y = 0\)). The headset's position relative to the physical floor will place the camera at the user's natural sitting eye level.

Handling Fallbacks

If a headset does not support physical floor detection, requesting local-floor will reject the session or fail back depending on the browser implementation. You can catch session errors or verify the active reference space by listening to session start events:

renderer.xr.addEventListener('sessionstart', () => {
    const baseReferenceSpace = renderer.xr.getReferenceSpace();
    console.log('Active Reference Space:', baseReferenceSpace);
});

Animation Loop

Always drive the rendering loop through setAnimationLoop instead of requestAnimationFrame to synchronize with the headset's native refresh rate:

renderer.setAnimationLoop(() => {
    renderer.render(scene, camera);
});
