Get GPU Vendor Information in Three.js

This guide explains how to extract unmasked GPU vendor and renderer details in Three.js for hardware-specific debugging. While standard WebGL queries often obfuscate hardware details for privacy reasons, utilizing WebGL context methods and debugging extensions allows developers to identify whether a client is running on dedicated or integrated graphics, inspect driver levels, and diagnose device-specific rendering bugs.

Accessing the WebGL Context

Three.js abstracts low-level WebGL interactions through its WebGLRenderer. To query hardware data, you must first access the underlying rendering context:

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer();
const gl = renderer.getContext();

Standard calls to gl.getParameter(gl.VENDOR) and gl.getParameter(gl.RENDERER) typically return generic identifiers like "WebKit" or "Google Inc." rather than hardware specifics due to browser fingerprinting defenses.

Querying Unmasked Hardware via Debug Extensions

To obtain accurate GPU vendor information, request the WEBGL_debug_renderer_info extension directly from the context. This extension provides two constants: UNMASKED_VENDOR_WEBGL and UNMASKED_RENDERER_WEBGL.

Here is a practical utility script to retrieve this data safely:

function getGPUDetails(renderer) {
  const gl = renderer.getContext();
  
  // Attempt to acquire the debug renderer extension
  const debugInfo = gl.getExtension('WEBGL_debug_renderer_info');

  if (!debugInfo) {
    return {
      vendor: gl.getParameter(gl.VENDOR),
      renderer: gl.getParameter(gl.RENDERER),
      isMasked: true
    };
  }

  return {
    vendor: gl.getParameter(debugInfo.UNMASKED_VENDOR_WEBGL),
    renderer: gl.getParameter(debugInfo.UNMASKED_RENDERER_WEBGL),
    isMasked: false
  };
}

// Example usage:
const gpuInfo = getGPUDetails(renderer);
console.log(`GPU Vendor: ${gpuInfo.vendor}`);
console.log(`GPU Model: ${gpuInfo.renderer}`);

Parsing Vendor Output for Debugging

The returned vendor string typically identifies companies such as NVIDIA, AMD, Intel, Apple, or Qualcomm, while the renderer string contains the specific chipset model (for example, "NVIDIA GeForce RTX 3080 Direct3D11 vs_5_0 ps_5_0" or "Apple M2").

When debugging in Three.js, this information is particularly useful for:

  • Identifying Dual-GPU Fallbacks: Confirming whether a laptop is defaulting to an integrated Intel GPU rather than a high-performance discrete NVIDIA/AMD GPU.
  • Conditional Shader Precision: Downgrading post-processing or shadow map resolutions on low-power mobile chipsets (such as ARM Mali or Qualcomm Adreno).
  • Targeting Driver Quirks: Applying workarounds for known floating-point precision bugs or texture-banding issues present in specific driver releases.

Important Limitations

  • Privacy Controls: Certain browsers (such as Firefox with strict privacy settings enabled or Safari on newer iOS versions) may intentionally block WEBGL_debug_renderer_info or return generic values regardless of the extension status. Always provide fallbacks if the returned values are undefined or generic.
  • WebGL 2 and WebGPU: In WebGPU implementations, hardware identification relies on GPUAdapterInfo via requestAdapterInfo(), as the WebGL extension model does not apply.
