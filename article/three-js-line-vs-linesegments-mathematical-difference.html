Three.js Line vs LineSegments: Mathematical Difference

In Three.js, rendering linear geometry relies on standard WebGL drawing primitives that dictate how the graphics pipeline interprets an ordered buffer of vertices. While both THREE.Line and THREE.LineSegments draw lines from coordinate buffers, they differ fundamentally in their primitive assembly topology, edge-count formulas, and vertex indexing logic. Understanding this mathematical distinction clarifies why identical geometry buffers produce vastly different visual results depending on the chosen class.

WebGL Primitive Assembly

Under the hood, Three.js maps these two objects directly to distinct WebGL primitive modes passed to gl.drawArrays or gl.drawElements:

  • THREE.Line compiles to gl.LINE_STRIP.
  • THREE.LineSegments compiles to gl.LINES.

The GPU rasterizer interprets the sequence of vertex indices differently based on these modes.

Index Mapping and Edge Formulation

Let the ordered set of vertices defined in a BufferGeometry be represented as:

\[V = \{v_0, v_1, v_2, \dots, v_{n-1}\}\]

where \(n\) is the total number of vertices in the buffer.

1. Continuous Line (THREE.Line)

For a continuous line rendered via gl.LINE_STRIP, each subsequent vertex connects to the previous one. The set of rendered edges \(E_{\text{line}}\) is defined as:

\[E_{\text{line}} = \{ (v_i, v_{i+1}) \mid 0 \le i < n - 1 \}\]

  • Total Edges Produced: \(|E_{\text{line}}| = n - 1\)
  • Vertex Degree: The boundary vertices \(v_0\) and \(v_{n-1}\) have a degree of 1, while every interior vertex \(v_i\) (where \(0 < i < n - 1\)) has a degree of 2.
  • Vertex Reuse: Vertices are implicitly shared across adjacent segments without requiring explicit duplicate index definitions.

2. Disjoint Segments (THREE.LineSegments)

For disconnected segments rendered via gl.LINES, the rasterizer groups vertices into disjoint, non-overlapping pairs. The set of rendered edges \(E_{\text{segments}}\) is defined as:

\[E_{\text{segments}} = \{ (v_{2k}, v_{2k+1}) \mid 0 \le k < \lfloor n/2 \rfloor \}\]

  • Total Edges Produced: \(|E_{\text{segments}}| = \lfloor n/2 \rfloor\)
  • Vertex Degree: Every vertex belongs to at most one edge, meaning the degree of any vertex in the topology is at most 1.
  • Odd Vertex Behavior: If \(n\) is odd, the final vertex \(v_{n-1}\) is ignored during the primitive assembly stage.

Mathematical Storage and Memory Trade-Off

To draw a connected path consisting of \(m\) segments:

  • Using THREE.Line, the geometry requires \(m + 1\) vertices in memory.
  • Using THREE.LineSegments, the same connected path requires explicit endpoint duplication, resulting in \(2m\) vertices:

\[(v_0, v_1), (v_1, v_2), (v_2, v_3), \dots, (v_{m-1}, v_m)\]

Conversely, representing \(m\) completely disconnected line segments using THREE.Line would require introducing degenerate (zero-length) or transparent segments, whereas THREE.LineSegments handles independent pairs natively with exactly \(2m\) vertices.
