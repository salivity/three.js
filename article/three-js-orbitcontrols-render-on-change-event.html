Three.js OrbitControls Render on Change Event

Standard Three.js applications typically run an infinite requestAnimationFrame loop, which needlessly consumes GPU and CPU resources when displaying static scenes. This article explains how to implement on-demand rendering by intercepting the change event dispatched by OrbitControls. By listening to this specific event, the WebGL renderer executes only when user input alters the camera’s position or orientation, delivering optimal application performance and battery efficiency.

Disabling the Continuous Loop

To render strictly on demand, eliminate the typical continuous requestAnimationFrame loop. Instead, encapsulate the rendering logic into a standalone function:

function render() {
    renderer.render(scene, camera);
}

Listening to the Change Event

OrbitControls fires a change event whenever the user pans, zooms, or rotates the camera. Attach a listener directly to the controls instance to invoke your render function whenever a transformation occurs:

import * as THREE from 'three';
import { OrbitControls } from 'three/examples/jsm/controls/OrbitControls.js';

// Setup Scene, Camera, and Renderer
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
camera.position.set(0, 2, 5);

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// Initialize OrbitControls
const controls = new OrbitControls(camera, renderer.domElement);

// Intercept movement and trigger a render
controls.addEventListener('change', render);

// Perform an initial render to display the scene on load
render();

Handling Window Resizing

Because the continuous loop is removed, any operation that updates projection matrices must manually invoke render(). Ensure window resize events update the camera aspect ratio and trigger a new frame:

window.addEventListener('resize', () => {
    camera.aspect = window.innerWidth / window.innerHeight;
    camera.updateProjectionMatrix();
    renderer.setSize(window.innerWidth, window.innerHeight);
    render();
});

Considerations for Damping (Inertia)

If you enable smooth motion using controls.enableDamping = true, the change event alone is insufficient because damping requires controls.update() to be called continuously until momentum ceases.

If damping is strictly required while still avoiding an indefinite render loop, use a conditional loop that runs only while the user interacts or while damping stabilizes:

controls.enableDamping = true;

let isRendering = false;

function animate() {
    if (!isRendering) return;

    requestAnimationFrame(animate);

    // controls.update() returns true if the camera is still moving toward target
    const dampingActive = controls.update();

    render();

    // Stop the loop once momentum has settled
    if (!dampingActive) {
        isRendering = false;
    }
}

// Start rendering loop when user interacts
controls.addEventListener('start', () => {
    if (!isRendering) {
        isRendering = true;
        animate();
    }
});

For applications that do not require inertia, keep controls.enableDamping = false (default) and rely entirely on controls.addEventListener('change', render).
