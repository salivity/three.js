Why flipY is True for Images but False for glTF in Three.js

In Three.js, the flipY property determines whether a texture is vertically inverted upon being uploaded to the GPU. Standard image textures default to flipY = true to bridge the gap between traditional HTML/2D image coordinates (origin at top-left) and WebGL's native texture coordinates (origin at bottom-left). Conversely, textures loaded via glTF models default to flipY = false because the glTF specification explicitly standardizes texture coordinates with a top-left origin, matching modern graphics APIs and eliminating the need for runtime inversion.

The WebGL vs. Image Coordinate Mismatch

Standard 2D raster formats (PNG, JPEG) and web APIs (HTML Canvas, DOM images) place the coordinate origin (0, 0) at the top-left corner, with the Y-axis increasing downward.

OpenGL and WebGL, by default, expect texture coordinates (UVs) to originate at the bottom-left corner (0, 0), with the V-axis increasing upward. When an image is directly mapped onto a 3D surface using traditional OpenGL UV mapping, the image appears upside down.

To make loading standard textures intuitive for web developers, Three.js defaults Texture.flipY to true. Under the hood, this triggers the WebGL pixel storage parameter gl.UNPACK_FLIP_Y_WEBGL = true, inverting the pixel rows vertically during texture upload so the image displays right-side up on standard Three.js geometries.

The glTF Standard Specification

The glTF (GL Transmission Format) standard, maintained by the Khronos Group, intentionally departed from legacy OpenGL conventions to achieve broad compatibility with modern graphics APIs such as Vulkan, Metal, and DirectX.

Under the glTF specification, texture coordinates are explicitly defined with (0, 0) at the top-left corner. 3D authoring tools (such as Blender or Maya) export glTF models with UV coordinates already calibrated for this top-left origin.

If Three.js were to flip a glTF texture vertically (flipY = true), the texture coordinates authored in the 3D tool would no longer align with the image data, resulting in inverted textures on the model. To adhere to the specification, GLTFLoader explicitly overrides the Three.js default and sets texture.flipY = false.

Performance and Modern Browser Pipelines

Setting flipY = false also provides technical and performance benefits:

  • ImageBitmap Compatibility: Modern Three.js loaders utilize createImageBitmap() to decode image data asynchronously off the main thread. While createImageBitmap() supports vertical flipping via options, avoiding the flip operation reduces CPU processing overhead and memory copies.
  • Render Targets and Compressed Textures: Compressed texture formats (such as KTX2/Basis Universal) and certain framebuffers cannot easily be flipped during upload via gl.UNPACK_FLIP_Y_WEBGL. Standardizing on flipY = false ensures consistency across both uncompressed textures and modern GPU-compressed asset pipelines.
