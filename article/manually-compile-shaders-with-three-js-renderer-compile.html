Manually Compile Shaders with Three.js renderer.compile

In Three.js, shaders are compiled lazily by default, meaning compilation occurs on the very first frame an object enters the camera view. This frequently results in noticeable frame drops or stuttering during gameplay or interactive experiences. This article explains how to use the WebGLRenderer.compile() method to manually pre-compile all materials and shaders in your scene before rendering anything to the screen.

The Problem with Lazy Compilation

When a mesh enters the rendering pipeline, Three.js must build and link the corresponding WebGL shader program based on the material properties, lights, shadows, and fog present in the scene. Because GPU shader compilation is computationally heavy and blocks the main thread, doing this dynamically causes noticeable latency spikes (commonly known as "jank").

Using renderer.compile

The renderer.compile() method forces Three.js to construct and link the underlying WebGL programs for all objects within a given hierarchy immediately, without drawing pixels to the canvas.

To use it, pass your scene (or any Object3D) along with the camera you intend to use for viewing:

import * as THREE from 'three';

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
const renderer = new THREE.WebGLRenderer({ antialias: true });

// Setup geometry, material, and lights
const geometry = new THREE.TorusKnotGeometry(10, 3, 100, 16);
const material = new THREE.MeshStandardMaterial({ color: 0xff6347, roughness: 0.2 });
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

const light = new THREE.DirectionalLight(0xffffff, 1);
light.position.set(5, 10, 7);
scene.add(light);

// Pre-compile the scene before starting the render loop
renderer.compile(scene, camera);

// Start the render loop afterward
function animate() {
  requestAnimationFrame(animate);
  renderer.render(scene, camera);
}
animate();

Compiling Specific Objects

You do not have to pass the entire active scene. If you are loading an asset in the background that you want to prepare before adding it to your main scene, you can compile that specific object tree using a temporary scene or by passing the object directly:

const assetGroup = new THREE.Group();
// ...populate assetGroup with loaded meshes...

// Pre-compile only this group
renderer.compile(assetGroup, camera);

// Add to the main scene when ready to display
scene.add(assetGroup);

Non-Blocking Compilation with compileAsync

In modern versions of Three.js (r154+), you can also use renderer.compileAsync(). This method takes advantage of the KHR_parallel_shader_compile WebGL extension if available on the user's hardware, compiling shaders asynchronously in the background so the main execution thread does not freeze:

await renderer.compileAsync(scene, camera);

Important Considerations

  1. Scene Context Matters: Shader generation in Three.js depends heavily on lighting, shadows, tone mapping, and fog configurations. If you compile a material with a scene that contains no lights, and later render it with multiple directional lights and shadows enabled, Three.js will be forced to recompile the shader to incorporate the lighting calculations.
  2. Camera Settings: Always use the same camera (or identical camera configuration) for compilation that will be used for rendering, as projection characteristics can influence the generated shader code.
  3. Execution Placement: Call renderer.compile() during your initial loading phase or right after dynamically instantiating complex materials to ensure smooth playback once user interaction begins.
