Dynamic Resolution Scaling in Three.js VR

Dynamic resolution scaling is a crucial optimization technique for Virtual Reality (VR) applications to maintain a steady target frame rate—such as 72Hz, 90Hz, or 120Hz—by adjusting rendering load on the fly. In Three.js, you can manage the rendering resolution of your WebXR experience using renderer.xr.setFramebufferScaleFactor(). This guide explains how framebuffer scaling impacts GPU performance, how to monitor frame performance in real time, and how to implement an adaptive resolution system to prevent dropped frames and motion sickness.

Understanding setFramebufferScaleFactor

In Three.js, renderer.xr.setFramebufferScaleFactor(factor) controls the size of the WebXR render buffer relative to the native display resolution of the VR headset:

  • A factor of 1.0 renders at the native recommended resolution of the headset.
  • A factor of 0.8 reduces the resolution along each axis to 80%, reducing total fragment shading load to approximately 64% of the original.
  • A factor greater than 1.0 (supersampling) sharpens visuals at the cost of significant GPU overhead.

Because lower resolutions directly reduce the number of pixels processed by fragment shaders, dropping the scale factor is the fastest way to relieve GPU bottlenecks.

WebXR Presentation Limitations

The standard WebXR XRWebGLLayer creates its framebuffer during session initialization. In Three.js, calling renderer.xr.setFramebufferScaleFactor() during an active presentation will log a warning because the WebGL framebuffer dimensions cannot be resized arbitrarily mid-session without reinitializing the layer.

To implement runtime scaling, you have two primary options:

  1. Quality Tiering (Pre-Session or Scene Transitions): Adjust setFramebufferScaleFactor before initiating the WebXR session or upon reloading scene tiers.
  2. Per-Frame Dynamic Viewport Scaling (requestViewportScale): Keep the base framebuffer static via Three.js, but instruct the underlying WebXR API to reduce the active viewport scale per frame when performance dips.

Step-by-Step Implementation

1. Configure the Baseline Scale

Set a sensible default before the user enters VR:

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.xr.enabled = true;

// Set default rendering scale before the session starts
renderer.xr.setFramebufferScaleFactor(1.0);

2. Monitor Frame Times

To decide whether to scale resolution, track the rolling average of frame render times using renderer.setAnimationLoop. If frame duration exceeds the refresh interval threshold (e.g., ~11.1ms for 90 FPS), you scale down.

let lastTime = performance.now();
let frameDurations = [];
const SAMPLES = 30;
const TARGET_FRAME_TIME = 11.1; // 90 Hz in milliseconds
const DROP_THRESHOLD = 12.0;    // Trigger downscale if consistently above
const RECOVER_THRESHOLD = 9.5;  // Trigger upscale if consistently below

function getAverageFrameTime(newDuration) {
  frameDurations.push(newDuration);
  if (frameDurations.length > SAMPLES) {
    frameDurations.shift();
  }
  const sum = frameDurations.reduce((a, b) => a + b, 0);
  return sum / frameDurations.length;
}

3. Dynamically Adjusting Viewport Scale in WebXR

To change the resolution dynamically during a running session without re-creating the layer, use requestViewportScale() on each active XRView via the WebXR frame:

let currentScale = 1.0;
const MIN_SCALE = 0.6;
const MAX_SCALE = 1.2;
const SCALE_STEP = 0.05;

renderer.setAnimationLoop((timestamp, xrFrame) => {
  const now = performance.now();
  const delta = now - lastTime;
  lastTime = now;

  const avgDelta = getAverageFrameTime(delta);

  // Dynamic performance evaluation
  if (avgDelta > DROP_THRESHOLD && currentScale > MIN_SCALE) {
    currentScale = Math.max(MIN_SCALE, currentScale - SCALE_STEP);
  } else if (avgDelta < RECOVER_THRESHOLD && currentScale < MAX_SCALE) {
    currentScale = Math.min(MAX_SCALE, currentScale + SCALE_STEP);
  }

  // Apply resolution scale directly to WebXR views if available
  if (xrFrame && xrFrame.session) {
    const session = xrFrame.session;
    const baseLayer = session.renderState.baseLayer;

    // Check for standard WebXR Dynamic Viewport Scaling support
    const referenceSpace = renderer.xr.getReferenceSpace();
    const pose = xrFrame.getViewerPose(referenceSpace);

    if (pose) {
      for (const view of pose.views) {
        if (typeof view.requestViewportScale === 'function') {
          view.requestViewportScale(currentScale);
        }
      }
    }
  }

  renderer.render(scene, camera);
});

Best Practices for VR Scaling

  • Clamp Minimum Values: Do not allow the scale factor to drop below 0.5 to 0.6. Overly blurry visuals cause eye strain and motion sickness.
  • Add Hysteresis: Ensure the recovery threshold (RECOVER_THRESHOLD) is sufficiently lower than the drop threshold (DROP_THRESHOLD) to prevent rapid oscillations between higher and lower resolutions.
  • Combine with Fixed Foveated Rendering: If targeting standalone headsets like Meta Quest, enable foveated rendering (renderer.xr.setFoveation(1.0)) alongside framebuffer scaling for maximum GPU efficiency.
