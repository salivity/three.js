How to Use onBeforeRender in Three.js for Meshes

This article explains how to intercept and customize the WebGL rendering pipeline for an individual Mesh using the onBeforeRender callback in Three.js. By hooking into this method, you can dynamically update shader uniforms, manipulate WebGL state, swap material properties, or trigger custom operations immediately before the object is drawn to the screen.

Understanding onBeforeRender

In Three.js, every Object3D (and by extension, Mesh) possesses an onBeforeRender callback. The renderer executes this function right after frustum culling and sorting, but immediately before issuing the WebGL draw calls for that specific object.

The callback provides direct access to the active rendering context through the following signature:

mesh.onBeforeRender = function (renderer, scene, camera, geometry, material, group) {
  // Custom execution logic
};

Key Parameters

  • renderer: The instance of WebGLRenderer currently processing the scene.
  • scene: The root scene or parent graph containing the object.
  • camera: The active camera rendering the current view.
  • geometry: The BufferGeometry instance assigned to the mesh.
  • material: The active Material being used to render the mesh.
  • group: The geometry group being processed (relevant if using multi-materials).

Common Implementation Patterns

1. Dynamically Updating Shader Uniforms

The most common use case is updating uniforms that depend on the camera position, object transformation, or high-precision time right before rendering:

const material = new THREE.ShaderMaterial({
  uniforms: {
    uTime: { value: 0 },
    uCameraDistance: { value: 0 }
  },
  vertexShader: `...`,
  fragmentShader: `...`
});

const mesh = new THREE.Mesh(geometry, material);

mesh.onBeforeRender = function (renderer, scene, camera) {
  // Update time-based uniform
  material.uniforms.uTime.value = performance.now() * 0.001;

  // Calculate distance to camera without polluting the global render loop
  const distance = mesh.position.distanceTo(camera.position);
  material.uniforms.uCameraDistance.value = distance;
};

2. Intercepting and Modifying WebGL States

You can use renderer.state within onBeforeRender to modify WebGL pipeline configurations, such as depth testing, blending, or stencil buffers, specifically for a single mesh:

mesh.onBeforeRender = function (renderer) {
  const gl = renderer.getContext();
  
  // Custom WebGL operations
  renderer.state.setDepthTest(false);
  gl.colorMask(true, false, false, true); // Render only to red and alpha channels
};

mesh.onAfterRender = function (renderer) {
  const gl = renderer.getContext();
  
  // Always revert global state changes in onAfterRender
  renderer.state.setDepthTest(true);
  gl.colorMask(true, true, true, true);
};

Best Practices and Performance Considerations

  • Avoid Allocations: onBeforeRender runs every frame for each instance of the mesh. Avoid creating new objects, vectors, or arrays inside this function to prevent triggering garbage collection spikes. Reuse existing instances via module or object-level caching.
  • Pair with onAfterRender: If you alter any low-level WebGL state on renderer or the underlying WebGLRenderingContext, you must implement onAfterRender to restore the state back to its default, preventing graphical bugs in subsequent draw calls.
  • Frustum Culling Awareness: If a mesh is culled out of the camera's view, onBeforeRender will not be called. If you need logic to run regardless of visibility, update the object in the main animation loop prior to renderer.render().
