Prevent Touch Scrolling on Three.js Canvas with CSS

When developing mobile-friendly 3D web applications with Three.js, interacting with the canvas via touch gestures often causes the surrounding webpage to scroll unintentionally. This article explains how to use the CSS touch-action property to cleanly and effectively disable the browser's default touch scrolling and panning behaviors on your Three.js canvas element, ensuring uninterrupted scene manipulation such as orbiting, rotating, and zooming.

The Problem with Default Touch Behavior

By default, mobile web browsers interpret dragging gestures (touchstart, touchmove) on a screen as navigational actions, such as scrolling vertically or pinch-to-zooming the viewport. When a user tries to interact with a 3D scene—such as rotating an object via OrbitControls—the browser prioritizes document scrolling over canvas interaction. This results in erratic scene movement or page scrolling instead of 3D navigation.

The Solution: touch-action: none

The modern, performant way to resolve this conflict is the CSS touch-action property. Setting touch-action: none informs the browser's compositor thread that all touch gestures on the element should be passed directly to your JavaScript application rather than handled by the browser's default gestures.

Method 1: Applying via CSS

If your Three.js canvas has an ID or class, or if it is the only canvas on the page, apply the rule directly in your stylesheet:

/* Apply to all canvas elements or a specific class/id */
canvas {
  touch-action: none;
}

If you assign a specific class to your renderer element:

.webgl-canvas {
  touch-action: none;
}

Method 2: Applying via JavaScript

You can also apply the style directly to the WebGLRenderer DOM element in your Three.js initialization script:

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer();
renderer.setSize(window.innerWidth, window.innerHeight);

// Prevent browser gestures on the canvas
renderer.domElement.style.touchAction = 'none';

document.body.appendChild(renderer.domElement);

Why Use touch-action Instead of preventDefault()?

Previously, developers relied on adding e.preventDefault() inside JavaScript touchstart or touchmove event listeners. However, modern browsers treat touch listeners as passive by default to ensure smooth scrolling performance. Calling preventDefault() inside a passive listener will fail and trigger console warnings unless { passive: false } is explicitly set.

Using CSS touch-action: none is superior because:

  • It eliminates the need for manual event cancellation in JavaScript.
  • It executes directly on the browser's compositor thread, preventing touch latency and UI stuttering.
  • It fully integrates with Three.js interaction libraries like OrbitControls, TrackballControls, and custom raycasting implementations.
