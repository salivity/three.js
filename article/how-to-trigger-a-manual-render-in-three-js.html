How to Trigger a Manual Render in Three.js

This article explains how to manually trigger a render cycle in Three.js without relying on an infinite requestAnimationFrame loop. By transitioning to on-demand rendering, you can drastically reduce GPU and CPU usage, extend mobile battery life, and improve application performance by only drawing frames when visual changes occur.

The Core Concept: Direct Render Calls

In a conventional Three.js application, the standard pattern involves an infinite loop that calls requestAnimationFrame() 60 or 120 times per second:

function animate() {
    requestAnimationFrame(animate);
    renderer.render(scene, camera);
}
animate();

To render manually, eliminate the recursive loop and define a standalone render function that explicitly calls renderer.render(scene, camera) only when invoked:

function render() {
    renderer.render(scene, camera);
}

Listening to Camera and Controls Changes

In static scenes or scenes where movement is driven purely by the user, attach your render function directly to interaction listeners.

If you use OrbitControls, listen to the 'change' event:

import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

const controls = new OrbitControls(camera, renderer.domElement);

// Re-render only when the user pans, rotates, or zooms
controls.addEventListener('change', render);

Handling Window Resizing

When the viewport changes dimensions, update the camera's aspect ratio, update the renderer's size, and invoke render() immediately:

window.addEventListener('resize', () => {
    camera.aspect = window.innerWidth / window.innerHeight;
    camera.updateProjectionMatrix();
    renderer.setSize(window.innerWidth, window.innerHeight);
    render();
});

Triggering Renders on Model or Material Updates

Any modification to meshes, materials, textures, or scene hierarchy requires an explicit call to render() after updating the relevant properties:

// Example: Updating an object's position on button click
button.addEventListener('click', () => {
    mesh.position.x += 1;
    render();
});

// Example: Rendering after an asynchronous texture or model load
textureLoader.load('texture.jpg', (texture) => {
    material.map = texture;
    material.needsUpdate = true;
    render();
});

Preventing Redundant Renders with requestAnimationFrame Batching

If multiple events occur simultaneously (such as rapid input events, data streaming, and window resizing), invoking render() multiple times in the same frame leads to unnecessary draw calls. You can batch these requests into a single update per display refresh using a flag:

let renderRequested = false;

function render() {
    renderRequested = false;
    renderer.render(scene, camera);
}

function requestRenderIfNotRequested() {
    if (!renderRequested) {
        renderRequested = true;
        requestAnimationFrame(render);
    }
}

// Attach the batching function to events
controls.addEventListener('change', requestRenderIfNotRequested);
window.addEventListener('resize', requestRenderIfNotRequested);

This pattern provides the best balance: rendering only executes when changes happen, and concurrent updates within a single display refresh are merged into one render cycle.
