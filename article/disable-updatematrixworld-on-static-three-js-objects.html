Disable updateMatrixWorld on Static Three.js Objects

This article explains how to stop Three.js from recursively computing transformation matrices for large, non-moving branches of a scene graph. By default, the render loop traverses every descendant node to recalculate its world matrix, causing measurable CPU overhead in dense scenes. You will learn the most effective techniques to pause this traversal, how to ensure the initial transform is properly applied before pausing, and how to safely resume or force updates when needed.

The Problem with Default Matrix Traversal

Every frame, Three.js calls scene.updateMatrixWorld(). This function recursively walks down every node in the scene graph. Even if a mesh does not change position, rotation, or scale, Three.js still checks properties and traverses its children. For static branches containing thousands of objects—such as architectural CAD data, city blocks, or dense foliage—this recursive check creates a significant CPU bottleneck.

Method 1: Override the updateMatrixWorld Method

The fastest and most direct way to halt traversal down an entire static subtree is to overwrite the root node's updateMatrixWorld function with an empty function. This prevents Three.js from stepping into the branch entirely.

1. Compute the Initial Transformation

Before muting the method, ensure the branch and its descendants calculate their initial world matrices at least once:

// Ensure local and world transforms are up to date
staticBranchRoot.updateMatrix();
staticBranchRoot.updateMatrixWorld(true);

2. Disable Recursion

Replace the method on the parent container:

// Pause all recursive matrix checks for this branch
staticBranchRoot.updateMatrixWorld = function() {};

Because the render loop calls updateMatrixWorld on the root of this branch and encounters an empty function, traversal stops immediately, bypassing all nested children.

3. Re-enabling or Forcing an Update

If objects within the branch move or are rearranged later, restore the prototype method or manually invoke the prototype function:

// Force a one-time update
THREE.Object3D.prototype.updateMatrixWorld.call(staticBranchRoot, true);

// Or restore automatic updates permanently
staticBranchRoot.updateMatrixWorld = THREE.Object3D.prototype.updateMatrixWorld;

Method 2: Use matrixWorldAutoUpdate (Three.js r144+)

Modern versions of Three.js include a built-in property designed to stop world matrix calculations without method overriding: matrixWorldAutoUpdate.

When matrixWorldAutoUpdate is set to false, Three.js avoids recalculating the object's world matrix unless a forced update propagates down from an ancestor.

// Recursively disable auto updates on the static branch
staticBranchRoot.traverse((child) => {
    child.matrixAutoUpdate = false;
    child.matrixWorldAutoUpdate = false;
});

// Calculate the world matrices once
staticBranchRoot.updateMatrixWorld(true);

Important Distinction

Setting matrixWorldAutoUpdate = false on only the parent does not always prevent Three.js from traversing nested children if child objects still have matrixWorldAutoUpdate = true. Therefore, you must traverse the branch once to set both matrixAutoUpdate = false and matrixWorldAutoUpdate = false on every descendant.

Which Approach to Choose?

  • Use Method 1 (Method Override) if you have an extremely deep hierarchy (thousands of nodes) and want zero function-call overhead for the entire branch.
  • Use Method 2 (matrixWorldAutoUpdate = false) if you want to adhere to the idiomatic Three.js API without monkey-patching methods on runtime objects.
