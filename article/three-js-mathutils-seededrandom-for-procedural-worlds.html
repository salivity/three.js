Three.js MathUtils.seededRandom for Procedural Worlds

Procedural generation allows developers to build vast, intricate 3D environments algorithmically rather than manually sculpting assets. This article explores how Three.js's MathUtils.seededRandom provides the deterministic foundation necessary to generate reproducible procedural worlds, ensuring that randomly distributed terrain, foliage, and structures remain identical across distinct user sessions, platforms, and network clients using a single shared seed.

The Limitation of Standard Randomness

JavaScript's native Math.random() is non-deterministic; it produces pseudorandom floating-point values between 0 and 1 based on an internal system state that cannot be set or reset by the developer. In procedural world generation, relying on Math.random() creates serious continuity issues:

  • Session Inconsistency: Reloading the webpage completely regenerates the world layout, preventing players from bookmarking or returning to the same location.
  • Desynchronized Multiplayer: Two clients connecting to the same world will generate completely different layouts, making shared spatial interactions impossible.
  • Bandwidth Overhead: To bypass client-side discrepancies, servers would be forced to transmit massive geometry or transform arrays over the network instead of a lightweight configuration value.

How MathUtils.seededRandom Solves the Problem

THREE.MathUtils.seededRandom(s) is a pseudorandom number generator (PRNG) built directly into the Three.js library. Unlike Math.random(), it takes an explicit seed value—an integer—and executes a mathematical formula (a variation of a Linear Congruential Generator) to return a predictable float between 0 and 1.

Because the algorithm is deterministic, providing the exact same seed value will always yield the exact same sequence of numbers.

import * as THREE from 'three';

// An initial seed value
let seed = 12345;

// Function to fetch the next deterministic random number
function getNextRandom() {
    seed = (seed + 1) % 0xffffffff;
    return THREE.MathUtils.seededRandom(seed);
}

By substituting standard random calls with a seeded pipeline, every step of the procedural world generation becomes completely reproducible.

Practical Applications in World Generation

1. Terrain Heightmaps and Noise

Procedural terrain often relies on stacking mathematical noise layers or displacing vertices on a THREE.PlaneGeometry. Using MathUtils.seededRandom to initialize the phase offsets or permutation tables of simplex/perlin noise algorithms guarantees that mountains, valleys, and rivers form in identical positions across every session.

2. Instanced Mesh Placement

Placing thousands of trees, rocks, and grass blades typically involves setting positions, rotations, and scales on a THREE.InstancedMesh. By iterating through instance indices and deriving transforms via MathUtils.seededRandom, every asset appears in the exact same orientation and coordinate in 3D space:

const dummy = new THREE.Object3D();
const count = 1000;
let currentSeed = worldSeed;

for (let i = 0; i < count; i++) {
    // Generate deterministic coordinates
    const x = THREE.MathUtils.seededRandom(currentSeed++) * 200 - 100;
    const z = THREE.MathUtils.seededRandom(currentSeed++) * 200 - 100;
    const scale = THREE.MathUtils.seededRandom(currentSeed++) * 0.5 + 0.5;

    dummy.position.set(x, 0, z);
    dummy.scale.set(scale, scale, scale);
    dummy.updateMatrix();
    
    instancedMesh.setMatrixAt(i, dummy.matrix);
}
instancedMesh.instanceMatrix.needsUpdate = true;

3. Efficient Multiplayer and Save States

Because the generation logic is fixed, the entire state of a massive world can be encapsulated in a single numeric or string variable (e.g., seed = 984321). To share a world layout, a user only needs to share that single seed string. When another player loads the application with that seed, their local hardware recalculates the exact same environment without streaming gigabytes of world data across a network.

Ensuring True Reproducibility

To maintain deterministic output when using MathUtils.seededRandom, developers must avoid two common pitfalls:

  • Execution Order Dependency: Generating assets asynchronously or using unordered promises can shuffle the sequence in which MathUtils.seededRandom is queried, resulting in world corruption. World generation loops must remain strictly sequential.
  • Coordinate-Independent Chunk Loading: In open-world games with dynamic chunk loading, players visit areas in arbitrary orders. Instead of relying on a global running counter, seeds should be derived mathematically from grid coordinates (e.g., combining chunkX and chunkZ with a bitwise hash) so each chunk generates identically regardless of when the camera enters it.
