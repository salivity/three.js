Raycaster setFromCamera in Multi-Viewport Three.js

In Three.js, configuring multiple viewports on a single canvas allows you to render split-screen perspectives, mini-maps, or synchronized multi-camera views. Handling user interaction in these layouts requires using Raycaster.setFromCamera to cast picking rays from a 2D pointer position into the 3D scene. This article explains how Raycaster.setFromCamera functions, why standard coordinate conversion fails in multi-viewport setups, and how to correctly normalize coordinates relative to individual viewports for accurate raycasting.

The Role of Raycaster.setFromCamera

The Raycaster.setFromCamera(coords, camera) method accepts two arguments:

  1. A Vector2 representing coordinates in Normalized Device Coordinates (NDC), where both \(x\) and \(y\) range from -1 to +1.
  2. A Camera object (such as a PerspectiveCamera or OrthographicCamera) currently viewing the scene.

Internally, this method unprojects the 2D coordinate using the camera's projection and world matrices. It determines the ray's origin and direction in 3D world space, allowing the raycaster to test for intersections with 3D objects using methods like raycaster.intersectObjects().

The Multi-Viewport Challenge

In a standard single-viewport application, the viewport matches the canvas boundaries. Converting mouse coordinates to NDC is straightforward:

const mouse = new THREE.Vector2();
mouse.x = (event.clientX / window.innerWidth) * 2 - 1;
mouse.y = -(event.clientY / window.innerHeight) * 2 + 1;

In multi-viewport configurations, a single canvas is divided into multiple sub-regions using WebGLRenderer.setViewport(x, y, width, height) and WebGLRenderer.setScissor(x, y, width, height). Each region often utilizes its own dedicated camera.

If you pass global canvas coordinates into Raycaster.setFromCamera, the ray will not originate from the correct optical center of the sub-camera. Because each camera's projection matrix assumes its viewing frustum covers the entire [-1, 1] NDC range, input coordinates must be normalized relative to the specific sub-viewport rather than the overall canvas.

Normalizing Coordinates for Sub-Viewports

To perform raycasting within a multi-viewport configuration, you must translate the pointer's canvas-relative position to the bounds of the specific viewport under the cursor.

1. Identify the Active Viewport

Track the dimensions and pixel offsets of each defined viewport:

const viewports = [
  { left: 0, bottom: 0, width: 0.5, height: 1.0, camera: cameraLeft },
  { left: 0.5, bottom: 0, width: 0.5, height: 1.0, camera: cameraRight }
];

2. Map Mouse Coordinates to the Viewport NDC

When an input event occurs, determine which viewport contains the pointer and convert the pixel coordinates to viewport-local NDC:

function getViewportNDC(event, viewport, canvas) {
  const rect = canvas.getBoundingClientRect();
  const mouseX = event.clientX - rect.left;
  const mouseY = event.clientY - rect.top;

  // Convert viewport relative bounds to pixel dimensions
  const vpPixelX = viewport.left * rect.width;
  const vpPixelY = (1 - viewport.bottom - viewport.height) * rect.height; // DOM Y is inverted
  const vpPixelWidth = viewport.width * rect.width;
  const vpPixelHeight = viewport.height * rect.height;

  // Check if cursor is inside this viewport
  if (
    mouseX >= vpPixelX &&
    mouseX <= vpPixelX + vpPixelWidth &&
    mouseY >= vpPixelY &&
    mouseY <= vpPixelY + vpPixelHeight
  ) {
    const localX = mouseX - vpPixelX;
    const localY = mouseY - vpPixelY;

    // Convert local pixels to [-1, 1] range
    return new THREE.Vector2(
      (localX / vpPixelWidth) * 2 - 1,
      -(localY / vpPixelHeight) * 2 + 1
    );
  }

  return null;
}

3. Apply to Raycaster

Once you compute the local NDC and isolate the corresponding camera, pass them to setFromCamera:

viewports.forEach((vp) => {
  const localNDC = getViewportNDC(event, vp, renderer.domElement);

  if (localNDC) {
    raycaster.setFromCamera(localNDC, vp.camera);
    const intersects = raycaster.intersectObjects(scene.children, true);

    if (intersects.length > 0) {
      // Process intersections for the active viewport
    }
  }
});

Summary

Raycaster.setFromCamera requires input in Normalized Device Coordinates that align with the projection plane of the target camera. In multi-viewport configurations, the method relies on you to translate global screen-space inputs into the local bounds of the sub-viewport before invocation. By remapping coordinates to the specific sub-rectangle and passing the matching camera, raycasting works reliably across complex, multi-view Three.js layouts.
