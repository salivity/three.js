Normalizing a Plane in Three.js for Accurate Distance

In Three.js, measuring the exact Euclidean distance from a point to a plane requires a unit-length normal vector. This guide explains why non-normalized THREE.Plane instances return distorted measurements, the critical mathematical distinction between normalizing just the normal vector versus the entire plane definition, and how to strictly normalize a plane using built-in methods to guarantee physically accurate distanceToPoint results.

Why Unnormalized Planes Yield Inaccurate Distances

The THREE.Plane object represents a plane in Hessian normal form using a 3D direction vector (normal) and a scalar offset (constant). The mathematical formula used internally by distanceToPoint(point) is:

\[\text{Distance} = (\mathbf{n} \cdot \mathbf{p}) + d\]

Where:

  • \(\mathbf{n}\) is plane.normal
  • \(\mathbf{p}\) is the target Vector3 point
  • \(d\) is plane.constant

For this formula to represent true Euclidean distance, the length (magnitude) of \(\mathbf{n}\) must equal exactly 1.0. If the normal vector has a magnitude other than 1—which often happens after applying non-uniform matrix transformations or constructing planes from unnormalized vectors—the returned distance is scaled by \(\|\mathbf{n}\|\), resulting in an overestimation or underestimation of the actual physical distance.

The Common Pitfall: Normalizing Only the Normal

A frequent mistake is directly normalizing the plane's normal property:

// INCORRECT: Modifies the plane's position in space
plane.normal.normalize();

Normalizing only the vector component without scaling the constant distorts the plane equation. The scalar constant represents the signed distance from the origin to the plane relative to the length of the normal vector. If the vector is rescaled independently, the plane physically shifts toward or away from the origin.

The Correct Method: Plane.normalize()

To strictly normalize a THREE.Plane, call the normalize() method directly on the plane instance.

import * as THREE from 'three';

// Create a plane with an unnormalized normal vector
const normal = new THREE.Vector3(2, 0, 0); // Magnitude is 2
const constant = -10;
const plane = new THREE.Plane(normal, constant);

// Normalize both the normal and constant uniformly
plane.normalize();

// Verify the result
const testPoint = new THREE.Vector3(10, 0, 0);
const accurateDistance = plane.distanceToPoint(testPoint); 
// Returns 5 (the true physical distance)

What Plane.normalize() Does Internally

When invoking plane.normalize(), Three.js executes the following logic:

  1. Computes the inverse length: 1.0 / plane.normal.length()
  2. Multiplies plane.normal by the inverse length, setting its length to 1.0.
  3. Multiplies plane.constant by the same inverse length scalar.

This preserves the plane's exact position and orientation in 3D space while enforcing \(\|\mathbf{n}\| = 1\), ensuring all subsequent calls to distanceToPoint return geometrically and physically accurate units.

Handling Degenerate Planes

If the normal vector has a length of zero (e.g., Vector3(0, 0, 0)), dividing by the length results in Infinity or NaN. Before normalizing dynamically calculated planes, verify that the normal is non-zero:

if (plane.normal.lengthSq() > 0) {
    plane.normalize();
} else {
    // Fallback: assign a valid default orientation
    plane.set(new THREE.Vector3(0, 1, 0), 0);
}
