Reading Z-Buffer Data with Three.js DepthTexture

In Three.js, accessing a rendered scene's depth buffer (z-buffer) is essential for advanced post-processing effects like screen-space ambient occlusion (SSAO), depth-of-field, and depth-based fog. This guide explains how to configure a THREE.DepthTexture, attach it to a THREE.WebGLRenderTarget, render the scene's depth data, and sample the resulting values within a GLSL shader.

1. Create the Render Target and DepthTexture

To capture the z-buffer, instantiate a THREE.DepthTexture and assign it to the depthTexture property of a THREE.WebGLRenderTarget.

import * as THREE from 'three';

const width = window.innerWidth;
const height = window.innerHeight;

// 1. Create the depth texture
const depthTexture = new THREE.DepthTexture();
depthTexture.type = THREE.UnsignedShortType; // Alternatively: THREE.UnsignedIntType or THREE.FloatType
depthTexture.format = THREE.DepthFormat; // Use THREE.DepthStencilFormat if stencil data is needed

// 2. Create the render target and assign the depth texture
const renderTarget = new THREE.WebGLRenderTarget(width, height, {
  minFilter: THREE.NearestFilter,
  magFilter: THREE.NearestFilter,
  depthTexture: depthTexture,
  depthBuffer: true
});

Selecting THREE.UnsignedShortType provides 16-bit depth precision, which is widely supported and sufficient for most use cases. For higher precision, use THREE.UnsignedIntType (24-bit/32-bit depending on device support).

2. Render the Scene to the Render Target

Direct the renderer to draw to your target instead of the default canvas buffer during your animation loop:

function animate() {
  requestAnimationFrame(animate);

  // Direct rendering output to the render target
  renderer.setRenderTarget(renderTarget);
  renderer.render(scene, camera);

  // Reset the render target back to the canvas for display
  renderer.setRenderTarget(null);

  // Render post-processing mesh or final output pass
  renderer.render(postProcessingScene, postProcessingCamera);
}

When renderer.render(scene, camera) completes, renderTarget.depthTexture contains the non-linear depth values of the geometry.

3. Sampling the DepthTexture in a Shader

Depth stored in the z-buffer is non-linear when using a perspective camera, meaning precision is heavily clustered near the camera's near clipping plane. To use this data, pass the texture and camera parameters into a custom ShaderMaterial.

const depthMaterial = new THREE.ShaderMaterial({
  uniforms: {
    tDepth: { value: renderTarget.depthTexture },
    cameraNear: { value: camera.near },
    cameraFar: { value: camera.far }
  },
  vertexShader: `
    varying vec2 vUv;
    void main() {
      vUv = uv;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `,
  fragmentShader: `
    #include <packing>

    varying vec2 vUv;
    uniform sampler2D tDepth;
    uniform float cameraNear;
    uniform float cameraFar;

    float readDepth(sampler2D depthSampler, vec2 coord) {
      float fragCoordZ = texture2D(depthSampler, coord).x;
      // Convert non-linear depth to linear view space distance
      return perspectiveDepthToViewZ(fragCoordZ, cameraNear, cameraFar);
    }

    void main() {
      // Sample depth
      float viewZ = readDepth(tDepth, vUv);
      
      // Normalize depth between 0.0 and 1.0 for visualization
      float linearDepth = (viewZ + cameraNear) / (cameraNear - cameraFar);

      gl_FragColor = vec4(vec3(linearDepth), 1.0);
    }
  `
});

The built-in Three.js shader chunk <packing> provides utility functions like perspectiveDepthToViewZ to convert raw non-linear z-buffer coordinates (fragCoordZ) into linear view coordinates.

4. Handling Window Resize

When the viewport changes size, resize the render target to maintain pixel alignment:

window.addEventListener('resize', () => {
  const newWidth = window.innerWidth;
  const newHeight = window.innerHeight;

  camera.aspect = newWidth / newHeight;
  camera.updateProjectionMatrix();

  renderer.setSize(newWidth, newHeight);
  renderTarget.setSize(newWidth, newHeight);
});
