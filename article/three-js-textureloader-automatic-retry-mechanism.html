Three.js TextureLoader Automatic Retry Mechanism

This article explains how to build a robust retry mechanism for failed texture downloads using Three.js. When dealing with unreliable network conditions or CDN hiccups, standard asset loading can fail silently or break 3D scenes. By wrapping the Three.js TextureLoader in a recursive function or Promise-based utility, you can automatically retry loading textures with customizable attempt counts and delay intervals.

The Standard TextureLoader Limitation

The standard THREE.TextureLoader.load() method accepts four arguments: the asset URL, an onLoad callback, an onProgress callback, and an onError callback. By default, if the HTTP request fails, the onError handler is triggered, but no subsequent download attempts are made.

To introduce automatic retries, you must intercept this onError callback and re-trigger the loading sequence until the asset loads successfully or a maximum attempt threshold is met.

Implementing a Promise-Based Retry Utility

The cleanest way to implement retries is by wrapping TextureLoader inside a custom function that returns a Promise. This allows you to handle loading asynchronously using async/await.

import * as THREE from 'three';

/**
 * Loads a texture with an automatic retry mechanism.
 * 
 * @param {string} url - Path or URL to the texture image.
 * @param {number} maxRetries - Maximum number of retry attempts.
 * @param {number} delay - Base delay between retries in milliseconds.
 * @param {boolean} useBackoff - Whether to use exponential backoff.
 * @returns {Promise<THREE.Texture>}
 */
function loadTextureWithRetry(url, maxRetries = 3, delay = 1000, useBackoff = true) {
  const loader = new THREE.TextureLoader();

  return new Promise((resolve, reject) => {
    let attempts = 0;

    function attemptLoad() {
      attempts++;

      loader.load(
        url,
        (texture) => {
          resolve(texture);
        },
        undefined, // onProgress is typically not supported by TextureLoader
        (error) => {
          if (attempts <= maxRetries) {
            const waitTime = useBackoff ? delay * Math.pow(2, attempts - 1) : delay;
            console.warn(
              `Attempt ${attempts} failed for texture "${url}". Retrying in ${waitTime}ms...`
            );
            setTimeout(attemptLoad, waitTime);
          } else {
            reject(
              new Error(`Failed to load texture "${url}" after ${maxRetries} retry attempts.`)
            );
          }
        }
      );
    }

    attemptLoad();
  });
}

How the Retry Logic Works

  1. Attempt Counter: The function tracks the total number of load attempts with the attempts variable.
  2. Recursive Execution: If loader.load() hits the error callback, the condition checks whether attempts <= maxRetries. If true, setTimeout queues another call to attemptLoad.
  3. Exponential Backoff: When useBackoff is enabled, the wait time doubles with each failed attempt (e.g., 1000ms, 2000ms, 4000ms). This prevents spamming servers that may be temporarily overloaded or rate-limiting incoming traffic.
  4. Resolution and Rejection: Upon a successful fetch, the Promise resolves with the newly instantiated THREE.Texture. If all retries are exhausted, the Promise rejects with an descriptive error.

Using the Function in a Scene

You can integrate this utility directly into your scene initialization routine:

async function initMaterial() {
  try {
    const texture = await loadTextureWithRetry('textures/diffuse.jpg', 3, 1500);
    const material = new THREE.MeshStandardMaterial({ map: texture });
    
    const mesh = new THREE.Mesh(new THREE.BoxGeometry(), material);
    scene.add(mesh);
  } catch (error) {
    console.error('Critical texture loading failure:', error);
    // Assign a fallback color or placeholder texture
  }
}

Using this approach prevents broken 3D models caused by transient network disruptions and ensures your application recovers automatically without requiring a full page refresh.
