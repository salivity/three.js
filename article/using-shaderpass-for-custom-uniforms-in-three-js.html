Using ShaderPass for Custom Uniforms in Three.js

In Three.js post-processing pipelines, ShaderPass acts as the critical bridge between JavaScript application logic and custom GLSL fragment shaders applied across an entire scene. This article explains the exact purpose of ShaderPass when handling dynamic custom uniforms—such as elapsed time and normalized mouse coordinates—detailing how it manages memory, enables continuous CPU-to-GPU data transmission inside the render loop, and automates full-screen quad rendering via EffectComposer.

The Core Purpose of ShaderPass

When implementing full-screen image processing in Three.js, shaders are not applied to individual 3D meshes. Instead, the final scene is rendered to an off-screen buffer (a render target) and then processed as a flat 2D texture.

ShaderPass simplifies this workflow by automatically provisioning an orthographic camera and a full-screen plane geometry. It takes a shader object containing vertex shaders, fragment shaders, and uniform declarations, binding them directly to an internal ShaderMaterial. Without ShaderPass, you would need to manually create an off-screen scene, an orthographic camera, a 1x1 quad mesh, and manage texture ping-ponging between render targets.

Managing and Exposing Custom Uniforms

Uniforms represent read-only variables within GLSL shaders that remain constant across all processed pixels in a single draw call, but which can be modified between draw calls from JavaScript.

When you pass a custom shader definition to ShaderPass, it stores the declared uniforms in its .uniforms property. The specific role of ShaderPass regarding custom uniforms includes:

  1. State Preservation: It maintains the current state of custom uniforms between frames, ensuring that variables not modified on every frame retain their previous values.
  2. GPU Texture Mapping: It automatically maps the scene's rendered output texture to the default tDiffuse uniform, allowing custom uniforms to interact directly with the underlying render.
  3. Direct CPU-to-GPU Access: It exposes a direct reference to the uniform values through JavaScript, allowing developers to target uniforms by key without interacting with lower-level WebGL buffer management.

Handling Dynamic Uniforms: Time and Mouse Coordinates

Dynamic visual effects—such as chromatic aberration, water ripples, noise distortion, and vignette tracking—require values that change continuously over time or in response to user input. ShaderPass allows these variables to be updated frame-by-frame.

Driving Procedural Animation with Time

Time uniforms (commonly named u_time or time) require scalar float values that increase monotonically. Inside the fragment shader, time is passed into trigonometric functions, procedural noise algorithms, or coordinate offsets to create continuous motion.

ShaderPass allows this value to be updated directly in the animation loop prior to rendering:

const clock = new THREE.Clock();

function animate() {
    requestAnimationFrame(animate);

    // Update the custom time uniform inside ShaderPass
    customShaderPass.uniforms['u_time'].value = clock.getElapsedTime();

    composer.render();
}

Enabling Interactivity with Mouse Coordinates

Mouse uniforms (commonly named u_mouse or mouse) are typically defined as a 2D vector (vec2). They translate normalized screen-space pointer coordinates into the coordinate space of the fragment shader, enabling effects centered on the user's cursor.

Event listeners capture the input on the CPU, and ShaderPass transmits the updated THREE.Vector2 directly to the active shader program during the next draw call:

const mouse = new THREE.Vector2();

window.addEventListener('mousemove', (event) => {
    mouse.x = event.clientX / window.innerWidth;
    mouse.y = 1.0 - (event.clientY / window.innerHeight); // Invert Y for GLSL texture coordinates
    
    customShaderPass.uniforms['u_mouse'].value.copy(mouse);
});

Execution Inside the EffectComposer

When composer.render() executes, ShaderPass performs three essential actions:

  1. Evaluates all references in its .uniforms map and marks modified values for GPU upload.
  2. Binds the updated uniform values (floats, vectors, matrices, or textures) to the compiled WebGL program.
  3. Draws the full-screen quad, running the fragment shader once for every pixel on the screen using the newly uploaded time and mouse parameters.

Through this mechanism, ShaderPass isolates shader parameter management from low-level WebGL state machine configuration, providing a clean, performant API for interactive post-processing shaders.
