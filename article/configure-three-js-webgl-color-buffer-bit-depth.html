Configure Three.js WebGL Color Buffer Bit Depth

Configuring specific color buffer bit depths in Three.js depends on whether you are adjusting the main canvas drawing buffer or rendering off-screen using render targets. While the default HTML5 WebGL canvas is generally constrained by the browser to an 8-bit-per-channel (RGBA8) format, Three.js allows you to implement specific bit depths—such as 16-bit half-precision, 32-bit full-precision floating-point, or packed integer formats—using custom THREE.WebGLRenderTarget instances or WebGL 2 capabilities.

Canvas Drawing Buffer Bit Depth

When initializing THREE.WebGLRenderer, the WebGL context is bound to an HTML <canvas> element. The default canvas drawing buffer is dictated by browser capabilities and standard WebGL context attributes, typically defaulting to 8 bits per color channel (24-bit RGB or 32-bit RGBA):

const renderer = new THREE.WebGLRenderer({
    antialias: true,
    alpha: true,
    powerPreference: 'high-performance'
});

Standard WebGL does not provide direct canvas context initialization attributes to force arbitrary channel bit depths (such as 10-bit or 12-bit native display buffers). For deep color output (e.g., Display P3 or Rec. 2020 on supported displays), configure the color space rather than raw bit depth directly:

renderer.outputColorSpace = THREE.SRGBColorSpace; // or THREE.LinearSRGBColorSpace

Specifying Bit Depth via WebGLRenderTarget

To achieve precise control over the color buffer bit depth during rendering passes, use THREE.WebGLRenderTarget. The type property defines the data format and precision of the color buffer.

1. 16-Bit Half-Float Buffers (RGBA16F)

Ideal for High Dynamic Range (HDR) rendering, post-processing pipelines, and bloom passes where higher color precision is needed without the performance overhead of full 32-bit floats:

const renderTarget16Bit = new THREE.WebGLRenderTarget(width, height, {
    type: THREE.HalfFloatType, // 16-bit float per channel
    format: THREE.RGBAFormat,
    minFilter: THREE.LinearFilter,
    magFilter: THREE.LinearFilter
});

2. 32-Bit Full-Float Buffers (RGBA32F)

Best for scientific calculations, deep G-buffers in deferred shading, or extreme-range physics data where maximum precision is required:

const renderTarget32Bit = new THREE.WebGLRenderTarget(width, height, {
    type: THREE.FloatType, // 32-bit float per channel
    format: THREE.RGBAFormat,
    minFilter: THREE.NearestFilter,
    magFilter: THREE.NearestFilter
});

3. 8-Bit Unsigned Byte Buffers (RGBA8)

The standard and most performant buffer depth for conventional rendering:

const renderTarget8Bit = new THREE.WebGLRenderTarget(width, height, {
    type: THREE.UnsignedByteType, // 8-bit unsigned integer per channel (default)
    format: THREE.RGBAFormat
});

4. Packed Low-Bit Depth Formats

For memory-constrained environments, Three.js supports packed 16-bit integer formats:

  • THREE.UnsignedShort565Type: 5 bits red, 6 bits green, 5 bits blue (16-bit total, no alpha).
  • THREE.UnsignedShort5551Type: 5 bits red, 5 bits green, 5 bits blue, 1 bit alpha.
  • THREE.UnsignedShort4444Type: 4 bits per RGBA channel.
const renderTarget565 = new THREE.WebGLRenderTarget(width, height, {
    type: THREE.UnsignedShort565Type,
    format: THREE.RGBFormat
});

Rendering Pipeline Execution

To render to your custom bit-depth buffer and display the result:

// Direct rendering into the high-precision target
renderer.setRenderTarget(renderTarget16Bit);
renderer.render(scene, camera);

// Reset back to the default canvas framebuffer
renderer.setRenderTarget(null);

If the high-precision buffer contains values outside the standard [0.0, 1.0] range, map it back to the screen using a post-processing quad with tone mapping (such as THREE.ACESFilmicToneMapping) to avoid clipping artifacts on standard 8-bit displays.
