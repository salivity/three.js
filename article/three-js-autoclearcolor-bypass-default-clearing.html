Three.js autoClearColor: Bypass Default Clearing

In Three.js, the WebGL renderer automatically wipes the screen clean before drawing every new frame. By setting renderer.autoClearColor = false, you can bypass the automatic clearing of the color buffer, allowing previously drawn pixels to persist on the canvas. This article explains how to implement this setting, how it interacts with the rendering loop, and the primary use cases for disabling automatic color clearing.

Understanding Three.js Clearing Behavior

By default, renderer.autoClear is set to true. When renderer.render(scene, camera) is invoked, Three.js automatically executes an internal clear operation on three separate WebGL buffers:

  • Color Buffer: Stores the RGBA values of pixels.
  • Depth Buffer: Stores distance data used for depth testing and occlusion.
  • Stencil Buffer: Stores mask data used for limiting rendering areas.

Three.js provides granular control over each buffer through three specific boolean properties: renderer.autoClearColor, renderer.autoClearDepth, and renderer.autoClearStencil. Setting autoClearColor to false instructs the renderer to retain the existing color pixels while still respecting or clearing the depth and stencil buffers based on their respective settings.

Implementing renderer.autoClearColor = false

To disable color buffer clearing, initialize your renderer and set autoClearColor to false:

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer();
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// Bypass the default color clearing
renderer.autoClearColor = false;

When you render objects in an animation loop without clearing the color buffer, new frames are drawn directly on top of the old ones:

function animate() {
    requestAnimationFrame(animate);

    // Rotate and animate your objects
    mesh.rotation.x += 0.01;
    mesh.rotation.y += 0.01;

    // Render without clearing previous color data
    renderer.render(scene, camera);
}

animate();

Depth Buffer Considerations

If renderer.autoClearDepth remains true (its default state), the depth buffer will still reset every frame. This means objects rendered in subsequent frames will not be occluded by previously drawn pixels, even though the visual colors remain on the screen.

If you want newly rendered objects to respect the depth values of previously drawn elements, you must also set:

renderer.autoClearDepth = false;

Alternatively, you can disable all clearing operations at once by setting renderer.autoClear = false, which stops color, depth, and stencil clearing simultaneously.

Manual Clearing

When automatic clearing is disabled, you frequently need to clear the screen manually at specific intervals. You can trigger manual clears using the renderer's clear methods:

  • renderer.clear(): Clears color, depth, and stencil buffers.
  • renderer.clearColor(): Clears only the color buffer.
  • renderer.clearDepth(): Clears only the depth buffer.
  • renderer.clearStencil(): Clears only the stencil buffer.

Example of clearing manually on specific frames or conditions:

function animate() {
    requestAnimationFrame(animate);

    // Manually clear only when needed (e.g., scene transition or keypress)
    if (needsReset) {
        renderer.clearColor();
        needsReset = false;
    }

    renderer.render(scene, camera);
}

Common Use Cases

  • Trail and Painting Effects: Moving geometries will leave trails across the canvas because the pixels from previous positions are never removed.
  • Multi-Scene Layering: Rendering an overlay, UI, or HUD scene directly over a 3D scene without overwriting the visual output of the background scene.
  • Multi-Camera Views: Drawing multiple viewports (such as a split-screen or minimap) within a single WebGL context without each draw call wiping the other.
