Custom Three.js WebXR VRButton Styling

This guide demonstrates how to replace the default look of the Three.js VRButton by injecting a custom DOM element over it. While the default VRButton handles essential WebXR checks, session states, and required user activation gestures, its default styling rarely fits modern application interfaces. By wrapping or overlaying the button with your own HTML and CSS, you can create a custom entry point without breaking the underlying WebXR session lifecycle.

The Challenge with WebXR Entry Points

Three.js includes an official utility, VRButton.js, which determines if WebXR is supported, enables the button when hardware is detected, and requests an immersive-vr session. Browsers require a direct, synchronous user gesture (such as a click) to enter WebXR. If you build a completely separate UI element and attempt to trigger the VRButton programmatically via JavaScript using .click(), the browser may block the request due to security policies regarding trusted user events.

The most reliable solution is to keep the functional VRButton in the DOM and layer your custom visual interface directly over or under it.

Approach: Transparent Interaction Overlay

The most robust technique is to create a custom HTML button for visual styling and position the official VRButton directly on top of it, rendered completely transparently (opacity: 0). When the user clicks your custom button visually, they are physically clicking the native VRButton, satisfying browser security requirements while displaying your custom UI.

1. HTML and CSS Structure

Set up a container element that holds both the visual custom element and the functional WebXR button:

.xr-button-wrapper {
  position: relative;
  display: inline-block;
  overflow: hidden;
  border-radius: 8px;
}

/* Your custom visual design */
.custom-vr-button {
  background: linear-gradient(135deg, #6e8efb, #a777e3);
  color: #ffffff;
  padding: 12px 24px;
  font-family: sans-serif;
  font-weight: 600;
  border: none;
  border-radius: 8px;
  cursor: pointer;
  display: flex;
  align-items: center;
  gap: 8px;
  pointer-events: none; /* Allows clicks to register on elements below if needed */
}

/* The transparent Three.js VRButton overlay */
.xr-button-wrapper > button {
  position: absolute !important;
  top: 0 !important;
  left: 0 !important;
  width: 100% !important;
  height: 100% !important;
  opacity: 0 !important;
  cursor: pointer !important;
  border: none !important;
  z-index: 2;
}

2. JavaScript Implementation

Import VRButton from the Three.js addons directory, generate the standard button, and inject it into your wrapper alongside your custom DOM structure:

import * as THREE from 'three';
import { VRButton } from 'three/addons/webxr/VRButton.js';

// Initialize Three.js renderer with WebXR enabled
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.xr.enabled = true;
document.body.appendChild(renderer.domElement);

// 1. Create the container wrapper
const buttonContainer = document.createElement('div');
buttonContainer.className = 'xr-button-wrapper';

// 2. Create your custom DOM element
const customVisual = document.createElement('div');
customVisual.className = 'custom-vr-button';
customVisual.innerHTML = `
  <span>Enter Virtual Reality</span>
`;

// 3. Generate the default Three.js VRButton
const vrButton = VRButton.createButton(renderer);

// 4. Assemble the elements
buttonContainer.appendChild(customVisual);
buttonContainer.appendChild(vrButton);

// 5. Inject the container into your UI layout
document.body.appendChild(buttonContainer);

Responding to WebXR State Changes

The native VRButton updates its text content and disabled state based on hardware capabilities (e.g., changing text to "VR NOT SUPPORTED"). To ensure your custom overlay reflects these status changes, attach a MutationObserver to the native button:

const observer = new MutationObserver(() => {
  if (vrButton.textContent.includes('NOT SUPPORTED')) {
    customVisual.textContent = 'VR Not Supported';
    customVisual.style.opacity = '0.5';
    buttonContainer.style.pointerEvents = 'none';
  } else if (vrButton.textContent.includes('EXIT VR')) {
    customVisual.textContent = 'Exit Reality';
  } else {
    customVisual.textContent = 'Enter Virtual Reality';
  }
});

observer.observe(vrButton, {
  childList: true,
  characterData: true,
  subtree: true
});

Using this approach ensures full styling freedom with standard CSS while relying on the Three.js runtime for session handling and browser security compliance.
