Loading Legacy Collada DAE Files in Three.js

Loading legacy Collada (.dae) assets in Three.js requires importing the specialized ColladaLoader, parsing the resulting data structure, and properly navigating its nested scene graph. This guide demonstrates how to fetch a .dae file, address typical Collada hierarchy characteristics such as deep node nesting and legacy axis orientations, and traverse the parsed structure to manipulate meshes, materials, and animations effectively.

1. Importing and Setting Up ColladaLoader

The ColladaLoader is not part of the Three.js core bundle and must be imported from the three/addons/ directory.

import * as THREE from 'three';
import { ColladaLoader } from 'three/addons/loaders/ColladaLoader.js';

const scene = new THREE.Scene();
const loader = new ColladaLoader();

2. Loading the .dae File

Use the load() method to retrieve the asset. The loader returns a response object containing the scene, kinematics, library, and any embedded animations.

loader.load(
    'models/legacy_model.dae',
    (collada) => {
        const daeScene = collada.scene;
        scene.add(daeScene);
    },
    (xhr) => {
        console.log((xhr.loaded / xhr.total * 100) + '% loaded');
    },
    (error) => {
        console.error('An error occurred loading the Collada file:', error);
    }
);

3. Handling Axis Orientation (Z-Up vs. Y-Up)

Collada files historically use a Z-up coordinate system, whereas Three.js defaults to Y-up. While modern versions of ColladaLoader automatically read the <up_axis> tag in the .dae XML and attempt to rotate the root node, older files may still import with unexpected rotations.

If the model is incorrectly oriented upon loading, rotate the wrapper scene rather than individual child nodes:

daeScene.rotation.x = -Math.PI / 2; // Correct Z-up to Y-up orientation if required

4. Navigating the Unique Hierarchical Structure

Collada models frequently nest meshes inside layers of dummy nodes, visual scene nodes, and transform groups. Rather than addressing specific child indices directly, traverse the hierarchy using the traverse method. This allows you to identify specific node types, cast shadows, or update legacy materials.

daeScene.traverse((child) => {
    if (child.isMesh) {
        child.castShadow = true;
        child.receiveShadow = true;

        // Legacy Collada files often import with MeshBasicMaterial or MeshLambertMaterial
        // Upgrade materials to Standard/Physical if modern PBR lighting is required
        if (child.material) {
            child.material = new THREE.MeshStandardMaterial({
                color: child.material.color,
                map: child.material.map || null
            });
        }
    }
});

5. Flattening or Reparenting Nested Nodes

If the deep nesting causes matrix transformation issues or makes it difficult to animate objects programmatically, you can extract specific meshes and attach them directly to the main scene.

const targetMesh = daeScene.getObjectByName('SpecificMeshName');

if (targetMesh) {
    // Retain the world transformation while detaching from the hierarchy
    targetMesh.applyMatrix4(targetMesh.parent.matrixWorld);
    scene.attach(targetMesh);
}

6. Handling Collada Animations

If the legacy file contains animations, they are exposed as AnimationClip instances on the collada result object rather than the meshes themselves. Use an AnimationMixer targeting the imported scene root to play them:

let mixer;

loader.load('models/legacy_model.dae', (collada) => {
    const daeScene = collada.scene;
    scene.add(daeScene);

    if (collada.animations && collada.animations.length > 0) {
        mixer = new THREE.AnimationMixer(daeScene);
        const action = mixer.clipAction(collada.animations[0]);
        action.play();
    }
});

// Update the mixer in the render loop
const clock = new THREE.Clock();
function animate() {
    requestAnimationFrame(animate);
    const delta = clock.getDelta();
    if (mixer) mixer.update(delta);
    renderer.render(scene, camera);
}
