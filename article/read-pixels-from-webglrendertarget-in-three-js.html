Read Pixels from WebGLRenderTarget in Three.js

Reading raw pixel data from a GPU render target back to the CPU in Three.js is accomplished using the WebGLRenderer.readRenderTargetPixels method. This process is essential for tasks such as color-based object picking, computer vision processing, and analytical computations. However, improperly executing this operation can cause severe performance bottlenecks due to synchronous GPU pipeline stalls, or result in corrupt data if the underlying buffer types do not align. This guide outlines how to configure your render target, allocate the correct typed array, and read pixel values safely and efficiently.

1. Match the TypedArray to the Texture Type

The most critical step in preventing memory corruption or runtime errors is ensuring your CPU buffer matches the data type and format of the WebGLRenderTarget.

By default, Three.js render targets use THREE.RGBAFormat and THREE.UnsignedByteType. Each pixel consists of 4 channels (Red, Green, Blue, Alpha), with each channel represented by an 8-bit unsigned integer (0–255).

  • Default (UnsignedByteType): Requires a Uint8Array.
  • Float Type (FloatType): Requires a Float32Array.
  • Half-Float Type (HalfFloatType): Requires a Uint16Array if accessing raw bits, or a Float32Array depending on platform support and Three.js version.

The buffer size is calculated as:
width * height * 4 (for RGBA)

2. Implementation Example

The following implementation renders an off-screen scene to a WebGLRenderTarget and reads the pixel data into a CPU-accessible array:

import * as THREE from 'three';

// 1. Initialize Renderer and RenderTarget
const renderer = new THREE.WebGLRenderer();
renderer.setSize(window.innerWidth, window.innerHeight);

const width = 512;
const height = 512;
const renderTarget = new THREE.WebGLRenderTarget(width, height, {
  format: THREE.RGBAFormat,
  type: THREE.UnsignedByteType,
  minFilter: THREE.NearestFilter,
  magFilter: THREE.NearestFilter
});

// 2. Allocate the Destination Buffer on the CPU
const buffer = new Uint8Array(width * height * 4);

// 3. Render the Scene to the Target
renderer.setRenderTarget(renderTarget);
renderer.render(scene, camera);
renderer.setRenderTarget(null); // Reset back to default framebuffer

// 4. Safely Read Back the Pixels
renderer.readRenderTargetPixels(
  renderTarget,
  0, // X coordinate
  0, // Y coordinate
  width, // Read width
  height, // Read height
  buffer // Target buffer
);

// 5. Access Pixel Data (e.g., pixel at x=10, y=20)
const x = 10;
const y = 20;
const pixelIndex = (y * width + x) * 4;

const r = buffer[pixelIndex];
const g = buffer[pixelIndex + 1];
const b = buffer[pixelIndex + 2];
const a = buffer[pixelIndex + 3];

console.log(`RGBA: ${r}, ${g}, ${b}, ${a}`);

3. Mitigating GPU Stalls and Performance Bottlenecks

readRenderTargetPixels is a synchronous operation. Calling it forces the CPU to wait until the GPU has finished all rendering commands up to that point before transferring the data over the PCIe bus. To minimize the impact on frame rate:

  • Read Minimal Bounds: If you are doing GPU-picking (checking which object is under the cursor), do not read the entire render target. Set width and height to 1 and read only the single pixel at the mouse coordinates. This dramatically reduces memory transfer overhead.
  • Avoid Per-Frame Execution: Do not read full-sized buffers inside the requestAnimationFrame loop unless absolutely necessary. Throttle reads or trigger them only in response to specific user actions.
  • Reuse Allocations: Never instantiate new Uint8Array(...) inside the render loop. Pre-allocate the typed array once and reuse it across multiple read operations to prevent garbage collection spikes.

4. Reading Asynchronously via WebGL2 Pixel Buffer Objects (PBOs)

Three.js's standard readRenderTargetPixels does not natively support non-blocking asynchronous readbacks. If you are using WebGL 2 and must transfer large frames continuously (such as for video recording), interact directly with the underlying WebGL context (renderer.getContext()) using gl.createBuffer() as a PIXEL_PACK_BUFFER and gl.fenceSync(). This allows you to read pixels with a 1-to-2 frame delay without stalling the main render thread.
