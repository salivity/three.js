Three.js getSpacedPoints for Uniform Movement Speed

This article explains how to achieve constant, uniform movement along a 3D path in Three.js by using the getSpacedPoints method of the THREE.Curve class. When animating objects along spline curves, standard parametric sampling often leads to erratic speeds where the object speeds up or slows down depending on control point density. By sampling positions based on cumulative arc length rather than parametric intervals, getSpacedPoints provides evenly distributed coordinates that keep your animation speed consistent from start to finish.

Why Standard Curve Interpolation Causes Speed Variations

In Three.js, curves like CatmullRomCurve3 parameterize paths using a variable \(t\) ranging from 0.0 to 1.0. Calling curve.getPoint(t) evaluates the mathematical formula of the curve at step \(t\). However, distance between control points is rarely uniform. When control points are bunched closely together, a fixed change in \(t\) translates to a tiny physical distance; when points are far apart, the same change in \(t\) covers a much larger physical distance. If you increment \(t\) linearly in your animation loop, your object will visibly accelerate and decelerate.

Using getSpacedPoints to Fix Speed Inconsistencies

The getSpacedPoints(divisions) method solves this by pre-calculating the curve's total arc length and dividing it into segments of equal physical distance. It returns an array of Vector3 (or Vector2) instances spaced equidistantly along the curve.

Here is how to extract these coordinates and use them for uniform movement:

import * as THREE from 'three';

// 1. Define the curve using control points
const curve = new THREE.CatmullRomCurve3([
  new THREE.Vector3(-10, 0, 10),
  new THREE.Vector3(-5, 5, 5),
  new THREE.Vector3(0, 0, 0),
  new THREE.Vector3(5, -5, 5),
  new THREE.Vector3(10, 0, 10)
]);

// 2. Extract an array of equidistant coordinates
// Specifying 200 divisions creates 201 evenly spaced points.
const divisions = 200;
const spacedPoints = curve.getSpacedPoints(divisions);

// 3. Setup the moving object
const mesh = new THREE.Mesh(
  new THREE.SphereGeometry(0.5, 16, 16),
  new THREE.MeshBasicMaterial({ color: 0xff0000 })
);
scene.add(mesh);

// 4. Animate across the spaced points
let currentIndex = 0;

function animate() {
  requestAnimationFrame(animate);

  if (currentIndex < spacedPoints.length) {
    mesh.position.copy(spacedPoints[currentIndex]);
    currentIndex++;
  } else {
    currentIndex = 0; // Loop the animation
  }

  renderer.render(scene, camera);
}

animate();

Alternative: Continuous Movement with getPointAt

If you need continuous, frame-rate independent movement rather than stepping through a pre-generated array of points, use curve.getPointAt(u).

While getSpacedPoints returns an array of discrete points, getPointAt(u) maps a normalized distance factor \(u\) (\(0 \le u \le 1\)) directly to the curve's arc length:

let distanceProgress = 0;
const speed = 0.002; // Constant speed factor

function animate() {
  requestAnimationFrame(animate);

  distanceProgress = (distanceProgress + speed) % 1;

  // getPointAt samples position based on equidistant arc length
  const targetPosition = curve.getPointAt(distanceProgress);
  mesh.position.copy(targetPosition);

  // Optional: Orient object forward along the path
  const tangent = curve.getTangentAt(distanceProgress);
  mesh.quaternion.setFromUnitVectors(new THREE.Vector3(0, 1, 0), tangent);

  renderer.render(scene, camera);
}

Both getSpacedPoints and getPointAt internally utilize the curve's calculated length cache, ensuring that translation across the geometry remains steady regardless of how unevenly your original control points were laid out.
