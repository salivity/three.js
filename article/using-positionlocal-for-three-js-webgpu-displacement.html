Using positionLocal for Three.js WebGPU Displacement

In Three.js WebGPU and the Three.js Shading Language (TSL), the positionLocal node represents an object's raw vertex coordinates in local model space before any matrix transformations occur. When implementing vertex displacement, positionLocal functions both as the spatial reference point for computing procedural offsets and as the base vector to which those calculated displacements are applied. Modifying or referencing this node enables developers to dynamically alter a mesh's geometry on the GPU while maintaining the integrity of standard transformation pipelines.

Accessing Untransformed Coordinates

In traditional WebGL GLSL pipelines, displacement begins by reading the mesh's attribute vec3 position. In the WebGPU node architecture, positionLocal provides direct access to this same attribute. Because these coordinates are relative to the mesh's origin and unaffected by world positioning, rotation, or scale, they offer a consistent coordinate space. This makes positionLocal essential for sampling displacement maps, procedural noise functions, or trigonometric waves, as sampling based on local coordinates ensures that the displacement pattern remains pinned to the mesh when the object moves through a scene.

Acting as the Displacement Base

The primary functional role of positionLocal during vertex displacement is serving as the baseline to which displacement offsets are added. To alter vertex positions, developers typically calculate a displacement vector—often by multiplying the vertex normal (normalLocal) by a scalar value or noise output—and add it directly to positionLocal.

For example, a common displacement expression in TSL follows this pattern:

const displacement = normalLocal.mul(noiseValue);
material.positionNode = positionLocal.add(displacement);

By assigning this combined node to the material's positionNode, the material pipeline substitutes the original static vertex coordinates with the displaced version.

Integration with the Transformation Pipeline

After positionLocal is augmented with displacement offsets, the node system automatically handles the downstream matrix transformations. The displaced local position is passed into the model-view-projection matrix chain, converting the custom local positions into clip space for rasterization. Because positionLocal sits at the very beginning of the vertex processing stage, displacing geometry via this node guarantees that depth calculations, shadow map generation, and bounding volume updates conform properly to the deformed mesh.
