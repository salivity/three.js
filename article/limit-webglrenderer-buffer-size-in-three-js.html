Limit WebGLRenderer Buffer Size in Three.js

Decoupling the WebGL drawing buffer size from the CSS display size allows you to cap rendering resolution and maintain high frame rates on high-DPI displays without breaking responsive page layouts. By default, Three.js synchronizes the canvas's internal pixel dimensions with its CSS dimensions. You can strictly constrain the internal buffer resolution while letting CSS scale the canvas to fill its container by disabling automatic style updates and clamping dimensions during resize events.

The Core Mechanism: renderer.setSize(width, height, false)

The key to separating buffer size from CSS size is the third parameter of WebGLRenderer.setSize(), which represents updateStyle. It defaults to true. When set to false, Three.js updates the internal drawing buffer attributes (canvas.width and canvas.height) without modifying the inline CSS properties (canvas.style.width and canvas.style.height).

Step 1: Configure CSS Dimensions

Let CSS manage the visual presentation and responsiveness of the canvas element. Assign the canvas a CSS class or inline styling so it stretches to fit its container:

canvas.webgl-canvas {
  width: 100%;
  height: 100%;
  display: block;
}

Step 2: Clamp Dimensions on Resize

When initializing or resizing the renderer, read the canvas's CSS layout dimensions via clientWidth and clientHeight (or window.innerWidth and window.innerHeight). Apply your maximum threshold to these values before passing them to renderer.setSize().

const canvas = document.querySelector('canvas.webgl-canvas');
const renderer = new THREE.WebGLRenderer({ canvas });

// Define the maximum hardware drawing buffer dimensions
const MAX_WIDTH = 1920;
const MAX_HEIGHT = 1080;

function resizeRenderer() {
  const displayWidth = canvas.clientWidth;
  const displayHeight = canvas.clientHeight;

  // Calculate aspect ratio from the display size to prevent image stretching
  const aspect = displayWidth / displayHeight;

  // Compute scaled buffer size that respects maximum thresholds
  let bufferWidth = displayWidth;
  let bufferHeight = displayHeight;

  if (bufferWidth > MAX_WIDTH || bufferHeight > MAX_HEIGHT) {
    if (bufferWidth / MAX_WIDTH > bufferHeight / MAX_HEIGHT) {
      bufferWidth = MAX_WIDTH;
      bufferHeight = Math.round(MAX_WIDTH / aspect);
    } else {
      bufferHeight = MAX_HEIGHT;
      bufferWidth = Math.round(MAX_HEIGHT * aspect);
    }
  }

  // Check if buffer dimensions actually changed to avoid unnecessary resizes
  const needResize = canvas.width !== bufferWidth || canvas.height !== bufferHeight;

  if (needResize) {
    // Pass false to prevent Three.js from overriding canvas.style dimensions
    renderer.setSize(bufferWidth, bufferHeight, false);
    
    camera.aspect = aspect;
    camera.updateProjectionMatrix();
  }
}

window.addEventListener('resize', resizeRenderer);
resizeRenderer();

Pixel Ratio Considerations

When implementing strict buffer limits, avoid using renderer.setPixelRatio(window.devicePixelRatio) concurrently with raw display dimensions, as this multiplies the internal buffer size and can easily exceed your target resolution on Retina or 4K screens.

If you want to account for device pixel ratio up to a strict limit, multiply the display dimensions by window.devicePixelRatio before applying your maximum clamp:

const pixelRatio = window.devicePixelRatio || 1;
const rawWidth = canvas.clientWidth * pixelRatio;
const rawHeight = canvas.clientHeight * pixelRatio;

const bufferWidth = Math.min(rawWidth, MAX_WIDTH);
const bufferHeight = Math.min(rawHeight, MAX_HEIGHT);

renderer.setPixelRatio(1); // Set to 1 because scaling is handled manually
renderer.setSize(bufferWidth, bufferHeight, false);

By manually calculating dimensions, setting renderer.setPixelRatio(1), and passing false to renderer.setSize(), the drawing buffer remains strictly within your performance budget while CSS handles display scaling cleanly.
