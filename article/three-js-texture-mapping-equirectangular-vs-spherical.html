Three.js Texture Mapping: Equirectangular vs Spherical

In Three.js, the Texture.mapping property dictates how two-dimensional image coordinates correspond to three-dimensional surfaces and reflection vectors. When switching between equirectangular and spherical environments, configuring Texture.mapping correctly is critical because it tells the underlying WebGL shaders which mathematical projection algorithm to use when sampling the texture. Without setting the proper mapping type, an environment will display severe distortions, pinching, or incorrectly oriented reflections on materials.

The Role of Texture.mapping

The Texture.mapping property defines the UV coordinate calculation mode for textures assigned as backgrounds, environment maps (scene.environment), or material properties (Material.envMap).

By default, standard textures load with THREE.UVMapping, which is intended for ordinary 2D surface wrapping. For environment and reflection maps, Three.js provides dedicated mapping constants that interpret 3D direction vectors to look up colors in specific image projections.

Equirectangular Environments

Equirectangular textures represent a 360-degree horizontal and 180-degree vertical panorama flattened into a standard 2:1 aspect ratio image, mapping spherical coordinates directly to latitude and longitude.

To use an equirectangular image as an environment:

texture.mapping = THREE.EquirectangularReflectionMapping;

When this constant is applied:

  • The shader converts the reflection vector into spherical coordinates (phi and theta) to sample the equirectangular map accurately across all viewing angles.
  • If refraction is needed instead of reflection, THREE.EquirectangularRefractionMapping is used.
  • Modern Three.js physically based rendering (PBR) workflows rely on EquirectangularReflectionMapping alongside PMREMGenerator to compute pre-filtered mipmaps for realistic roughness and image-based lighting (IBL).

Spherical Environments

Spherical environment maps—often called "sphere maps" or "matcap-style" maps—represent the environment as if reflected on a mirrored sphere viewed from an infinite distance (a circular fish-eye projection contained within a square image).

To switch to a traditional spherical map:

texture.mapping = THREE.SphericalReflectionMapping;

When this constant is applied:

  • The shader calculates texture coordinates based on the view-space normal vectors, looking up pixels directly from the circular spherical projection.
  • Because the image assumes a fixed viewpoint, it does not provide true 360-degree rotational awareness in free-camera scenes and is mostly reserved for static, lightweight stylized reflections or legacy assets.

Impact of Switching Mappings

Switching between these formats requires both changing the image source and updating the Texture.mapping property:

  1. Shader Recompilation: When mapping is updated on an active material or scene environment, Three.js must select different sampling logic in the fragment shader. You must set material.needsUpdate = true or reassign scene.environment to trigger the update.
  2. Distortion Prevention: Assigning an equirectangular image to THREE.SphericalReflectionMapping causes the panorama to appear pinched into an unnatural circular warp. Conversely, assigning a spherical map to THREE.EquirectangularReflectionMapping results in extreme seam artifacts, stretched poles, and distorted horizons.
  3. Lighting Consistency: Modern PBR materials expect cubemaps or equirectangular textures processed via PMREMGenerator. Spherical reflection mapping does not integrate natively with standard PBR IBL pipelines, meaning diffuse irradiance and specular roughness will not compute correctly without an equirectangular source.
