Global Custom Shader Chunks in Three.js

Three.js manages its internal shading pipeline using modular GLSL code snippets known as shader chunks. By directly modifying the THREE.ShaderChunk dictionary, you can register custom GLSL functions, constants, or overrides that become globally accessible across your application. This guide explains how to define a custom shader chunk, reference it using the #include directive, and override default Three.js shader behavior globally.

Understanding THREE.ShaderChunk

In Three.js, THREE.ShaderChunk is a standard JavaScript object containing string-based GLSL code snippets. Built-in materials (such as MeshStandardMaterial and MeshBasicMaterial) construct their complete vertex and fragment programs by stitching together these chunks.

Because THREE.ShaderChunk is exposed on the global THREE namespace, you can add new keys to it or overwrite existing keys at application startup.

Defining and Assigning a New Chunk

To create a reusable GLSL block, assign a template literal string containing your GLSL code to a new property on THREE.ShaderChunk.

import * as THREE from 'three';

// Define a reusable custom GLSL chunk
THREE.ShaderChunk['simplex_noise'] = `
  vec3 mod289(vec3 x) { return x - floor(x * (1.0 / 289.0)) * 289.0; }
  vec4 mod289(vec4 x) { return x - floor(x * (1.0 / 289.0)) * 289.0; }
  vec4 permute(vec4 x) { return mod289(((x*34.0)+1.0)*x); }
  vec4 taylorInvSqrt(vec4 r) { return 1.79284291400159 - 0.85373472095314 * r; }

  float snoise(vec3 v) {
    // Simplex noise implementation...
    return 0.0;
  }
`;

Using the Custom Chunk in Materials

Once registered, you can include your custom chunk in any ShaderMaterial or through the onBeforeCompile hook of standard materials using the #include <chunk_name> syntax. Three.js preprocesses this directive and substitutes it with your stored string before sending the shader to the GPU.

In a ShaderMaterial

const customMaterial = new THREE.ShaderMaterial({
  vertexShader: `
    varying vec2 vUv;
    void main() {
      vUv = uv;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `,
  fragmentShader: `
    varying vec2 vUv;
    
    // Include the globally registered chunk
    #include <simplex_noise>

    void main() {
      float n = snoise(vec3(vUv * 10.0, 1.0));
      gl_FragColor = vec4(vec3(n), 1.0);
    }
  `
});

In Built-in Materials with onBeforeCompile

You can also inject the chunk into existing materials without rewriting the standard lighting models:

const standardMaterial = new THREE.MeshStandardMaterial({ color: 0xffffff });

standardMaterial.onBeforeCompile = (shader) => {
  // Inject the custom chunk before the main entry point
  shader.fragmentShader = `
    #include <simplex_noise>
  ` + shader.fragmentShader;

  // Use the included function inside the shader logic
  shader.fragmentShader = shader.fragmentShader.replace(
    '#include <dithering_fragment>',
    `
    #include <dithering_fragment>
    gl_FragColor.rgb += snoise(vec3(vWorldPosition * 0.1));
    `
  );
};

Globally Overriding Existing Built-in Chunks

To alter the visual behavior of all standard materials across your entire scene, you can overwrite existing Three.js chunks directly.

For example, to globally modify how fog behaves across all materials:

// Overwrite the default fog chunk globally
THREE.ShaderChunk['fog_fragment'] = `
  #ifdef USE_FOG
    float customFogDepth = length(vViewPosition);
    float customFogFactor = smoothstep(fogNear, fogFar, customFogDepth);
    gl_FragColor.rgb = mix(gl_FragColor.rgb, fogColor, customFogFactor);
  #endif
`;

Any standard material compiled after this assignment will automatically use your modified fog algorithm instead of the Three.js default. Ensure all modifications to THREE.ShaderChunk occur before compiling materials to avoid caching issues.
