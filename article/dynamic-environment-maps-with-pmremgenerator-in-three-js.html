Dynamic Environment Maps with PMREMGenerator in Three.js

This guide explains how to generate prefiltered environment maps dynamically using PMREMGenerator in Three.js. You will learn how to capture real-time scene data using a CubeCamera, process the cubemap into a prefiltered radiance environment map (PMREM), apply it to physically based materials for accurate reflections, and manage GPU memory efficiently during dynamic updates.

Understanding PMREM in Three.js

Physically Based Rendering (PBR) materials such as MeshStandardMaterial and MeshPhysicalMaterial rely on Image-Based Lighting (IBL) to display realistic ambient light and reflections. Rough surfaces require blurred reflections, while smooth surfaces require sharp reflections.

PMREMGenerator (Prefiltered Mipmapped Radiance Environment Map Generator) precomputes these blur levels across cube map mipmaps. While static HDR images are typically processed once at load time, dynamic scenes—such as changing day-night cycles, moving objects, or moving reflective bodies—require generating these maps on the fly.

Step-by-Step Implementation

1. Instantiate the PMREMGenerator

Initialize the PMREMGenerator by passing your active WebGLRenderer instance. It is recommended to compile the internal shaders ahead of time using compileCubemapShader().

import * as THREE from 'three';

const pmremGenerator = new THREE.PMREMGenerator(renderer);
pmremGenerator.compileCubemapShader();

2. Set Up a CubeCamera and Render Target

To capture dynamic surroundings, create a WebGLCubeRenderTarget and a CubeCamera.

const cubeRenderTarget = new THREE.WebGLCubeRenderTarget(256, {
  type: THREE.HalfFloatType,
  format: THREE.RGBAFormat,
  generateMipmaps: false,
  minFilter: THREE.LinearFilter,
  magFilter: THREE.LinearFilter
});

const cubeCamera = new THREE.CubeCamera(0.1, 1000, cubeRenderTarget);
scene.add(cubeCamera);

3. Update and Generate the PMREM Dynamically

In your animation loop or update trigger, hide the reflective object to prevent it from rendering itself, update the CubeCamera, generate the prefiltered texture using pmremGenerator.fromCubemap(), and assign it to your scene or material.

let dynamicEnvMap = null;

function updateEnvironmentMap(reflectiveMesh) {
  // Hide the reflective object so it doesn't reflect itself
  reflectiveMesh.visible = false;

  // Position the cubeCamera at the reflective object's position
  cubeCamera.position.copy(reflectiveMesh.position);

  // Update the cube camera
  cubeCamera.update(renderer, scene);

  // Make the object visible again
  reflectiveMesh.visible = true;

  // Dispose of the previous PMREM render target to prevent memory leaks
  if (dynamicEnvMap) {
    dynamicEnvMap.dispose();
  }

  // Generate the PMREM from the cubemap texture
  dynamicEnvMap = pmremGenerator.fromCubemap(cubeRenderTarget.texture);

  // Apply to the specific material or the entire scene
  reflectiveMesh.material.envMap = dynamicEnvMap.texture;
  reflectiveMesh.material.needsUpdate = true;
  
  // Alternatively apply globally:
  // scene.environment = dynamicEnvMap.texture;
}

4. Using pmremGenerator.fromScene() Alternative

If you do not need a local perspective from a CubeCamera and instead want to re-filter an entire scene (for instance, when changing dynamic sky lighting or background colors), you can use pmremGenerator.fromScene() directly:

function updateSceneEnvironment() {
  if (dynamicEnvMap) {
    dynamicEnvMap.dispose();
  }

  // Generates PMREM directly from a scene setup
  dynamicEnvMap = pmremGenerator.fromScene(scene, 0.04); // second param is sigma/blur
  scene.environment = dynamicEnvMap.texture;
}

Performance and Memory Management

Generating a PMREM involves rendering the scene six times (once for each cube face) and then running multiple filtering passes across mip levels. Doing this on every frame will cause performance drops.

  • Throttle Updates: Update the PMREM map only when scene conditions change, or stagger updates across multiple frames (e.g., updating once every 5 to 10 frames).
  • Lower Resolution: Keep the WebGLCubeRenderTarget resolution low (e.g., 128x128 or 256x256). Because roughness blurs the environment map, high resolutions are rarely necessary for realistic lighting.
  • Dispose Textures: Always call .dispose() on the resulting WebGLRenderTarget returned by pmremGenerator.fromCubemap() before overwriting it to avoid GPU memory leaks.
  • Cleanup: When the component or scene unmounts, call pmremGenerator.dispose(), cubeRenderTarget.dispose(), and dispose of any generated textures.
