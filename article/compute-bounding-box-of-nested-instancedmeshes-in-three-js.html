Compute Bounding Box of Nested InstancedMeshes in Three.js

Computing the world-space bounding box of nested InstancedMesh hierarchies in Three.js requires compounding scene graph transformations with individual instance transformation matrices. Because InstancedMesh decouples a single geometry from multiple render instances via an internal matrix buffer, standard Three.js methods like Box3.setFromObject() fail to account for per-instance spatial extents. This article details the mathematical foundation and an optimized algorithmic implementation to compute a precise world-space Axis-Aligned Bounding Box (AABB) for complex, nested instanced hierarchies.

The Mathematical Problem

An object's position in a Three.js scene graph is governed by its global world matrix, \(M_{world}\), which is the recursive product of its local transformation matrix and all ancestor transformation matrices:

\[M_{world} = \prod_{i=0}^{n} M_{local}^{(i)}\]

For a standard Mesh, computing the world-space AABB involves applying \(M_{world}\) directly to the 8 vertices of its local bounding box \(B_{local} = [\mathbf{v}_{min}, \mathbf{v}_{max}]\).

However, an InstancedMesh adds an additional layer of transformation. Each instance \(k \in [0, N-1]\) possesses its own transformation matrix \(I_k\). Therefore, the definitive transformation \(W_k\) that maps a local vertex \(\mathbf{x}\) of instance \(k\) to world space is:

\[W_k = M_{world} \cdot I_k\]

Given that an affine transformation matrix \(W_k\) consists of a \(3 \times 3\) linear transformation block \(A_k\) and a translation vector \(\mathbf{t}_k\):

\[W_k = \begin{bmatrix} A_k & \mathbf{t}_k \\ \mathbf{0}^T & 1 \end{bmatrix}\]

Applying this transformation to all instances across multiple nested hierarchies requires computing the minimal and maximal components along all three Cartesian axes across all transformed geometries:

\[B_{global} = \left[ \min_{k, j} \left( W_k \mathbf{v}_j \right), \max_{k, j} \left( W_k \mathbf{v}_j \right) \right]\]

where \(\mathbf{v}_j\) denotes the vertices of the base BufferGeometry.

Transforming Local Bounding Boxes Efficiently

Transforming every vertex of a high-poly geometry for thousands of instances is computationally prohibitive (\(O(N \cdot V)\), where \(N\) is the instance count and \(V\) is the vertex count).

Instead, transform the local AABB of the geometry (\(O(N)\)). While transforming an AABB and re-aligning it introduces slight conservative padding compared to transforming raw vertices, it remains mathematically rigorous for spatial partitioning and frustum culling.

For an axis-aligned box defined by center \(\mathbf{c}\) and half-extents \(\mathbf{e}\):

\[\mathbf{c} = \frac{\mathbf{v}_{max} + \mathbf{v}_{min}}{2}, \quad \mathbf{e} = \frac{\mathbf{v}_{max} - \mathbf{v}_{min}}{2}\]

Under affine transform \(W_k = (A_k, \mathbf{t}_k)\), the transformed center \(\mathbf{c}'\) and the new half-extents \(\mathbf{e}'\) are:

\[\mathbf{c}' = A_k \mathbf{c} + \mathbf{t}_k\]

\[\mathbf{e}' = |A_k| \mathbf{e}\]

where \(|A_k|\) is the matrix containing the absolute values of the elements of \(A_k\):

\[e'_i = \sum_{j=1}^{3} |A_{k, ij}| e_j \quad \text{for } i \in \{1, 2, 3\}\]

The transformed instance bounds \([ \mathbf{c}' - \mathbf{e}', \mathbf{c}' + \mathbf{e}' ]\) are then merged into the master bounding box.

Algorithmic Implementation

To compute the bounding box over an arbitrarily nested group:

  1. Force a synchronous update of all parent transforms using updateWorldMatrix(true, true).
  2. Traverse the scene graph depth-first.
  3. For each encountered node:
    • If it is a standard Mesh, apply the conventional bounding transform.
    • If it is an InstancedMesh, retrieve the base geometry bounds, iterate over all instance indices, compute \(W_k = M_{world} \cdot I_k\), compute the instance AABB, and expand the master Box3.
import * as THREE from 'three';

const _instanceMatrix = new THREE.Matrix4();
const _combinedMatrix = new THREE.Matrix4();
const _box = new THREE.Box3();

export function computeNestedInstancedBoundingBox(rootObject) {
    // 1. Ensure all world matrices in the hierarchy are up to date
    rootObject.updateWorldMatrix(true, true);

    const totalBounds = new THREE.Box3();
    totalBounds.makeEmpty();

    // 2. Traverse the hierarchy
    rootObject.traverse((node) => {
        if (!node.geometry) return;

        // Ensure geometry has a valid local bounding box
        if (!node.geometry.boundingBox) {
            node.geometry.computeBoundingBox();
        }
        const localBox = node.geometry.boundingBox;

        if (node.isInstancedMesh) {
            const count = node.count !== undefined ? node.count : node.instanceMatrix.count;

            for (let i = 0; i < count; i++) {
                // Get the instance matrix relative to the InstancedMesh local space
                node.getMatrixAt(i, _instanceMatrix);

                // Multiply: CombinedMatrix = NodeWorldMatrix * InstanceLocalMatrix
                _combinedMatrix.multiplyMatrices(node.matrixWorld, _instanceMatrix);

                // Transform local geometry box by the combined matrix
                _box.copy(localBox).applyMatrix4(_combinedMatrix);

                // Union into the total AABB
                totalBounds.union(_box);
            }
        } else if (node.isMesh) {
            _box.copy(localBox).applyMatrix4(node.matrixWorld);
            totalBounds.union(_box);
        }
    });

    return totalBounds;
}

Edge Cases and Performance Considerations

  • Dynamic Instance Counts: When an InstancedMesh uses dynamic allocation, the count property defines the active renderable subset. The loop must iterate up to node.count, not the underlying array buffer capacity (node.instanceMatrix.count), to prevent indexing uninitialized or phantom instances at the origin.
  • Morph Targets and Skinned Meshes: If instances utilize vertex displacement shaders or software bones, static CPU bounding calculations based on the base BufferGeometry do not account for custom vertex deformations without custom bounding routines.
  • Memory Allocation: Instantiating temporary Box3, Vector3, or Matrix4 objects inside traversal loops introduces severe garbage collection latency. Cache static references (_instanceMatrix, _combinedMatrix, _box) outside the evaluation scope.
