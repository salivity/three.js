Three.js Stencil Buffer Masking in EffectComposer

This article provides a direct guide on using the WebGL stencil buffer to mask post-processing effects in Three.js using EffectComposer. You will learn how to configure a render target with stencil support, mark specific geometries in the stencil buffer, and leverage Three.js's built-in MaskPass and ClearMaskPass to isolate post-processing shaders so they affect only designated objects in your scene.

1. Enable the Stencil Buffer in EffectComposer

By default, the internal render targets created by EffectComposer may not have stencil operations properly configured. You must initialize a THREE.WebGLRenderTarget with stencilBuffer: true and pass it to the composer constructor.

import * as THREE from 'three';
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { ShaderPass } from 'three/addons/postprocessing/ShaderPass.js';
import { MaskPass, ClearMaskPass } from 'three/addons/postprocessing/MaskPass.js';

// Create a custom render target with stencil support
const renderTarget = new THREE.WebGLRenderTarget(
    window.innerWidth,
    window.innerHeight,
    {
        stencilBuffer: true,
        depthBuffer: true
    }
);

const composer = new EffectComposer(renderer, renderTarget);

2. Configure the RenderPass

Add your primary RenderPass to render the initial scene. Ensure your main WebGLRenderer has stencil: true in its initialization options (enabled by default in Three.js).

const renderPass = new RenderPass(scene, camera);
composer.addPass(renderPass);

3. Set Up Masking with MaskPass and ClearMaskPass

Three.js provides MaskPass and ClearMaskPass explicitly to handle stencil buffer masking inside the post-processing pipeline. MaskPass renders a designated scene (or sub-scene) directly into the stencil buffer, enabling hardware clipping for any passes placed between it and ClearMaskPass.

Creating the Mask Scene

Create an isolated scene containing only the meshes that should serve as the mask:

const maskScene = new THREE.Scene();

// The mesh to act as the mask boundary
const maskMesh = new THREE.Mesh(geometry, new THREE.MeshBasicMaterial());
maskScene.add(maskMesh);

Keep the transform (position, rotation, scale) of maskMesh synchronized with the object in the main scene you want to mask.

Adding the Passes to the Composer

Assemble the passes in sequence: write the mask, apply the effect, and clear the mask.

// 1. Write the mask shape into the stencil buffer
const maskPass = new MaskPass(maskScene, camera);
composer.addPass(maskPass);

// 2. Add the effect pass to be restricted (e.g., an inversion or glitch shader)
const effectPass = new ShaderPass(MyCustomPostShader);
composer.addPass(effectPass);

// 3. Disable the stencil mask and reset the buffer state
const clearMaskPass = new ClearMaskPass();
composer.addPass(clearMaskPass);

MaskPass automatically sets up the required stencil functions:

  • It sets gl.stencilFunc(gl.ALWAYS, 1, 0xff).
  • It writes values where the mask geometry renders (gl.stencilOp(gl.KEEP, gl.KEEP, gl.REPLACE)).
  • Subsequent passes are rendered with gl.stencilFunc(gl.EQUAL, 1, 0xff), restricting pixel rendering strictly to the masked region.
  • ClearMaskPass resets the stencil testing state and clears the stencil bits.

4. Alternative: Manual Stencil Configuration via Materials

If you prefer not to use a separate MaskPass and maskScene, you can configure materials directly within the main scene to write to the stencil buffer during the initial RenderPass.

Configure the target mesh's material:

const stencilMaterial = new THREE.MeshStandardMaterial({ color: 0xff0000 });
stencilMaterial.stencilWrite = true;
stencilMaterial.stencilRef = 1;
stencilMaterial.stencilFunc = THREE.AlwaysStencilFunc;
stencilMaterial.stencilZPass = THREE.ReplaceStencilOp;

To restrict a subsequent custom ShaderPass to this stencil value, inject stencil state management into the pass execution:

const effectPass = new ShaderPass(MyCustomPostShader);

// Hook into pass rendering to enforce stencil testing
const originalRender = effectPass.render.bind(effectPass);
effectPass.render = function (renderer, writeBuffer, readBuffer, deltaTime, maskActive) {
    const gl = renderer.getContext();
    
    renderer.state.buffers.stencil.setTest(true);
    renderer.state.buffers.stencil.setFunc(gl.EQUAL, 1, 0xff);
    renderer.state.buffers.stencil.setOp(gl.KEEP, gl.KEEP, gl.KEEP);

    originalRender(renderer, writeBuffer, readBuffer, deltaTime, maskActive);

    renderer.state.buffers.stencil.setTest(false);
};

composer.addPass(effectPass);

Critical Caveats

  • Buffer Swapping: EffectComposer alternates between two internal render targets. Ensure the custom render target created in Step 1 is duplicated correctly by the composer so both read and write buffers retain depth and stencil allocations.
  • Auto-Clear Settings: If subsequent passes clear the frame buffer automatically, the stencil values can be wiped prematurely. MaskPass handles clearing internally; if executing manually, verify that pass.clear = false on passes operating inside the masked boundary.
