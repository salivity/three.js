Synchronize AnimationAction Phase with syncWith in Three.js

This guide explains how to precisely align the playback phase of two separate AnimationAction instances in Three.js using the .syncWith() method. You will learn the mechanics behind .syncWith(), how to handle animation clips with identical or differing durations, and how to combine phase synchronization with weight crossfading for seamless transitions such as blending a walk cycle into a run cycle.

Understanding syncWith

In Three.js, an AnimationAction controls the playback of an AnimationClip. When transitioning between cyclic animations (like locomotion cycles), failing to align the phase causes limbs to snap or desynchronize.

The syncWith(action) method synchronizes the calling action to a reference action by copying two internal properties:

  • time: Sets the current playback position (in seconds) to match the target action.
  • timeScale: Sets the playback speed to match the target action.
secondaryAction.syncWith(primaryAction);

Synchronizing Clips of Equal Duration

When both animation clips share the exact same duration, synchronizing the phase requires only a single call to .syncWith().

// Retrieve actions from your AnimationMixer
const walkAction = mixer.clipAction(walkClip);
const walkFastAction = mixer.clipAction(walkFastClip);

// Start the primary action
walkAction.play();

// Prepare and synchronize the second action
walkFastAction.play();
walkFastAction.syncWith(walkAction);

Because their durations are identical, matching absolute playback time (time) automatically matches the normalized playback phase (\(0.0\) to \(1.0\)).

Synchronizing Clips of Different Durations

If two cyclic clips have different durations (for example, a 1.2-second walk cycle and an 0.8-second run cycle), copying absolute time directly will cause phase misalignment. To achieve identical phase synchronization, you must adjust the playback speed (timeScale) or normalize the time relative to their durations.

Method: Scale timeScale to Maintain Proportional Phase

To keep both actions continuously in phase over multiple loops, adjust the timeScale of the target action proportionally to the ratio of their durations before calling .syncWith():

const walkAction = mixer.clipAction(walkClip); // duration: 1.2s
const runAction = mixer.clipAction(runClip);   // duration: 0.8s

// Calculate the duration ratio
const ratio = runClip.duration / walkClip.duration;

// Match the phase dynamically
runAction.time = (walkAction.time / walkClip.duration) * runClip.duration;
runAction.timeScale = walkAction.timeScale * ratio;

// Call syncWith to link synchronization
runAction.syncWith(walkAction);

By factoring the duration ratio into timeScale, both clips complete their full cycles in parallel, ensuring that key phase events (such as footfalls) occur at the exact same moment.

Seamless Blending and Crossfading

Synchronizing phase is most commonly used right before crossfading between two animations. Synchronize the phase immediately before applying the transition to eliminate visual stutter:

function transitionToRun(mixer, walkAction, runAction, duration = 0.5) {
    // 1. Ensure the destination action is enabled and active
    runAction.reset();
    runAction.enabled = true;

    // 2. Align the phase of the new action to the current action
    runAction.syncWith(walkAction);

    // 3. If durations differ, adjust timeScale relative to duration
    const ratio = runAction.getClip().duration / walkAction.getClip().duration;
    runAction.timeScale = walkAction.timeScale * ratio;

    // 4. Crossfade weights smoothly
    walkAction.crossFadeTo(runAction, duration, true);
    runAction.play();
}

Essential Rules for Stable Synchronization

  • Call order matters: Ensure the primary action is already updating or playing so that its time value is valid before passing it into syncWith().
  • Loop settings: Both actions should share the same loop configuration (typically THREE.LoopRepeat) to prevent one action from stopping while the other continues.
  • Mixer updates: Phase synchronization calculations should occur outside or prior to mixer.update(deltaTime) in your render loop to prevent one-frame synchronization offsets.
