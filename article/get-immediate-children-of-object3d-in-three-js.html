Get Immediate Children of Object3D in Three.js

Extracting the immediate children of an Object3D in Three.js without triggering a recursive traversal of the entire scene graph is straightforward. This guide explains how to access direct child nodes using the native .children property, contrasts this approach with deep-traversal methods like .traverse(), and covers best practices for safely reading or modifying direct descendants.

Using the .children Property

In Three.js, every instance of THREE.Object3D (including Mesh, Group, and Scene) contains a native property named children. This property is a standard JavaScript array containing references only to the object's immediate direct children.

Unlike the .traverse() method, which recursively visits every descendant down through all nested levels of the hierarchy, accessing .children does not step into nested child objects.

Reading Immediate Children

To inspect or process immediate children without modifying the hierarchy, you can read or iterate through the array directly:

// Access the direct children array
const directChildren = myObject.children;

// Iterate over direct children only
myObject.children.forEach((child) => {
  console.log(child.name || child.uuid);
});

Safely Copying the Children Array

If your goal is to extract the list to manipulate, re-parent, or remove the children, you should create a shallow copy of the array.

Modifying an object's parentage (for example, calling parent.remove(child) or scene.add(child)) mutates the original .children array in place. Iterating over the live array while mutating it leads to skipped elements and index shifting.

Example: Cloning the Array Before Mutation

Use the spread operator or .slice() to extract an independent array of immediate child references:

// Create a shallow copy of the immediate children
const immediateChildren = [...myObject.children];

// Now it is safe to iterate and remove or re-parent
immediateChildren.forEach((child) => {
  myObject.remove(child);
  // or perform other operations such as moving to a new parent:
  // anotherObject.add(child);
});

By relying directly on myObject.children instead of .traverse(), you ensure your operations remain strictly confined to the immediate level of your object's hierarchy with optimal performance.
