How to Change Three.js Mesh Depth Sorting Point

In Three.js, transparent meshes are automatically sorted and rendered back-to-front based on their distance to the camera, which is evaluated directly from each mesh's origin (matrixWorld position). For elongated, offset, or asymmetric geometries, this default behavior often causes sorting artifacts because the origin may not represent the visual depth of the mesh. You can override this behavior either by overriding the renderer's default sorting function using renderer.setTransparentSort() to calculate depth against custom coordinates, or by shifting the underlying geometry so the mesh origin sits at the desired evaluation point.

Method 1: Using renderer.setTransparentSort

The cleanest and most flexible way to evaluate sorting against a custom coordinate is to implement a custom transparent sorting function on the WebGLRenderer. Three.js assigns each render item a .z depth during the scene traversal, but setTransparentSort lets you redefine how items are compared before rendering.

Store your custom sorting point in the mesh's userData, then compute the distance from the camera to that point inside the custom sort callback:

import * as THREE from 'three';

// 1. Assign a custom evaluation coordinate in world space
mesh.userData.sortPoint = new THREE.Vector3(10, 0, 5);

// Vectors for calculation to avoid garbage collection
const posA = new THREE.Vector3();
const posB = new THREE.Vector3();

// 2. Override the transparent sort function
renderer.setTransparentSort((a, b) => {
    // Check if custom sort points are defined, otherwise fall back to object origin
    const pointA = a.object.userData.sortPoint 
        ? posA.copy(a.object.userData.sortPoint) 
        : a.object.getWorldPosition(posA);

    const pointB = b.object.userData.sortPoint 
        ? posB.copy(b.object.userData.sortPoint) 
        : b.object.getWorldPosition(posB);

    // Transform points to camera space to get depth along the camera's view axis
    pointA.applyMatrix4(camera.matrixWorldInverse);
    pointB.applyMatrix4(camera.matrixWorldInverse);

    // Sort back-to-front (larger negative z values render first)
    return pointA.z - pointB.z;
});

If your custom point is local to the mesh rather than static in world space, transform it by the mesh's world matrix first:

mesh.userData.localSortPoint = new THREE.Vector3(0, 2, -1);

// Inside the sorting function:
pointA.copy(a.object.userData.localSortPoint).applyMatrix4(a.object.matrixWorld);

Method 2: Offsetting Geometry at the Mesh Level

If you prefer not to override the renderer's sorting algorithm globally, you can adjust the origin of the mesh itself so that its translation matrix aligns with the desired evaluation point.

Translate the geometry vertices in the opposite direction of the desired pivot point:

// Shift the geometry vertices so (0, 0, 0) represents your desired depth anchor
geometry.translate(-targetX, -targetY, -targetZ);

// Move the mesh position to the target coordinates in the scene
mesh.position.set(targetX, targetY, targetZ);

This ensures the mesh origin—and therefore the default Three.js depth evaluation coordinate—sits precisely where the sorting logic needs it to be without altering the visible placement of the geometry.

Manual Render Order Override

When an object must always render in front of or behind another regardless of camera movement, bypassing coordinate calculation entirely via renderOrder is often the most performant solution:

mesh.renderOrder = 1; // Evaluated after meshes with default renderOrder = 0

Setting renderOrder explicitly forces Three.js to render meshes in strict ascending numerical order, completely bypassing distance-based depth sorting for those specific objects.
