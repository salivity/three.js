How FontLoader Converts JSON to TextGeometry in Three.js

This article explains how Three.js processes typography, detailing the pipeline where FontLoader parses a Typeface JSON file into two-dimensional vector paths and how TextGeometry transforms those paths into 3D extrusions. You will learn how font glyph commands are interpreted into vector shapes, how inner holes like those in the letters "O" and "B" are handled, and how the underlying extrusion engine generates a renderable 3D mesh.

The Typeface JSON Structure

Before conversion begins, TrueType (.ttf) or OpenType (.otf) fonts are converted into a JSON format using tools like facetype.js. This JSON file stores font metrics and individual glyph definitions instead of rasterized textures.

A typical glyph object in the JSON contains:

  • ha (Horizontal Advance): The horizontal distance the cursor advances after rendering the glyph.
  • x_min, x_max, y_min, y_max: Bounding box coordinates for the glyph.
  • o (Outline string): A sequence of vector path drawing commands, similar to SVG paths.

These outline commands represent discrete geometric instructions:

  • m: Move to (moveTo)
  • l: Line to (lineTo)
  • q: Quadratic Bézier curve (quadraticCurveTo)
  • b: Cubic Bézier curve (bezierCurveTo)

Step 1: Parsing with FontLoader

FontLoader loads the JSON file via FileLoader and passes the parsed JSON object to the Font class constructor (three/addons/loaders/FontLoader.js).

The Font instance acts as a layout and translation engine. It does not create 3D meshes directly; instead, it exposes the generateShapes() method, which converts a string of text into an array of THREE.Shape objects.

Step 2: Converting Path Commands into ShapePaths

When font.generateShapes(text, size) is called, the loader performs the following layout and conversion process:

  1. Scale Calculation: A scale factor is calculated by dividing the desired size by the font's internal resolution (unitsPerEm).
  2. String Traversal: The method iterates through each character in the input string, applying kerning and advancing the horizontal offset using each glyph's ha attribute.
  3. Command Execution: For each character, the outline commands are parsed and converted into a THREE.ShapePath object:
    • An m x y command starts a new sub-path at the scaled coordinates.
    • An l x y command calls path.lineTo(x, y).
    • A q x1 y1 x y command calls path.quadraticCurveTo(controlX, controlY, x, y).
    • A b x1 y1 x2 y2 x y command calls path.bezierCurveTo(cp1X, cp1Y, cp2X, cp2Y, x, y).

Step 3: Determining Solids and Holes

A character can consist of multiple closed outlines. For example, the letter "O" consists of an outer boundary and an inner boundary.

THREE.ShapePath.toShapes() processes these closed paths to separate solid geometry from voids:

  1. Winding Order (Orientation): The engine checks the orientation of each path loop using the Shoelace formula to compute the signed area. Typically, clockwise paths represent solid outer boundaries, while counter-clockwise paths represent interior cutouts (or vice versa, depending on configuration).
  2. Point Inclusion Tests: For ambiguous cases, the algorithm runs ray-casting point-in-polygon tests to detect whether one loop is nested entirely inside another.
  3. Hole Association: If a loop is determined to be inside an outer shape, it is pushed into the parent shape's holes array (shape.holes.push(holePath)).

The result of this stage is an array of fully defined THREE.Shape instances, each representing a complete, punctured 2D planar polygon.

Step 4: Extrusion via TextGeometry

TextGeometry is a specialized subclass of ExtrudeGeometry. When instantiated:

new TextGeometry(text, { font: font, size: 80, depth: 20, ... });

It immediately calls font.generateShapes() and passes the resulting array of THREE.Shape objects directly to the ExtrudeGeometry constructor along with extrusion parameters such as depth, bevelEnabled, bevelThickness, and bevelSegments.

The extrusion engine completes the transformation:

  1. Triangulation: The 2D front faces of the shapes (including their holes) are triangulated using the Earcut polygon triangulation algorithm.
  2. Side Wall Generation: Quad faces (split into two triangles) are generated between corresponding vertices on the front and back planes across the specified depth.
  3. Beveling (Optional): If beveling is enabled, normal offsets are calculated to taper or round the edges of the face before pushing the geometry along the Z-axis.
  4. BufferGeometry Output: All resulting vertices, normals, and UVs are packaged into a standard THREE.BufferGeometry, ready to be assigned a material and rendered in the 3D scene.
