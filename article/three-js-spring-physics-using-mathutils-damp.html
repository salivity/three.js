Three.js Spring Physics Using MathUtils.damp

This article explains how to achieve smooth, frame-rate independent movement in Three.js using the built-in THREE.MathUtils.damp function. By factoring in the render loop's delta time, you can simulate critically damped spring motion that behaves identically across displays with varying refresh rates, such as standard 60Hz screens and high-refresh 120Hz or 144Hz monitors.

The Problem with Traditional Lerping

A common method for smoothing movement toward a target is linear interpolation (lerp):

// Frame-rate dependent
currentPosition += (targetPosition - currentPosition) * 0.1;

This approach is inherently tied to the frame rate. At 144 FPS, this calculation runs more than twice as often as it does at 60 FPS, causing the object to reach the target significantly faster on high-refresh displays.

How MathUtils.damp Solves Frame-Rate Dependency

THREE.MathUtils.damp provides an analytical solution to an exponential decay differential equation (a critically damped system). Instead of using a fixed per-frame multiplier, it uses an exponential function based on the elapsed time between frames (delta).

The signature is:

THREE.MathUtils.damp(current, target, lambda, delta);
  • current: The current value (e.g., position, rotation, scale).
  • target: The destination value.
  • lambda: The damping factor. Higher values make the motion snap to the target faster; lower values produce a softer, slower spring effect.
  • delta: The time in seconds since the last frame, typically obtained from THREE.Clock.

The underlying formula is:

\[\text{value} = \text{target} + (\text{current} - \text{target}) \times e^{-\lambda \times \Delta t}\]

Because \(e^{-\lambda \times \Delta t}\) scales continuously with time, the object moves at the exact same physical speed regardless of how frequently frames are rendered.

Basic Implementation: Critically Damped Following

For UI elements, camera smoothing, or cursor-following objects that should smoothly glide into place without overshooting, use MathUtils.damp directly on the transform properties:

import * as THREE from 'three';

const clock = new THREE.Clock();
const mesh = new THREE.Mesh(geometry, material);
const targetPosition = new THREE.Vector3(5, 2, 0);
const lambda = 4.0; // Adjust for stiffness/speed

function animate() {
  requestAnimationFrame(animate);

  const delta = clock.getDelta();

  mesh.position.x = THREE.MathUtils.damp(mesh.position.x, targetPosition.x, lambda, delta);
  mesh.position.y = THREE.MathUtils.damp(mesh.position.y, targetPosition.y, lambda, delta);
  mesh.position.z = THREE.MathUtils.damp(mesh.position.z, targetPosition.z, lambda, delta);

  renderer.render(scene, camera);
}

animate();

Creating an Oscillating (Bouncy) Spring

Direct damping produces a critically damped motion (smooth glide with no bounce). If your project requires an underdamped spring with physical oscillation and overshoot, you can combine standard Hooke's Law spring acceleration with MathUtils.damp applied to the velocity:

import * as THREE from 'three';

const clock = new THREE.Clock();
const mesh = new THREE.Mesh(geometry, material);

const target = new THREE.Vector3(0, 0, 0);
const velocity = new THREE.Vector3();

const stiffness = 80.0; // Pull force towards target
const damping = 3.0;    // Decay factor for velocity

function animate() {
  requestAnimationFrame(animate);

  const delta = clock.getDelta();

  // 1. Calculate spring displacement force
  const displacement = new THREE.Vector3().subVectors(target, mesh.position);
  velocity.addScaledVector(displacement, stiffness * delta);

  // 2. Damp the velocity toward zero frame-independently
  velocity.x = THREE.MathUtils.damp(velocity.x, 0, damping, delta);
  velocity.y = THREE.MathUtils.damp(velocity.y, 0, damping, delta);
  velocity.z = THREE.MathUtils.damp(velocity.z, 0, damping, delta);

  // 3. Update the mesh position
  mesh.position.addScaledVector(velocity, delta);

  renderer.render(scene, camera);
}

animate();

In this implementation, stiffness governs how quickly the object seeks the target, while damping in MathUtils.damp controls how long the spring bounces before settling into rest. Both parameters remain completely stable across fluctuating frame rates.
