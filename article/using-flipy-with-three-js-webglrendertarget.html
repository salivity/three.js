Using flipY with Three.js WebGLRenderTarget

Rendering scenes to a WebGLRenderTarget in Three.js often results in vertically inverted textures due to discrepancies between standard image coordinate systems and WebGL framebuffer orientation. This article explains why the flipY property does not behave on WebGLRenderTarget textures the way it does on standard textures and provides practical, efficient solutions to ensure your rendered textures display with the correct vertical orientation.

Why flipY Does Not Work on WebGLRenderTarget

When loading external images via TextureLoader, Three.js sets texture.flipY = true by default. Under the hood, WebGL handles this during the CPU-to-GPU memory transfer using the WebGL state command:

gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true);

This unpack parameter only affects data transferred from CPU memory (such as an Image, Canvas, or ImageData) into GPU memory.

A WebGLRenderTarget, however, allocates a Framebuffer Object (FBO) directly in GPU memory. Because the pixels are rendered directly by the GPU, no pixel unpack operation takes place. Consequently, modifying renderTarget.texture.flipY = true has no effect on how the raw texture data is written or sampled. The texture’s coordinate origin remains at the bottom-left corner \((0, 0)\), matching native OpenGL screen coordinates.

Solution 1: Invert UV Coordinates via Texture Transform

The most performant and standard way to flip the orientation of a render target texture without re-rendering is to adjust its matrix transformation. You can achieve this by modifying the repeat and offset properties on the texture.

const renderTarget = new THREE.WebGLRenderTarget(width, height);

// Set up the target texture mapping
const texture = renderTarget.texture;
texture.wrapS = THREE.ClampToEdgeWrapping;
texture.wrapT = THREE.ClampToEdgeWrapping;

// Invert the vertical axis
texture.repeat.y = -1;
texture.offset.y = 1;

When this texture is applied to standard materials (like MeshBasicMaterial or MeshStandardMaterial), Three.js automatically incorporates the offset and repeat matrices into the vertex shader, sampling the texture right-side up.

Solution 2: Invert Coordinates in Custom Shaders

If you are sampling the render target within a custom ShaderMaterial or RawShaderMaterial, manually invert the vertical component of the texture coordinate (UV) in the fragment shader.

uniform sampler2D uRenderTargetTexture;
varying vec2 vUv;

void main() {
    // Invert the Y-axis UV coordinate
    vec2 correctedUv = vec2(vUv.x, 1.0 - vUv.y);
    vec4 color = texture2D(uRenderTargetTexture, correctedUv);

    gl_FragColor = color;
}

This approach avoids altering the texture's transformation properties and is ideal for custom post-processing pipelines.

Solution 3: Render Pass Flipping with Orthographic Camera

If you are using an intermediate render target to perform post-processing or screen-space blitting, you can flip the output at the projection stage. By rendering a full-screen quad using a reversed orthographic camera, the output geometry inverts naturally during the rasterization stage:

// Top and bottom values inverted: top = -1, bottom = 1
const blitCamera = new THREE.OrthographicCamera(-1, 1, -1, 1, 0, 1);
const blitQuad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), blitMaterial);

// Render pass to target or screen
renderer.setRenderTarget(null);
renderer.render(blitQuad, blitCamera);

Summary of Best Practices

  • Do not rely on renderTarget.texture.flipY = true because it does not trigger a GPU-side texture flip.
  • Use texture.repeat.y = -1 combined with texture.offset.y = 1 when assigning render target textures to built-in Three.js materials.
  • Use vec2(uv.x, 1.0 - uv.y) when sampling render targets inside custom fragment shaders.
