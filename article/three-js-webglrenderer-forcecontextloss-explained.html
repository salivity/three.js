Three.js WebGLRenderer forceContextLoss Explained

Calling WebGLRenderer.forceContextLoss() in a Three.js application programmatically simulates a GPU crash or driver failure by invalidating the active WebGL rendering context. This article explains the internal mechanics triggered by this method, detailing how Three.js queries browser extensions, clears internal GPU states, dispatches DOM events, and halts subsequent rendering commands.

Invocation of the WEBGL_lose_context Extension

Under the hood, WebGLRenderer.forceContextLoss() does not destroy the <canvas> DOM element or execute custom garbage collection routines. Instead, it accesses the browser's standard WEBGL_lose_context extension via the internal WebGLExtensions cache. The internal implementation in Three.js executes:

const extension = extensions.get( 'WEBGL_lose_context' );
if ( extension ) extension.loseContext();

If the browser supports this debugging extension, calling loseContext() tells the underlying graphics driver to detach the context from the underlying GPU hardware.

Hardware Resource Invalidation

Once loseContext() is triggered, the browser immediately purges all native WebGL resources allocated by that context. The GPU memory associated with the following resources is invalidated:

  • Compiled vertex and fragment shaders (WebGLProgram, WebGLShader)
  • Texture objects (WebGLTexture)
  • Vertex Buffer Objects (VBOs) and Index Buffer Objects (IBOs)
  • Framebuffer and Renderbuffer bindings (WebGLFramebuffer)

Subsequent low-level WebGL API calls to this context are treated as no-ops or will return gl.CONTEXT_LOST_WEBGL. Any state queries made to the context return null or default zero values.

The webglcontextlost Event Dispatch

Immediately after the driver invalidates the context, the browser fires the native DOM event webglcontextlost on the canvas element.

Three.js binds an internal listener to this event upon initialization. When fired, the renderer flags its internal state to prevent further draw calls. If event.preventDefault() is called within a listener attached to webglcontextlost, the browser is instructed that the application may attempt to restore the context later. If not prevented, the context remains permanently lost, requiring a full re-instantiation of the WebGLRenderer.

Impact on Three.js Internal Subsystems

Because Three.js uses centralized managers to track WebGL objects, the loss of context impacts several subsystems:

  • WebGLState: The internal state cache, which tracks active blend modes, depth functions, and bound textures to minimize redundant OpenGL state switches, becomes desynchronized with the actual GPU state.
  • WebGLTextures & WebGLGeometries: The internal WeakMap caches still hold references to CPU-side BufferGeometry and Texture instances, but the mapping to GPU-side memory addresses points to dead resource handles.
  • WebGLPrograms: The internal shader cache retains cached program metadata, meaning shaders must be recompiled from scratch if the context is ever restored.

Rendering Pipeline Suspension

If the application continues to call renderer.render(scene, camera) in an active requestAnimationFrame loop after calling forceContextLoss(), Three.js intercepts the cycle. Because the context is lost, the renderer skips binding framebuffers and suppresses draw operations (gl.drawElements or gl.drawArrays), preventing unhandled runtime exceptions from crashing the JavaScript execution thread.
