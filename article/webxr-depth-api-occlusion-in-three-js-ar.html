WebXR Depth API Occlusion in Three.js AR

This article provides a practical guide on implementing real-world object occlusion in a Three.js augmented reality (AR) scene using the WebXR Depth Sensing API. You will learn how to configure the WebXR session to request depth data, extract the hardware-generated depth information during the render loop, and utilize custom shaders to discard or mask virtual fragments that sit physically behind real-world obstacles.

1. Requesting the Depth Sensing Feature

To access depth data, you must request the depth-sensing feature when initializing the WebXR session. In Three.js, this is configured through the session initialization options passed to the ARButton or your custom session request.

You need to specify usage and data format preferences:

const sessionInit = {
  requiredFeatures: ['depth-sensing'],
  depthSensing: {
    usagePreference: ['gpu-optimized', 'cpu-optimized'],
    dataFormatPreference: ['float32', 'luminance-alpha']
  }
};

document.body.appendChild(ARButton.createButton(renderer, sessionInit));

The gpu-optimized format is preferred for real-time rendering because it exposes the depth buffer directly as a WebGL texture, avoiding CPU-to-GPU data transfer overhead.

2. Accessing the Depth Texture in the Render Loop

During each animation frame, obtain the XRCPUDepthInformation or XRWebGLDepthInformation from the current XRFrame and XRView.

With gpu-optimized mode, retrieve the depth texture directly from the WebGL context:

renderer.setAnimationLoop((timestamp, frame) => {
  if (frame) {
    const referenceSpace = renderer.xr.getReferenceSpace();
    const session = frame.session;
    const pose = frame.getViewerPose(referenceSpace);

    if (pose) {
      const view = pose.views[0];
      const depthInfo = frame.getDepthInformation(view);

      if (depthInfo) {
        // Retrieve the WebGL depth texture
        const glBinding = new XRWebGLBinding(session, renderer.getContext());
        const depthTexture = glBinding.getDepthTexture(depthInfo);

        // Update custom shader uniforms
        occlusionMaterial.uniforms.uDepthTexture.value = depthTexture;
        occlusionMaterial.uniforms.uRawValueToMeters.value = depthInfo.rawValueToMeters;
        occlusionMaterial.uniforms.uUvTransform.value.fromArray(
          depthInfo.normDepthBufferFromNormView.matrix
        );
      }
    }
  }

  renderer.render(scene, camera);
});

The normDepthBufferFromNormView matrix translates normalized view coordinates (screen UVs) to normalized depth buffer coordinates, accommodating camera rotation and sensor orientation mismatches.

3. Creating the Occlusion Shader

To evaluate depth comparison, virtual objects need a custom shader or a modified Three.js material that samples the WebXR depth texture. If the real-world distance is smaller than the distance from the camera to the virtual fragment, the fragment is discarded.

Below is an example using a custom ShaderMaterial:

const occlusionMaterial = new THREE.ShaderMaterial({
  uniforms: {
    uDepthTexture: { value: null },
    uRawValueToMeters: { value: 0.0 },
    uUvTransform: { value: new THREE.Matrix4() }
  },
  vertexShader: `
    varying vec4 vScreenPos;
    varying float vViewDepth;

    void main() {
      vec4 mvPosition = modelViewMatrix * vec4(position, 1.0);
      vViewDepth = -mvPosition.z; // Metric distance in Three.js view space
      gl_Position = projectionMatrix * mvPosition;
      vScreenPos = gl_Position;
    }
  `,
  fragmentShader: `
    uniform sampler2D uDepthTexture;
    uniform float uRawValueToMeters;
    uniform mat4 uUvTransform;

    varying vec4 vScreenPos;
    varying float vViewDepth;

    void main() {
      // Calculate normalized device coordinates (0.0 to 1.0)
      vec2 screenUV = (vScreenPos.xy / vScreenPos.w) * 0.5 + 0.5;

      // Transform UVs to match depth buffer orientation
      vec2 depthUV = (uUvTransform * vec4(screenUV, 0.0, 1.0)).xy;

      // Sample depth (format handling depends on dataFormatPreference)
      float rawDepth = texture2D(uDepthTexture, depthUV).r;
      float realDepthInMeters = rawDepth * uRawValueToMeters;

      // Occlusion test: discard if real geometry is closer than virtual geometry
      if (realDepthInMeters > 0.0 && realDepthInMeters < vViewDepth) {
        discard;
      }

      gl_FragColor = vec4(0.2, 0.6, 1.0, 1.0); // Render object color
    }
  `
});

4. Handling Depth Discontinuities and Soft Edges

Raw depth sensors produce noisy, low-resolution arrays that can cause jagged edges around occluding real-world objects. To mitigate edge artifacts:

  • Depth Biasing: Subtract a small tolerance value (e.g., 0.03 to 0.05 meters) from vViewDepth during the comparison to prevent surface z-fighting between virtual objects placed flush against real walls or floors.
  • Alpha Blending: Instead of a hard discard, calculate an interpolation factor around the boundary to create soft silhouettes for occluded geometry.
