Three.js Path vs Shape: 2D Extrusion Differences

In Three.js, both Path and Shape are used to define two-dimensional vectors, but they serve different structural roles when creating 3D meshes through extrusion. While a Path defines a single, continuous 2D contour or line sequence, a Shape extends Path to define a closed, solid 2D surface that can contain interior holes. Because ExtrudeGeometry requires a closed surface to triangulate front and back caps and sweep side faces into a 3D volume, it requires a Shape (or an array of Shape objects) rather than a raw Path.

Inheritance and Class Hierarchy

The primary difference stems from the object-oriented hierarchy in Three.js:

  • THREE.CurvePath: The base container for a series of connected curves.
  • THREE.Path (extends CurvePath): Adds 2D drawing methods like moveTo, lineTo, quadraticCurveTo, and bezierCurveTo. It tracks 2D points to form an open or closed continuous boundary.
  • THREE.Shape (extends Path): Inherits all drawing methods from Path to form an outer boundary, but introduces an internal array called holes, which holds multiple Path instances.

Because Shape inherits from Path, an instance of Shape is a Path for its outer perimeter, but with the added structural capability to represent topology.

The Structural Role of Holes

A Path represents a single coordinate sequence. It has no built-in mechanism to associate one outline with another. Even if you draw a circle and then draw a smaller circle within the same Path using moveTo, the engine treats them as disconnected line segments within one collection, not as a boundary with a cutout.

A Shape structures this relationship explicitly:

  • Outer Contour: Defined by the methods called directly on the Shape instance.
  • Inner Voids (holes): Defined by instantiating separate Path objects and pushing them into the shape.holes array.
// Outer boundary
const shape = new THREE.Shape();
shape.absarc(0, 0, 50, 0, Math.PI * 2, false);

// Inner void
const holePath = new THREE.Path();
holePath.absarc(0, 0, 20, 0, Math.PI * 2, true);

// Structural nesting
shape.holes.push(holePath);

Why ExtrudeGeometry Requires Shape

ExtrudeGeometry transforms a 2D profile into a 3D solid by generating three components: front caps, back caps, and side walls. To accomplish this, the geometry engine must perform polygon triangulation on the 2D plane:

  1. Planar Triangulation: Three.js uses the Earcut algorithm to divide the 2D surface into triangles. Earcut requires knowledge of both the outer winding boundary and any internal cutouts. A Shape supplies this exact data structure through its perimeter points and holes array. A Path does not possess the structural fields required by the triangulation step.
  2. Cap Generation: The triangulated 2D surface creates the planar caps at \(Z = 0\) and \(Z = \text{depth}\). Without a defined solid area, front and back caps cannot be generated.
  3. Wall Generation: The extrusion process creates rectangular side faces along the segments of the outer perimeter, as well as along the inverted perimeters of any defined holes, yielding hollowed corridors through the 3D volume.

Passing a raw Path into ExtrudeGeometry fails because the geometry generator relies on shape.extractPoints(), a method designed to resolve outer contours and hole contours separately for mesh generation.
