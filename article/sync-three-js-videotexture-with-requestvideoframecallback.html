Sync Three.js VideoTexture with requestVideoFrameCallback

Synchronizing video playback in Three.js often causes redundant GPU uploads and stuttering when driven solely by the display's refresh loop. This guide explains how to use the HTML5 requestVideoFrameCallback (rVFC) API with Three.js textures to ensure the texture only updates precisely when a new video frame is decoded and ready for presentation, optimizing rendering performance and eliminating frame pacing artifacts.

The Problem with Standard VideoTexture

By default, THREE.VideoTexture sets its internal needsUpdate flag to true on every render tick via requestAnimationFrame. If your display runs at 60Hz or 144Hz and the source video is 24fps or 30fps, Three.js re-uploads identical pixel data to the GPU multiple times per video frame. Conversely, if a display frame drops, frames may be skipped entirely.

The Solution: requestVideoFrameCallback

The HTMLVideoElement.requestVideoFrameCallback() method allows developers to register a callback that fires whenever a new video frame is submitted to the compositor. Tying texture updates directly to this event guarantees that:

  1. Texture upload to the GPU occurs exactly once per video frame.
  2. Bandwidth consumption and GPU processing are significantly reduced.
  3. Audio-video synchronization remains precise without visual micro-stutters.

Implementation

To bypass the automatic per-render upload behavior of THREE.VideoTexture, instantiate a base THREE.Texture with the video element as its source, or disable the automatic updates of THREE.VideoTexture.

Here is the direct implementation using THREE.Texture:

import * as THREE from 'three';

// 1. Initialize Video Element
const video = document.createElement('video');
video.src = 'path/to/video.mp4';
video.loop = true;
video.muted = true;
video.playsInline = true;
video.crossOrigin = 'anonymous';

// 2. Create the Texture using the base Texture class
// This prevents the default per-tick texture upload of THREE.VideoTexture
const videoTexture = new THREE.Texture(video);
videoTexture.minFilter = THREE.LinearFilter;
videoTexture.magFilter = THREE.LinearFilter;
videoTexture.format = THREE.RGBAFormat;

// 3. Create a Material and Mesh
const material = new THREE.MeshBasicMaterial({ map: videoTexture });
const geometry = new THREE.PlaneGeometry(16, 9);
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);

// 4. Implement the Synchronization Loop
function onNewVideoFrame(now, metadata) {
  // Flag the texture for a single GPU upload
  videoTexture.needsUpdate = true;

  // Re-register the callback for the next available frame
  video.requestVideoFrameCallback(onNewVideoFrame);
}

// 5. Start Playback and Frame Listening
video.play().then(() => {
  if ('requestVideoFrameCallback' in HTMLVideoElement.prototype) {
    video.requestVideoFrameCallback(onNewVideoFrame);
  } else {
    // Fallback for browsers without rVFC support (e.g., older Safari versions)
    video.addEventListener('timeupdate', () => {
      videoTexture.needsUpdate = true;
    });
  }
});

Color Space and Texture Configuration

When rendering video frames, match the texture encoding to the video source for color accuracy. Set the texture's color space to match your project's color pipeline:

videoTexture.colorSpace = THREE.SRGBColorSpace;

If your source video has non-power-of-two dimensions (such as standard 1080p or 4K resolutions), ensure videoTexture.generateMipmaps is set to false, which is default for video sources, to prevent unnecessary mipmap generation overhead on each frame update.

Handling Video Cleanup

When disposing of the scene or changing video sources, stop the frame callback cycle to prevent memory leaks:

function stopVideoSync() {
  video.pause();
  video.removeAttribute('src');
  video.load();
  videoTexture.dispose();
  material.dispose();
}
