How to Manually Update Shadows in Three.js

Rendering dynamic shadows every frame can cause significant performance overhead in Three.js, especially in scenes with complex geometry or static lighting. This guide explains how to boost rendering efficiency by disabling automatic shadow map updates with shadowMap.autoUpdate = false and manually triggering shadow recomputations with shadowMap.needsUpdate = true strictly when an object's position, rotation, or scale changes.

Why Disable Automatic Shadow Updates

By default, Three.js re-renders the shadow map for every shadow-casting light during every frame of the render loop. If the scene is mostly static or objects only move intermittently, continuously recalculating shadow maps wastes GPU cycles. Disabling automatic updates frees up GPU resources, maintaining a higher frame rate.

Disabling autoUpdate on the Renderer

To take control of the shadow update pipeline, enable shadow maps on your WebGLRenderer instance and set autoUpdate to false:

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);

// Enable shadows and disable automatic updates
renderer.shadowMap.enabled = true;
renderer.shadowMap.autoUpdate = false;

document.body.appendChild(renderer.domElement);

Because autoUpdate is disabled, Three.js will not calculate shadows until you explicitly request an update.

Triggering an Initial Shadow Pass

When the scene loads, the shadow map is empty. You must request an initial update so the base shadows are drawn:

// Render the initial shadows once the scene is set up
renderer.shadowMap.needsUpdate = true;

Once rendered, the shadows remain permanently cached in the texture buffer until you flag needsUpdate again.

Updating Shadows on Object Movement

Whenever a mesh, light, or camera moves, you must flag renderer.shadowMap.needsUpdate = true before the next render call. Once the render pass completes, Three.js automatically resets needsUpdate back to false.

Example: Movement Function

Create a centralized update function to handle moving the mesh and triggering the shadow map update:

function moveObject(mesh, newPosition) {
  mesh.position.copy(newPosition);
  mesh.updateMatrixWorld();

  // Flag that shadows need to recalculate
  renderer.shadowMap.needsUpdate = true;
}

Example: Animation Loop with Conditional Updates

If an object's movement is managed within the render loop (such as through user input, animation curves, or physics), you can evaluate state changes and trigger updates conditionally:

let objectMoved = false;

function onUserInteraction() {
  cube.position.x += 1;
  objectMoved = true;
}

function animate() {
  requestAnimationFrame(animate);

  if (objectMoved) {
    renderer.shadowMap.needsUpdate = true;
    objectMoved = false; // Reset the movement flag
  }

  renderer.render(scene, camera);
}

animate();

Best Practices

  • Update on Light Changes: If a light source moves, changes intensity, or alters its shadow camera properties (such as near, far, or bias), remember to also set renderer.shadowMap.needsUpdate = true.
  • Transform Controls: When using utilities like TransformControls for interactive editors, attach an event listener to the 'change' event to trigger shadow map updates during drag interactions.
  • Animated Objects: For scenes with continuous animation, leave autoUpdate enabled only during active animations, then toggle it off once the movement stops to conserve performance.
