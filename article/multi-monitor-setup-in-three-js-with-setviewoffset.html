Multi-Monitor Setup in Three.js with setViewOffset

This article explains how to use the Three.js camera.setViewOffset method to partition a single 3D scene across multiple physical displays or viewports. By defining a master virtual canvas and mapping specific coordinate sub-regions to individual renderers, you can create cohesive multi-monitor walls, seamless simulator rigs, and bezel-compensated display arrays.

Understanding camera.setViewOffset

The setViewOffset method modifies a camera's projection matrix so that it renders only a specific sub-window of a larger, full-size viewport without changing the field of view or aspect ratio distortion of the broader scene.

The method accepts six parameters:

camera.setViewOffset(fullWidth, fullHeight, x, y, width, height);
  • fullWidth: The total pixel width of the combined multi-screen display grid.
  • fullHeight: The total pixel height of the combined multi-screen display grid.
  • x: The horizontal starting offset of the sub-view relative to the top-left corner of the virtual display.
  • y: The vertical starting offset of the sub-view relative to the top-left corner of the virtual display.
  • width: The pixel width of the current monitor or viewport.
  • height: The pixel height of the current monitor or viewport.

Implementation for a Multi-Monitor Array

Consider a two-monitor horizontal setup where each monitor has a resolution of 1920x1080 pixels. The total combined virtual resolution is 3840x1080.

1. Configure the Left Monitor (Screen 0)

The left monitor starts at coordinate (0, 0):

const screenWidth = 1920;
const screenHeight = 1080;
const totalWidth = screenWidth * 2;
const totalHeight = screenHeight;

const camera = new THREE.PerspectiveCamera(75, totalWidth / totalHeight, 0.1, 1000);

// Left screen: x = 0, y = 0
camera.setViewOffset(totalWidth, totalHeight, 0, 0, screenWidth, screenHeight);

const renderer = new THREE.WebGLRenderer();
renderer.setSize(screenWidth, screenHeight);

2. Configure the Right Monitor (Screen 1)

The right monitor displays the second half of the scene and offsets horizontally by the width of the first screen:

// Right screen: x = 1920, y = 0
camera.setViewOffset(totalWidth, totalHeight, screenWidth, 0, screenWidth, screenHeight);

const renderer = new THREE.WebGLRenderer();
renderer.setSize(screenWidth, screenHeight);

Compensating for Physical Bezels

In physical multi-monitor setups, monitor frames (bezels) create a visual gap between screens. If you do not account for this space, straight lines traversing both screens will appear misaligned.

To implement bezel compensation, increase the fullWidth and fullHeight by the physical width of the gaps between display surfaces, then shift the sub-window offsets accordingly:

const screenWidth = 1920;
const screenHeight = 1080;
const bezelWidth = 40; // Combined frame thickness in pixels

const totalWidth = (screenWidth * 2) + bezelWidth;
const totalHeight = screenHeight;

// Camera for Left Monitor
leftCamera.setViewOffset(totalWidth, totalHeight, 0, 0, screenWidth, screenHeight);

// Camera for Right Monitor (starts after the screen width + bezel width)
rightCamera.setViewOffset(totalWidth, totalHeight, screenWidth + bezelWidth, 0, screenWidth, screenHeight);

Dynamic Updates and Resetting

If the browser window resizes, recalculate the virtual grid values and call setViewOffset again with updated dimensions, followed by camera.updateProjectionMatrix().

To return the camera to standard, single-viewport rendering, use:

camera.clearViewOffset();
camera.updateProjectionMatrix();
