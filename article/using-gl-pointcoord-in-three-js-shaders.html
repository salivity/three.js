Using gl_PointCoord in Three.js Shaders

In Three.js, rendering particles using point primitives natively produces square billboard quads on the screen. This article explains how to use the built-in GLSL variable gl_PointCoord inside a custom fragment shader to manipulate the shape, transparency, and texture mapping of individual points, transforming default squares into circles, soft glows, or custom textured sprites.

Understanding gl_PointCoord

The gl_PointCoord variable is a built-in GLSL vec2 available exclusively within fragment shaders when rendering point primitives (gl.POINTS). It provides normalized coordinates ranging from (0.0, 0.0) at the top-left corner to (1.0, 1.0) at the bottom-right corner of each point rasterized according to gl_PointSize.

Because standard UV attributes apply to the entire geometry rather than each individual particle, gl_PointCoord serves as a local coordinate space for each point.

Implementing Points with a Custom Shader

To utilize gl_PointCoord, use THREE.ShaderMaterial assigned to a THREE.Points mesh.

const material = new THREE.ShaderMaterial({
  vertexShader: `
    uniform float uSize;
    void main() {
      vec4 mvPosition = modelViewMatrix * vec4(position, 1.0);
      gl_PointSize = uSize * (300.0 / -mvPosition.z); // Attenuation
      gl_Position = projectionMatrix * mvPosition;
    }
  `,
  fragmentShader: `
    uniform vec3 uColor;
    void main() {
      // Logic using gl_PointCoord goes here
      gl_FragColor = vec4(uColor, 1.0);
    }
  `,
  uniforms: {
    uSize: { value: 10.0 },
    uColor: { value: new THREE.Color(0x00ffcc) }
  },
  transparent: true
});

const points = new THREE.Points(geometry, material);
scene.add(points);

Common Techniques Using gl_PointCoord

1. Rendering Circular Particles

To make points circular instead of square, calculate the distance from the center (0.5, 0.5). Discard fragments where the distance exceeds 0.5:

void main() {
  // Center is at (0.5, 0.5)
  float dist = distance(gl_PointCoord, vec2(0.5));

  if (dist > 0.5) {
    discard;
  }

  gl_FragColor = vec4(uColor, 1.0);
}

2. Creating Soft Glows and Radial Fades

Instead of abruptly discarding fragments, create a smooth gradient from the center to the edge using smoothstep:

void main() {
  float dist = distance(gl_PointCoord, vec2(0.5));
  
  // Smoothly fade alpha from the center (1.0) to edge (0.0)
  float alpha = 1.0 - smoothstep(0.0, 0.5, dist);

  gl_FragColor = vec4(uColor, alpha);
}

3. Mapping Textures to Individual Points

Treat gl_PointCoord as UV coordinates to sample a 2D texture across each particle:

uniform sampler2D uTexture;

void main() {
  vec4 texColor = texture2D(uTexture, gl_PointCoord);
  
  if (texColor.a < 0.1) {
    discard;
  }

  gl_FragColor = texColor;
}

Modifying Existing PointsMaterial with onBeforeCompile

If you prefer using THREE.PointsMaterial to retain built-in features like fog and lighting, inject gl_PointCoord logic directly via the onBeforeCompile hook:

const material = new THREE.PointsMaterial({ size: 10, transparent: true });

material.onBeforeCompile = (shader) => {
  shader.fragmentShader = shader.fragmentShader.replace(
    `#include <premultiplied_alpha_fragment>`,
    `
    #include <premultiplied_alpha_fragment>
    float dist = distance(gl_PointCoord, vec2(0.5));
    if (dist > 0.5) discard;
    `
  );
};

Using gl_PointCoord provides full control over the rasterization of point primitives, allowing efficient particle rendering without the overhead of instanced geometry.
