alphaTest vs Discard Performance in Three.js

When rendering partially transparent surfaces in Three.js, developers often wonder whether to rely on the built-in alphaTest property or implement a manual discard call inside a custom fragment shader. In terms of low-level GPU execution, alphaTest and manual discard are fundamentally the same, as Three.js implements alphaTest by injecting a conditional discard statement directly into its internal shaders. However, noticeable performance differences can still arise depending on GPU Early-Z behavior, shadow map passes, uniform evaluation, and pipeline integration.

How Three.js Implements alphaTest

In standard Three.js materials (such as MeshStandardMaterial or MeshBasicMaterial), defining an alphaTest value (e.g., material.alphaTest = 0.5) injects a specific shader chunk (alphatest_fragment.glsl.js) during shader compilation:

#ifdef USE_ALPHATEST
    if ( diffuseColor.a < alphaTest ) discard;
#endif

Because of this direct translation, assigning alphaTest generates the exact same underlying GPU instruction as writing a conditional discard manually within a ShaderMaterial or RawShaderMaterial.

Hardware-Level GPU Impact: Disabling Early-Z

Both alphaTest and explicit discard operations carry identical hardware-level performance penalties on modern GPUs. Normally, the GPU performs Early-Z (early depth testing) before running the fragment shader, immediately rejecting obscured fragments to save compute power.

When a fragment shader contains a discard statement—whether injected by alphaTest or written manually—the GPU must disable or alter its Early-Z optimization for that draw call. The hardware cannot know whether a pixel will be discarded until the fragment shader finishes computing the alpha value. As a result:

  • Fragment shaders execute for occluded fragments that would otherwise have been discarded earlier.
  • Fill rate and memory bandwidth consumption increase on high-overdraw scenes.
  • The GPU must calculate derivative footprints across 2x2 fragment quads even if individual pixels within the quad end up being discarded.

Pipeline Integration and Depth Passes

While raw execution speed inside the shader core is identical, real-world engine performance diverges in how Three.js handles depth and shadow passes.

  1. Automatic Depth/Shadow Synchronization: When using alphaTest on standard Three.js materials, the engine automatically propagates the threshold to internal depth and shadow map materials. This guarantees that shadows and depth pre-passes also execute the necessary discard logic seamlessly.
  2. Custom Shader Overhead: When writing a manual discard inside a custom ShaderMaterial, Three.js does not automatically apply that logic to shadow casting or depth-prepass buffers. To get correct shadows and depth testing, you must manually supply a matching customDepthMaterial and customDistanceMaterial. Forgetting to do so results in performance bugs (rendering incorrect full-geometry shadows) or extra CPU overhead from improperly managed fallback materials.

Uniform Lookup vs. Hardcoded Constants

A minor performance difference can occur based on how the threshold is evaluated:

  • Three.js alphaTest: Passes the threshold as a dynamic uniform (uniform float alphaTest;). This allows runtime alterations without triggering expensive shader recompilations, though it incurs a trivial uniform register read per fragment.
  • Hardcoded Custom discard: If you write if (color.a < 0.5) discard;, the value is hardcoded as a constant. The compiler may optimize constant comparisons slightly more aggressively on constrained mobile chipsets, though this benefit is negligible on modern hardware.

Summary

There is no hardware execution speed advantage to manually writing discard over setting alphaTest in Three.js, as both evaluate to the exact same GPU operations and impose the same Early-Z pipeline restrictions. Using the built-in alphaTest property is generally superior because it integrates automatically with depth, shadow, and deferred passes throughout the Three.js rendering pipeline without the maintenance and synchronization overhead of custom depth shaders.
