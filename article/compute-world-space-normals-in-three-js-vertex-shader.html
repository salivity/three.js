Compute World-Space Normals in Three.js Vertex Shader

Calculating accurate world-space normal vectors inside a custom Three.js vertex shader requires transforming the mesh's local normal attribute using the appropriate transformation matrix. While standard position vectors transform directly via the model matrix, normal vectors require specific handling to prevent distortion when meshes undergo non-uniform scaling. This guide explains how to properly compute world-space normals using default Three.js matrices for both uniform and non-uniform scale scenarios.

Uniform Scaling: Direct Model Matrix Transformation

When an object undergoes translation, rotation, and uniform scaling (where the X, Y, and Z scale factors are identical), transforming the normal vector into world space is straightforward. You can cast the 4x4 modelMatrix to a 3x3 matrix to discard the translation component and multiply it by the incoming normal attribute:

varying vec3 vWorldNormal;

void main() {
    // Extract rotation and uniform scale from the modelMatrix
    vWorldNormal = normalize(mat3(modelMatrix) * normal);

    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}

Normalizing the result ensures that any uniform scaling applied by the modelMatrix does not alter the unit length of the normal vector.

Non-Uniform Scaling: The Inverse Transpose

If a mesh is scaled non-uniformly (for example, scaled by (1.0, 2.0, 1.0)), using mat3(modelMatrix) distorts the normal vector, causing it to lose orthogonality to the surface. To maintain perpendicularity, a normal vector must be multiplied by the transpose of the inverse of the transformation matrix.

Three.js automatically supplies a normalMatrix uniform, but this matrix transforms normals from object space directly into view (camera) space, defined as:

\[\text{normalMatrix} = (\text{modelViewMatrix}^{-1})^T\]

To obtain true world-space normals under non-uniform scaling, you have two primary methods using Three.js default uniforms.

Method 1: Computing the World Normal Matrix in GLSL (WebGL 2)

If your project targets WebGL 2 (the default in modern Three.js releases), the GLSL functions inverse() and transpose() are available natively:

varying vec3 vWorldNormal;

void main() {
    // Invert and transpose the 3x3 model matrix to handle non-uniform scale
    mat3 worldNormalMatrix = transpose(inverse(mat3(modelMatrix)));
    vWorldNormal = normalize(worldNormalMatrix * normal);

    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}

Method 2: Transforming View-Space Normals Back to World Space

If you prefer to avoid computing matrix inversions inside the shader per-vertex, you can use the built-in normalMatrix to first transform the normal into view space, and then rotate it back into world space using the viewMatrix.

Because camera matrices generally do not have non-uniform scaling, the inverse of the view rotation matrix is simply its transpose:

varying vec3 vWorldNormal;

void main() {
    // 1. Transform object-space normal to view space using the built-in normalMatrix
    vec3 viewNormal = normalize(normalMatrix * normal);

    // 2. Un-rotate from view space back to world space using the transpose of mat3(viewMatrix)
    // For an orthogonal matrix, transpose(M) == inverse(M)
    mat3 viewToWorld = transpose(mat3(viewMatrix));
    vWorldNormal = normalize(viewToWorld * viewNormal);

    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}

Passing to the Fragment Shader

Ensure that the resulting vWorldNormal is normalized again inside the fragment shader, as linear interpolation between vertices can cause slight deviations from unit length:

varying vec3 vWorldNormal;

void main() {
    vec3 normal = normalize(vWorldNormal);
    // Use the normalized world normal for lighting, reflections, or environment mapping
    gl_FragColor = vec4(normal * 0.5 + 0.5, 1.0);
}
