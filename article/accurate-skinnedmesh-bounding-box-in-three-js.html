Accurate SkinnedMesh Bounding Box in Three.js

Calculating an accurate bounding box for a SkinnedMesh in Three.js requires evaluating the dynamic, weighted transformations applied by its skeleton. Calling mesh.geometry.computeBoundingBox() only checks the vertices in their original bind pose, failing to account for any skeletal animations or bone poses driven on the GPU. To obtain an exact bounding box, you must manually transform the geometry's vertex attributes on the CPU using the skeleton's current bone matrices and the corresponding skin weights and indices.

The Problem with Default Bounding Calculations

Three.js executes skeletal deformation inside vertex shaders on the GPU. The underlying BufferGeometry stores static vertex positions that remain unchanged regardless of how the skeleton moves. Consequently, methods like Box3.setFromObject(skinnedMesh) or geometry.computeBoundingBox() calculate boundaries based strictly on the unrigged rest pose.

Accurate CPU Skinning Implementation

To calculate the exact world-space bounding box, you must iterate over each vertex in the geometry, multiply it by the active transformation matrices of its assigned bones, weight the results, and expand a THREE.Box3 with the final coordinates.

Here is the complete implementation:

import * as THREE from 'three';

const _vertex = new THREE.Vector3();
const _temp = new THREE.Vector3();
const _skinned = new THREE.Vector3();
const _boneMatrix = new THREE.Matrix4();

function getAccurateSkinnedBox(skinnedMesh, targetBox = new THREE.Box3()) {
  targetBox.makeEmpty();

  const geometry = skinnedMesh.geometry;
  const position = geometry.attributes.position;
  const skinIndex = geometry.attributes.skinIndex;
  const skinWeight = geometry.attributes.skinWeight;

  const skeleton = skinnedMesh.skeleton;
  const bones = skeleton.bones;
  const boneInverses = skeleton.boneInverses;
  const bindMatrix = skinnedMesh.bindMatrix;

  // Ensure world matrices are up to date
  skinnedMesh.updateWorldMatrix(true, false);
  skeleton.update();

  for (let i = 0; i < position.count; i++) {
    _vertex.fromBufferAttribute(position, i);
    _skinned.set(0, 0, 0);

    for (let j = 0; j < 4; j++) {
      const weight = skinWeight.getComponent(i, j);
      if (weight === 0) continue;

      const boneIdx = skinIndex.getComponent(i, j);

      // Compute skinning matrix for this specific bone
      _boneMatrix
        .multiplyMatrices(bones[boneIdx].matrixWorld, boneInverses[boneIdx])
        .multiply(bindMatrix);

      _temp.copy(_vertex).applyMatrix4(_boneMatrix);
      _skinned.addScaledVector(_temp, weight);
    }

    targetBox.expandByPoint(_skinned);
  }

  return targetBox;
}

Performance Considerations and Optimizations

Iterating over every vertex on the CPU is computationally expensive and will cause frame drops if executed every tick on dense geometries. Consider the following techniques to mitigate performance overhead:

  • Compute on Demand: Only run the calculation when needed, such as during frustum culling updates, collision checks, or visibility triggers, rather than inside the main animation loop.
  • Bounding Bone Approximation: If absolute mathematical accuracy is not required, approximate the bounds by creating a Box3 around the skeleton's bone positions, then expanding the box by a static margin representing the mesh thickness: 
    function getFastApproximateBox(skinnedMesh, padding = 0.5, targetBox = new THREE.Box3()) {
  targetBox.makeEmpty();
  const bones = skinnedMesh.skeleton.bones;

  for (let i = 0; i < bones.length; i++) {
    _temp.setFromMatrixPosition(bones[i].matrixWorld);
    targetBox.expandByPoint(_temp);
  }

  targetBox.expandByScalar(padding);
  return targetBox;
}
  • Simplified Proxy Geometry: Create an invisible, low-poly proxy mesh that uses the same skeleton. Calculating bounds across a few dozen proxy vertices yields near-identical limits with negligible CPU usage.
