Dispose Three.js WebGL Context on Component Unmount

Properly cleaning up a Three.js WebGL rendering context when unmounting frontend framework components prevents memory leaks, stops orphaned animation frames, and avoids hitting the browser's hardware-enforced WebGL context limit. This article outlines the exact sequence required to cleanly tear down a Three.js scene: stopping the render loop, disposing of scene graph assets, disposing of the renderer, forcing context loss via the WebGL API, and freeing DOM references.

1. Stop the Render Loop

Before freeing GPU memory, immediately halt the rendering loop. Continuing to call renderer.render() during or after disposal will trigger errors and reallocate resources.

let animationFrameId;

function animate() {
  animationFrameId = requestAnimationFrame(animate);
  renderer.render(scene, camera);
}

// On component unmount:
cancelAnimationFrame(animationFrameId);

2. Traverse and Dispose of Assets

Three.js does not automatically clear GPU memory for geometries, materials, and textures when a scene is cleared or discarded. You must traverse the scene graph to invoke their respective .dispose() methods.

function cleanScene(scene) {
  scene.traverse((object) => {
    if (!object.isMesh) return;

    // Dispose geometry
    if (object.geometry) {
      object.geometry.dispose();
    }

    // Dispose materials and attached textures
    if (object.material) {
      if (Array.isArray(object.material)) {
        object.material.forEach((mat) => cleanMaterial(mat));
      } else {
        cleanMaterial(object.material);
      }
    }
  });

  // Clear scene children
  while (scene.children.length > 0) {
    scene.remove(scene.children[0]);
  }
}

function cleanMaterial(material) {
  material.dispose();

  // Dispose textures mapped to the material
  for (const key of Object.keys(material)) {
    const value = material[key];
    if (value && typeof value === 'object' && 'minFilter' in value) {
      value.dispose();
    }
  }
}

3. Dispose of the WebGLRenderer

Calling renderer.dispose() releases the internal Three.js caches, render targets, and WebGL state structures.

renderer.dispose();

4. Force WebGL Context Loss

Browsers restrict the total number of active WebGL contexts per page (often between 8 and 16). While renderer.dispose() clears Three.js states, the underlying canvas context might remain active until garbage collection runs. To force the browser to discard the context immediately, call renderer.forceContextLoss():

renderer.forceContextLoss();

Alternatively, you can trigger context loss directly using the WebGL extension:

const gl = renderer.getContext();
const loseContextExt = gl.getExtension('WEBGL_lose_context');
if (loseContextExt) {
  loseContextExt.loseContext();
}

5. Remove the Canvas and Clear References

Finally, remove the <canvas> element from the DOM and nullify all references to allow the JavaScript garbage collector to reclaim CPU memory.

if (renderer.domElement && renderer.domElement.parentNode) {
  renderer.domElement.parentNode.removeChild(renderer.domElement);
}

renderer.domElement = null;
renderer = null;
scene = null;
camera = null;

Complete Implementation Example

In modern component lifecycles (such as React's useEffect cleanup or Vue's onBeforeUnmount), group these steps into a unified teardown function:

function destroyThreeJsInstance({ renderer, scene, frameId }) {
  // 1. Cancel animation
  cancelAnimationFrame(frameId);

  // 2. Dispose scene graph objects
  cleanScene(scene);

  // 3. Force context destruction
  renderer.forceContextLoss();

  // 4. Dispose renderer
  renderer.dispose();

  // 5. Remove canvas and detach references
  if (renderer.domElement && renderer.domElement.parentNode) {
    renderer.domElement.parentNode.removeChild(renderer.domElement);
  }
}
