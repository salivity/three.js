How Three.js KTX2Loader Selects Transcoding Formats

In Three.js, KTX2Loader determines the optimal Basis Universal transcoding target by evaluating the client's WebGL context for supported compressed texture extensions and matching them against a prioritized hierarchy of target formats. By querying hardware capabilities on the main thread and dispatching these constraints to WebAssembly-powered Web Workers, the loader ensures textures are transcoded into GPU-native formats such as ASTC, BC7, or DXT with maximum visual fidelity and minimal memory consumption.

Detecting WebGL Compressed Texture Extensions

Before transcoding begins, KTX2Loader requires an active WebGLRenderer instance via the detectSupport(renderer) method. This method queries the underlying WebGL context for vendor-specific and standard compressed texture extensions:

  • ASTC: WEBGL_compressed_texture_astc
  • BC7 / BPTC: EXT_texture_compression_bptc
  • DXT / S3TC: WEBGL_compressed_texture_s3tc (and WEBGL_compressed_texture_s3tc_srgb)
  • ETC2 / ETC1: WEBGL_compressed_texture_etc or WEBGL_compressed_texture_etc1
  • PVRTC: WEBGL_compressed_texture_pvrtc

The results are assembled into a capability profile that indicates which compression schemes the client GPU natively decodes.

Passing Capabilities to Web Workers

To avoid blocking the main rendering loop, KTX2Loader delegates the heavy decompression and transcoding workloads to a pool of Web Workers running compiled Basis Universal WebAssembly (WASM) modules.

When a texture load request is initiated, the capability profile collected on the main thread is sent to the worker along with the raw .ktx2 binary data. This ensures the WASM worker knows precisely which target targets are viable for the target system.

Header Inspection and Source Format Identification

Inside the Web Worker, the Basis Universal transcoder reads the KTX2 container header to identify the source encoding mode:

  1. ETC1S: Highly compressed, lower fidelity, suitable for simple textures or UI assets.
  2. UASTC: High-fidelity format designed to transcode efficiently to ASTC, BC7, and other modern formats with minimal quality degradation.

The source format alters the selection matrix because certain target formats are better suited for UASTC than ETC1S.

Format Priority Evaluation

The transcoder evaluates the intersection of available GPU extensions and container encoding using an internal priority cascade:

  • Modern Mobile Targets: If WEBGL_compressed_texture_astc is present (standard on modern iOS and Android devices), the transcoder preferentially selects ASTC 4x4. ASTC offers high fidelity and unified support across mobile hardware.
  • Modern Desktop Targets: If ASTC is unavailable but EXT_texture_compression_bptc is present (common on modern desktop GPUs), BC7 is chosen, especially for UASTC sources, due to its exceptional quality-to-size ratio.
  • Legacy Desktop Targets: If BC7 is unsupported, the loader checks for WEBGL_compressed_texture_s3tc. If available, it selects BC1 (DXT1) for opaque textures or BC3 (DXT5) for textures with alpha channels.
  • Alternative Mobile Targets: If ASTC is absent, the transcoder searches for ETC2, then ETC1, and historically PVRTC for older Apple devices.
  • Uncompressed Fallback: If the browser or GPU supports none of the hardware-accelerated formats, the transcoder decompresses the image into uncompressed 8-bit RGBA (RGBA32) or 16-bit formats (RGB565 / RGBA4444).

Once the optimal target format is determined, the Basis Universal WASM transcoder translates the intermediate KTX2 data blocks directly into the target GPU format and returns the transcoded buffer to the main thread for uploading to the GPU via CompressedTexture.
