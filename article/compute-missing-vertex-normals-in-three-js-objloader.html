Compute Missing Vertex Normals in Three.js OBJLoader

This article explains how to handle 3D models with missing vertex normals when importing them using the Three.js OBJLoader. Because OBJLoader does not feature a built-in configuration flag to automatically compute missing normals during the parsing phase, developers must calculate them post-load. Below is a concise guide demonstrating how to traverse the loaded model hierarchy and generate smooth vertex normals for every mesh using the native BufferGeometry.computeVertexNormals() method.

Why Missing Normals Matter

In Three.js, lighting and shading algorithms rely heavily on vertex normals to determine how light reflects off surfaces. If an OBJ file lacks normal definitions (designated by vn records in the raw file), standard materials such as MeshStandardMaterial or MeshPhongMaterial will appear black, incorrectly shaded, or unlit.

Automating Normal Calculation Upon Import

While OBJLoader does not offer an option like loader.setComputeNormals(true), you can achieve automated calculation by traversing the loaded object tree directly inside the onLoad callback.

Here is the implementation:

import * as THREE from 'three';
import { OBJLoader } from 'three/examples/jsm/loaders/OBJLoader.js';

const loader = new OBJLoader();

loader.load(
    'path/to/model.obj',
    (object) => {
        // Traverse the loaded object hierarchy
        object.traverse((child) => {
            if (child.isMesh && child.geometry) {
                // Check if normals are missing
                if (!child.geometry.attributes.normal) {
                    child.geometry.computeVertexNormals();
                }
            }
        });

        // Add the configured object to the scene
        scene.add(object);
    },
    (xhr) => {
        console.log((xhr.loaded / xhr.total * 100) + '% loaded');
    },
    (error) => {
        console.error('An error occurred loading the OBJ model:', error);
    }
);

Wrapping OBJLoader for Reusable Automatic Generation

If your application loads multiple OBJ assets, you can wrap OBJLoader.load into a custom helper function or extend the class to ensure normals are calculated automatically every time without repeating code:

class AutoNormalOBJLoader extends OBJLoader {
    load(url, onLoad, onProgress, onError) {
        super.load(
            url,
            (object) => {
                object.traverse((child) => {
                    if (child.isMesh && child.geometry && !child.geometry.attributes.normal) {
                        child.geometry.computeVertexNormals();
                    }
                });
                if (onLoad) onLoad(object);
            },
            onProgress,
            onError
        );
    }
}

// Usage
const autoLoader = new AutoNormalOBJLoader();
autoLoader.load('path/to/model.obj', (obj) => {
    scene.add(obj);
});

Key Considerations

  • Indexed vs. Non-Indexed Geometries: computeVertexNormals() works on both indexed and non-indexed BufferGeometry. For non-indexed geometries, shared vertices across adjacent faces will not average their normals, resulting in faceted (flat) shading. If smooth shading is required on a non-indexed geometry, merge identical vertices first using BufferGeometryUtils.toCreasedNormals() or BufferGeometryUtils.mergeVertices() prior to computing normals.
  • Performance: Calling computeVertexNormals() executes on the CPU during load time. For complex models with millions of polygons, this operation may cause a momentary frame rate dip. Consider computing normals asynchronously via Web Workers for extremely large meshes.
