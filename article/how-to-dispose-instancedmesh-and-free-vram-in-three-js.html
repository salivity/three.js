How to Dispose InstancedMesh and Free VRAM in Three.js

This guide explains how to properly dispose of a Three.js InstancedMesh to guarantee that its internal matrix buffers and instance colors are deallocated from GPU memory (VRAM). While standard meshes only require disposing of their geometry and materials, InstancedMesh objects allocate additional WebGL buffers for instance transformations that can easily lead to memory leaks if not cleaned up correctly.

The Role of InstancedMesh.dispose()

Unlike a standard Mesh, an InstancedMesh contains custom buffer attributes: instanceMatrix and optionally instanceColor. When rendered, the Three.js WebGLRenderer creates dedicated WebGL buffer objects in VRAM to store these transformation matrices.

Calling instancedMesh.dispose() dispatches a dispose event. The internal WebGLObjects management system listens for this event and immediately deletes the associated WebGL buffers for instanceMatrix and instanceColor via WebGLAttributes.remove().

Complete Memory Cleanup Procedure

To ensure all resources associated with an InstancedMesh are purged from VRAM and system RAM, follow this lifecycle pattern:

function disposeInstancedMesh(mesh, scene) {
    // 1. Remove the mesh from the scene graph
    if (mesh.parent) {
        mesh.parent.remove(mesh);
    } else if (scene) {
        scene.remove(mesh);
    }

    // 2. Clear the instanced matrix and color buffers from VRAM
    mesh.dispose();

    // 3. Dispose of the base geometry
    if (mesh.geometry) {
        mesh.geometry.dispose();
    }

    // 4. Dispose of the material (and its textures if unique)
    if (mesh.material) {
        if (Array.isArray(mesh.material)) {
            mesh.material.forEach((mat) => disposeMaterial(mat));
        } else {
            disposeMaterial(mesh.material);
        }
    }
}

function disposeMaterial(material) {
    // Dispose of any textures bound to the material
    for (const key of Object.keys(material)) {
        const value = material[key];
        if (value && typeof value === 'object' && 'minFilter' in value) {
            value.dispose();
        }
    }
    material.dispose();
}

Manual Buffer Attribute Disposal in Older Versions

In Three.js versions prior to r136, InstancedMesh.prototype.dispose() was not fully linked to renderer-level buffer cleanup. If you are maintaining a project on an older release, explicitly instruct the renderer to deallocate the attribute buffers:

// Fallback for older Three.js releases
if (mesh.instanceMatrix) {
    mesh.instanceMatrix.dispose();
}

if (mesh.instanceColor) {
    mesh.instanceColor.dispose();
}

Verifying VRAM Release

To verify that the underlying instanced buffers have been removed from the GPU, inspect the renderer memory metrics before and after the cleanup:

console.log('Geometries in VRAM:', renderer.info.memory.geometries);
console.log('Textures in VRAM:', renderer.info.memory.textures);

You can also inspect the WebGL context directly via renderer.getContext() or monitor GPU process memory in your browser's developer tools (such as Chrome's Task Manager under the "GPU Process" column) to confirm that memory pressure decreases after garbage collection runs.
