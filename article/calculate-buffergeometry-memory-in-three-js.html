Calculate BufferGeometry Memory in Three.js

Calculating the exact memory footprint of a Three.js BufferGeometry involves tallying the byte sizes of its underlying typed arrays across all vertex attributes and its optional index buffer. This article provides a straightforward method and code implementation to measure the exact byte count consumed by any BufferGeometry instance on both the CPU and the GPU.

Understanding BufferGeometry Memory

A BufferGeometry stores mesh data inside WebGL-ready typed arrays (such as Float32Array, Uint16Array, or Uint32Array). In WebGL, memory is allocated primarily in two places:

  1. System Memory (RAM): Retained by the JavaScript engine in the typed arrays assigned to each attribute.
  2. Video Memory (VRAM): Allocated as WebGL Vertex Buffer Objects (VBOs) when the geometry is uploaded to the graphics card.

Because the GPU buffers mirror the binary data of the CPU-side typed arrays, calculating the byte size of these typed arrays gives you the exact baseline data footprint for that specific geometry.

The Calculation Method

To find the exact memory size, sum the byteLength property of each BufferAttribute array in geometry.attributes, then add the byteLength of the geometry.index array if present.

Here is the complete function to calculate the byte size:

function getGeometryMemoryBytes(geometry) {
  let totalBytes = 0;

  // 1. Calculate size of standard and custom vertex attributes
  for (const name in geometry.attributes) {
    const attribute = geometry.attributes[name];
    if (attribute && attribute.array) {
      totalBytes += attribute.array.byteLength;
    }
  }

  // 2. Calculate size of the index buffer (if indexed)
  if (geometry.index && geometry.index.array) {
    totalBytes += geometry.index.array.byteLength;
  }

  return totalBytes;
}

Formatting the Output

Raw bytes can be converted into human-readable units (kilobytes or megabytes) using a helper:

function formatBytes(bytes) {
  if (bytes === 0) return '0 Bytes';
  const k = 1024;
  const sizes = ['Bytes', 'KB', 'MB', 'GB'];
  const i = Math.floor(Math.log(bytes) / Math.log(k));
  return parseFloat((bytes / Math.pow(k, i)).toFixed(2)) + ' ' + sizes[i];
}

const geometry = new THREE.BoxGeometry(1, 1, 1);
const bytes = getGeometryMemoryBytes(geometry);

console.log(`Geometry Size: ${formatBytes(bytes)}`);

CPU vs. GPU Footprint Details

  • Active WebGL Allocation: When a mesh is rendered, the total memory consumed across the system is roughly 2x the calculated byte count: 1x in system RAM (JavaScript heap) and 1x in VRAM (GPU buffer).
  • Interleaved Attributes: If your geometry uses InterleavedBufferAttribute, calculate the byteLength of the underlying InterleavedBuffer directly rather than traversing individual attributes to prevent counting shared data multiple times.
  • Morph Targets: If your geometry utilizes morph targets (geometry.morphAttributes), iterate through every array inside each morph attribute group and add their byteLength properties to the total count.
