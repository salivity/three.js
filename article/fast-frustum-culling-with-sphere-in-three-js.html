Fast Frustum Culling with Sphere in Three.js

This article explains how to implement fast, coarse frustum culling in Three.js using the THREE.Sphere mathematical object. By testing a lightweight bounding sphere against a camera's view frustum, you can quickly discard off-screen objects and avoid costly render operations or complex geometry-level intersection tests.

Why Use Bounding Spheres for Frustum Checks

Three.js includes automatic frustum culling on a per-object basis, but manual, coarse-grained culling is essential when managing custom rendering pipelines, particle collections, instanced meshes, or hierarchical scene nodes.

Testing a sphere against a frustum is computationally inexpensive. A view frustum consists of six planes. A sphere intersection test only requires computing the dot product between the sphere's center and each plane's normal, followed by a comparison of that distance against the sphere's radius. If the sphere is completely behind any single plane, it is immediately discarded.

Essential Components

Manual sphere-frustum culling in Three.js relies on three core classes:

  1. THREE.Frustum: Represents the six-sided viewing pyramid of the camera.
  2. THREE.Matrix4: Used to combine the camera's projection and view matrices.
  3. THREE.Sphere: Represents the bounding volume in 3D space with a center (THREE.Vector3) and a radius (float).

Step-by-Step Implementation

1. Initialize the Frustum and Helper Variables

To avoid allocating new memory inside the animation loop, instantiate your mathematical objects once outside your render loop.

import * as THREE from 'three';

const frustum = new THREE.Frustum();
const projScreenMatrix = new THREE.Matrix4();
const worldSphere = new THREE.Sphere();

2. Update the Frustum from the Camera

The frustum must be updated whenever the camera moves or changes its projection parameters (e.g., field of view or aspect ratio). Compute the combined view-projection matrix and extract the frustum planes:

function updateFrustum(camera) {
  projScreenMatrix.multiplyMatrices(
    camera.projectionMatrix,
    camera.matrixWorldInverse
  );
  frustum.setFromProjectionMatrix(projScreenMatrix);
}

3. Obtain the World-Space Bounding Sphere

Geometries in Three.js calculate bounding spheres in local space via geometry.computeBoundingSphere(). To test against the world-space camera frustum, transform the local sphere by the object's world matrix:

// Ensure the local bounding sphere exists
if (!mesh.geometry.boundingSphere) {
  mesh.geometry.computeBoundingSphere();
}

// Copy the local sphere and transform it to world space
worldSphere.copy(mesh.geometry.boundingSphere);
worldSphere.applyMatrix4(mesh.matrixWorld);

4. Execute the Intersection Test

Use frustum.intersectsSphere() to perform the visibility check. Based on the boolean result, toggle object visibility, skip animations, or filter draw lists.

const isVisible = frustum.intersectsSphere(worldSphere);
mesh.visible = isVisible;

Complete Example in the Render Loop

function animate() {
  requestAnimationFrame(animate);

  // 1. Update camera matrices and frustum
  camera.updateMatrixWorld();
  updateFrustum(camera);

  // 2. Perform coarse culling on a list of objects
  for (let i = 0; i < objects.length; i++) {
    const obj = objects[i];

    // Ensure the world matrix is up to date
    obj.updateMatrixWorld();

    // Transform bounding sphere to world coordinates
    worldSphere.copy(obj.geometry.boundingSphere);
    worldSphere.applyMatrix4(obj.matrixWorld);

    // Check intersection
    if (frustum.intersectsSphere(worldSphere)) {
      obj.visible = true;
      // Perform expensive tasks (e.g., updates, LOD selection) here
    } else {
      obj.visible = false;

}

Performance Considerations

  • Avoid Reallocation: Always reuse pre-allocated instances of THREE.Frustum, THREE.Matrix4, and THREE.Sphere inside the animation loop to prevent garbage collection spikes.
  • Hierarchical Culling: Group nearby objects under a single parent with a larger bounding sphere. If the parent sphere fails the frustum check, you can skip checking all child objects entirely.
  • Static Objects: If an object does not move, compute its world-space bounding sphere once and cache it, removing the need to call applyMatrix4 on every frame.
