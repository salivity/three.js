Load 6 HDR Images for a Three.js Skybox

This guide explains how to configure a high-dynamic range (HDR) skybox in Three.js by sequentially loading six separate HDR face textures. While the default CubeTextureLoader targets 8-bit image formats, handling Radiance HDR files (.hdr) requires combining RGBELoader logic with a CubeTexture container. You will learn how to enforce sequential loading using asynchronous JavaScript and assign the resulting texture as an environment map for realistic scene lighting.

Why Standard CubeTextureLoader Needs an Extension

The default THREE.CubeTextureLoader internally instantiates THREE.ImageLoader, which cannot parse floating-point or RGBE data formats. For HDR cube textures, Three.js provides HDRCubeTextureLoader, which uses RGBELoader under the hood.

To guarantee that six distinct HDR images load strictly in sequence—reducing network congestion or managing memory on low-spec hardware—you can iterate through the file list sequentially using async/await and RGBELoader, then assemble the loaded data into a THREE.CubeTexture.

Sequential Loading Implementation

The order of cubemap faces in Three.js follows standard Cartesian coordinates: Positive X, Negative X, Positive Y, Negative Y, Positive Z, and Negative Z (px, nx, py, ny, pz, nz).

Here is how to load each face sequentially and bind them to a CubeTexture:

import * as THREE from 'three';
import { RGBELoader } from 'three/addons/loaders/RGBELoader.js';

async function loadHDRCubeTextureSequentially(basePath, files) {
  const loader = new RGBELoader();
  loader.setPath(basePath);

  // Array to hold the decoded image data for all 6 faces
  const loadedFaces = [];

  // Iterate strictly in sequence
  for (let i = 0; i < files.length; i++) {
    const fileName = files[i];
    
    // Await ensures the previous file completes before the next request begins
    const texture = await loader.loadAsync(fileName);
    loadedFaces.push(texture.image);
    
    // Dispose the standalone texture container to free memory
    texture.dispose();
  }

  // Create the cubemap from the 6 individual face images
  const cubeTexture = new THREE.CubeTexture(loadedFaces);
  cubeTexture.type = THREE.HalfFloatType; // Optimal precision for HDR lighting
  cubeTexture.needsUpdate = true;

  return cubeTexture;
}

Applying the CubeTexture to the Scene

Once the sequential loader resolves, the generated CubeTexture must be assigned to the scene's background and environment properties. To ensure physically based materials react correctly to the HDR data, pre-filter the texture with PMREMGenerator.

const files = [
  'px.hdr', 'nx.hdr',
  'py.hdr', 'ny.hdr',
  'pz.hdr', 'nz.hdr'
];

const pmremGenerator = new THREE.PMREMGenerator(renderer);
pmremGenerator.compileCubemapShader();

loadHDRCubeTextureSequentially('/path/to/hdr/faces/', files)
  .then((cubeTexture) => {
    // Generate pre-filtered mipmaps for realistic roughness reflections
    const pmremRenderTarget = pmremGenerator.fromCubemap(cubeTexture);
    
    // Set scene properties
    scene.background = cubeTexture;
    scene.environment = pmremRenderTarget.texture;

    // Clean up textures
    cubeTexture.dispose();
    pmremGenerator.dispose();
  })
  .catch((error) => {
    console.error('An error occurred loading the HDR faces:', error);
  });

Alternative: Using HDRCubeTextureLoader

If strict chronological network queuing is not required and managed parallel loading is acceptable, you can use the built-in HDRCubeTextureLoader. It handles parsing internally and accepts an array of six files:

import { HDRCubeTextureLoader } from 'three/addons/loaders/HDRCubeTextureLoader.js';

const hdrLoader = new HDRCubeTextureLoader();
hdrLoader.setPath('/path/to/hdr/faces/');
hdrLoader.setDataType(THREE.HalfFloatType);

hdrLoader.load(
  ['px.hdr', 'nx.hdr', 'py.hdr', 'ny.hdr', 'pz.hdr', 'nz.hdr'],
  (hdrCubeMap) => {
    scene.background = hdrCubeMap;
    scene.environment = hdrCubeMap;
  }
);

For constrained environments requiring strict serial execution, the RGBELoader loop implementation provides direct control over network execution order and progress monitoring per face.
