Uniform vs Varying in Three.js ShaderMaterial

In a Three.js ShaderMaterial, the functional difference between uniform and varying variables lies in their data source, scope within the rendering pipeline, and whether their values undergo interpolation. Uniforms are global, constant values passed directly from JavaScript on the CPU to both the vertex and fragment shaders on the GPU. Varyings, by contrast, act as an internal bridge within the GPU pipeline, transporting data calculated in the vertex shader down to the fragment shader while smoothly interpolating those values across the rendered geometry.

Uniform Variables

Uniforms provide a way for your JavaScript code to communicate directly with your GLSL shaders. When you define a uniform in a ShaderMaterial, that value remains constant (uniform) for all vertices and fragments processed during a single draw call.

  • Data Origin: JavaScript (CPU) to GPU shaders.
  • Accessibility: Available to both the vertex shader and fragment shader.
  • Value Consistency: Constant across all vertices and fragments during the draw call.
  • Mutability in Shader: Read-only inside the GLSL code.
  • Common Use Cases: Global parameters such as elapsed time (uTime), light positions, texture maps, projection matrices, and object-wide color tints.

In JavaScript, uniforms are passed as an object containing a value property:

const material = new THREE.ShaderMaterial({
  uniforms: {
    uTime: { value: 0.0 },
    uColor: { value: new THREE.Color(0xff0000) }
  },
  vertexShader: `...`,
  fragmentShader: `...`
});

Varying Variables

Varyings are used strictly for communication between the vertex shader and the fragment shader. They cannot be populated directly from JavaScript. Instead, the vertex shader computes or assigns a value to a varying for each vertex. As the GPU rasterizes the polygon into individual fragments (pixels), it automatically performs perspective-correct interpolation of that varying value across the surface.

  • Data Origin: Calculated per-vertex inside the vertex shader.
  • Accessibility: Written in the vertex shader, read in the fragment shader.
  • Value Consistency: Varies per pixel due to linear interpolation between vertices.
  • Mutability in Shader: Writable in the vertex shader; read-only in the fragment shader.
  • Common Use Cases: Interpolated UV coordinates, surface normals, world positions, and vertex colors.

To use a varying, you must declare it with the exact same name and type in both the vertex and fragment shaders:

// Vertex Shader
varying vec2 vUv;

void main() {
    vUv = uv; // uv is an attribute provided by Three.js
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}
// Fragment Shader
varying vec2 vUv;

void main() {
    // vUv is now interpolated for this specific pixel
    gl_FragColor = vec4(vUv, 0.0, 1.0);
}

Key Differences at a Glance

  • Pipeline Flow: Uniforms flow horizontally from CPU to both shader stages (JS -> Vertex & Fragment). Varyings flow vertically down the GPU pipeline (Vertex -> Fragment).
  • Interpolation: Uniforms are never interpolated; every fragment sees the exact same value. Varyings are blended across the face of a polygon, producing smooth gradients between vertices.
  • Performance: Uniforms require memory transfer from CPU to GPU when updated, but are computationally cheap on the GPU. Varyings require vertex calculation and hardware-accelerated interpolation across the rasterizer.
