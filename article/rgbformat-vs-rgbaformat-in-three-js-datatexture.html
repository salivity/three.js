RGBFormat vs RGBAFormat in Three.js DataTexture

When creating a DataTexture in Three.js, the choice between RGBFormat and RGBAFormat dictates the underlying structure, dimensions, and index math of the binary data buffer. This guide outlines the mathematical differences between the two formats, covering memory allocation, channel stride, coordinate-to-index mapping formulas, and WebGL memory alignment constraints.

Array Buffer Size Calculation

The primary mathematical divergence is the channel multiplier applied to the pixel dimensions. Given a texture of width \(W\) and height \(H\):

  • RGBFormat: Uses 3 color channels per pixel (Red, Green, Blue). The total number of elements required in the typed array is: \[\text{Length}_{\text{RGB}} = W \times H \times 3\]
  • RGBAFormat: Uses 4 color channels per pixel (Red, Green, Blue, Alpha). The total number of elements required is: \[\text{Length}_{\text{RGBA}} = W \times H \times 4\]

Consequently, an RGBAFormat texture allocates exactly \(33.33\%\) more memory than an RGBFormat texture for an identical resolution and data type (such as Uint8Array or Float32Array).

Indexing and Stride Mathematics

To retrieve or modify the color components of a specific pixel at coordinates \((x, y)\)—where \(0 \le x < W\) and \(0 \le y < H\)—the linear memory index is calculated via stride multiplication.

For RGBFormat (Stride = 3):

The starting index \(i\) for pixel \((x, y)\) is: \[i = (y \times W + x) \times 3\]

The individual channel components are stored contiguously:

  • \(\text{Red} = \text{data}[i]\)
  • \(\text{Green} = \text{data}[i + 1]\)
  • \(\text{Blue} = \text{data}[i + 2]\)

For RGBAFormat (Stride = 4):

The starting index \(i\) for pixel \((x, y)\) is: \[i = (y \times W + x) \times 4\]

The individual channel components are mapped as:

  • \(\text{Red} = \text{data}[i]\)
  • \(\text{Green} = \text{data}[i + 1]\)
  • \(\text{Blue} = \text{data}[i + 2]\)
  • \(\text{Alpha} = \text{data}[i + 3]\)

Row Alignment and Byte Padding

WebGL enforces an unpack alignment rule that defaults to 4 bytes per row. This default creates an operational difference between 8-bit implementations of the two formats:

  • RGBAFormat with 8-bit values (Uint8Array): Each pixel consumes 4 bytes (\(4 \times 1\text{ byte}\)). Because \(W \times 4\) is always divisible by 4, every row automatically aligns with WebGL's default 4-byte boundary requirement regardless of width: \[(W \times 4) \pmod 4 = 0\]
  • RGBFormat with 8-bit values (Uint8Array): Each pixel consumes 3 bytes (\(3 \times 1\text{ byte}\)). If the texture width \(W\) is not a multiple of 4, the byte size of a row will fail the alignment condition: \[(W \times 3) \pmod 4 \neq 0\] In this scenario, texture creation fails or produces skewed sampling artifacts unless texture.unpackAlignment is explicitly set to 1.
