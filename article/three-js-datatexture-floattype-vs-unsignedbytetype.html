Three.js DataTexture: FloatType vs UnsignedByteType

When building custom data textures in Three.js using THREE.DataTexture, choosing between THREE.UnsignedByteType and THREE.FloatType dictates how your raw data is stored in memory and interpreted by the GPU. While UnsignedByteType stores 8-bit integers ideal for standard visual representations and lightweight lookups, FloatType stores full 32-bit floating-point numbers necessary for high-precision scientific calculations, physics simulations, and High Dynamic Range (HDR) data. Selecting the correct type determines the precision of your pipeline and directly impacts GPU memory consumption and performance.

Understanding THREE.UnsignedByteType

THREE.UnsignedByteType is the default texture data type in Three.js. It pairs with a JavaScript Uint8Array or Uint8ClampedArray to store values ranging from 0 to 255 per channel. When sampled in a WebGL shader, these values are automatically normalized to a floating-point range of [0.0, 1.0].

Primary Use Cases

  • Standard Visual Textures: Procedurally generated diffuse, albedo, or opacity maps where human perception cannot distinguish beyond 256 levels of gradation per color channel.
  • Simple Masks and Lookup Tables (LUTs): 1D or 2D step functions, color grading tables, and basic boolean or threshold masks.
  • Low-Precision Vector Fields: Small direction vectors that do not require sub-pixel accuracy and can be encoded into normalized values (e.g., packing a normal vector into RGB via (v * 0.5) + 0.5).

Advantages and Limitations

  • Low Memory Footprint: Consumes only 1 byte per channel (4 bytes per pixel for an RGBA format), minimizing VRAM bandwidth.
  • Universal Hardware Support: Supported natively across all WebGL devices without requiring WebGL extensions.
  • Precision Constraints: Insufficient for storing negative values, numbers greater than 255, or arbitrary floating-point values without manual encoding and quantization artifacts.

Understanding THREE.FloatType

THREE.FloatType pairs with a JavaScript Float32Array to store raw 32-bit IEEE 754 floating-point values. In shaders, these values are not clamped or normalized; the exact floating-point value passed to the array is preserved and accessible directly in GLSL.

Primary Use Cases

  • GPGPU Computations: Storing arbitrary dynamic states for particle systems (such as particle positions, velocities, and lifespans) updated every frame via custom compute shaders or render targets.
  • Displacement and Elevation Maps: High-precision terrain elevation or geometric vertex displacement where 8-bit depth causes visible "stepping" or banding artifacts.
  • HDR and Lighting Information: Storing high dynamic range lighting data, spherical harmonics, or radiance fields that require values well above 1.0.
  • Physics and Vector Simulation: Storing flow maps, velocity fields for fluid simulations, or complex coordinate data where negative values and decimal precision are required.

Advantages and Limitations

  • High Precision: Can represent negative numbers, fractional values, and values beyond standard color boundaries without manual packing algorithms.
  • Higher Resource Cost: Consumes 4 bytes per channel (16 bytes per pixel for RGBA), requiring four times the VRAM and texture bandwidth of UnsignedByteType.
  • Hardware Requirements: In WebGL 1, using floating-point textures requires the OES_texture_float extension, and rendering to them requires WEBGL_color_buffer_float. While standard in WebGL 2, older mobile GPUs may still face performance penalties when linearly filtering float textures (OES_texture_float_linear).

Key Decision Factors

Backing TypedArray Uint8Array Float32Array

Use UnsignedByteType whenever your data fits cleanly within a normalized [0.0, 1.0] range and does not suffer from 8-bit quantization artifacts. Reserve FloatType for workflows requiring exact numerical accuracy, broad dynamic ranges, or direct mathematical simulations on the GPU.
