Force ShaderMaterial Recompile in Three.js

In Three.js, shaders are compiled once and cached by the WebGL renderer to optimize rendering performance. This article explains how to explicitly force a ShaderMaterial to recompile at runtime by mutating its defines dictionary and setting the needsUpdate flag, ensuring updated preprocessor directives are properly injected into your GLSL code.

The Role of the defines Object

The defines property in THREE.ShaderMaterial is a JavaScript object representing GLSL preprocessor macros (e.g., #define FLAG value). When Three.js builds the shader program, it prepends these defines to your vertex and fragment shader source code.

Because GLSL macros are evaluated at compile time rather than draw time, changing a define requires the WebGL pipeline to completely rebuild and recompile the shader program.

Steps to Force Recompilation

Three.js does not actively observe nested mutations inside the defines object. Modifying a property within defines will not trigger a recompilation on its own. You must explicitly mark the material as dirty using the needsUpdate flag.

Here is the standard implementation:

// 1. Modify, add, or delete the define key
material.defines.ENABLE_FEATURE = 1;

// Alternatively, remove a define completely
// delete material.defines.ENABLE_FEATURE;

// 2. Explicitly notify Three.js that the material needs recompilation
material.needsUpdate = true;

On the subsequent render call, the WebGLRenderer detects that material.needsUpdate is set to true. It evaluates the new state of the material, regenerates the program's cache key incorporating the modified defines, compiles the new WebGL program, and binds it to the geometry.

Handling Dynamic Values: Defines vs. Uniforms

Recompiling a shader is an expensive operation that blocks the main thread and can introduce noticeable frame drops (jank). When architecting your runtime modifications:

  • Use defines when you need structural code changes, such as conditionally branching out large code paths, toggling loops, or including different lighting algorithms with preprocessor directives like #ifdef or #if.
  • Use uniforms if you are updating continuous values (such as colors, time, positions, or simple toggles that can be evaluated via standard if statements in GLSL) to avoid triggering a shader recompilation.

Custom Program Cache Keys

If you are generating complex custom shaders or using a customProgramCacheKey, ensure that your cache key function incorporates the values of your dynamic defines:

material.customProgramCacheKey = function () {
  return (this.defines.ENABLE_FEATURE ? 'feat_on' : 'feat_off');
};

This guarantees that the internal renderer properly distinguishes between the different compiled states and correctly retrieves or creates the appropriate program.
