Prevent Parent Scale Inheritance in Three.js

In Three.js, child objects automatically inherit transformations from their parents through hierarchical matrix multiplication. While this is desirable for translation and rotation, it often causes unintended distortion when a parent is scaled non-uniformly or dynamically. This article explains how to prevent a child object from inheriting its parent's scale by decomposing, normalizing, and recomposing its world matrix directly within the render loop or via custom matrix updates.

The Problem: The Transform Hierarchy

When updateMatrixWorld() runs, Three.js calculates an object's global transformation by multiplying its local matrix with its parent's world matrix:

\[\text{child.matrixWorld} = \text{parent.matrixWorld} \times \text{child.matrix}\]

Because scale is embedded directly into the column vectors of a \(4\times4\) transformation matrix, any scaling applied to the parent directly compounds with the child's local scale.

The Solution: Manipulate the World Matrix

To strip parent scale while retaining parent position and orientation, you can intercept the child's world matrix calculation. The most robust approach is overriding the child object's updateMatrixWorld method. This ensures raycasting, frustum culling, and rendering all use the correct transform.

Implementation

To prevent garbage collection overhead inside the render loop, allocate reusable instances of Vector3 and Quaternion outside the update function:

import * as THREE from 'three';

const _position = new THREE.Vector3();
const _quaternion = new THREE.Quaternion();
const _scale = new THREE.Vector3();

function ignoreParentScale(child) {
  // Store the original method reference
  const defaultUpdateMatrixWorld = child.updateMatrixWorld;

  child.updateMatrixWorld = function (force) {
    // 1. Run standard update to compute normal matrix hierarchy
    defaultUpdateMatrixWorld.call(this, force);

    // 2. Extract current world position and rotation
    this.matrixWorld.decompose(_position, _quaternion, _scale);

    // 3. Reconstruct matrixWorld using the child's own local scale
    // (or THREE.Vector3(1, 1, 1) for a fixed unit scale)
    this.matrixWorld.compose(_position, _quaternion, this.scale);
  };
}

Usage

Apply this function to any child object that should ignore its parent's scale:

const parent = new THREE.Mesh(geometry, material);
const child = new THREE.Mesh(childGeometry, childMaterial);

parent.add(child);
scene.add(parent);

// Apply the override
ignoreParentScale(child);

// Now scaling the parent will not distort the child
parent.scale.set(2, 5, 1);

How It Works

  1. Hierarchy Calculation: defaultUpdateMatrixWorld allows Three.js to resolve the combined position and rotation from all ancestor nodes down to the target object.
  2. Decomposition: matrixWorld.decompose() extracts the resulting world position, world quaternion, and the compounded world scale into temporary variables.
  3. Recomposition: matrixWorld.compose() overwrites matrixWorld in-place. It combines the derived world position and world orientation with the child's local scale property instead of the inherited _scale, neutralizing the parent's scale influence.
