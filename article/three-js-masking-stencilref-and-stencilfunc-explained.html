Three.js Masking: stencilRef and stencilFunc Explained

The stencil buffer in Three.js provides a high-performance, per-pixel masking pipeline that controls which fragments of a mesh are rendered to the screen. At the core of this system are the stencilRef and stencilFunc material properties, which work together to define the logic of the stencil test: stencilRef supplies a reference integer value, while stencilFunc defines the comparison rule used to test that reference against the value currently stored in the stencil buffer.

The Role of stencilRef

stencilRef is a material property that sets an 8-bit integer reference value (ranging from 0 to 255). This value serves two distinct roles depending on whether a material is writing to or reading from the stencil buffer:

  • As a Comparison Value: When performing stencil testing, the GPU compares stencilRef directly to the integer value currently present in the stencil buffer at the corresponding pixel coordinate.
  • As a Write Value: When using stencil write operations—such as THREE.ReplaceStencilOp defined in stencilZPass or stencilFail—the GPU writes this stencilRef value directly into the stencil buffer to establish the mask area.

The Role of stencilFunc

stencilFunc defines the comparison operator that determines whether a fragment passes or fails the stencil test. If the test passes, the pixel is rendered (or processed further down the depth/blending pipeline); if it fails, the pixel is discarded.

Three.js maps stencilFunc to standard WebGL stencil functions, including:

  • THREE.NeverStencilFunc: Always fails; the fragment is never drawn.
  • THREE.AlwaysStencilFunc: Always passes; used commonly when drawing a mask object that only exists to write values into the stencil buffer.
  • THREE.EqualStencilFunc: Passes only if stencilRef is equal to the stencil buffer value.
  • THREE.NotEqualStencilFunc: Passes only if stencilRef differs from the stencil buffer value.
  • THREE.LessStencilFunc / THREE.LessEqualStencilFunc: Passes if stencilRef is less than (or less than or equal to) the buffer value.
  • THREE.GreaterStencilFunc / THREE.GreaterEqualStencilFunc: Passes if stencilRef is greater than (or greater than or equal to) the buffer value.

The actual comparison evaluated by the graphics hardware is:

(stencilRef & stencilFuncMask) [stencilFunc] (stencilBufferValue & stencilFuncMask)

How stencilRef and stencilFunc Work Together for Masking

Creating a mask in Three.js requires coordinating these two properties across at least two different render passes or objects:

1. Writing the Mask

To define a masking region, a geometry representing the mask shape is rendered with:

  • stencilWrite set to true.
  • stencilFunc set to THREE.AlwaysStencilFunc, ensuring every pixel of the mask passes the test.
  • stencilRef set to an identifier, such as 1.
  • stencilZPass set to THREE.ReplaceStencilOp, which overwrites the stencil buffer with the stencilRef value (1) wherever this geometry renders.
  • Optionally, colorWrite and depthWrite set to false if the mask geometry itself should remain invisible.

2. Reading the Mask

To restrict another object so it only renders inside (or outside) that masked shape:

  • stencilWrite set to true.
  • stencilRef set to the same identifier (1).
  • stencilFunc set to THREE.EqualStencilFunc (to render only inside the mask) or THREE.NotEqualStencilFunc (to render only outside the mask).
  • stencilZPass set to THREE.KeepStencilOp so the rendered object reads the mask without altering the stored stencil values.

By pairing an explicit reference value (stencilRef) with a matching evaluation condition (stencilFunc), Three.js allows you to create complex portals, cutaways, selective lighting passes, and 2D UI masks directly on 3D geometry.
