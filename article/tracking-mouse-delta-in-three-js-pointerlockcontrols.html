Tracking Mouse Delta in Three.js PointerLockControls

Tracking exact mouse delta during an active PointerLockControls session in Three.js requires intercepting native browser mouse events rather than reading standard cursor coordinates. Because the Pointer Lock API locks the cursor to a fixed screen position and hides it, absolute coordinates such as clientX and clientY stop updating. Instead, the browser provides relative motion values through movementX and movementY on the native mouse event. This guide outlines how to capture, process, and synchronize these raw deltas within your Three.js render loop.

The Role of movementX and movementY

When PointerLockControls.lock() is invoked, the browser locks mouse input to the target DOM element. During this state, standard mouse coordinate tracking fails because the OS cursor does not traverse screen pixels.

To determine how far and in what direction the mouse has moved between frames, you must listen directly to the mousemove event and read the relative change supplied by the Pointer Lock API:

  • event.movementX: The horizontal distance moved since the last mousemove event.
  • event.movementY: The vertical distance moved since the last mousemove event.

Capturing the Delta Alongside PointerLockControls

PointerLockControls internally binds to mousemove to adjust the camera rotation, but it does not expose the per-frame delta values directly on the control instance. To capture the delta for custom gameplay logic (such as weapon swaying, aiming calculations, or UI widgets), bind a secondary event listener to the document.

import * as THREE from 'three';
import { PointerLockControls } from 'three/addons/controls/PointerLockControls.js';

// Setup basic scene and camera
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
const renderer = new THREE.WebGLRenderer();
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// Initialize controls
const controls = new PointerLockControls(camera, renderer.domElement);

// Store the mouse deltas
const mouseDelta = {
    x: 0,
    y: 0
};

// Listen for mousemove events
document.addEventListener('mousemove', (event) => {
    // Only capture delta when the pointer lock session is active
    if (controls.isLocked) {
        // Fallbacks included for older browser implementations
        const deltaX = event.movementX || event.mozMovementX || event.webkitMovementX || 0;
        const deltaY = event.movementY || event.mozMovementY || event.webkitMovementY || 0;

        mouseDelta.x += deltaX;
        mouseDelta.y += deltaY;
    }
});

Synchronizing with the Render Loop

Because multiple mousemove events can fire within a single animation frame (especially with high-polling-rate gaming mice), accumulate the deltas inside the event listener and process them inside the requestAnimationFrame loop.

Once the accumulated delta is consumed in your animation update, reset the values to zero to prevent continuous movement when the mouse remains stationary.

function updateCustomLogic(deltaX, deltaY) {
    // Example: apply delta to a secondary mesh or custom weapon sway
    if (deltaX !== 0 || deltaY !== 0) {
        // Your custom logic here
    }
}

function animate() {
    requestAnimationFrame(animate);

    if (controls.isLocked) {
        // Pass accumulated frame deltas to your logic
        updateCustomLogic(mouseDelta.x, mouseDelta.y);

        // Reset deltas after consumption for the current frame
        mouseDelta.x = 0;
        mouseDelta.y = 0;
    }

    renderer.render(scene, camera);
}

animate();

Key Considerations

  • Lock State Verification: Always check controls.isLocked (or verify that document.pointerLockElement === renderer.domElement) inside your event listener to avoid reading unintentional cursor movements before pointer lock initiates or after it exits.
  • Sensitivity and Normalization: High-DPI mice can produce large delta spikes. Multiply raw delta values by a configurable sensitivity constant to ensure predictable behavior across different user hardware setups.
