How to Stop UI Glow with Three.js UnrealBloomPass

Controlling post-processing bloom on user interface (UI) components is a common challenge in Three.js development. When using UnrealBloomPass, high-luminance UI elements often produce unwanted halos that obscure text and create visual noise. This article explains how to fine-tune the threshold and knee properties—often controlled via luminance pass settings—to ensure only intentional in-game light sources emit bloom while keeping UI elements crisp and readable.

Understanding How UnrealBloomPass Evaluates Luminance

The UnrealBloomPass isolates bloom using a high-pass luminance filter. It calculates the brightness of each pixel and determines whether that pixel should contribute to the blur pyramid based on two primary factors:

  • Threshold: The minimum brightness value required for a pixel to trigger bloom.
  • Knee (Smoothness): The transition zone around the threshold. Instead of a hard binary cut, the knee creates a gradual, soft-knee ramp (smoothstep) from non-blooming to blooming pixels.

When UI elements are rendered with standard white textures or hex colors (#FFFFFF), their RGB values sit at 1.0. If your bloom threshold is below 1.0, or if a wide knee soft-falloff extends down into the standard [0.0, 1.0] color range, those UI elements will inevitably bloom.

Step 1: Adopt an Extended HDR Range for Emissive Objects

The most robust way to protect UI elements is to push your blooming scene objects beyond standard dynamic range (SDR) and anchor your bloom threshold at or above 1.0.

In Three.js, standard UI materials should use standard SDR color values where pure white equals 1.0:

const uiMaterial = new THREE.MeshBasicMaterial({ 
    color: 0xffffff // RGB: (1.0, 1.0, 1.0)
});

For 3D elements that should glow, increase the emissive intensity past 1.0:

const glowingMaterial = new THREE.MeshStandardMaterial({
    color: 0x00ff00,
    emissive: 0x00ff00,
    emissiveIntensity: 3.0 // Driven past the standard [0, 1] range
});

Step 2: Set the Hard Threshold

Set the threshold of the UnrealBloomPass to at least 1.0. This ensures that any pixel with a maximum SDR luminance of 1.0 (such as pure white UI text) falls strictly below the activation cutoff.

const bloomPass = new UnrealBloomPass(
    new THREE.Vector2(window.innerWidth, window.innerHeight),
    1.5, // Strength
    0.4, // Radius
    1.0  // Threshold
);

Step 3: Tighten the Knee to Prevent Transition Leaks

The high-pass filter in UnrealBloomPass includes a property that defines the softness of the threshold transition—often referred to mathematically as the knee, or exposed as smoothHighPassFilter / smoothness.

A high knee value softens the cutoff, causing pixels slightly below the threshold to contribute partial bloom. If your threshold is 1.0 and your knee parameter is wide, a UI pixel with a luminance of 0.95 or 1.0 will still bleed into the bloom buffer.

To completely prevent UI bleeding, collapse the knee to create a sharp cutoff:

// Access the internal high-pass material properties if exposed directly
if (bloomPass.highPassUniforms) {
    bloomPass.highPassUniforms['smoothWidth'].value = 0.01; // Extremely narrow knee
}

By keeping the knee close to 0.0 (or a very low value like 0.01 to 0.05), you remove the soft ramp. Pixels must strictly exceed the 1.0 threshold to produce any bloom.

Step 4: Validate Tone Mapping and Color Space

Ensure your renderer's tone mapping does not clamp HDR values before the bloom pass runs. The bloom pass should evaluate linear, unclamped values:

renderer.toneMapping = THREE.ACESFilmicToneMapping;
renderer.toneMappingExposure = 1.0;

When configured correctly, pure white UI elements capped at 1.0 luminance will be entirely ignored by the high-pass filter, while objects with emissive intensities above 1.0 will generate clean, artifact-free bloom.
