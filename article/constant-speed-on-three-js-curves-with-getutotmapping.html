Constant Speed on Three.js Curves with getUtoTmapping

Moving an object along a 3D spline at a constant velocity requires decoupling the curve’s mathematical parameterization from physical distance. By default, interpolating a spline using its normalized parameter \(t\) causes objects to speed up or slow down depending on the density and spacing of the control points. This article demonstrates how to use the Three.js method Curve.getUtoTmapping to translate an equidistant arc-length fraction \(u\) into the parameter \(t\), strictly maintaining a uniform speed regardless of curve complexity.

Understanding the Parameterization Problem: \(t\) vs. \(u\)

In Three.js, evaluating a curve with curve.getPoint(t) takes a value \(t\) between 0.0 and 1.0. Splines, such as CatmullRomCurve3, do not distribute distance linearly across \(t\). Segments with closely packed control points represent shorter spatial distances than segments with distant control points, yet both occupy equivalent intervals of \(t\). Incrementing \(t\) linearly per frame results in erratic object acceleration.

To enforce constant speed, motion must be driven by arc length, represented as \(u \in [0, 1]\), where equal changes in \(u\) correspond to equal physical distances along the curve. The Curve.getUtoTmapping(u, distance) method bridges this gap. It searches pre-calculated segment lengths using binary search to find the exact parameter \(t\) that yields the target arc-length fraction \(u\).

Step-by-Step Implementation

Enforcing constant velocity requires calculating the total curve length, tracking elapsed distance over delta time, and converting normalized distance to the spline parameter.

1. Instantiate the Spline and Calculate Lengths

Create your curve using your set of points. Three.js caches curve segment lengths internally, but calling getLength() ensures that the arc-length lookup table is built.

import * as THREE from 'three';

const points = [
  new THREE.Vector3(-10, 0, 10),
  new THREE.Vector3(-5, 5, 5),
  new THREE.Vector3(0, 0, 0),
  new THREE.Vector3(5, -5, 5),
  new THREE.Vector3(10, 0, 10)
];

const curve = new THREE.CatmullRomCurve3(points);
const totalLength = curve.getLength();

2. Track Linear Distance via Delta Time

In your animation loop, compute the spatial distance traversed in the current frame using the object's defined speed and clock.getDelta(). Accumulate this value to track the absolute distance traveled.

const speed = 5.0; // Units per second
let distanceTraveled = 0.0;
const clock = new THREE.Clock();

function updatePosition() {
  const delta = clock.getDelta();
  distanceTraveled += speed * delta;

  // Loop the motion along the curve length
  distanceTraveled = distanceTraveled % totalLength;

  // Normalize distance to a [0, 1] range (u)
  const u = distanceTraveled / totalLength;

  // Map the equidistant distance 'u' to curve parameter 't'
  const t = curve.getUtoTmapping(u);

  // Retrieve the strictly uniform coordinate
  const position = curve.getPoint(t);
  mesh.position.copy(position);
}

3. Orienting the Moving Object

When moving an object at a constant speed, you typically also need it to face the direction of travel. Because you have the mapped value \(t\), you can query the curve tangent directly using curve.getTangent(t).

// Calculate orientation from tangent
const tangent = curve.getTangent(t).normalize();
const lookTarget = position.clone().add(tangent);
mesh.lookAt(lookTarget);

getUtoTmapping vs. getPointAt

Three.js provides curve.getPointAt(u), which internally executes curve.getPoint(curve.getUtoTmapping(u)). While getPointAt is sufficient for fetching coordinates directly, using getUtoTmapping explicitly is necessary when:

  • You need to reuse the resolved parameter \(t\) across multiple queries, such as evaluating position via getPoint(t) and direction via getTangent(t) without repeating the internal binary search.
  • You need to pass \(t\) to shaders or external interpolation libraries to sync animations, camera zooms, or particle emitters precisely with the movement along the spline.

Improving Lookup Accuracy

The binary search in getUtoTmapping relies on the resolution of the curve's arc-length cache. If you notice micro-stuttering on extremely long or highly complex curves, increase the internal subdivisions before running animations:

// Default division count is 200; increase it for high-precision paths
curve.arcLengthDivisions = 1000;
curve.updateArcLengths();

Increasing arcLengthDivisions produces a denser segment table, allowing getUtoTmapping to resolve \(t\) with higher precision, ensuring perfectly smooth motion along tight loops and sharp turns.
