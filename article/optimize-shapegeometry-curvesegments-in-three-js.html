Optimize ShapeGeometry curveSegments in Three.js

In Three.js, rendering complex curved shapes can quickly degrade performance if vertex counts are excessively high. This article explains how to dynamically optimize rendering performance by adjusting the curveSegments property of a ShapeGeometry according to camera distance, covering both real-time procedural recreation and the Level of Detail (LOD) caching pattern to maintain a stable 60 FPS.

Understanding the curveSegments Property

When generating a mesh using THREE.ShapeGeometry or THREE.ExtrudeGeometry, the curveSegments parameter controls how many linear segments represent curved paths, such as arcs, beziers, or splines.

A high value creates smooth curves at the expense of a significantly higher vertex and triangle count. A low value drastically reduces polygon counts, ideal when the mesh is far from the camera or moves rapidly across the viewport.

Because Three.js constructs fixed buffer attributes (position, normal, uv, and index buffers) when a geometry is initialized, you cannot alter the segment count by simply changing a property value on an existing geometry instance. Adjusting the detail level requires swapping or recreating the geometry.

Method 1: Using THREE.LOD (Recommended)

The most performant approach is precomputing several geometries with varying curveSegments and assigning them to a THREE.LOD (Level of Detail) node. This avoids runtime memory allocations and garbage collection pauses.

import * as THREE from 'three';

function createLODShape(shape, material) {
  const lod = new THREE.LOD();

  // High detail (close-up)
  const highGeo = new THREE.ShapeGeometry(shape, 24);
  lod.addLevel(new THREE.Mesh(highGeo, material), 0);

  // Medium detail
  const medGeo = new THREE.ShapeGeometry(shape, 10);
  lod.addLevel(new THREE.Mesh(medGeo, material), 25);

  // Low detail (far distance)
  const lowGeo = new THREE.ShapeGeometry(shape, 3);
  lod.addLevel(new THREE.Mesh(lowGeo, material), 50);

  return lod;
}

This method delegates distance calculations and mesh visibility toggling to Three.js internal frustum and distance routines.

Method 2: Dynamic Real-Time Regeneration

If memory constraints prevent pre-generating multiple geometries, or if you need continuous, distance-based scalar adjustments, you can rebuild the geometry on the fly.

To prevent memory leaks, you must explicitly call .dispose() on the obsolete geometry to clear WebGL GPU buffers.

import * as THREE from 'three';

const shape = new THREE.Shape();
// Define your shape paths here...

const material = new THREE.MeshStandardMaterial({ color: 0x0077ff });
let currentSegments = 12;

const mesh = new THREE.Mesh(
  new THREE.ShapeGeometry(shape, currentSegments),
  material
);
scene.add(mesh);

function updateGeometryDetail(camera, mesh, shape) {
  const distance = camera.position.distanceTo(mesh.position);

  // Map distance to segment resolution
  let targetSegments = Math.round(100 / distance);
  
  // Clamp values to prevent over-tessellation or collapse
  targetSegments = THREE.MathUtils.clamp(targetSegments, 3, 32);

  if (targetSegments !== currentSegments) {
    // Free GPU buffers
    mesh.geometry.dispose();

    // Reconstruct with updated curve resolution
    mesh.geometry = new THREE.ShapeGeometry(shape, targetSegments);
    currentSegments = targetSegments;
  }
}

Performance Best Practices

  • Throttle Distance Checks: Do not re-evaluate distances and recreate buffers on every render tick. Use a timer or frame counter to evaluate geometry updates once every 10 to 30 frames.
  • Hysteresis Buffers: When using dynamic regeneration, apply a threshold buffer between step levels to prevent the geometry from rapidly flipping back and forth between two segment counts at boundary distances.
  • Dispose Correctly: Forgetting to call geometry.dispose() during dynamic recreation will rapidly leak GPU VRAM and cause the WebGL context to crash.
