Three.js Flow vs InstancedFlow Along a Spline

Animating 3D geometry along a path in Three.js can be achieved using the CurveModifier extension, which provides two primary classes: Flow and InstancedFlow. While both deform vertices along a curved spline using GPU vertex shaders and curve data encoded into textures, they differ fundamentally in rendering architecture, performance overhead, and scaling capability. This guide breaks down the core distinctions between standard Flow and InstancedFlow, helping you determine the ideal approach for your WebGL application.

Target Object Type and Architecture

The most fundamental difference lies in the type of Three.js object each class manipulates:

  • Flow operates on a standard THREE.Mesh. It deforms a single geometry instance along a path, maintaining individual material definitions, uniforms, and transforms.
  • InstancedFlow operates on a THREE.InstancedMesh. Instead of deforming isolated meshes, it distributes multiple instances of a single base geometry across one or more curves simultaneously.

Draw Calls and Performance

Performance is the main deciding factor when choosing between the two implementations:

  • Flow generates one draw call per mesh. If you have fifty objects traveling down a path, the GPU must execute fifty separate draw calls. This creates significant CPU-to-GPU communication overhead, limiting frame rates when scaling to large numbers of objects.
  • InstancedFlow renders all instances in a single draw call. By leveraging hardware-accelerated GPU instancing, hundreds or thousands of deformed objects can be rendered simultaneously with virtually the same draw-call overhead as a single object.

Spline and Animation Control

Both classes allow geometry to advance along a spline by shifting an offset value, but they manage per-object parameters differently:

  • With Flow: Animating position involves calling flow.moveAlongCurve(amount) on that specific instance. Controlling multiple objects requires tracking and updating each Flow instance individually in your animation loop.
  • With InstancedFlow: You assign specific curve indices, offsets, and scales to individual instance IDs using methods such as instancedFlow.setUniformsIndex(index) and instancedFlow.moveIndividualAlongCurve(index, amount). Furthermore, InstancedFlow can store multiple curves within a single curve texture, allowing different instances to travel along completely different paths within the same draw call.

Memory Usage and Shader Overhead

Because Flow treats every object independently, duplicating it multiple times duplicates data structures, uniforms, and texture bindings.

InstancedFlow shares the underlying geometry buffers and material shaders across all instances. It encodes multiple curves into a single data texture read by the vertex shader. While setting up an InstancedFlow requires slightly more boilerplate code to define capacity, instance transforms, and curve assignments, it is vastly more memory-efficient when handling repetitive visual elements.

When to Use Each Approach

  • Use Flow when: You only need to deform a single object or a very small number of unique objects with distinct geometries and materials (such as a single train winding through a landscape, a bendable tube, or a snake).
  • Use InstancedFlow when: You need to animate tens, hundreds, or thousands of repeated meshes along splines (such as a school of fish, highway traffic, particle-like ribbons, or bloodstream cells).
