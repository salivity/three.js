Configuring outputColorSpace for PBR in Three.js

This article explains how to properly configure the WebGLRenderer.outputColorSpace property in Three.js to achieve accurate, physically based rendering (PBR) colors. You will learn the correct color space settings for modern Three.js versions, how linear rendering interacts with sRGB display outputs, and how to configure textures to prevent models from appearing washed out or excessively dark.

Understanding Color Spaces in Modern Three.js

Physically based rendering calculations must occur in a linear color space so that light accumulation, reflections, and material properties behave mathematically correctly according to the laws of physics. However, computer monitors display colors using the non-linear sRGB color space.

To bridge this gap, Three.js performs all internal shader calculations in linear space and must convert the final image to sRGB right before presenting it to the screen.

Setting WebGLRenderer.outputColorSpace

In modern Three.js (r152 and newer), color management is enabled by default. To ensure the final rendered image is converted from linear space to standard display space, set the renderer's outputColorSpace property to THREE.SRGBColorSpace.

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);

// Configure the output color space for PBR
renderer.outputColorSpace = THREE.SRGBColorSpace;

document.body.appendChild(renderer.domElement);

(Note: In versions prior to r152, this was handled by renderer.outputEncoding = THREE.sRGBEncoding, which is now deprecated.)

Aligning Texture Color Spaces

Configuring outputColorSpace on the renderer is only half of the workflow. For colors to display correctly, input textures must also have their color spaces declared properly:

  1. Color Data (Albedo / Base Color / Diffuse): Textures that represent visible color are usually authored in sRGB space. They must be tagged as THREE.SRGBColorSpace so Three.js can convert them to linear space for shader calculations.
  2. Non-Color Data (Roughness, Metalness, Normal, Ambient Occlusion): Textures containing mathematical data must remain in linear space. Set their color space to THREE.NoColorSpace (or THREE.LinearSRGBColorSpace).

Texture Configuration Example

const textureLoader = new THREE.TextureLoader();

// Base color texture (sRGB)
const baseColorMap = textureLoader.load('textures/albedo.jpg');
baseColorMap.colorSpace = THREE.SRGBColorSpace;

// Normal map / Data texture (Linear)
const normalMap = textureLoader.load('textures/normal.jpg');
normalMap.colorSpace = THREE.NoColorSpace;

const material = new THREE.MeshStandardMaterial({
    map: baseColorMap,
    normalMap: normalMap,
    roughness: 0.5,
    metalness: 0.5
});

When using GLTFLoader, color space settings for textures are handled automatically according to the glTF 2.0 specification. As long as renderer.outputColorSpace is set to THREE.SRGBColorSpace, glTF models will render with mathematically correct colors directly out of the box.
