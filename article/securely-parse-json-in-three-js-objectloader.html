Securely Parse JSON in Three.js ObjectLoader

Parsing user-uploaded JSON files with the Three.js ObjectLoader exposes applications to severe vulnerabilities, including Prototype Pollution, Cross-Site Scripting (XSS), and Denial of Service (DoS). Because ObjectLoader dynamically instantiates objects, handles image URLs for textures, and historically supports embedded execution scripts, raw input must never be passed directly to the loader. Securing this pipeline requires a multi-layered sanitization process consisting of structural schema validation, prototype sanitization, URL whitelisting, and the stripping of executable definitions prior to instantiation.

1. Prototype Pollution Prevention

JSON payloads can contain dangerous properties such as __proto__, constructor, and prototype. When processed recursively by internal Three.js assignment operations, these keys can modify the global JavaScript object prototype.

Sanitize the raw string or parsed object to remove these keys entirely before handing the data to ObjectLoader:

function sanitizeObjectKeys(obj) {
  if (obj !== null && typeof obj === 'object') {
    delete obj.__proto__;
    delete obj.constructor;
    delete obj.prototype;

    for (const key of Object.keys(obj)) {
      sanitizeObjectKeys(obj[key]);
    }
  }
  return obj;
}

Alternatively, use a secure parsing method with a reviver function during initial parsing:

const cleanData = JSON.parse(jsonString, (key, value) => {
  if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
    return undefined;
  }
  return value;
});

2. Remove Embedded Scripts

The Three.js scene format supports an optional scripts object, traditionally used by the Three.js Editor to attach executable JavaScript code to objects via UUIDs. If an attacker injects a script into this section, downstream applications or custom runtimes parsing this metadata can execute arbitrary code.

Explicitly remove the scripts property from the root payload:

if (cleanData.scripts) {
  delete cleanData.scripts;
}

3. Sanitize Asset and Texture URLs

Three.js scenes specify texture sources inside an images array located at the root of the JSON payload. Malicious users can supply javascript: pseudo-protocols to execute XSS or target internal endpoints to trigger unauthorized requests.

Iterate through the images definition and strictly enforce permitted URL formats:

  • Allow only safe data URIs (e.g., image/png, image/jpeg).
  • Allow only fully-qualified URLs pointing to trusted CDNs or enforce relative paths mapped to a safe asset directory.
  • Block dangerous URI schemes completely.
const ALLOWED_IMAGE_MIME_TYPES = ['image/png', 'image/jpeg', 'image/webp'];

function sanitizeImages(imagesArray) {
  if (!Array.isArray(imagesArray)) return;

  imagesArray.forEach((image) => {
    if (typeof image.url === 'string') {
      const url = image.url.trim();

      if (url.startsWith('data:')) {
        const mimeType = url.substring(5, url.indexOf(';'));
        if (!ALLOWED_IMAGE_MIME_TYPES.includes(mimeType)) {
          image.url = ''; // Nullify untrusted data URI
        }
      } else {
        try {
          const parsedUrl = new URL(url, window.location.origin);
          const isAllowedDomain = parsedUrl.origin === window.location.origin;

          if (!isAllowedDomain || !['http:', 'https:'].includes(parsedUrl.protocol)) {
            image.url = ''; // Block external domains or unapproved schemes
          }
        } catch {
          image.url = ''; // Invalid URL format
        }
      }
    }
  });
}

4. Strict Schema and Geometry Limits

To prevent memory-exhaustion DoS attacks, validate payload sizes and geometric structures using a schema validator such as Ajv or Zod before invoking THREE.ObjectLoader.

  • Buffer Sizes: Inspect geometries arrays to enforce maximum limits on data.attributes.position.array lengths to prevent out-of-memory crashes.
  • Payload Constraints: Limit incoming JSON strings to a realistic file size limit (e.g., 20MB) prior to parsing.
  • Metadata Verification: Ensure the metadata.type property strictly matches "Object" or "Scene".

5. Executing Safe Parsing

Combine all sanitization steps in a dedicated loader wrapper:

import * as THREE from 'three';

export function loadSafeJSONScene(jsonString) {
  // 1. Enforce file size boundaries
  if (jsonString.length > 20 * 1024 * 1024) {
    throw new Error('File exceeds maximum allowable size.');
  }

  // 2. Parse and strip prototype pollution vectors
  const parsedData = JSON.parse(jsonString, (key, value) => {
    if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
      return undefined;
    }
    return value;
  });

  // 3. Validate metadata
  if (!parsedData.metadata || parsedData.metadata.version !== 4.5) {
    throw new Error('Unsupported or missing Three.js JSON format metadata.');
  }

  // 4. Strip executable hooks
  delete parsedData.scripts;

  // 5. Sanitize resources
  if (parsedData.images) {
    sanitizeImages(parsedData.images);
  }

  // 6. Safe instantiation
  const loader = new THREE.ObjectLoader();
  return loader.parse(parsedData);
}
