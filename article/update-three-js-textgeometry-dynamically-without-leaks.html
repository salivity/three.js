Update Three.js TextGeometry Dynamically Without Leaks

Updating text content in Three.js using TextGeometry requires regenerating the underlying vertex buffers, which rapidly causes severe GPU memory leaks if stale resources are not explicitly freed. Because TextGeometry produces a static polygonal mesh rather than a mutable text buffer, changing the text requires creating a new geometry instance and destroying the old one. This guide explains how to properly dispose of previous geometry data and swap in new text dynamically.

Why Memory Leaks Occur

In Three.js, JavaScript's native garbage collector does not automatically release WebGL buffer allocations on the GPU. When you assign a new TextGeometry to an existing mesh without manual cleanup, the previous geometry’s vertex, normal, and UV buffers remain allocated in GPU memory. Over time, repeated updates will exhaust GPU VRAM and crash the WebGL context.

The Update Pattern

To update text dynamically without leaking memory:

  1. Remove or unbind the old geometry from the mesh.
  2. Call .dispose() on the old geometry to deallocate GPU buffers.
  3. Instantiate a new TextGeometry with the updated string and original font.
  4. Assign the new geometry to the mesh.
  5. Recompute bounding boxes or centers if positioning depends on text dimensions.

Implementation Example

The following function updates an existing Mesh with new text while ensuring all previous geometry resources are released:

import { TextGeometry } from 'three/examples/jsm/geometries/TextGeometry.js';

function updateTextMesh(mesh, newText, font, options = {}) {
    // Merge custom options with default parameters
    const textOptions = {
        font: font,
        size: options.size || 1,
        depth: options.depth || 0.2,
        curveSegments: options.curveSegments || 12,
        bevelEnabled: options.bevelEnabled || false,
        bevelThickness: options.bevelThickness || 0.03,
        bevelSize: options.bevelSize || 0.02,
        bevelOffset: 0,
        bevelSegments: options.bevelSegments || 5
    };

    // 1. Dispose of the existing geometry to prevent GPU leaks
    if (mesh.geometry) {
        mesh.geometry.dispose();
    }

    // 2. Generate the new geometry
    const newGeometry = new TextGeometry(newText, textOptions);

    // 3. Optional: Re-center geometry if your layout requires it
    newGeometry.computeBoundingBox();
    if (options.center) {
        newGeometry.center();
    }

    // 4. Bind the new geometry to the existing mesh
    mesh.geometry = newGeometry;
}

Usage

Create the initial mesh once, then call the update function whenever the string changes:

import * as THREE from 'three';
import { FontLoader } from 'three/examples/jsm/loaders/FontLoader.js';

const loader = new FontLoader();

loader.load('fonts/helvetiker_regular.typeface.json', (font) => {
    const material = new THREE.MeshStandardMaterial({ color: 0xffffff });
    const textMesh = new THREE.Mesh(undefined, material);
    scene.add(textMesh);

    // Set initial text
    updateTextMesh(textMesh, 'Score: 0', font);

    // Update text later dynamically
    setTimeout(() => {
        updateTextMesh(textMesh, 'Score: 100', font);
    }, 2000);
});

Performance Consideration for Rapid Updates

Generating TextGeometry involves CPU-bound triangulation and glyph parsing. While calling dispose() completely prevents memory leaks, updating TextGeometry on every frame (such as for a high-speed counter or clock) can introduce frame rate drops. For high-frequency updates, use a dynamic HTML Canvas mapped to a CanvasTexture on a PlaneGeometry, or use Signed Distance Field (SDF) text rendering libraries instead of rebuilding 3D solid geometry.
