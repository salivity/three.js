How to Use Three.js Cache.enabled for Asset Caching

When developing Three.js applications, repeatedly requesting the same textures, models, or data files causes unnecessary network overhead and degrades performance. This article explains how to set the THREE.Cache.enabled boolean to true, ensuring that assets loaded via FileLoader and higher-level loaders like TextureLoader or GLTFLoader are cached in memory and reused across your application.

Understanding THREE.Cache

In Three.js, asset loading typically relies internally on THREE.FileLoader. To prevent redundant network requests when fetching the same URI multiple times, Three.js includes a built-in caching system accessible via the global THREE.Cache object.

By default, caching is disabled:

THREE.Cache.enabled = false;

When disabled, every loader request queries the network or relies purely on the browser's HTTP cache. Enabling THREE.Cache keeps an in-memory reference to previously loaded responses, allowing any loader relying on FileLoader to retrieve assets instantaneously without making duplicate HTTP requests.

Enabling the Cache

To activate the internal cache, set THREE.Cache.enabled to true in your codebase before executing any loading operations.

import * as THREE from 'three';

// Enable the internal cache
THREE.Cache.enabled = true;

This single line of configuration affects all loaders that use THREE.FileLoader internally, including:

  • THREE.TextureLoader
  • THREE.ImageBitmapLoader
  • THREE.AudioLoader
  • GLTFLoader
  • OBJLoader
  • FBXLoader

Practical Example Across Different Loaders

Once enabled, loading the same file path using different loaders or multiple instances of the same loader pulls the response directly from the internal cache.

import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';

// 1. Enable caching globally
THREE.Cache.enabled = true;

const textureLoader = new THREE.TextureLoader();
const gltfLoader = new GLTFLoader();

// 2. Load an asset
textureLoader.load('textures/shared_normal_map.png', (texture) => {
  // Texture downloaded and stored in THREE.Cache
});

// 3. Requesting the same file path uses the cached version
textureLoader.load('textures/shared_normal_map.png', (cachedTexture) => {
  // Retrieved directly from memory without a network round-trip
});

Managing Cache Memory

Because THREE.Cache holds files in JavaScript memory, large scenes with numerous assets can increase memory usage over time. You can inspect, retrieve, or clear cached items using the methods provided by the Cache API:

  • Check or get an item: THREE.Cache.get('path/to/asset.png')
  • Add an item manually: THREE.Cache.add('key', fileData)
  • Remove a single item: THREE.Cache.remove('path/to/asset.png')
  • Clear the entire cache: THREE.Cache.clear()

When transitioning between scenes or levels where previous assets are no longer required, call THREE.Cache.clear() to free up memory:

function unloadScene() {
  THREE.Cache.clear();
}
