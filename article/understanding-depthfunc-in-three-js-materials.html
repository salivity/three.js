Understanding depthFunc in Three.js Materials

This article provides an overview of the depthFunc property in Three.js, detailing how it directly controls the WebGL depth-testing function for rendered materials. You will learn how depthFunc dictates whether a fragment is drawn or discarded relative to existing depth buffer data, the standard constants available to configure it, and how it differs from CPU-level object sorting.

What is depthFunc?

In Three.js, depthFunc is a property inherited by all materials from the base THREE.Material class. Its primary function is to define the comparison algorithm used by the GPU during the depth test—specifically mapping to the WebGL API call gl.depthFunc().

When a 3D mesh is drawn, each fragment (potential pixel) carries a depth value (Z-buffer value) representing its distance from the camera. The depthFunc determines the exact mathematical condition under which this incoming fragment’s depth value is compared against the depth value already stored in the frame's depth buffer. If the comparison evaluates to true, the fragment passes the depth test and is rendered (or written to the buffer, assuming depthWrite is active); if false, the fragment is discarded.

Available Depth Functions

Three.js provides several constants to define custom depth-testing behavior:

  • THREE.LessEqualDepth (Default): A fragment is rendered if its depth is less than or equal to the stored depth. This is the standard behavior for realistic 3D occlusion, where closer objects hide objects farther away.
  • THREE.LessDepth: Renders the fragment only if its depth is strictly less than the stored depth.
  • THREE.GreaterEqualDepth: Renders the fragment only if its depth is greater than or equal to the stored depth.
  • THREE.GreaterDepth: Renders the fragment only if it is strictly behind existing geometry.
  • THREE.EqualDepth: Renders the fragment only if its depth matches the stored depth exactly.
  • THREE.NotEqualDepth: Renders the fragment only if its depth differs from the stored depth.
  • THREE.AlwaysDepth: Bypasses occlusion comparisons completely and always renders the fragment, regardless of what is in front of it.
  • THREE.NeverDepth: Never passes the depth test; the fragments are always discarded.

How It Interacts with Depth Sorting

It is important to distinguish depthFunc from CPU-side scene sorting. Three.js sorts transparent objects back-to-front and opaque objects front-to-back before dispatching draw calls. The depthFunc property does not alter the order in which meshes are processed in JavaScript; instead, it provides per-fragment evaluation on the GPU.

By altering depthFunc, developers can bypass standard visual rules without manually manipulating render queues. Common use cases include:

  • X-Ray / Occlusion Effects: Setting depthFunc to THREE.GreaterDepth allows geometry to render only when it is hidden behind walls or other meshes.
  • Always-Visible UI / Overlays: Setting depthFunc to THREE.AlwaysDepth forces 3D UI elements, gizmos, or crosshairs to render on top of all existing geometry without disabling the depth buffer entirely.
  • Z-Fighting Mitigation: Custom depth functions can be used alongside polygon offsets to control which overlapping coplanar surface takes rendering precedence.
