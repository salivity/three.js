How to Pause Three.js Clock on Tab Switch

When a user switches browser tabs, requestAnimationFrame pauses, but the internal THREE.Clock continues tracking real-world time. Once the tab becomes active again, the next call to clock.getDelta() returns a massive elapsed time value, causing physics simulations to explode, animations to skip, and camera controls to teleport. This article explains how to prevent these delta spikes using the browser's Page Visibility API to automatically stop and resume the Three.js clock.

Why Delta Jumps Happen

The THREE.Clock.getDelta() method calculates the difference in seconds between the current call and the previous call. In a normal animation loop running at 60 FPS, this value is approximately 0.016 seconds.

Browsers throttle or completely halt requestAnimationFrame in inactive background tabs to conserve CPU, GPU, and battery usage. If a user backgrounds the tab for 15 seconds, the render loop halts. When the user returns, the render loop resumes, and clock.getDelta() calculates an elapsed time of 15 seconds. If that delta is passed directly into a physics engine or positional updates, objects will leap across the scene instantaneously.

The Solution: Page Visibility API

To fix this, use the native visibilitychange event provided by the Page Visibility API. By pairing this event with the clock.stop() and clock.start() methods, you halt the internal timer while the tab is hidden and reset the delta baseline when it regains focus.

Implementation

import * as THREE from 'three';

const clock = new THREE.Clock();

// Handle tab switching
document.addEventListener('visibilitychange', () => {
    if (document.hidden) {
        // Pauses the clock and stops internal time accumulation
        clock.stop();
    } else {
        // Resets the internal previous time baseline and resumes tracking
        clock.start();
    }
});

function animate() {
    requestAnimationFrame(animate);

    // If the clock is stopped, getDelta() safely returns 0
    const delta = clock.getDelta();

    // Update animations, physics, and scene logic
    updateScene(delta);

    renderer.render(scene, camera);
}

animate();

How clock.stop() and clock.start() Work Internally

  1. clock.stop(): Sets clock.running to false and records the total elapsed time up to that moment. If getDelta() is called while the clock is stopped, it returns 0.
  2. clock.start(): Sets clock.running to true, marks the current performance timestamp as the oldTime, and resets the baseline for the next getDelta() invocation. Because oldTime is updated to the moment the tab becomes visible, the subsequent getDelta() call only measures the fraction of a second between tab reactivation and the first resumed frame.

Recommended Safety Measure: Clamping Delta

While the Page Visibility API handles tab switches, temporary freezes caused by heavy garbage collection or system lag can still cause smaller delta spikes (e.g., 200–500ms). To ensure complete stability, combine the visibility listener with delta clamping:

const MAX_DELTA = 0.1; // Maximum allowed frame step (100ms)

function animate() {
    requestAnimationFrame(animate);

    // Clamp delta to prevent unexpected jumps during frame drops
    const delta = Math.min(clock.getDelta(), MAX_DELTA);

    updateScene(delta);
    renderer.render(scene, camera);
}

By combining clock.stop() / clock.start() on visibility changes with a maximum delta threshold, your Three.js application remains stable across tab switches, window minimizes, and system-level performance hiccups.
