Custom Bounding Sphere for Frustum Culling in Three.js

In Three.js, the renderer uses bounding spheres to perform frustum culling, automatically skipping meshes outside the camera’s view to preserve performance. By default, Three.js computes this sphere directly from the vertices in a mesh's BufferGeometry. This guide explains how to define and lock a custom THREE.Sphere on your geometry to manually control frustum culling behavior, which is essential when dealing with vertex shader displacements, expansive particle systems, or skeletal animations that exceed standard geometry bounds.

Why Override the Bounding Sphere?

When vertices are manipulated via custom shaders (such as vertex displacement, waves, or wind effects) or custom bone rigs, the actual rendered positions differ from the base geometry data. Because the default frustum culling relies purely on the static attributes of BufferGeometry, the camera may cull (hide) a mesh while parts of it should still be visible on screen. Setting a custom, enlarged bounding sphere ensures the mesh stays rendered without the heavy performance penalty of disabling frustum culling entirely via mesh.frustumCulled = false.

Defining the Custom Bounding Sphere

Frustum culling calculations evaluate the boundingSphere property located on the geometry of the Mesh, expressed in the geometry's local coordinate space.

To define a custom bounding sphere, instantiate a THREE.Sphere with a specified center (THREE.Vector3) and radius, then assign it directly to the geometry:

import * as THREE from 'three';

// 1. Create your geometry and mesh
const geometry = new THREE.BoxGeometry(2, 2, 2);
const material = new THREE.MeshStandardMaterial();
const mesh = new THREE.Mesh(geometry, material);

// 2. Define custom center and radius (in local space)
const customCenter = new THREE.Vector3(0, 0, 0);
const customRadius = 10; // Extended radius to account for displacements

// 3. Explicitly assign the custom bounding sphere
mesh.geometry.boundingSphere = new THREE.Sphere(customCenter, customRadius);

Preventing Automatic Overwrites

Three.js may invoke geometry.computeBoundingSphere() internally during certain operations, scene graph updates, or loaders, which resets geometry.boundingSphere to the default calculated size.

To permanently preserve your custom bounding sphere, override the computeBoundingSphere method on that specific geometry instance:

// Prevent Three.js internals from recalculating the bounding sphere
mesh.geometry.computeBoundingSphere = function() {
    // Keep the assigned custom sphere intact
    this.boundingSphere = new THREE.Sphere(customCenter, customRadius);
};

Alternatively, override it with an empty function if you have already set the instance:

mesh.geometry.boundingSphere = new THREE.Sphere(customCenter, customRadius);
mesh.geometry.computeBoundingSphere = () => {};

Local Space vs. World Space

The boundingSphere set on BufferGeometry must be defined in local coordinates. During the render loop, Three.js automatically multiplies this local sphere by mesh.matrixWorld to derive the final world-space sphere used for frustum intersection tests. You do not need to manually account for the position, rotation, or scale of the Mesh instance itself when setting the sphere radius and center.
