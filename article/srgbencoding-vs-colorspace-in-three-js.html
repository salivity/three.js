sRGBEncoding vs colorSpace in Three.js

This article provides an overview of the transition in Three.js from the legacy sRGBEncoding system to the modern colorSpace property. Introduced around release r152, this update fundamentally changed how the library handles color management, moving away from numeric encoding constants to standardized, string-based color space definitions. Below is a direct breakdown of the technical differences, underlying motivations, and practical implications of this shift.

Numeric Constants vs. Standard String Identifiers

The most immediate difference is the data type and naming convention:

  • Legacy (sRGBEncoding): Represented as an integer constant (internally evaluated as 3001). It was set on properties such as renderer.outputEncoding and texture.encoding.
  • Modern (colorSpace): Represented as a standardized string literal, defined via constants such as THREE.SRGBColorSpace (evaluating to 'srgb') and THREE.LinearSRGBColorSpace (evaluating to 'srgb-linear'). It is set on renderer.outputColorSpace and texture.colorSpace.

Semantic Scope: Encodings vs. Full Color Spaces

The shift in terminology addresses a technical limitation in how Three.js previously described color data:

  • Encoding strictly refers to a transfer function (the electro-optical transfer function or gamma curve) applied to color values to compress them efficiently for storage or display.
  • Color Space encompasses both the color gamut (the chromaticity coordinates of the red, green, and blue primaries plus the white point) and the transfer function.

By upgrading to colorSpace, Three.js aligned itself with modern web standards (such as CSS Color Module 4 and WebGPU) and glTF specifications, paving the way for wider gamuts (like Display P3) rather than being architecturally limited to sRGB gamma curves.

Integration with the ColorManagement API

Under the old sRGBEncoding paradigm, color management was fragmented. Developers often had to manually manage whether color conversions occurred in shaders, hex color instantiations, or textures, which frequently led to "double-gamma" correction or washed-out renders.

Under the modern system:

  • Color management is globally centralized and enabled by default (THREE.ColorManagement.enabled = true).
  • Color values defined in materials (e.g., new THREE.Color(0xff0000)) are automatically accounted for in working linear color space.
  • Setting texture.colorSpace = THREE.SRGBColorSpace explicitly informs Three.js of the input's source gamut and transfer curve so it can accurately linearize the texture before lighting calculations occur.
  • Setting renderer.outputColorSpace = THREE.SRGBColorSpace handles the final conversion from linear working space to the target display space during the final render pass.

Migration Summary

To modernize code using the deprecated properties:

// Old (Deprecated)
renderer.outputEncoding = THREE.sRGBEncoding;
texture.encoding = THREE.sRGBEncoding;

// Modern
renderer.outputColorSpace = THREE.SRGBColorSpace;
texture.colorSpace = THREE.SRGBColorSpace;

For uncompressed data textures or normal/roughness maps where values represent raw mathematical vectors rather than visible color:

// Old (Deprecated)
texture.encoding = THREE.LinearEncoding;

// Modern
texture.colorSpace = THREE.NoColorSpace; // or THREE.LinearSRGBColorSpace where appropriate
