Using MeshoptDecoder with GLTFLoader in Three.js

Integrating MeshoptDecoder with GLTFLoader in Three.js allows you to load models compressed with the meshoptimizer library, significantly reducing file sizes, bandwidth consumption, and GPU memory usage. This guide outlines the exact steps required to import the decoder, bind it to your loader instance, and parse compressed glTF or GLB assets efficiently.

1. Import the Required Modules

You must import GLTFLoader along with MeshoptDecoder from the Three.js library. If you are using an npm environment, MeshoptDecoder is located within the three/examples/jsm/libs/meshopt_decoder.module.js directory.

import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
import { MeshoptDecoder } from 'three/examples/jsm/libs/meshopt_decoder.module.js';

If you are using script tags or CDN-based import maps, link the appropriate ESM build for both the loader and the decoder module.

2. Configure GLTFLoader with MeshoptDecoder

Instantiate the GLTFLoader and assign the decoder using the .setMeshoptDecoder() method. Unlike some other decoders (like Draco), MeshoptDecoder does not require configuring a path to external WebAssembly worker files; the module handles the WebAssembly loading and execution internally.

const loader = new GLTFLoader();
loader.setMeshoptDecoder(MeshoptDecoder);

3. Load the Compressed Asset

Once configured, use the loader as normal. When GLTFLoader encounters the EXT_meshopt_compression extension in a glTF or GLB file, it delegates the decompression work to the registered MeshoptDecoder.

loader.load(
  'path/to/meshopt-compressed-model.glb',
  (gltf) => {
    // Add the loaded scene to your Three.js scene
    scene.add(gltf.scene);
  },
  (xhr) => {
    console.log(`${(xhr.loaded / xhr.total) * 100}% loaded`);
  },
  (error) => {
    console.error('An error occurred loading the model:', error);
  }
);

Complete Implementation Example

import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
import { MeshoptDecoder } from 'three/examples/jsm/libs/meshopt_decoder.module.js';

// Setup basic scene
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// Setup loader with meshoptimizer support
const gltfLoader = new GLTFLoader();
gltfLoader.setMeshoptDecoder(MeshoptDecoder);

// Load the model
gltfLoader.load(
  'models/optimized_asset.glb',
  (gltf) => {
    scene.add(gltf.scene);
    renderer.render(scene, camera);
  },
  undefined,
  (error) => {
    console.error('Failed to load asset:', error);
  }
);

Key Considerations

  • WebAssembly Readiness: In modern browsers, MeshoptDecoder automatically compiles its WebAssembly binary on import. If supporting environments that strictly require asynchronous preparation, ensure MeshoptDecoder.ready has resolved before loading models.
  • Compatibility: Using loader.setMeshoptDecoder() does not prevent the loader from opening uncompressed models; it only activates when the EXT_meshopt_compression extension is detected.
