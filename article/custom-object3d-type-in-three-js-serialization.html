Custom Object3D Type in Three.js Serialization

This article explains how to assign a custom user-defined string to the Object3D.type property in Three.js to support custom serialization and deserialization. By extending the base THREE.Object3D class and properly mapping the custom type within THREE.ObjectLoader, you can preserve domain-specific metadata and reconstruct custom objects seamlessly across JSON export and import cycles.

Extending Object3D with a Custom Type

In Three.js, serialization methods like toJSON() rely on the type property of an object to define how it is represented in the resulting JSON schema. To assign a custom string to Object3D.type, extend the THREE.Object3D class (or any of its subclasses, such as THREE.Mesh) and override the type property inside the constructor.

import * as THREE from 'three';

class CustomNode extends THREE.Object3D {
  constructor() {
    super();
    this.type = 'CustomNode';
  }
}

Serializing the Custom Object

When you serialize a scene graph using object.toJSON(), Three.js automatically includes the type property in the exported data structure under the object field.

const node = new CustomNode();
node.name = 'MyCustomNode';

const jsonOutput = node.toJSON();
console.log(jsonOutput.object.type); // Outputs: "CustomNode"

If your custom class includes additional custom properties that need to be serialized, override the toJSON method while invoking super.toJSON:

class CustomNode extends THREE.Object3D {
  constructor() {
    super();
    this.type = 'CustomNode';
    this.customId = 12345;
  }

  toJSON(meta) {
    const data = super.toJSON(meta);
    data.object.customId = this.customId;
    return data;
  }
}

Deserializing with ObjectLoader Mapping

By default, THREE.ObjectLoader does not recognize custom string values for type and falls back to standard types or logs a warning. To restore your custom class when parsing serialized JSON, extend or patch the ObjectLoader.prototype.parseObject method to map your custom type back to its constructor.

import * as THREE from 'three';

class CustomObjectLoader extends THREE.ObjectLoader {
  parseObject(data, geometries, materials, textures, animations) {
    if (data.type === 'CustomNode') {
      const object = new CustomNode();

      object.name = data.name || '';
      object.castShadow = data.castShadow || false;
      object.receiveShadow = data.receiveShadow || false;
      object.visible = data.visible !== undefined ? data.visible : true;
      object.customId = data.customId;

      if (data.matrix !== undefined) {
        object.matrix.fromArray(data.matrix);
        if (data.matrixAutoUpdate !== undefined) {
          object.matrixAutoUpdate = data.matrixAutoUpdate;
        }
        if (object.matrixAutoUpdate) {
          object.matrix.decompose(object.position, object.quaternion, object.scale);
        }
      }

      if (data.children !== undefined) {
        const children = data.children;
        for (let i = 0; i < children.length; i++) {
          object.add(this.parseObject(children[i], geometries, materials, textures, animations));
        }
      }

      return object;
    }

    return super.parseObject(data, geometries, materials, textures, animations);
  }
}

Loading the Serialized Object

To load the exported scene or object back into Three.js, instantiate the extended loader:

const loader = new CustomObjectLoader();
const restoredNode = loader.parse(jsonOutput);

console.log(restoredNode instanceof CustomNode); // Outputs: true
console.log(restoredNode.type); // Outputs: "CustomNode"
console.log(restoredNode.customId); // Outputs: 12345
