Force Three.js Dynamic Texture Mipmap Generation

Updating texture pixel data directly via the CPU in Three.js often causes rendering artifacts or visual aliasing if mipmaps are not properly regenerated. When modifying a DataTexture or CanvasTexture at runtime, Three.js does not always rebuild the mipmap chain by default. This guide details how to configure your texture and force WebGL to automatically regenerate full mipmap chains whenever your CPU-side pixel buffer changes.

1. Enable Mipmap Generation on the Texture

By default, standard THREE.Texture instances have mipmap generation enabled, but specific classes like THREE.DataTexture default generateMipmaps to false. You must explicitly set this property to true:

texture.generateMipmaps = true;

2. Configure a Mipmapped Minification Filter

WebGL will only sample and allocate mipmaps if the minification filter (minFilter) is configured to use them. Set minFilter to one of the mipmap-enabled modes:

texture.minFilter = THREE.LinearMipmapLinearFilter; // Trilinear filtering (recommended)
// Or: THREE.LinearMipmapNearestFilter, THREE.NearestMipmapLinearFilter, THREE.NearestMipmapNearestFilter

Ensure that the magnification filter (magFilter) remains a non-mipmap filter, such as THREE.LinearFilter or THREE.NearestFilter.

3. Flag the Texture for Update

Whenever you alter the underlying pixel array (such as a Uint8Array in texture.image.data) on the CPU, mark the texture as dirty. Setting needsUpdate to true tells the renderer to re-upload the pixel buffer to the GPU and invoke the underlying gl.generateMipmap() call:

// 1. Modify your CPU data buffer
const data = texture.image.data;
data[0] = 255; // Red
data[1] = 0;   // Green
data[2] = 0;   // Blue
data[3] = 255; // Alpha

// 2. Trigger the GPU upload and mipmap regeneration
texture.needsUpdate = true;

Complete Implementation Example

import * as THREE from 'three';

const width = 512;
const height = 512;
const size = width * height;
const data = new Uint8Array(4 * size);

// Create the DataTexture
const dynamicTexture = new THREE.DataTexture(
  data,
  width,
  height,
  THREE.RGBAFormat
);

// Configure mipmaps
dynamicTexture.generateMipmaps = true;
dynamicTexture.minFilter = THREE.LinearMipmapLinearFilter;
dynamicTexture.magFilter = THREE.LinearFilter;

// Function to update CPU data and force mipmap generation
function updateTexturePixels() {
  const pixelData = dynamicTexture.image.data;

  for (let i = 0; i < pixelData.length; i += 4) {
    pixelData[i] = Math.floor(Math.random() * 256);     // R
    pixelData[i + 1] = Math.floor(Math.random() * 256); // G
    pixelData[i + 2] = Math.floor(Math.random() * 256); // B
    pixelData[i + 3] = 255;                             // A
  }

  // Instruct Three.js to re-upload and regenerate mipmaps
  dynamicTexture.needsUpdate = true;
}

Important Caveats

  • Power-of-Two Dimensions: If targeting WebGL 1, texture dimensions must be powers of two (e.g., 256×256, 512×512) for mipmaps to generate correctly. While WebGL 2 supports non-power-of-two mipmaps, power-of-two dimensions prevent cross-platform rendering issues.
  • Performance Impact: Regenerating mipmaps requires the GPU to downsample your image across multiple levels every time needsUpdate is flagged. Keep updates to the minimum required frequency to avoid GPU pipeline stalls.
