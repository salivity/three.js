Remove Three.js Event Listeners to Prevent Memory Leaks

Failing to properly unbind event listeners in a Three.js application leads to detached DOM nodes, retained geometry and material references, and memory leaks that degrade WebGL performance over time. Because Three.js uses both standard browser DOM events and an internal custom event dispatching system, complete cleanup requires targeting both mechanisms. This guide explains how to properly store function references, detach listeners from Three.js objects and DOM elements, and safely dispose of scene-related controls.

1. Always Use Named Functions

The most common cause of memory leaks is attaching anonymous functions or dynamically generated inline arrow functions. When you pass an anonymous function to an event listener, JavaScript allocates a new function instance that cannot be targeted later by removal methods.

To ensure a listener can be removed, define the handler as a named function or store the bound method in a persistent variable:

// Incorrect: Anonymous function cannot be removed later
window.addEventListener('resize', () => onWindowResize());

// Correct: Stored reference allows exact targeting
function onWindowResize() {
  camera.aspect = window.innerWidth / window.innerHeight;
  camera.updateProjectionMatrix();
  renderer.setSize(window.innerWidth, window.innerHeight);
}

window.addEventListener('resize', onWindowResize);

2. Removing Three.js EventDispatcher Listeners

Three.js objects—such as controls, custom loaders, and instances extending THREE.EventDispatcher—implement their own addEventListener and removeEventListener methods. These listeners exist entirely in JavaScript memory, preventing the Three.js object from being garbage-collected as long as the listener is active.

To remove an event listener from a Three.js object:

// Function reference
const onControlsChange = () => {
  renderer.render(scene, camera);
};

// Add listener
controls.addEventListener('change', onControlsChange);

// Correctly remove listener when cleaning up
controls.removeEventListener('change', onControlsChange);

3. Cleaning Up DOM and Window Listeners

Interactive Three.js scenes typically rely on browser-level listeners for raycasting, window resizing, and pointer tracking. These are bound to the window, document, or renderer.domElement.

When unmounting or destroying a scene, mirror every addEventListener with removeEventListener:

function onPointerMove(event) {
  pointer.x = (event.clientX / window.innerWidth) * 2 - 1;
  pointer.y = -(event.clientY / window.innerHeight) * 2 + 1;
}

// Attach
renderer.domElement.addEventListener('pointermove', onPointerMove);
window.addEventListener('resize', onWindowResize);

// Detach on cleanup
renderer.domElement.removeEventListener('pointermove', onPointerMove);
window.removeEventListener('resize', onWindowResize);

4. Disposing of Helper Controls

Pre-built add-ons like OrbitControls, TransformControls, or PointerLockControls attach internal listeners to both DOM elements and internal state machines. Merely dereferencing the control object will not unbind these DOM hooks.

Always invoke the dispose() method provided by the control instance, which detaches all internal event handlers automatically:

controls.removeEventListener('change', onControlsChange);
controls.dispose();

5. Systematic Scene Teardown Pattern

In modern component-based frameworks (like React, Vue, or Angular), assemble your removal operations into a centralized destruction routine. This ensures all event listeners and WebGL resources are purged together:

function destroyScene() {
  // 1. Remove DOM and window listeners
  window.removeEventListener('resize', onWindowResize);
  renderer.domElement.removeEventListener('pointermove', onPointerMove);

  // 2. Remove Three.js object listeners and dispose controls
  controls.removeEventListener('change', onControlsChange);
  controls.dispose();

  // 3. Clean up WebGL context and DOM element
  renderer.dispose();
  if (renderer.domElement && renderer.domElement.parentElement) {
    renderer.domElement.parentElement.removeChild(renderer.domElement);
  }
}
