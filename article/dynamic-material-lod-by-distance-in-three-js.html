Dynamic Material LOD by Distance in Three.js

This article explains how to implement a custom Level-of-Detail (LOD) system in Three.js that dynamically swaps an object's materials based on its distance from the camera. While Three.js includes a native THREE.LOD class primarily designed for swapping entire meshes and geometries, swapping only materials on a single geometry reduces shader complexity, texture overhead, and GPU load without duplicating vertex buffers. Below, you will find the architectural approach, implementation code using squared distance calculations, and performance optimization techniques.

Step 1: Prepare the Materials

Create your materials outside the render loop. Pre-instantiate each level of detail so that memory is allocated only once.

import * as THREE from 'three';

// High detail: Complex PBR material for close-up inspection
const materialHigh = new THREE.MeshStandardMaterial({
  color: 0x55aaff,
  roughness: 0.2,
  metalness: 0.8,
  wireframe: false
});

// Medium detail: Simpler Lambert material for moderate distances
const materialMedium = new THREE.MeshLambertMaterial({
  color: 0x55aaff
});

// Low detail: Unlit, cheap Basic material for far distances
const materialLow = new THREE.MeshBasicMaterial({
  color: 0x336699
});

Step 2: Set Up the LOD Thresholds and Mesh

Define distance thresholds. To maximize performance, use squared distances (distanceToSquared) to avoid the computational overhead of square root operations during distance checks.

// Define threshold ranges (in world units)
const DISTANCE_MEDIUM = 20;
const DISTANCE_LOW = 50;

// Compute squared thresholds once
const THRESHOLD_MEDIUM_SQ = DISTANCE_MEDIUM * DISTANCE_MEDIUM; // 400
const THRESHOLD_LOW_SQ = DISTANCE_LOW * DISTANCE_LOW;         // 2500

// Create a single geometry and assign the default high material
const geometry = new THREE.TorusKnotGeometry(2, 0.6, 128, 32);
const mesh = new THREE.Mesh(geometry, materialHigh);
scene.add(mesh);

Step 3: Implement the Distance Check and Swapping Logic

Create an update function to calculate the distance between the camera and the mesh in world space. Update mesh.material only when a threshold boundary is crossed to prevent unnecessary state assignments.

const meshWorldPosition = new THREE.Vector3();
const cameraWorldPosition = new THREE.Vector3();

function updateMaterialLOD(targetMesh, camera) {
  // Obtain world coordinates
  targetMesh.getWorldPosition(meshWorldPosition);
  camera.getWorldPosition(cameraWorldPosition);

  // Compute squared distance
  const distanceSq = meshWorldPosition.distanceToSquared(cameraWorldPosition);

  let targetMaterial;

  if (distanceSq > THRESHOLD_LOW_SQ) {
    targetMaterial = materialLow;
  } else if (distanceSq > THRESHOLD_MEDIUM_SQ) {
    targetMaterial = materialMedium;
  } else {
    targetMaterial = materialHigh;
  }

  // Only swap if the material has changed
  if (targetMesh.material !== targetMaterial) {
    targetMesh.material = targetMaterial;
  }
}

Step 4: Integrate into the Render Loop

Invoke the update logic within your animation loop before the scene is rendered.

function animate() {
  requestAnimationFrame(animate);

  // Update LOD state
  updateMaterialLOD(mesh, camera);

  renderer.render(scene, camera);
}

animate();

Alternative: Using the Native THREE.LOD Object

If your project already uses THREE.LOD, you can attach multiple meshes that share the same geometry reference but hold different materials.

const lod = new THREE.LOD();

const meshHigh = new THREE.Mesh(geometry, materialHigh);
const meshMedium = new THREE.Mesh(geometry, materialMedium);
const meshLow = new THREE.Mesh(geometry, materialLow);

// Add levels with distance parameters
lod.addLevel(meshHigh, 0);
lod.addLevel(meshMedium, 20);
lod.addLevel(meshLow, 50);

scene.add(lod);

// In the animation loop:
function animate() {
  requestAnimationFrame(animate);
  lod.update(camera);
  renderer.render(scene, camera);
}

Performance Best Practices

  • Throttle Distance Calculations: For scenes containing hundreds of objects, running distance checks every frame causes a CPU bottleneck. Use an interval or modulo counter on the frame index to distribute calculations across multiple frames.
  • Reuse Vectors: Never instantiate new THREE.Vector3 objects inside the render or update loop, as this triggers garbage collection spikes.
  • Frustum Culling: Ensure that distance-checking logic skips objects that are outside the camera’s view frustum.
