VectorKeyframeTrack vs QuaternionKeyframeTrack in Three.js

When creating keyframe animations in Three.js, choosing between VectorKeyframeTrack and QuaternionKeyframeTrack depends primarily on the target property type, the dimensional structure of the data, and the required mathematical interpolation. This guide outlines the core distinctions between the two classes, detailing their data layouts, interpolation behaviors, and ideal use cases to ensure smooth and accurate 3D animations.

1. Target Properties and Dimensionality

The most fundamental difference lies in the number of values stored per keyframe and the properties they animate on a Three.js object:

  • VectorKeyframeTrack: Handles 3-dimensional data. It is primarily used to animate properties such as .position and .scale. Each keyframe requires an array of three sequential floating-point numbers: [x, y, z].
  • QuaternionKeyframeTrack: Handles 4-dimensional rotational data. It is specifically designed to animate the .quaternion property. Each keyframe requires four floating-point numbers representing a normalized quaternion: [x, y, z, w].

2. Value Array Sizing

Because the track types consume different numbers of coordinates per keyframe, the length of the values array relative to the times array differs:

  • For a VectorKeyframeTrack, the values array length must equal times.length * 3.
  • For a QuaternionKeyframeTrack, the values array length must equal times.length * 4.
// VectorKeyframeTrack example (Position)
const positionTimes = [0, 1];
const positionValues = [
  0, 0, 0,  // Time 0: x, y, z
  0, 5, 0   // Time 1: x, y, z
];
const posTrack = new THREE.VectorKeyframeTrack('.position', positionTimes, positionValues);

// QuaternionKeyframeTrack example (Rotation)
const rotationTimes = [0, 1];
const rotationValues = [
  0, 0, 0, 1,                           // Time 0: x, y, z, w (Identity)
  0, 0.7071068, 0, 0.7071068             // Time 1: x, y, z, w (90° on Y)
];
const rotTrack = new THREE.QuaternionKeyframeTrack('.quaternion', rotationTimes, rotationValues);

3. Interpolation Mechanics

Interpolating rotations directly as linear vectors leads to distortion, unwanted scaling, and gimbal lock. Three.js resolves this by providing specialized interpolation math inside QuaternionKeyframeTrack:

  • VectorKeyframeTrack relies on standard Euclidean interpolation methods: THREE.InterpolateLinear (lerp), THREE.InterpolateDiscrete, or THREE.InterpolateSmooth (cubic spline).
  • QuaternionKeyframeTrack automatically performs Spherical Linear Interpolation (SLERP) when set to linear mode. SLERP ensures constant angular velocity along the shortest arc on a 4D unit sphere, keeping the rotation smooth and normalized throughout playback.

4. Summary of Use Cases

  • Use VectorKeyframeTrack whenever translating an object across 3D space (.position) or expanding and shrinking an object (.scale).
  • Use QuaternionKeyframeTrack for all skeletal joint adjustments and object rotations (.quaternion). Avoid animating Euler angles (.rotation) with vector tracks, as quaternions prevent gimbal lock and deliver smoother rotational transitions.
