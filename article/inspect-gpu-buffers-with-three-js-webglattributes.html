Inspect GPU Buffers with Three.js WebGLAttributes

This article explains how to access and inspect underlying WebGL GPU buffers in Three.js using the internal WebGLAttributes class. By tapping into the renderer's attributes cache, developers can debug memory consumption, verify buffer updates, inspect WebGL data types, and check the active state of buffers bound to geometry attributes.

Accessing the WebGLAttributes Instance

In Three.js, GPU memory allocation for vertex data is managed by an instance of WebGLAttributes, exposed directly through the WebGL renderer:

const attributesManager = renderer.attributes;

This manager maps high-level Three.js BufferAttribute instances to low-level WebGL representations, holding references to the created WebGLBuffer objects, their data types, and state versions.

Retrieving Buffer Details

Before a buffer can be inspected through WebGLAttributes, it must be initialized on the GPU. This occurs automatically after the mesh is rendered at least once, or when explicitly forced by calling renderer.initTexture() or pre-compiling the scene.

To retrieve the low-level buffer data corresponding to a geometry attribute, pass the BufferAttribute to renderer.attributes.get():

// Access a specific attribute from your geometry
const positionAttribute = geometry.attributes.position;

// Ensure the object has been rendered or initialized
renderer.render(scene, camera);

// Retrieve the WebGL buffer information
const gpuBufferData = renderer.attributes.get(positionAttribute);

console.log(gpuBufferData);

The returned object contains the following key properties:

  • buffer: The raw WebGL WebGLBuffer handle allocated in GPU memory.
  • type: The WebGL data type constant (e.g., gl.FLOAT, gl.UNSIGNED_SHORT).
  • bytesPerElement: The byte size of each data element in the buffer.
  • version: The internal version integer used by Three.js to detect when needsUpdate = true requires re-uploading data to the GPU.

Verifying Currently Bound Buffers

WebGLAttributes maintains the reference to the WebGLBuffer, but determining if that buffer is actively bound to the WebGL context requires querying the native WebGL state. You can extract the WebGL rendering context from the renderer and compare the active binding with the buffer obtained from WebGLAttributes:

const gl = renderer.getContext();

// Get the currently bound ARRAY_BUFFER from the WebGL context
const currentlyBoundBuffer = gl.getParameter(gl.ARRAY_BUFFER_BINDING);

// Inspect the position attribute's GPU buffer
const positionBufferData = renderer.attributes.get(geometry.attributes.position);

if (positionBufferData && positionBufferData.buffer === currentlyBoundBuffer) {
    console.log("The position attribute buffer is currently bound to GL_ARRAY_BUFFER.");
} else {
    console.log("The position buffer is not currently bound.");
}

Inspecting Buffer Allocation and Updates

You can also use WebGLAttributes to verify buffer recreation and update lifecycles. When modifying attribute data without reallocating memory:

// Check buffer handle before update
const initialBuffer = renderer.attributes.get(positionAttribute).buffer;

// Modify data
positionAttribute.array[0] = 1.0;
positionAttribute.needsUpdate = true;
renderer.render(scene, camera);

// Check buffer handle after update
const updatedBuffer = renderer.attributes.get(positionAttribute).buffer;

// True indicates data was updated via gl.bufferSubData without reallocating the GPU handle
console.log(initialBuffer === updatedBuffer);

If renderer.attributes.get(attribute) returns undefined, the geometry attribute has not yet been processed by the renderer or has been deallocated through geometry.dispose().
