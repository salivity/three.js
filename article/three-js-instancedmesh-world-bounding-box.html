Three.js InstancedMesh World Bounding Box

In Three.js, calculating the world-space bounding box of an InstancedMesh requires accounting for each individual instance's transformation matrix alongside the root mesh's world matrix. By default, the geometry's standard bounding box only reflects the original base geometry in its local coordinates. This guide details how to accurately calculate a complete world-space Box3 encompassing every instance using both modern Three.js native methods and manual matrix iteration.

Method 1: Using Built-in Methods (Three.js r151+)

Modern versions of Three.js provide a built-in computeBoundingBox() method specifically for InstancedMesh. This method iterates over all instances internally to create a bounding box in the local space of the InstancedMesh. You then transform this local box into world coordinates using the mesh's world matrix.

import * as THREE from 'three';

function getInstancedMeshWorldBoundingBox(instancedMesh) {
  // Ensure the world matrix of the mesh is up to date
  instancedMesh.updateMatrixWorld(true);

  // Compute the local bounding box across all instances
  instancedMesh.computeBoundingBox();

  // Clone the computed box and apply the world matrix
  const worldBox = instancedMesh.boundingBox.clone();
  worldBox.applyMatrix4(instancedMesh.matrixWorld);

  return worldBox;
}

Method 2: Manual Calculation Across All Instances

If you are using an older version of Three.js, or need to calculate bounds dynamically without mutating instancedMesh.boundingBox, you can iterate through the instances manually. This approach extracts each instance matrix, combines it with the object's matrixWorld, transforms the base geometry's bounding box, and merges them into a single Box3.

import * as THREE from 'three';

function computeManualInstancedWorldBox(instancedMesh) {
  const geometry = instancedMesh.geometry;

  // 1. Ensure the base geometry has a bounding box
  if (!geometry.boundingBox) {
    geometry.computeBoundingBox();
  }

  // 2. Ensure the InstancedMesh world matrix is updated
  instancedMesh.updateMatrixWorld(true);

  const totalWorldBox = new THREE.Box3();
  const instanceBox = new THREE.Box3();
  const instanceMatrix = new THREE.Matrix4();
  const worldMatrix = new THREE.Matrix4();

  // 3. Loop through all instances
  for (let i = 0; i < instancedMesh.count; i++) {
    // Retrieve the local transformation matrix for this instance
    instancedMesh.getMatrixAt(i, instanceMatrix);

    // Multiply the mesh's world matrix by the instance's matrix
    worldMatrix.multiplyMatrices(instancedMesh.matrixWorld, instanceMatrix);

    // Transform the base geometry's bounding box to world space
    instanceBox.copy(geometry.boundingBox).applyMatrix4(worldMatrix);

    // Expand the total bounding box to enclose this instance
    if (i === 0) {
      totalWorldBox.copy(instanceBox);
    } else {
      totalWorldBox.union(instanceBox);
    }
  }

  return totalWorldBox;
}

Important Considerations

  • Matrix Synchronization: Always ensure instancedMesh.updateMatrixWorld(true) is called before calculating bounding boxes. If instances were updated via .setMatrixAt(), make sure instancedMesh.instanceMatrix.needsUpdate = true was set prior to computation.
  • Performance: Computing the bounding box by iterating over thousands of instances can be computationally expensive. Avoid running this calculation inside your render loop. Instead, compute and cache the resulting Box3, updating it only when instance transforms change.
  • Frustum Culling: Three.js uses bounding spheres and boxes for camera frustum culling. If you update instances dynamically and objects disappear prematurely, call instancedMesh.computeBoundingSphere() and instancedMesh.computeBoundingBox() so the engine's internal culling remains accurate.
