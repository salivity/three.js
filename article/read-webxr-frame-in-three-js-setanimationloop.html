Read WebXR Frame in Three.js setAnimationLoop

This article explains how to access the XRFrame parameter inside the Three.js setAnimationLoop callback to retrieve low-level WebXR tracking data. When an immersive VR or AR session is active, Three.js provides the raw XRFrame directly within the render loop, allowing developers to query reference spaces, viewer poses, controller orientations, and hit-test results that are not automatically mapped to the scene graph.

The setAnimationLoop Callback Signature

In standard Three.js development, renderer.setAnimationLoop takes a callback function used to render frames. When WebXR is enabled on the renderer (renderer.xr.enabled = true) and a session is presenting, Three.js supplies two arguments to this callback: the DOMHighResTimeStamp and the active XRFrame.

renderer.setAnimationLoop((timestamp, frame) => {
  // 'timestamp' is the frame presentation time
  // 'frame' is the active XRFrame (or null if not in an XR session)
});

If the user is not currently in an immersive session, the frame parameter is null or undefined. Always verify that frame exists before querying device tracking data.

Obtaining the Reference Space

To compute spatial poses from an XRFrame, you must supply an XRReferenceSpace. Three.js manages this reference space internally, and you can retrieve it using renderer.xr.getReferenceSpace().

renderer.setAnimationLoop((timestamp, frame) => {
  if (frame) {
    const referenceSpace = renderer.xr.getReferenceSpace();
    
    if (referenceSpace) {
      // Query poses using frame and referenceSpace
    }
  }

  renderer.render(scene, camera);
});

Accessing Viewer and Head Tracking Data

The primary method for accessing headset tracking data from an XRFrame is frame.getViewerPose(referenceSpace). This method returns an XRViewerPose object containing the viewer's position, orientation, and an array of views (one for each eye in stereoscopic rendering).

renderer.setAnimationLoop((timestamp, frame) => {
  if (frame) {
    const referenceSpace = renderer.xr.getReferenceSpace();
    const viewerPose = frame.getViewerPose(referenceSpace);

    if (viewerPose) {
      // Read the head transform matrix
      const matrix = viewerPose.transform.matrix;
      
      // Read position and orientation
      const position = viewerPose.transform.position; // { x, y, z, w }
      const orientation = viewerPose.transform.orientation; // { x, y, z, w }

      // Access individual eye views
      viewerPose.views.forEach((view) => {
        const projectionMatrix = view.projectionMatrix;
        const eyeTransform = view.transform;
      });
    }
  }

  renderer.render(scene, camera);
});

Accessing Input Source and Controller Poses

To query tracking data for controllers or tracked hands directly from the WebXR API, use frame.getPose(space, referenceSpace). You can extract the targetRaySpace or gripSpace from the session's input sources.

renderer.setAnimationLoop((timestamp, frame) => {
  if (frame) {
    const session = frame.session;
    const referenceSpace = renderer.xr.getReferenceSpace();

    for (const inputSource of session.inputSources) {
      if (inputSource.gripSpace) {
        const gripPose = frame.getPose(inputSource.gripSpace, referenceSpace);

        if (gripPose) {
          const gripPosition = gripPose.transform.position;
          const gripOrientation = gripPose.transform.orientation;
          // Use raw grip position/orientation for custom logic
        }
      }
    }
  }

  renderer.render(scene, camera);
});

While Three.js simplifies controller tracking via renderer.xr.getController() and renderer.xr.getControllerGrip(), accessing frame.getPose() directly is necessary when writing custom XR subsystems, handling AR anchors, or querying hit-test sources.
