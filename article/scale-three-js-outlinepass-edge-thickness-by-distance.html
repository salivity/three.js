Scale Three.js OutlinePass Edge Thickness by Distance

This article explains how to dynamically calculate and scale the edgeThickness property of the Three.js OutlinePass so that the outline around a 3D object maintains a consistent physical or relative size regardless of camera distance. By calculating the distance from the camera to the target object and adjusting the post-processing outline thickness in your render loop, you can prevent outlines from appearing disproportionately thick or thin as the camera moves.

The Screen-Space Problem

In Three.js, OutlinePass generates selection outlines using a post-processing blur shader that operates directly in screen space (pixel coordinates). Because the default edgeThickness value is defined in texels rather than world units, an object moving away from the perspective camera shrinks in screen size while its outline retains a fixed pixel width. This causes the outline to overpower distant objects and appear negligible on close-up objects.

The Distance Scaling Formula

To make an outline scale naturally with perspective—behaving like fixed world-space geometry—the screen-space edgeThickness must be proportional to the object's projected size on screen.

For a perspective camera, the projected height of an object is inversely proportional to its distance from the camera and is influenced by the camera's field of view (FOV):

\[\text{Scale Factor} = \frac{1}{2 \cdot \tan\left(\frac{\text{FOV} \cdot \pi}{360}\right) \cdot \text{distance}}\]

Applying this to edgeThickness:

\[\text{edgeThickness} = \text{baseThickness} \cdot \left(\frac{\text{referenceDistance}}{\text{currentDistance}}\right)\]

Where:

  • baseThickness is your desired outline thickness at a known reference distance.
  • referenceDistance is the distance at which the outline looks optimal.
  • currentDistance is the Euclidean distance between the camera and the target mesh.

Implementation in Three.js

Calculate the distance to your selected object and update outlinePass.edgeThickness within the animation loop before rendering.

import * as THREE from 'three';

// Configuration
const BASE_THICKNESS = 2.5;
const REFERENCE_DISTANCE = 10.0;
const MIN_THICKNESS = 0.5;
const MAX_THICKNESS = 6.0;

function updateOutlineThickness(outlinePass, camera, targetObject) {
    if (!targetObject || !outlinePass.selectedObjects.length) return;

    // 1. Get the world position of the target object
    const targetPosition = new THREE.Vector3();
    targetObject.getWorldPosition(targetPosition);

    // 2. Compute distance from the camera to the object
    const distance = camera.position.distanceTo(targetPosition);

    // Prevent division by zero
    if (distance <= 0.001) return;

    // 3. Calculate perspective-scaled thickness
    const scaledThickness = BASE_THICKNESS * (REFERENCE_DISTANCE / distance);

    // 4. Clamp the value to prevent visual artifacts in the blur pass
    outlinePass.edgeThickness = THREE.MathUtils.clamp(
        scaledThickness,
        MIN_THICKNESS,
        MAX_THICKNESS
    );
}

// Render loop integration
function animate() {
    requestAnimationFrame(animate);

    if (outlinePass.selectedObjects.length > 0) {
        updateOutlineThickness(outlinePass, camera, outlinePass.selectedObjects[0]);
    }

    composer.render();
}

Handling Multiple Selected Objects

If your OutlinePass.selectedObjects array contains multiple meshes located at varying depths, calculating the distance to a single object will distort the appearance of outlines on others. To address this:

  1. Use Bounding Spheres: Calculate a unified THREE.Box3 or THREE.Sphere containing all selected objects, then measure the distance from the camera to the bounding center.
  2. Multiple Outline Passes: Split objects at significantly different depths into separate OutlinePass instances, updating each pass's edgeThickness independently.

Clamping and Shader Limits

The OutlinePass blur shader samples neighboring pixels based on edgeThickness. Setting edgeThickness below 1.0 may cause lines to disappear or shimmer due to subpixel rasterization limits, while setting it too high (typically above 6.0 to 8.0, depending on render resolution) will produce noticeable sampling gaps and banding artifacts rather than a smooth border. Always clamp the resulting thickness between practical visual bounds.
