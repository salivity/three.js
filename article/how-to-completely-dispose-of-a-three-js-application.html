How to Completely Dispose of a Three.js Application

Completely destroying a Three.js application instance requires freeing both CPU and GPU resources to prevent critical memory leaks, especially within Single Page Applications (SPAs). This process involves canceling the active animation frame loop, systematically traversing the scene graph to dispose of geometries, materials, and textures, tearing down active controllers and event listeners, and finally disposing of the WebGL renderer and its canvas element.

1. Cancel the Animation Loop

Before releasing any WebGL resources, stop the rendering loop. Continuing to render during or after disposal will trigger runtime errors and attempt to access destroyed WebGL contexts.

// If using requestAnimationFrame
cancelAnimationFrame(animationFrameId);

// If using WebGLRenderer's setAnimationLoop
renderer.setAnimationLoop(null);

2. Traverse and Dispose of the Scene

The Scene object is an organizational node, but its child objects hold direct references to GPU buffers (geometries) and WebGL programs (materials and textures). You must traverse the hierarchy and dispose of these items explicitly.

function cleanScene(scene) {
  scene.traverse((object) => {
    if (!object.isMesh) return;

    // Dispose geometry
    if (object.geometry) {
      object.geometry.dispose();
    }

    // Dispose material and associated textures
    if (object.material) {
      cleanMaterial(object.material);
    }
  });

  // Remove all child objects from the scene graph
  while (scene.children.length > 0) {
    scene.remove(scene.children[0]);
  }
}

function cleanMaterial(material) {
  // Handle multi-material arrays
  if (Array.isArray(material)) {
    material.forEach(cleanMaterial);
    return;
  }

  // Dispose all texture maps assigned to the material
  for (const key of Object.keys(material)) {
    const value = material[key];
    if (value && typeof value === 'object' && 'minFilter' in value) {
      value.dispose();
    }
  }

  material.dispose();
}

3. Handle Cameras and Controls

Cameras themselves do not allocate WebGL buffers and do not feature a .dispose() method. However, auxiliary controls connected to cameras (such as OrbitControls) bind DOM events and internal state that must be freed:

if (controls) {
  controls.dispose();
}

If the camera was added to the scene hierarchy (common when attaching light sources or audio listeners to it), ensure it is detached when clearing the scene.

4. Dispose of the WebGLRenderer

Calling .dispose() on the renderer releases its WebGL context and internal caches (such as render targets, programs, and shadow maps). Afterward, remove the canvas from the DOM.

// Dispose renderer resources
renderer.dispose();

// Force the WebGL context loss to free VRAM immediately (optional but recommended)
renderer.forceContextLoss();

// Remove the canvas element from the DOM
if (renderer.domElement && renderer.domElement.parentNode) {
  renderer.domElement.parentNode.removeChild(renderer.domElement);
}

5. Remove Event Listeners and References

Unbind any global or element-specific listeners created for the instance, such as resize or pointer events:

window.removeEventListener('resize', onWindowResize);

Finally, set all primary instance variables (renderer, scene, camera, controls) to null so the JavaScript garbage collector can reclaim their host memory.
