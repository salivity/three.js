HalfFloatType Extensions for Three.js Rendering

Rendering textures configured with THREE.HalfFloatType in Three.js provides high dynamic range (HDR) color precision while conserving memory compared to standard 32-bit float textures. Depending on whether your application runs on WebGL 1.0 or WebGL 2.0, different GPU extensions are mandatory to support creating, sampling, and rendering to 16-bit floating-point textures. This guide details the exact hardware extensions required in both environments.

WebGL 1.0 Requirements

In a legacy WebGL 1 context, half-precision floating-point textures are not natively supported and rely entirely on extensions:

  1. OES_texture_half_float
    This base extension allows WebGL 1 to allocate, upload, and read pixel data in half-precision format (gl.HALF_FLOAT_OES). Without this, configuring a texture with THREE.HalfFloatType will cause a WebGL error during texture upload.

  2. OES_texture_half_float_linear
    By default, OES_texture_half_float only supports nearest-neighbor filtering (THREE.NearestFilter). If you configure minFilter or magFilter to use THREE.LinearFilter or mipmap linear interpolation, this extension must be present on the client hardware. Without it, sampling the texture returns invalid data or causes rendering artifacts.

  3. EXT_color_buffer_half_float
    If you use THREE.WebGLRenderTarget with type: THREE.HalfFloatType to render a scene or post-processing pass into a half-float buffer, this extension is required. It enables the GPU to bind 16-bit floating-point textures to framebuffers as color attachments.

WebGL 2.0 Requirements

WebGL 2.0 includes standard texture storage for half-float formats natively, removing the need for base allocation extensions. However, advanced operations still depend on specific extensions:

  1. Native Support (Core)
    Basic storage, pixel transfers, and nearest-neighbor sampling for half-float formats (such as RGBA16F, RGB16F, and R16F) are built into core WebGL 2.0. No extension is needed solely to define or upload a THREE.HalfFloatType texture.

  2. OES_texture_float_linear
    While nearest filtering is built-in, linear filtering for both 32-bit and 16-bit floating-point textures requires this extension in WebGL 2.0. If an application attempts to use THREE.LinearFilter on a HalfFloatType texture without this extension, WebGL 2 will fall back to returning black/incomplete texture data.

  3. EXT_color_buffer_float
    In WebGL 2.0, rendering into a THREE.WebGLRenderTarget configured with THREE.HalfFloatType requires EXT_color_buffer_float. This extension permits rendering to 16-bit floating-point framebuffers (such as RGBA16F) as well as 32-bit floating-point buffers.

Verifying Extension Availability in Three.js

Three.js checks and activates these extensions automatically when needed, but you can verify hardware support programmatically through the renderer:

const gl = renderer.getContext();

// WebGL 2 checks
const hasLinearFilter = renderer.extensions.has('OES_texture_float_linear');
const canRenderToHalfFloat = renderer.extensions.has('EXT_color_buffer_float');

// WebGL 1 checks (if applicable)
const hasHalfFloat = renderer.extensions.has('OES_texture_half_float');
const hasHalfFloatLinear = renderer.extensions.has('OES_texture_half_float_linear');
const canRenderToHalfFloatWGL1 = renderer.extensions.has('EXT_color_buffer_half_float');

If the hardware lacks linear filtering support, set texture.minFilter = THREE.NearestFilter and texture.magFilter = THREE.NearestFilter to maintain functional rendering.
