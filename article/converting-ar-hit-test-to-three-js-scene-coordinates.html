Converting AR Hit Test to Three.js Scene Coordinates

Accurately placing 3D objects in augmented reality requires transforming the raw hit-test poses returned by the WebXR Device API into the appropriate local coordinate space of your Three.js scene graph. Because the WebXR hit test yields transformations relative to a specific XR reference space, you must align these results with Three.js's world space and subsequently convert them into the local space of your target parent container using inverse transformations.

1. Retrieve the Pose from the XRHitTestResult

When performing a hit test in an active WebXR session, each hit yields an XRHitTestResult. To extract its real-world position and orientation, query its pose against the session's active reference space (usually 'local-floor' or 'viewer').

const hitTestResults = frame.getHitTestResults(hitTestSource);

if (hitTestResults.length > 0) {
  const hit = hitTestResults[0];
  const referenceSpace = renderer.xr.getReferenceSpace();
  const pose = hit.getPose(referenceSpace);

  if (pose) {
    // pose.transform represents the position and orientation in XR space
    applyHitToThreeObject(pose.transform, myMesh, targetParent);
  }
}

2. Map the XR Pose to Three.js World Coordinates

The pose.transform.matrix is a 16-element Float32Array representing a standard 4x4 transformation matrix in column-major order. Three.js matrices share this format, allowing you to load the pose directly into a THREE.Matrix4.

const hitMatrix = new THREE.Matrix4();
hitMatrix.fromArray(pose.transform.matrix);

If your Three.js scene's root reference space aligns 1:1 with the XR session reference space (which is standard when using renderer.xr.enabled = true), this matrix represents the target's transform in Three.js world space.

3. Convert World Space to Local Scene Coordinates

If you are adding the object directly to the root scene, you can decompose the matrix directly to set the object's position and quaternion. However, if the object is being placed inside an existing THREE.Group or another parent with its own transformations, you must convert the world coordinates into the parent’s local space.

Use the parent container's world matrix to invert the hit transformation:

function placeObjectInParent(hitMatrix, childObject, parentContainer) {
  // Ensure the parent's world matrix is current
  parentContainer.updateWorldMatrix(true, false);

  // Compute the inverse of the parent's world matrix
  const inverseParentMatrix = new THREE.Matrix4();
  inverseParentMatrix.copy(parentContainer.matrixWorld).invert();

  // Multiply the parent's inverse by the hit world matrix to get the local matrix
  const localMatrix = new THREE.Matrix4();
  localMatrix.multiplyMatrices(inverseParentMatrix, hitMatrix);

  // Decompose local matrix into the child object's local transforms
  localMatrix.decompose(
    childObject.position,
    childObject.quaternion,
    childObject.scale
  );
}

Alternative: Using Vector Conversion

If you only need position and orientation without complex hierarchical scaling, you can decompose the world matrix first and use the built-in helper method:

const worldPosition = new THREE.Vector3();
const worldQuaternion = new THREE.Quaternion();
const worldScale = new THREE.Vector3();

// Decompose the hit pose matrix
hitMatrix.decompose(worldPosition, worldQuaternion, worldScale);

// Convert world position to parent's local space
parentContainer.worldToLocal(worldPosition);

// Assign local position
childObject.position.copy(worldPosition);

// Assign local orientation (adjusting for parent rotation)
childObject.quaternion.copy(worldQuaternion)
  .premultiply(parentContainer.getWorldQuaternion(new THREE.Quaternion()).invert());

Best Practices

  • Update Matrices First: Always call parent.updateWorldMatrix(true, false) before transforming coordinates if the parent or its ancestors have moved in the same frame.
  • Reuse Math Objects: Avoid garbage collection spikes inside your render loop by instantiating THREE.Matrix4, THREE.Vector3, and THREE.Quaternion instances once outside the setAnimationLoop callback and reusing them.
  • Reticle Smoothing: Instead of immediately moving objects to the raw hit position, interpolate (lerp for position, slerp for quaternion) to prevent jitter caused by sensor noise in tracking.
