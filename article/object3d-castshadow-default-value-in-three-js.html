Object3D castShadow Default Value in Three.js

This article explains the default boolean value of the Object3D.castShadow property in Three.js and the technical reasons behind its architectural design. In real-time 3D graphics, managing rendering performance is critical, and understanding how Three.js handles shadow casting by default allows developers to build efficient, high-performance web applications without running into unexpected GPU bottlenecks.

The Default Value

In Three.js, the default value of Object3D.castShadow is false. Because nearly all renderable entities—including Mesh, Points, and Line—inherit directly from Object3D, instances of these objects will not cast shadows onto other surfaces unless explicitly configured to do so.

const geometry = new THREE.BoxGeometry();
const material = new THREE.MeshStandardMaterial({ color: 0x00ff00 });
const cube = new THREE.Mesh(geometry, material);

console.log(cube.castShadow); // Output: false

Why castShadow Defaults to False

The decision to make castShadow false by default is primarily driven by rendering performance, GPU resource constraints, and developer control.

1. High Performance Overhead of Shadow Mapping

Three.js predominantly uses shadow maps to generate dynamic shadows. A shadow map requires an extra rendering pass from the perspective of each shadow-casting light source:

  • The scene must be rendered from the light's point of view to record depth information into a shadow texture.
  • If every object cast shadows automatically, the renderer would have to process every vertex and face in the scene multiple times per frame (once for the main camera and once for each active shadow light).
  • Defaulting castShadow to true would severely degrade frame rates, particularly on mobile devices and integrated GPUs with limited fill-rate and memory bandwidth.

2. The Opt-In Design Principle

Three.js follows an opt-in philosophy for computationally expensive features. By requiring developers to explicitly set mesh.castShadow = true, the engine ensures that only visually critical objects contribute to the depth map calculations. Many objects in a typical scene—such as background foliage, distant terrain, particles, UI elements, and interior room walls—do not need to cast shadows to produce a convincing image.

3. Draw Call and State Change Reduction

Every object included in a shadow pass requires additional draw calls and WebGL state changes. Minimizing the number of objects rendered during the shadow-casting phase directly minimizes CPU overhead and WebGL API communication, ensuring smoother overall application performance.

Enabling Shadows in Practice

To project shadows from a mesh, you must deliberately set the property to true on the specific object while also ensuring shadows are enabled on the renderer and the illuminating light:

// 1. Enable shadows on the renderer
renderer.shadowMap.enabled = true;

// 2. Enable shadows on a supported light
const light = new THREE.DirectionalLight(0xffffff, 1);
light.castShadow = true;
scene.add(light);

// 3. Enable casting on the mesh
mesh.castShadow = true;

// 4. Enable receiving on the surface receiving the shadow
floor.receiveShadow = true;

By keeping castShadow set to false by default, Three.js prevents accidental performance degradation and encourages deliberate, optimized scene construction.
