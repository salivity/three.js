Understanding morphTargetsRelative in Three.js

In Three.js, the morphTargetsRelative property on a BufferGeometry determines whether morph target attribute data represents absolute world-space positions or relative displacement vectors. By default, this boolean is set to false, treating target vertices as complete coordinates. Toggling it to true reconfigures the vertex shader mathematics from an interpolation between full coordinates to an additive accumulation of positional deltas, fundamentally changing how vertex positions, normals, and tangents are computed on the GPU.

Absolute Morph Targets (morphTargetsRelative = false)

When morphTargetsRelative is false, each morph target buffer stores the absolute coordinates of the mesh in that specific morphed state. A vertex in the morph target buffer is defined in the same coordinate space as the base position attribute.

Mathematically, the shader calculates the displacement by finding the difference between the morph target's position and the original base vertex position before applying the target's influence weight:

\[\mathbf{v}_{\text{final}} = \mathbf{v}_{\text{base}} + \sum_{i=1}^{n} w_i (\mathbf{v}_{\text{target}, i} - \mathbf{v}_{\text{base}})\]

Where:

  • \(\mathbf{v}_{\text{base}}\) is the original vertex position attribute.
  • \(\mathbf{v}_{\text{target}, i}\) is the absolute position defined in morph target \(i\).
  • \(w_i\) is the scalar weight (influence) of morph target \(i\).

In this mode, if an individual weight \(w_i\) is 1.0 and all other weights are 0.0, the vertex position simplifies directly to \(\mathbf{v}_{\text{target}, i}\). However, combining multiple morph targets requires the shader to subtract the base position repeatedly for every active target buffer.

Relative Morph Targets (morphTargetsRelative = true)

When morphTargetsRelative is set to true, each morph target buffer does not store absolute positions. Instead, it stores precomputed delta values—the displacement vector (\(\Delta \mathbf{v}\)) representing how far a vertex moves away from the base mesh.

The shader calculation eliminates the subtraction step entirely and performs pure additive blending:

\[\mathbf{v}_{\text{final}} = \mathbf{v}_{\text{base}} + \sum_{i=1}^{n} w_i \Delta \mathbf{v}_i\]

Where:

  • \(\Delta \mathbf{v}_i\) is the precomputed offset stored directly inside the morph target attribute buffer.

Because the buffer data already represents the vector difference (\(\mathbf{v}_{\text{target}} - \mathbf{v}_{\text{base}}\)), the GPU simply multiplies the offset by the influence weight and adds it to the base position.

Impact on Normals and Tangents

The mathematics apply identically to morph normals and morph tangents:

  • Absolute Mode (false): The shader computes \((\mathbf{n}_{\text{target}, i} - \mathbf{n}_{\text{base}}) \times w_i\) and adds it to the base normal.
  • Relative Mode (true): The shader assumes the buffer holds precomputed delta normals (\(\Delta \mathbf{n}_i\)) and computes \(\mathbf{n}_{\text{base}} + \sum (w_i \Delta \mathbf{n}_i)\), followed by normalization.

Practical Implications and Performance

  1. Format Standards: Modern 3D formats like glTF 2.0 define morph targets as relative displacements by design. When loading glTF models via GLTFLoader, Three.js automatically sets morphTargetsRelative = true. Older formats or manual buffer setups often use absolute coordinates.
  2. Shader Efficiency: Relative targets require fewer arithmetic operations in the vertex shader. The GPU skips calculating \((\mathbf{v}_{\text{target}} - \mathbf{v}_{\text{base}})\) for every vertex across every active morph target on every frame, executing a single multiply-add operation per target instead.
  3. Sparse Updates and Storage: Relative offsets naturally lend themselves to sparse morph target data, as unchanged vertices have an offset of \((0, 0, 0)\), whereas absolute targets must duplicate the base mesh positions for unmoved vertices.
